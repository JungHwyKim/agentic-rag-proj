# 경고 순서를 자식 컨텍스트로 되돌리고, 유료 경계 가드를 건다

- 검증일: 2026-08-25
- 대상: [task_log/2026-08-25-경고순서-자식컨텍스트.md](../task_log/2026-08-25-경고순서-자식컨텍스트.md)
  (`loader/content/` 의 `base.py` · `router.py`, 미커밋)
- 비용: **외부 API 호출 없음.** vision 0회 · llamaparse 0회 · 임베딩 0회. 측정 스크립트가
  `openai_api_key` · `llama_cloud_api_key` 를 빈 문자열로 덮었고 실측에서도 `vision_calls=0`
  이었다. `-m integration` 은 안 돌렸다

## 1. 확인하려 한 것

**"규칙이 도는가" 쪽이다.** 임계값을 정하는 검증이 아니다.

1. 병렬 워커가 남긴 경고가 **완료 순서가 아니라 문서 순서**로 쌓이는가
2. 직렬 핸들러의 경고와 **제자리에 섞이는가**
3. `absorb()` 가 **유료 카운터가 묻은 자식을 거부하는가**
4. 이 장치가 산출물이나 성능을 바꾸지 않는가

**1~3 은 실파일이 못 답한다** — 아래 3절에 이유가 있다. 4만 실파일이 답한다.

## 2. 가상 데이터

무엇을 고립시켰나: **리전마다 서로 다른 경고**를 남기게 하고 완료 순서를 문서 순서와
어긋나게 만들었다. 앞 회차의 `_fake_ocr` 헬퍼에 `on_call(ctx, index)` 로 리전 번호를 넘겨,
경고 문구가 자기 자리를 담게 한 것이 이번에 바꾼 축이다.

```python
# tests/conftest.py 의 png_bytes 를 그대로 쓴다. 리전 i 는 폭 400+i
# 지연은 (개수 - i) 에 비례 — 뒤 리전이 먼저 끝나 완료 순서가 문서 순서와 어긋난다
def _extract(image, config, **kwargs):
    index = image.width - 400
    time.sleep((count - index) * delay)
    if on_call is not None:
        on_call(kwargs.get("ctx"), index)
    return f"텍스트-{index}"

_fake_ocr(mocker, 12, on_call=lambda ctx, index: ctx.warn(f"경고 {index:02d}"))
regions = [_image_region(i, png_bytes(400 + i, 200)) for i in range(12)]
```

### 고치기 전에 먼저 돌렸다

**테스트를 먼저 쓰고 옛 코드에서 깨지는 것을 확인했다.** 안 깨지면 그 테스트는 아무것도
안 지킨다.

```
FAILED test_warning_order_follows_document_order
  At index 0 diff: '경고 07' != '경고 00'
FAILED test_serial_and_parallel_warnings_interleave
  At index 0 diff: '이미지 2' != '이미지 0'
```

앞엣것이 **완료 순서**로 쌓였다는 증거이고, 뒤엣것이 **병렬 경고가 직렬 경고보다 통째로
앞에 몰렸다**는 증거다(`['이미지 2', '이미지 0', '텍스트 1', '텍스트 3']`).

### 결과

| 입력 | 기대 | 실측 | 판정 |

| 이미지·텍스트 4개 교차, 둘 다 경고 | `이미지 0 · 텍스트 1 · 이미지 2 · 텍스트 3` | 그대로 | 통과 |

## 7. 재지 못한 것

- **핸들러 경고가 실제로 나는 실파일에서 못 쟀다.** 위 3절 참고 — 이 문서는 OCR 이 47/47
  성공해 병렬 구간이 경고를 안 낸다. 가상으로만 확인했다
- **`absorb()` 가드가 실전에서 발화하는 것을 못 봤다.** 코드를 잘못 고쳐야 도달하는 자리라
  가상으로만 확인했고, 그것이 이 가드의 목적이다
- **`evaluation/run_eval.py` 리포트의 경고 순서 개선을 못 쟀다.** 그쪽은 전체 `ingest()` 를
  타므로 이번 변경의 수혜자인데, 돌리려면 임베딩 과금이 붙어 안 돌렸다
- **`regression.measure` 의 cp949 크래시는 이번에도 그대로다** — 달라진 항목이 있을 때
  마지막 요약 줄의 em-dash 가 `UnicodeEncodeError` 를 낸다(출력은 다 나온 뒤라 수치에는
  영향 없음). 이번 변경과 무관하고 고치지 않았다
