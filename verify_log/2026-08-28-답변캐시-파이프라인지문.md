## 1. 확인하려 한 것

둘인데 종류가 다르다.

- **규칙이 도는가** — 저장 시점의 설정 지문이 payload 에 실리고, 조회 때 대조돼 다르면
  미스가 나는가. 그리고 컬렉션 차원이 어긋날 때 **예외 없이** 저장만 접는가
- **지문이 실제로 무엇을 담는가** — 이건 개발자 머신의 실제 `.env` 로만 보인다.
  단위 테스트는 꽂아 넣은 설정을 재므로 *`.env` 가 무엇을 흘려보내는지* 를 못 잡는다

**임계값은 이 회차에 없다.** 지문은 문자열 동등 비교라 정할 값이 없다.

## 2. 가상 데이터

무엇을 고립시켰나: **실제 qdrant 엔진을 쓰되 내용은 합성**이다. 임시 경로에 컬렉션을 만들고
근거 청크 하나를 진짜로 색인한 뒤, **지문만 한 축으로 바꿔** 히트/미스를 본다.
운영 `.qdrant` 를 안 건드리는 것이 요점이고(서버가 배타 잠금을 든다), 임베더는 늘 같은 단위
벡터를 주는 가짜라 외부 호출이 없다.

```python
"""실제 qdrant 로 지문 왕복을 확인한다. 외부 API 를 안 부르고 임시 경로만 쓴다."""

from __future__ import annotations

import tempfile
from pathlib import Path

from rag_pipeline.answer_cache import QdrantAnswerCache
from rag_pipeline.config import AnswerCacheConfig, EmbeddingConfig, IndexingConfig
from rag_pipeline.ingestion.indexing.qdrant_store import QdrantStore
from rag_pipeline.schemas.answer import Answer
from rag_pipeline.schemas.retrieval import RetrievedChunk
from rag_pipeline.schemas.vector import VectorRecord, point_id_for

FP_A = "v1|bm25=1|top_k=5|rewrite(rewrite_mode=fuse)"
FP_B = "v1|bm25=1|top_k=5|rewrite(rewrite_mode=replace)"
VECTOR = [0.6, 0.8] + [0.0] * 6


# 늘 같은 단위 벡터를 주는 임베더 자리. 외부 호출이 없다
class Embedder:
    def embed_query(self, text: str) -> list[float]:
        return list(VECTOR)


def main() -> None:
    with tempfile.TemporaryDirectory() as tmp:
        path = Path(tmp) / "qdrant"
        indexing = IndexingConfig(qdrant_path=path)
        embedding = EmbeddingConfig(embedding_model="테스트모델", embedding_dimensions=len(VECTOR))
        store = QdrantStore(indexing, embedding)
        try:
            # 근거 청크를 진짜로 색인한다 — 무효화 판정이 이것을 되짚는다
            chunk_id = "안내서.pdf:0001"
            store.ensure_collection(len(VECTOR))
            store.upsert(
                [
                    VectorRecord(
                        id=point_id_for(chunk_id),
                        vector=VECTOR,
                        document_id="안내서.pdf",
                        chunk_id=chunk_id,
                        text="제12조 유예기간은 6개월로 한다.",
                        metadata={"source_name": "안내서.pdf", "page": 4},
                    )
                ]
            )

            cache = QdrantAnswerCache(
                store,
                indexing=indexing,
                embedding=embedding,
                config=AnswerCacheConfig(),
                mode="exact",
                threshold=None,
            )
            embedder = Embedder()
            source = RetrievedChunk(
                chunk_id=chunk_id,
                document_id="안내서.pdf",
                text="제12조 유예기간은 6개월로 한다.",
                metadata={"source_name": "안내서.pdf", "page": 4},
                dense_score=0.9,
            )
            answer = Answer(query="유예기간이 언제까지인가요?", text="6개월입니다.", sources=[source])

            print(cache.put(answer, embedder=embedder, fingerprint=FP_A))
            print(cache.lookup(answer.query, embedder=embedder, fingerprint=FP_A) is not None)
            print(cache.lookup(answer.query, embedder=embedder, fingerprint=FP_B) is not None)
            print(cache.lookup(answer.query, embedder=embedder, fingerprint=FP_A) is not None)
            print(cache.collection, cache.warnings)
        finally:
            store.close()


if __name__ == "__main__":
    main()
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `put(fingerprint=FP_A)` | `True` | `True` | 통과 |
| `lookup(fingerprint=FP_A)` | 히트 | 히트 | 통과 |
| `lookup(fingerprint=FP_B)` — `fuse`→`replace` | **미스** | 미스 | 통과 |
| 다시 `lookup(fingerprint=FP_A)` | **히트** (안 지웠으니) | 히트 | 통과 |
| `cache.warnings` | `[]` | `[]` | 통과 |

넷째 줄이 이 회차의 결정 하나를 실물로 확인한다 — **지문 불일치는 `_drop()` 을 안 부른다.**
지웠다면 여기서 미스가 났을 것이다.

컬렉션 이름은 `qa_cache___8` 로 나왔다. `collection_name_for()` 의 `_UNSAFE` 가 한글 모델명
`테스트모델` 을 통째로 `_` 로 바꾼 것이고, **이 회차와 무관한 관찰이다**(실제 모델명은 ASCII).

### 서버 E2E — 실제로 돌렸다 (2026-08-28)

`.env` 에 `ANSWER_CACHE_MODE=exact` 를 임시로 넣고 **`--reload` 없이 하나만** 띄웠다.
조건을 바꿀 때마다 트리를 죽이고 다시 띄워, 매번 **포트 8000 리슨이 PID 하나**이고 그
프로세스 생성 시각이 `.env` 편집보다 **뒤**인 것을 확인했다(중복 바인딩 함정).
질의는 셸을 안 거치고 `urllib` 으로 보냈다.

| 조건 | 회 | 걸린 시간 | 캐시 | 화면의 재작성 줄 | 왕복 문구 |
|---|---:|---:|---|---|---|
| A · `REWRITE_MODE=fuse` | 1 | 6.55초 | 미스 | 있음 | 일치 |
| A · `REWRITE_MODE=fuse` | 2 | **0.03초** | **히트**(배지 렌더링) | 없음 | 일치 |
| B · `REWRITE_MODE=replace` | 1 | 3.17초 | **미스** | 있음 | 일치 |
| B · `REWRITE_MODE=replace` | 2 | **0.00초** | 히트 | 없음 | 일치 |

**B-1 이 이 작업의 전부다.** 0.03초에 히트하던 그 질문이 `REWRITE_MODE` 한 줄 때문에
미스가 되어 파이프라인을 다시 돌았다. 지문이 없었으면 여기서 `fuse` 시절 답이 나왔을 것이고
**에러도 안 났을 것이다.**

곁가지로 **캐시 히트면 재작성도 안 돈다**가 화면에서 확인됐다 — 히트한 두 회차에서 재작성
줄이 사라진다(검사가 `retrieve()` 앞이라 저절로 그렇다).

**왕복 문구 4/4 일치** — 응답의 사용자 말풍선이 보낸 문자열과 글자까지 같다. cp949 로
도착했으면 여기서 갈렸다.

저장소 상태:

| 항목 | 값 |
|---|---|
| 만들어진 컬렉션 | `qa_cache_nlpai-lab_KURE-v1_default` · dim 1024 |
| `points` (A 뒤 / B 뒤) | 1 / **1** |
| payload 의 `pipeline` (A 뒤 / B 뒤) | `…rewrite_mode=fuse…` / `…rewrite_mode=replace…` |

**`points` 가 둘 다 1인 것은 동어반복이라 판정에 안 쓴다** (2026-08-28 정정).
`put()` 이 `id=cache_point_id_for(answer.query)` 로 저장해 **id 가 질의 문자열 하나로만**
파생되고(지문은 payload 에만 있다) qdrant `upsert` 는 같은 id 면 덮어쓰므로, 같은 질문을
두 번 저장해서 2가 될 경우의 수가 애초에 없었다.

**한때 이것을 「`_drop()` 을 안 부른다」의 근거로 적었는데 틀렸다.** 그 결정의 위험은
`exact` 가 아니라 **`semantic`** 에 있다 — 저쪽은 `lookup()` 이 **제일 가까운** point 를
찾아 남의 질의 point 를 물 수 있고, 그러면 `put()` 은 다른 id 에 써 **불일치 항목이 그대로
남는다.** 여기서 잰 것은 안전한 쪽이고, **위험한 쪽은 `semantic` 이 임계값 없이는 안 켜져
이번에 원리적으로 못 쟀다.**

**그 결정 자체는 검증됐다 — 다만 2절이 한 것이다**(`FP_A` 저장 → `FP_B` 미스 →
`FP_A` **다시 히트**). 지웠으면 거기 셋째 줄이 미스였다.

`query_log` 도 같은 것을 다른 자리에서 말한다:

```
cached=False   6510ms  rewrite_mode=fuse     기록물 보존기간은 어떻게 정하나요?
cached=True       2ms  rewrite_mode=None     기록물 보존기간은 어떻게 정하나요?
cached=False   3120ms  rewrite_mode=replace  기록물 보존기간은 어떻게 정하나요?
cached=True       1ms  rewrite_mode=None     기록물 보존기간은 어떻게 정하나요?
```

되돌린 것: `qa_cache_*` 컬렉션 삭제 · `.env` 복원(**sha256 `e8f8d98bbc58` · 4956 bytes
백업과 바이트 일치**) · uvicorn 0개 확인.

**부작용 하나가 남았다** — `data/queries.jsonl` 이 **38 → 42** 줄이 됐고 넷이 전부 같은
질의라, 아래 반복률을 **위로 민다**. 이 로그가 테스트 질의로 오염된다는 그 미결을
이번 검증이 한 번 더 밟았다.

### 질의 로그 반복률 (`exact` 를 켤지의 근거)

`data/queries.jsonl` 을 `key` 로 세었다.

| 항목 | 값 |
|---|---:|

| 서로 다른 `key` | 37 |
| 반복(2회째 이상) | 1 |

| `cached=true` 인 줄 | 0 |

**표본이 «값을 하는가» 에 답할 만큼이 아니고**, 상당수가 cp949 로 깨진 테스트 질의다.
깨진 질의는 서로 다른 문자열이라 **반복률을 아래로 민다** — 판정 보류.
**위 수치는 서버 E2E 전의 값이다.** E2E 가 같은 질의 4건을 더해 38 → 42 가 됐고,
그쪽은 반대로 반복률을 **위로 민다**. 두 오염이 방향이 반대라 상쇄되지 않는다 —
각각 다른 줄을 오염시킨다.

**갈래를 갈라 세면 셋이고 서로 반대 방향으로 민다** (42줄 기준).

| 갈래 | 줄 | 서로 다른 key | 반복 | 그 갈래의 반복률 | 전체 지표를 |
|---|---:|---:|---:|---:|---|
| uuid 꼬리 프로브 (2026-08-27 재작성 지연 측정) | 28 | 28 | 0 | 0.000 | **아래로** |
| 깨짐 (cp949) | 4 | 4 | 0 | 0.000 | **아래로** |
| 서버 E2E (같은 질의 4회) | 4 | 1 | 3 | 0.750 | **위로** |
| 진짜 사람 질의 | 6 | 5 | 1 | 0.167 | — |
| **합계** | **42** | **38** | **4** | **0.095** | |

읽을 것 셋:

- **오염의 3분의 2는 uuid 프로브 28줄이다.** 그 세션이 재작성 캐시를 늘 미스나게 하려고
  일부러 `uuid4` 꼬리를 붙인 것이라 측정 설계로는 옳았고, 부작용이 여기 남았다
- **그래서 «깨진 줄을 빼고 센다» 로는 안 고쳐진다** — 지표가 오히려 살짝 오르면서 더 큰
  왜곡 둘이 그대로 남는다. 방향이 반대라 상쇄도 안 된다
- **구멍의 위치는 계층이다.** 이 로그는 `run_eval` 오염을 막으려 일부러 backend 에 있고
  `tests/api` 는 autouse 픽스처가 막는다. **안 막힌 것은 사람이 HTTP 로 넣는 측정
  트래픽**이고, 검증 세션이 실사용과 **같은 문으로** 들어온다

덤으로 이 지표는 `key` **완전 일치**만 세므로 **`semantic` 이 값을 할지는 원리적으로 못
답한다.** 실사용 6줄로는 그쪽에 관해 아무 말도 할 수 없다.

| `points` 가 A 뒤·B 뒤 모두 1 | **동어반복 — 판정에 안 쓴다**(id 가 질의로만 파생된다) |
| `semantic` 갈래의 불일치 항목 잔류 | **못 쟀다** — 임계값이 없어 켤 수가 없다 |
