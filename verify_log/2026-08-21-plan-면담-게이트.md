# plan mode 면담 게이트 — 문구 판정과 마커 수명 검증

- 검증일: 2026-08-21
- 대상: [task_log/2026-08-21-plan-면담-게이트.md](../task_log/2026-08-21-plan-면담-게이트.md) (미커밋)
- 비용: 외부 API 호출 없음 (`-m integration` 안 돌림)

## 1. 확인하려 한 것

둘 다 "규칙이 도는가" 쪽이고 임계값을 정하는 검증이 아니다.

- **문구 판정**이 변형을 받아들이면서 부정형을 걸러내나 — 양쪽으로 틀리면 값이 다르다.
  헛되이 열리면 면담 없이 계획이 나가고, 안 열리면 `SKIP_PLANINTERVIEW=1` 이 습관이 된다
- **마커 수명**이 설계대로인가 — `PreToolUse` 는 소비하지 않고 `PostToolUse` 만 소비한다

여기에 하나 더. 훅 입력에 `permission_mode` 가 실제로 오는지 몰라서 리마인더를 fail-open 으로
짰다. **그 가정 자체를 실물로 확인한다**(3절).

## 2. 가상 데이터

무엇을 고립시켰나: **훅 입력 payload 한 축만** 바꿨다. 이벤트·문구·`permission_mode` 를
각각 바꾸고 나머지는 고정한다. 파일도 문서도 필요 없다 — 이 훅의 입력은 JSON 하나다.

```python
# 저장소 루트에서. tests/hooks/test_plan_interview_check.py 의 _run() 과 같은 것을 손으로 편 것
import io, json, sys, pathlib, tempfile
sys.path.insert(0, ".claude/hooks")
import _hookutil, plan_interview_check as pic

root = pathlib.Path(tempfile.mkdtemp()); (root / ".git").mkdir()
_hookutil.PROJECT_ROOT = root          # 마커가 실제 .git/ 에 안 남게 한다
SESSION = "sess-verify"

def run(payload):
    raw = json.dumps(payload, ensure_ascii=False).encode("utf-8")
    # StringIO 가 아니라 TextIOWrapper 다 — read_payload() 가 stdin.reconfigure() 를 부른다
    sys.stdin = io.TextIOWrapper(io.BytesIO(raw), encoding="utf-8")
    pic.main()

def prompt(text, **extra):
    return {"hook_event_name": "UserPromptSubmit", "session_id": SESSION,
            "user_input": text, **extra}

def exit_plan(event):
    return {"hook_event_name": event, "session_id": SESSION, "tool_name": "ExitPlanMode"}

def ready():
    return _hookutil.is_marked(pic.READY_NS, SESSION)
```

### 2-2. 마커 수명

| 순서 | 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|---|
| 1 | `PreToolUse` (문구 전) | deny | deny + 사유에 해제 문구 | 일치 |
| 2 | `UserPromptSubmit` "설계서 작성해줘" | 마커 생김 | 생김 | 일치 |
| 3 | `PreToolUse` ×2 | 통과, **마커 유지** | 통과, 유지 | 일치 |
| 4 | `PostToolUse` | 마커 사라짐 | 사라짐 | 일치 |
| 5 | `PreToolUse` (다시) | deny | deny | 일치 |
| — | `PreToolUse` (`tool_name="Write"`) | 무시 | 출력 없음 | 일치 |
| — | `SKIP_PLANINTERVIEW=1` + `PreToolUse` | 통과 | 출력 없음 | 일치 |

3행이 계약이다. `PreToolUse` 에서 소비하도록 되돌리면 **계획을 거절하고 수정을 요청한
사용자가 다시 막힌다.**

### 2-3. `UserPromptSubmit` 이 0 아닌 종료코드를 내지 않는다

이 이벤트에서 종료코드 2 는 사용자가 방금 친 글을 지운다. 임포트 실패·인코딩 사고까지
잡으려고 **실제 subprocess** 로 쟀다.

| stdin | 기대 | 실측 |
|---|---|---|
| 빈 입력 | 0 | 0 |
| `not json at all` | 0 | 0 |
| `[]` (dict 아님) | 0 | 0 |
| BOM + 정상 JSON | 0 | 0 |
| `user_input: null` | 0 | 0 |

## 3. 실제 데이터

`tests/fixtures/` 문서는 이 검증과 무관하다. 대신 **하네스 실물**을 잰다 — 훅 입력에
`permission_mode` 가 오는가는 문서가 아니라 CLI 바이너리가 답한다.

| 파일 | bytes | sha256(12) |
|---|---:|---|
| `claude.exe` (`C:/Users/junghwy/.local/bin/`) | 330,167,456 | `406167231b36` |

| 항목 | 구현 전 가정 | 이번 실측 | 판정 |
|---|---|---|---|
| `permission_mode` 가 훅 입력에 오나 | **모름** (fail-open 으로 짬) | 온다 | 의도한 변화 |
| 어느 객체에 담기나 | 모름 | `session_id`·`transcript_path`·`cwd`·`prompt_id` 와 같은 공통부 | 의도한 변화 |
| plan mode 의 값 | 모름 | 문자열 `"plan"` | 의도한 변화 |

근거는 바이너리에서 뽑은 payload 생성부다. 훅 이벤트마다 이 객체를 펴 넣으므로
`UserPromptSubmit` 에도 온다.

```
return{session_id:e.id,transcript_path:Qz(e.id),cwd:t,prompt_id:nct()??void 0,
permission_mode:r,agent_id:n?.agentId,agent_type:o,effort:a}
```

값 목록도 같은 바이너리에 리터럴로 있다 — `"default","acceptEdits","bypassPermissions","plan"`.
훅의 비교(`str(mode).strip().lower() == "plan"`)가 이것과 맞는다.

**이 수치는 버전에 묶인다.** 위 sha256 이 아닌 `claude.exe` 에서는 다시 확인해야 한다.

## 7. 재지 못한 것

- **실제 plan mode 왕복을 못 쟀다.** 훅이 실제로 배선돼 도는지, deny 사유가 모델에게 어떻게
  보이는지는 사람이 plan mode 에 들어가 확인해야 한다. 단위 테스트는 handler 를 직접 부르고
  `settings.json` 배선은 `test_hook_wiring.py` 가 정적으로만 본다 — **둘 사이가 비어 있다.**
  절차는 `task_log/2026-08-21-plan-면담-게이트.md` 7절에 있다
- **리마인더가 실제로 출력되는 것을 못 봤다.** `permission_mode` 가 온다는 것은 3절에서
  확인했지만, 이 세션은 plan mode 배선 **이전**에 plan mode 를 지났다
- **`PostToolUse` 가 거절된 `ExitPlanMode` 에서 안 도는 것**을 못 쟀다. 하네스 동작이라
  훅 단위로는 확인할 방법이 없다. 마커가 살아남는 것이 이 가정에 걸려 있고, 틀려도
  "문구를 한 번 더 말한다"로 끝난다
