# 면담 게이트를 AskUserQuestion 답변으로 여는 규칙의 검증

- 검증일: 2026-08-23
- 대상: [task_log/2026-08-23-면담게이트-선택지개방.md](../task_log/2026-08-23-면담게이트-선택지개방.md) (미커밋)
- 비용: **외부 API 호출 없음** (`-m integration` 안 돌림. 전사 분석은 로컬 파일 읽기뿐)

## 1. 확인하려 한 것

둘을 갈라서 쟀다.

- **규칙이 도는가** — 답변 payload 로 게이트가 열리고, 열리면 안 되는 payload 로는 안 열리는가.
  가상 데이터로 답한다
- **어느 규칙을 고를 것인가** — 후보 셋(질문·선택지까지 훑기 / 답만 / 답+대안 가드) 중
  오탐·누락이 가장 적은 것. **가상으로는 못 답한다** — 합성 payload 는 내가 기대한 모양을
  그대로 갖고 있어 자기 확인이 된다. 실제 대화 기록(전사)이 있어야 정해진다

## 2. 가상 데이터

무엇을 고립시켰나: **답 텍스트**와 **그 문항의 선택지 구성** 두 축만 바꾼다. 나머지
(도구 이름·이벤트·세션)는 고정이다.

```python
# tests/hooks/test_plan_interview_check.py 의 헬퍼. 실제 tool_response 모양 그대로다 —
# {questions, answers, annotations} 이고 answers 가 {질문 텍스트: 고른 라벨}
def _ask(rounds: list[tuple[str, list[str], str]], *, field: str = "tool_response") -> dict:
    return {
        "hook_event_name": "PostToolUse",
        "session_id": SESSION,
        "tool_name": "AskUserQuestion",
        field: {
            "questions": [
                {
                    "question": question,
                    "header": "진행",
                    "multiSelect": False,
                    "options": [{"label": label, "description": ""} for label in labels],
                }
                for question, labels, _ in rounds
            ],
            "answers": {question: chosen for question, _, chosen in rounds},
            "annotations": {},
        },
    }
```

| 입력 (선택지 → 고른 답) | 기대 | 실측 | 판정 |
|---|---|---|---|
| `[지금 설계서 작성, 라운드 더]` → `지금 설계서 작성` | 열림 + 안내 1줄 | 열림 + 안내 1줄 | 일치 |
| `["설계서 작성" 포함 변형, 정확히 "설계서 작성해줘" 만]` → 앞엣것 | **안 열림** | 안 열림 | 일치 |
| `[설계서 작성해줘, 라운드를 더 돌자]` → `라운드를 더 돌자` (질문 텍스트에 문구 있음) | 안 열림 | 안 열림 | 일치 |
| `[합성+실파일 둘 다, 합성만, 실파일만]` → `1번. 설계서 작성해줘` (Other 자유입력) | 열림 | 열림 | 일치 |
| `[지금 설계서 작성, 라운드 더]` → `아직 설계서 작성하지 마` | 안 열림 | 안 열림 | 일치 |
| 같은 payload 를 `tool_input` 에 실어 보냄 | 열림 | 열림 | 일치 |
| 답변 → `PreToolUse(ExitPlanMode)` | 조용히 통과 | 조용히 통과 | 일치 |
| 같은 답변 2회 | 안내 2줄 (throttle 없음) | 2줄 | 일치 |

### 변이 검사 — 그 테스트가 실제로 무는가

대안 가드(`if any(not _opens_gate(label) for label in labels)`)를 `if True` 로 바꿔 돌렸다.

| 변이 | 기대 | 실측 |
|---|---|---|
| 대안 가드 제거 | `test_answer_without_an_alternative_leaves_the_gate_closed` 만 실패 | 1 failed, 149 passed — 정확히 그 하나 |

원복 후 150 passed 로 복귀했다.

## 3. 실제 데이터

`tests/fixtures/` 문서가 아니라 **이 저장소의 대화 전사**가 입력이다. 게이트를 여는 문구가
과거 대화에서 어떻게 나타났는지는 이것으로만 잴 수 있다.

| 입력 | 개수 | bytes |
|---|---:|---:|
| `~/.claude/projects/C--agentic-rag-proj/*.jsonl` | 55 | 64,150,236 |

**파일별 sha256 을 적지 않는다.** 이 코퍼스는 세션마다 계속 자라서 해시가 즉시 낡는다 —
실제로 분석 시점에 `AskUserQuestion` 결과가 **114건**이었는데 이 기록을 쓰는 사이 **117건**이
됐다. 신원 대신 **분석 시점의 모집단 크기**를 적는 것이 이 입력의 재현 단위다.

모집단: `AskUserQuestion` 결과 **114건** · 답 **236개** (분석 시점). 답 값 타입은 236/236이
문자열이고, `multiSelect` 문항 10개도 문자열 하나로 온다.

### 후보 규칙 대조

| 무엇을 훑나 | 열림 | 진짜 | 오탐 | 누락 |
|---|---:|---:|---:|---:|
| 질문·선택지 텍스트까지 | 9 | 3 | 5 | 0 |
| 답(`answers`)만 | 4 | 3 | 1 | 0 |
| **답 + 대안 선택지 존재** | **3** | **3** | **0** | **0** |

정답(진짜 3건)의 정체 — 전사에서 사람이 실제로 설계서를 요청한 자리다.

```
header=회귀 방지선  answer='1번. 설계서 작성해줘'          (Other 자유입력)  대안 있음
header=다음         answer='설계서 작성해줘'                (선택지 라벨)     대안 있음
header=진행         answer='지금 설계서 작성 (추천)'        (선택지 라벨)     대안 있음
```

오탐 1건 — 대안 가드가 걸러낸 것.

```
header=트리거 문구  answer='"설계서 작성" 포함 변형 (추천)'
                    선택지 = ['"설계서 작성" 포함 변형 (추천)', '정확히 "설계서 작성해줘" 만']
                    → 둘 다 문구를 담아 어느 쪽을 골라도 열리는 문항. 대안 없음
```

`header` 를 고정값으로 못 박는 안도 함께 쟀다 — `header` 에 `설계서` 가 든 문항은
**0건**이라 진짜 3건을 전부 놓친다.

## 7. 재지 못한 것

- **`AskUserQuestion` 에 `PostToolUse` 훅이 실제로 도는가.** 이 설계의 성립 조건인데
  합성 payload 로는 못 잰다(핸들러를 직접 부르기 때문). 배포된 `claude.exe` 의 훅 문서가
  `PostToolUse | Tool name | Run after successful tool` 이고 제외 목록이 없다는 것까지가
  확인이고, **배선 확인은 아니다.** 사람이 plan mode 왕복을 한 번 하고
  `.git/claude_plan_interview_ready/<session>` 이 생기는지 봐야 한다
- **모델이 선택지를 기울여 쓰는 경우.** 대안 가드는 "대안이 있었나"만 보고 "그 대안이
  진짜였나"는 못 본다. 그런 라운드가 실제로 나와야 잴 수 있다
- **`_in_plan_mode()` 를 안 씌운 판단의 대가.** plan mode 밖에서 이 경로가 헛나오는 빈도는
  전사 실측(114건 중 3건, 전부 설계 논의 세션)으로 추정만 했고 앞으로를 잰 것은 아니다
