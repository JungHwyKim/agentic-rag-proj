## 1. 확인하려 한 것

**"규칙이 도는가"가 아니라 "무엇이 안 잡히나"다.** 임계값을 정하는 작업도 아니다 —
기준선의 miss 23건이 **왜** 안 잡혔는지를 갈래로 나누는 것이 목적이고, 갈래 기준은
읽기 **전에** 정해뒀다(`plan_log/평가-세트.md` 8회차).

| 갈래 | 판정 기준 (미리 정한 것) |
|---|---|
| 세트 문제 | 질의와 정답의 짝이 dense 로 원리적으로 안 맞는다. 정답 청크의 전체 순위가 깊다 |
| 청킹 문제 | 정답이 든 청크가 다른 내용에 묻혔다 — `[제목 > 경로]` 머리가 본문을 압도하는 등 |
| 검색 문제 | 짝도 청크도 멀쩡한데 순위만 밀린다. 전체 순위 21~50 이면 유력 |
| 확인 필요 | 셋 중 못 고르면 여기 둔다. **억지로 욱여넣지 않는다** |

가설 하나를 함께 걸었다 — **`include_heading_in_text` 의 머리가 짧은 청크의 임베딩을 덮나.**

## 2. 가상 데이터

무엇을 고립시켰나: 해부 도구의 **판정이 갈리는 세 자리**만 떼어 고정했다. 전 구간은 색인된
컬렉션이 있어야 돌아 여기서 못 쓴다.

```python
# tests/evaluation/test_inspect_misses.py — 그대로 돌면 같은 입력이 나온다
def _group(chunk_id: str, rank: int | None) -> MissGroup:
    return MissGroup(chunk_id=chunk_id, rank=rank, score=0.5, page=1, heading_path=[], text="본문")

rows = [(f"sch-0{i}", _group("지침.pdf:0007", 61)) for i in range(2, 6)]
rows.append(("bas-02", _group("계획.pdf:0013", 25)))
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 같은 청크를 가리키는 질의 4건 | 덩어리 1개 · `query_ids` 넷 | 그대로 | 일치 |
| 순위 300 · None · 22 | `[22, 300, None]` 순 | 그대로 | 일치 |
| `count()` 414 vs 기대 414 | 통과 | 통과 | 일치 |
| `count()` 0 · 413 · 415 · 828 | `SystemExit` + `--dense` 안내 | 전부 발생 | 일치 |
| `[붙임1] …` 본문 · `heading_path` 없음 | 머리비율 **0.0** | 0.0 | 일치 |
| `[A > B]\n` + 본문 100자 | 접두사 길이 / 전체 | 그대로 | 일치 |
| 빈 텍스트 | 0.0 (0으로 안 나눈다) | 0.0 | 일치 |

**`[붙임1]` 케이스가 이 중 유일하게 실파일이 못 만드는 것이다** — 본문이 대괄호로 시작하는
청크를 정규식으로 긁으면 머리로 오인하는데, 그 상황이 실측 코퍼스에 우연히 있어야만 걸린다.

### 3-3. 가설 검증 — 제목 머리가 정답 청크를 덮나 (**기각**)

`hit_rank()` 로 이긴 질의 37건의 정답 청크도 같은 방식으로 찾아 대봤다.

| | n | 머리비율 중앙 | 길이 중앙 | 제목 경로에 `목 차` |
|---|---:|---:|---:|---:|
| miss | 23 | **15.6%** | 349자 | 48% |
| hit | 37 | **16.6%** | 433자 | 49% |
| top3 | 18 | **16.6%** | 470자 | 50% |

**틈이 없다.** 세 무리가 사실상 같은 값이라 이 가설로는 miss 를 설명 못 한다.

반대 방향(머리지배 청크가 상위를 차지해 정답을 밀어내나)도 봤다.

### 3-4. 가설과 별개로 나온 것 — 코퍼스의 제목 머리가 두껍다
