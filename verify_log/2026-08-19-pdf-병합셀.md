# PDF 병합 셀을 되풀이로 채웠다 — 세로 435칸, 가로는 226칸을 일부러 비웠다

- 검증일: 2026-08-19
- 대상: [task_log/2026-08-19-pdf-병합셀.md](../task_log/2026-08-19-pdf-병합셀.md) ·
  [plan_log/표-경로.md](../plan_log/표-경로.md) 3회차
- 비용: **외부 API 호출 없음.** `find_tables()` · `detect_regions()` 만 썼다

## 1. 확인하려 한 것

둘이다. 앞의 것이 풀려야 뒤가 성립한다.

1. **PDF 에서 "병합에 덮인 자리"와 "그냥 빈 칸"을 가릴 수 있는가.** HWPX 는 `cellAddr`·
   `cellSpan` 이 명시적이지만 PDF 는 그런 것이 없어 보였다. 못 가르면 되풀이 자체가 불가능하다
2. **세로 병합과 가로 병합을 가를 수 있는가.** 규칙이 서로 반대라(되풀이 / 비움) 못 가르면
   한쪽이 반드시 틀린다

## 2. 가상 데이터

무엇을 고립시켰나: **세로·가로·평범한 빈 칸 셋을 각각 한 표에 하나씩만** 뒀다. 실파일에는
셋이 섞여 있어 어느 규칙이 작동했는지 분리할 수 없다.

```python
# tests/ingestion/loader/document/test_pdf.py — PyMuPDF 표를 흉내낸다.
# cells 의 None 이 병합에 덮인 자리이고 extract() 는 그 자리에 빈 문자열을 준다
def _fake_table(rows):
    return SimpleNamespace(
        rows=[SimpleNamespace(cells=cells) for cells, _ in rows],
        extract=lambda: [list(values) for _, values in rows],
    )
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 세로 3행 span (`None` 아래로 둘) | 첫 칸이 `준비` 로 채워짐 | 세 행 모두 `준비` | 일치 |
| 가로 span (왼쪽 칸 x1=300 이 전 열을 덮음) + **위에 앵커 있음** | 비운 채로 | `["전체", "", ""]` | 일치 |
| 앵커도 왼쪽도 없는 빈 칸 | 그대로 | `""` | 일치 |

둘째 축이 이번 회차의 핵심이다 — **위에 앵커가 있어도 가로가 이긴다.**

### 눈으로 확인한 표

시행령 4쪽(리전 되붙이기까지 적용된 상태).

```
['단계', '실행항목',  '세부내용 및 방법',        '담당']
['준비', '기준마련',  '기록관리 지침(실행방법) …', '국가기록원\n(디지털기록혁신…']
['준비', '지침확인',  '기록관리 지침 확인',       '시스템부서,\n기록관 공통']

['준비', '대상 확인', '(‘20년) 시스템관리부서…',  '기록관']
```

`준비` 가 4행에, `대상 확인` 이 자기 span 만큼 채워졌다. 고치기 전에는 전부 빈 칸이었다.

### 기준선 대조

**11개 문서 전부 실제 변화 0.** `page_count` · `regions_total` · `regions_by_type` ·
`pages_by_type` · `warnings` 어느 것도 안 움직였다.

`.hwp` 항목 3줄(`regions_by_type` · `pages_by_type` · `warnings` 가 `None → {}`/`[]`)은
**측정 스크립트가 기준선의 "측정 안 함(None)" 을 빈 값으로 적은 표기 차이**이지 변화가 아니다.

이것이 예측과 맞다 — 이번 변경은 **칸의 내용**을 채우지 리전 수를 안 건드린다.

## 5. 판정

- **병합/비병합 구분 — 가능했다.** `row.cells[j] is None` 과 `extract()` 의 빈 문자열을 겹쳐
  보면 갈린다. 이 사실이 없었으면 이번 작업 자체가 성립하지 않는다
- **세로/가로 구분 — 가능했고, 반드시 필요했다.** 34.2% 라는 겹침 비율이 "위만 보면 된다"를
  기각한 근거다
- **기준선 불변 — 회귀 없음.** 칸 내용만 바뀌고 리전 구조는 그대로다
- **토큰·칸 수 증가 — 의도한 변화.** 각 행이 제 구분 값을 갖게 된 대가다
- **확인 필요 — 채우지 않은 226+116+108 = 450칸.** 가로 병합이거나 근거가 없어 비워 뒀다.
  이 중 진짜 가로 병합이 몇 개이고 판정 실수가 몇 개인지는 **사람이 문서를 열어 세지 않았다**
