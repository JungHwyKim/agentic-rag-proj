# hybrid 의 이득을 가르는 것은 누가 썼나가 아니라 낱말이 겹치나였다

- 검증일: 2026-08-24
- 대상: `plan_log/평가-세트.md` 의 **LLM 어휘 편향** 미결 ·
  [verify_log/2026-08-23-사람질의-편향.md](2026-08-23-사람질의-편향.md) 의 결론에 축을 하나 더한다
- 비용: **외부 API 호출 없음.** 기존 실행 JSON 과 세트 파일만 읽었다. 코드 변경 0

## 1. 확인하려 한 것

앞 회차가 *"사람이 쓴 질의에서도 hybrid 이득이 남으니 LLM 어휘 편향이 아니다"* 로 닫았다
(`hit@10` +0.2000). 그 결론은 **저자**를 축으로 삼는데, 편향 가설이 실제로 말하는 것은
저자가 아니라 **질의 낱말이 정답 문장과 겹치는 정도**다. 사람이 썼어도 겹칠 수 있고 LLM 이
썼어도 안 겹칠 수 있으므로, **저자는 겹침의 대리 변수일 뿐**이다.

그래서 겹침을 **직접 재고** 그것으로 갈랐다. 임계값을 정하는 회차가 아니라 **이미 있는 두
세트의 성질**을 재는 회차라 실파일 쪽만 있다.

가설: **이득은 겹침이 높은 질의에 몰려 있다.**

## 2. 가상 데이터

없음. 재는 것이 *실측 세트가 실제로 가진 어휘 분포*라 합성 질의가 답할 수 있는 질문이 없다 —
합성으로 만들면 겹침을 내가 정해 넣는 셈이라 자기 확인이 된다.

## 3. 실제 데이터

입력은 파일이 아니라 **세트와 기존 실행 리포트**다. 파일 신원 대신 그 신원을 적는다.

| 항목 | 값 |
|---|---|
| 질의 세트 | `evaluation/qa_set.jsonl` 60건 · `evaluation/qa_set_human.jsonl` 20건 |
| 순위 출처 | `.cache/evaluation/runs/phase2-{dense,hybrid}-pdf.json` (60건) |
| | `.cache/evaluation/runs/human2-{dense,hybrid}-pdf.json` (20건) |
| 기준 커밋 | `357c93f` |
| 겹침 자[尺] | `rag_pipeline/retrieval/tokenize.py` 의 `tokenize()` — **BM25 가 실제로 보는 토큰** |

**공백 분리로 재지 않은 것이 요점이다.** 이 저장소의 BM25 는 한글을 문자 bigram 으로 자르므로
`시행령은` 과 `시행령` 이 두 토큰을 공유한다. 공백으로 재면 조사 때문에 겹침이 과소평가되고,
그것은 BM25 가 보는 세계가 아니다. 지표는 `|질의토큰 ∩ 정답토큰| / |질의토큰|` 이다.

### 3-1. 두 세트의 겹침 분포 — 앞 회차의 전제가 서는지 먼저 봤다

| 세트 | 중앙 | 평균 | 최소 | 최대 | 겹침 0 |
|---|---:|---:|---:|---:|---:|
| LLM 초안 60건 | **0.200** | 0.210 | 0.000 | 0.550 | 8건 |
| 사람이 쓴 20건 | **0.128** | 0.154 | 0.000 | 0.600 | 4건 |

**사람이 쓴 질의가 실제로 겹침을 낮췄다**(중앙 −36%). 이 확인이 없으면 앞 회차의
*"어투를 통째로 바꿔도 이득이 안 사라진다"* 는 **조작이 먹혔는지 모르는 채로 한 말**이 된다.
먹혔다. 다만 **0 으로 만들지는 못했고**, 그 남은 겹침이 아래 결과를 만든다.

### 3-2. 겹침으로 가른 이득 — 낮은 쪽에서 정확히 0 이다

| 세트 | 겹침 구간 | n | dense `hit@10` | hybrid `hit@10` | 이득 | 순위 변화 |
|---|---|---:|---:|---:|---:|---|
| LLM 60 | 0.00~0.12 | 20 | 0.400 | 0.400 | **±0.000** | ↑6 ↓5 |
| LLM 60 | 0.14~0.27 | 20 | 0.400 | 0.700 | +0.300 | ↑12 ↓0 |
| LLM 60 | 0.27~0.55 | 20 | 0.650 | 0.900 | +0.250 | ↑12 ↓0 |
| 사람 20 | 0.00~0.12 | 10 | 0.300 | 0.400 | +0.100 | ↑3 ↓2 |
| 사람 20 | 0.14~0.60 | 10 | 0.500 | 0.800 | +0.300 | ↑8 ↓1 |

**순위 변화 칸이 `hit@10` 보다 강하다.** 겹침이 낮은 20건은 ↑6 ↓5 로 **개선과 악화가 맞비긴다** —
이득이 0인 것이 "작아서 안 보인다"가 아니라 **방향이 없다**는 뜻이다. 반대로 겹치는 40건은
↑24 ↓0 으로 **나빠진 질의가 하나도 없다.**

**같은 패턴이 사람 세트에서 반복된다.** 저자가 아니라 겹침이 축이라는 것의 직접 증거다 —
사람이 쓴 질의 안에서도 겹치는 절반이 이득을 거의 다 만든다.

### 3-3. 곁가지 — "적재 밖" 6건은 겹침이 낮아서가 아니다

[2026-08-23-포맷비교.md](2026-08-23-포맷비교.md) 가 적재 밖으로 확정하고 hybrid 도 못 주운 6건.

| 질의 | 겹침 | 백분위 | dense → hybrid |
|---|---:|---:|---|
| `sih-15` | 0.462 | 92% | 없음 → 18 |
| `sih-04` | 0.273 | 65% | 없음 → 없음 |
| `bas-15` · `bas-02` · `sih-07` | 0.200 | 48% | 없음 → 없음 |
| `sih-14` | 0.125 | 28% | 없음 → 없음 |

**6건 중 5건이 중앙값 이상**이다. 낱말은 멀쩡히 겹치는데 BM25 도 못 찾으므로
**어휘 불일치가 범인이 아니다**가 한 겹 더 굳었다 — 3-2 의 "겹치면 BM25 가 줍는다"가
**이 여섯에는 안 통한다**는 뜻이라, 이들은 3-2 의 규칙이 설명하지 못하는 별개 무리다.

정답 span 을 열어 본 것은 **관측으로만 남긴다.**

```
bas-15  "작년 운영 결과는 어떻게 정리돼 있나요?"
        → | 구분 | 25년도 운영 결과 분석 | 26년도 정책방향 시사점 |
bas-02  "위원회는 언제까지 꾸려야 하나요?"
        → 구성: 매 학년도 시작일로부터 2개월 이내 ※ 타 위원회와 통합하여 운영 가능
sih-04  "시범사업 대상 규모가 어느 정도인가요?"
        → 시범사업 추진 ⇨ 중앙부처 수요조사 기반 50개 시스템(’20.8.~12.)
```

표 조각이거나 앞뒤 문맥 없이는 뜻이 안 서는 짧은 줄이고, `bas-02` 는 **정답에 "위원회"라는
말이 아예 없다.** 그럴듯하지만 **표본이 6이라 승격하지 않는다** — 이 코퍼스에서 제목 가설이
세 번 연속 기각된 것이 정확히 이런 식의 성급한 일반화였다(CLAUDE.md).

### 3-4. 겹침 0 구간에서 hybrid 는 **중립이 아니라 잡음이다**

3-2 의 `±0.000` 을 *"아무 일도 안 일어난다"* 로 읽으면 틀린다. **11건의 순서가 실제로
흔들렸고 방향만 없다.** (`hybrid-search-phase-2-completion` 세션의 지적이고, 재보니 맞다.)

| 나빠진 5건 | | 좋아진 6건 | |
|---|---|---|---|
| `ai-03` | 20 → **없음** | `ai-07` | 없음 → 13 |
| `ai-12` | 11 → **없음** | `bas-10` | 10 → 4 |
| `ai-04` | 9 → **11** (top10 밖) | `sih-01` | 12 → **9** (top10 안) |
| `sch-09` | 2 → 4 | `sch-08` | 4 → 2 |
| `ai-15` | 2 → 3 | `sch-11` | 2 → 1 |
| | | `ai-14` | 16 → 11 |

**`hit@10` 이 ±0 인 것은 상쇄의 결과다** — `ai-04` 가 나가고 `sih-01` 이 들어와 1:1 로
맞비겼다. 집계가 조용한 것과 아무 일이 없는 것은 다르다.

**두 건은 후보 창 밖으로 밀렸다**(`ai-03` 20→없음 · `ai-12` 11→없음). `k=20` 밖은 어떤
리랭커도 못 되살리므로, 이 둘은 *"순위가 조금 나빠진 것"* 이 아니라 **후보에서 사라진 것**이다.

폭은 좋아진 쪽이 크다(순위 차 중앙 5 대 2). 그래도 **평균이 이득으로 안 나온 이유**는 그
둘이 창 밖으로 나가며 손실 쪽 꼬리를 길게 만들었기 때문이다.

**기전을 가설로 넘겼고, 그것이 재어져 기각됐다.**

넘긴 가설은 *"정답과 안 겹쳐도 다른 낱말이 겹치는 청크가 BM25 후보로 들어와 맞는 dense
결과를 밀어낸다"* 였다(저쪽 세션의 설명). 이 회차는 순위만 읽어 확인할 수 없었고,
경로별 점수를 가진 쪽이 재서 **틀린 것으로 나왔다** —
[2026-08-23-사람질의-편향.md](2026-08-23-사람질의-편향.md) 5-4절, 커밋 `5f3a435`.

**밀어낸 후보 35개 중 BM25 에만 걸린 것은 1개뿐**이고 나머지는 dense 후보에도 이미 있었다.
**침입이 아니었다.** 실제 기전은 **RRF 의 동등 투표권**이다 — 정답이 BM25 에서 dense 보다
낮게 잡히고(`ai-04` dense #9 / BM25 #25 · `sch-09` #2 / #6 · `ai-15` #2 / #9) RRF 가 두
순위를 반씩 섞어 뒤집는다. `ai-04` 의 추월자 둘은 **다른 문서**인데 dense 가 #28·#46 으로
**올바르게** 낮춰 놓은 것을 BM25 가 #3·#4 로 끌어올렸다.

**즉 문제는 후보 풀이 아니라 투표권이다.** RRF 가 점수를 버리고 순위만 쓰는 것은 단위 다른
두 점수를 섞게 해준 성질인데(`plan_log/검색-생성.md` 1회차), 그 대가로 **BM25 가 얼마나
확신하는지를 못 본다.** 겹침이 없어 BM25 상위가 사실상 임의일 때도 그 #3 을 dense 의 #3 과
같은 무게로 센다.

**피해는 이 구간에 갇혀 있다.** 기전 자체는 겹침과 무관하게 일반적이지만 — BM25 가 정답을
dense 보다 낮게 놓는 질의면 어디서든 난다 — 실측으로 **나빠진 질의 5건이 전부 겹침 하위
20건에 있고 중간·상위 구간은 0건**이다. 겹침이 있으면 BM25 도 정답을 제대로 올리기 때문이고,
그래서 3-2 의 `↑24 ↓0` 과 앞뒤가 맞는다.

**고치지 않기로 했다**(저쪽 판단, 동의한다). `candidate_k` 로는 못 고친다 — 추월자가
상위권이라 후보를 줄여도 안 걸러진다. 남은 축은 *BM25 기여를 확신도로 재는 것*인데 그러면
RRF 를 고른 이유로 되돌아간다. 재판정 조건은 **"겹침 0 구간이 실제 사용자 질의에서 얼마나
흔한가"** 이고, 20~60건짜리 세트로 정할 문제가 아니다.

## 5. 판정

| 항목 | 판정 |
|---|---|
| 겹침 낮은 20건에서 이득 ±0.000 (↑6 ↓5) | **새 관측** — 이 회차의 결론 |
| 그 구간에서 2건이 `k=20` 밖으로 밀렸다 | **회귀** — 집계에 안 잡히는 실제 손실 (3-4) |
| 사람 세트에서 같은 패턴 반복 | **새 관측** — 축이 저자가 아니라 겹침이라는 증거 |
| 사람 질의가 겹침을 낮췄다 (0.200 → 0.128) | **의도한 변화 확인** — 앞 회차 조작이 먹혔다 |
| "적재 밖" 6건이 겹침 중앙값 이상 5/6 | **새 관측** — 어휘 불일치 기각이 한 겹 굳었다 |
| 6건의 정답 span 이 표 조각·짧은 줄 | **확인 필요** — 표본 6, 승격 안 함 |

**앞 회차를 뒤집지 않는다. 조건을 붙인다.** *"사람 질의에서도 +20.0%p"* 는 그대로 맞고,
그 세트 **안에서도** 겹치는 절반이 이득을 거의 다 만들었다는 것이 더해진다.

**읽는 법 — 두 문장이 필요하고, 하나로 줄이면 둘 다 거짓이 된다.**

*(1) 켜는 것은 맞다.* 겹치는 40건에서 **↑24 ↓0** 이고 이쪽이 세트의 3분의 2다.
집계로도 `hit@10` 이 크게 오른다.

*(2) 그러나 "손해 보는 구간이 없다" 는 틀렸다.* 겹침 0 구간에서 **5건이 나빠지고 그중 둘은
후보 창 밖으로 밀렸다**(3-4). 집계가 ±0 인 것은 상쇄이지 무해가 아니다. 이 구간에서
hybrid 는 **중립이 아니라 잡음**이다.

그래서 *"검색이 +18%p 좋아진다"* 는 기대는 **사용자가 문서 표현을 따라 쓸 때만** 성립하고,
자기 말로 묻는 사용자에게 hybrid 는 dense 와 **같지 않다 — 조금 나쁠 수 있다.**
그 구간을 고칠 수단은 BM25 가 아니다.

**초판에 (2)를 빠뜨렸다.** `↑24 ↓0` 을 보고 *"손해 보는 구간이 없다"* 로 적었는데 그것은
겹치는 쪽 이야기였고, 낮은 구간의 `↑6 ↓5` 를 이득 0으로만 읽어 **11건이 흔들린 사실을
지웠다.** 저쪽 세션의 지적으로 고쳤다.

**스크립트를 저장소에 안 남긴다.** 일회성 분석이고, 남기면 `evaluation/` 의 공개 진입점처럼
보인다. 대신 여기 그대로 싣는다 — 이 회차의 입력은 파일이 아니라 **이 코드**다.

```python
"""질의-정답 어휘 겹침이 hybrid 이득을 가르는지 본다. 과금 없음 — 기존 실행 JSON 만 읽는다."""
import json, statistics as st
from rag_pipeline.retrieval.tokenize import tokenize

RUNS = ".cache/evaluation/runs"

def load(path):
    return [json.loads(l) for l in open(path, encoding="utf-8") if l.strip()]

def ranks(name):
    r = json.load(open(f"{RUNS}/{name}.json", encoding="utf-8"))
    return {row["query_id"]: row["rank"] for row in r["per_query"]}

# 질의 토큰 중 정답 span 에도 있는 것의 비율. **BM25 가 실제로 보는 토큰**으로 잰다 —
# 공백 분리로 재면 조사 때문에 겹침이 과소평가되고, 그건 BM25 가 보는 세계가 아니다
def overlap(item):
    q = set(tokenize(item["query"]))
    s = set()
    for span in item["gold_spans"]:
        s |= set(tokenize(span))
    return len(q & s) / len(q) if q else 0.0

def buckets(title, items, dense, hybrid, n_buckets):
    D, H = ranks(dense), ranks(hybrid)
    rows = sorted((overlap(it), it["query_id"]) for it in items if it["query_id"] in D)
    n = len(rows); size = n // n_buckets
    print(f"### {title} (n={n})")
    for b in range(n_buckets):
        part = rows[b * size : (n if b == n_buckets - 1 else (b + 1) * size)]
        hit = lambda r: r is not None and r <= 10
        far = lambda r: r if r else 99
        dh = sum(1 for _, q in part if hit(D[q]))
        hh = sum(1 for _, q in part if hit(H[q]))
        up = sum(1 for _, q in part if far(H[q]) < far(D[q]))
        dn = sum(1 for _, q in part if far(H[q]) > far(D[q]))
        m = len(part)
        print(f"  {part[0][0]:.2f}~{part[-1][0]:.2f}  n={m:2d}  "
              f"dense {dh/m:.3f}  hybrid {hh/m:.3f}  이득 {(hh-dh)/m:+.3f}  ↑{up} ↓{dn}")
    print()

def spread(title, items):
    v = [overlap(i) for i in items]
    print(f"{title}: 중앙 {st.median(v):.3f} · 평균 {st.fmean(v):.3f} · "
```

## 7. 재지 못한 것

- **겹침이 0 인 구간을 무엇으로 고치나.** 두 갈래가 다 열려 있다 — *못 찾는 것*은 임베딩의
  한국어 변별력이 남은 후보이고 두 번째 모델이 있어야 잰다(`plan_log/embedding.md` 미결),
  *나빠지는 것*은 3-4 에서 RRF 동등 투표권으로 기전이 밝혀졌지만 **고치면 RRF 를 고른 이유로
  되돌아가므로 안 고쳤다.** 뒤엣것의 재판정 조건은 실제 사용자 질의 분포다
- **구간을 3분위로 자른 것은 임의다.** 겹침 분포에 눈에 띄는 틈이 없어 임계값을 못 골랐고,
  그래서 **임계값이 아니라 순서**로 갈랐다. `0.12` 를 경계값으로 읽으면 안 된다
- **표본.** 구간당 20건(사람 세트는 10건)이라 질의 1개가 5~10%p 다. 낮은 구간의 ±0.000 은
  ↑6 ↓5 라는 방향 없음이 뒷받침하지만, 구간 간 이득 차이(+0.300 vs +0.250)는 못 가른다
- **정답 쪽 편향.** 앞 회차가 남긴 한계 그대로다 — 사람 질의의 정답 span 을 모델이 골랐다.
  겹침을 직접 재는 이 회차는 그 영향을 **덜 받지만**(저자가 아니라 결과물의 성질을 잰다)
  span 선택이 겹침을 높이는 쪽으로 기울었을 가능성은 남는다
- **`--format hwpx` 에서의 재현.** PDF 실행만 봤다
