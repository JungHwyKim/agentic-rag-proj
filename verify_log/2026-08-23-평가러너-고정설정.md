# 평가 러너가 개발자 `.env` 에 안 흔들리는지 — 그리고 오타가 조용히 무시되는 자리

- 검증일: 2026-08-23
- 대상: [task_log/2026-08-23-평가러너-고정설정.md](../task_log/2026-08-23-평가러너-고정설정.md) ·
  커밋 전. 설계 근거는 [plan_log/평가-세트.md](../plan_log/평가-세트.md) 7회차
- 비용: **실제 청구 0.** `--check` 는 파싱 캐시 8/8 적중이고, `--dense` 는 돌렸는데
  `usage` 가 **0토큰 · 0호출** 이었다(문서·질의 임베딩 둘 다 캐시 적중). `vision_calls` 도
  네 문서 모두 0 이다. 사용자 승인 받음

## 1. 확인하려 한 것

**"규칙이 도는가" 쪽이다.** 임계값을 정하는 작업이 아니다.

1. `eval_config()` 가 `.env` 와 환경변수를 **이긴다**
2. 고정하지 않기로 한 둘(API 키·`tesseract_cmd`)은 **여전히 `.env` 에서 온다**
3. `EVAL_SETTINGS` 의 오타가 잡히는가 — 설정 클래스가 전부 `extra="ignore"` 라
   **이름을 틀리면 아무 에러 없이 그 항목만 조용히 안 먹는다**
4. `corpus.py` 와 `run_eval.py` 가 **같은** 설정을 쓰는가
5. `IndexResult.metadata` 추가가 기존 계약을 안 깨는가

## 2. 가상 데이터

무엇을 고립시켰나: **환경변수 하나씩만 흔든다.** `monkeypatch.setenv` 로 `.env` 와 반대되는
값을 넣고 고정값이 나오는지 본다. 문서·파싱은 전혀 안 탄다 — 여기서 볼 것이 설정 해석뿐이라
입력 문서가 답에 기여하지 않는다.

```python
# tests/evaluation/test_eval_config.py — 그대로 돌면 같은 입력이 나온다
@pytest.mark.parametrize(
    ("env_key", "env_value", "attr"),
    [
        ("TABLE_PDF_HANDLER", "llamaparse", "table_pdf_handler"),
        ("IMAGE_HANDLER", "skip", "image_handler"),
        ("VISION_MODEL", "gpt-4o", "vision_model"),
        ("MAX_VISION_CALLS_PER_DOC", "1", "max_vision_calls_per_doc"),
        ("OCR_PSM", "3", "ocr_psm"),
    ],
)
def test_env_cannot_move_fixed_content_settings(monkeypatch, env_key, env_value, attr) -> None:
    monkeypatch.setenv(env_key, env_value)
    assert getattr(eval_config().content, attr) == EVAL_SETTINGS["content"][attr]
```

넣은 값은 전부 **지금 `.env` 나 기본값과 다른 것**으로 골랐다. 같은 값을 넣으면 통과해도
아무것도 검증하지 않는다.

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `TABLE_PDF_HANDLER=llamaparse` | `pymupdf` | `pymupdf` | 일치 |
| `IMAGE_HANDLER=skip` | `hybrid` | `hybrid` | 일치 |
| `VISION_MODEL=gpt-4o` | `gpt-4.1-mini` | `gpt-4.1-mini` | 일치 |

`DETECT_HEADINGS` 를 넣은 이유는 이것이 **제일 크게 어긋나는 축**이어서다 — 제목 승격이
꺼지면 splitter 가 경계를 못 얻어 청크가 통째로 달라진다.

세 번째 가설(오타)은 두 겹으로 본다. 이름 대조(`model_fields` 와 집합 차)만으로는 **이름이
맞아도 값이 안 실리는 경우**를 못 잡으므로, 실제 객체에서 다시 읽어 대조한다.

k 축 계산도 같은 방식으로 고립시켰다.

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `axes_for(20)` | `(1, 3, 5, 10, 20)` | `(1, 3, 5, 10, 20)` | 일치 |
| `axes_for(10)` | `(1, 3, 5, 10)` | `(1, 3, 5, 10)` | 일치 |
| `axes_for(7)` | `(1, 3, 5, 7)` | `(1, 3, 5, 7)` | 일치 |

기준선 대비 승·패·무도 합성 입력으로 봤다. `rank=None`(못 찾음)을 **제일 뒤로 미는** 것이
맞는지가 핵심이다 — 안 그러면 `없음 → 3` 이 이김으로 안 세어진다.

```python
rep = {"format": "pdf", "k": 20, "per_query": [
    {"query_id": "a", "rank": 3}, {"query_id": "b", "rank": None}, {"query_id": "c", "rank": 5}]}
base = {"format": "pdf", "k": 20, "per_query": [
    {"query_id": "a", "rank": None}, {"query_id": "b", "rank": 2}, {"query_id": "c", "rank": 5}]}
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 위 두 리포트 대조 | 이김 1 · 짐 1 · 그대로 1 | 이김 1 · 짐 1 · 그대로 1 | 일치 |
| `없음 → 3` | `↑` | `↑ a 없음 → 3` | 일치 |
| `2 → 없음` | `↓` | `↓ b 2 → 없음` | 일치 |
| 기준선이 `hwpx` 인데 이번이 `pdf` | 비교 거부 | *"직접 비교하지 않습니다"* | 일치 |

## 7. 재지 못한 것

- **`vision_calls` 가 왜 0 인지 안 봤다.** 표시 크기 필터(`min_image_display_pt`·
  `max_image_aspect_ratio`)에 걸린 것인지 `classify()` 가 글자 위주로 판정한 것인지 갈리지
  않았다. 카운터만으로는 *"안 불렀다"* 까지이고 *"왜"* 는 `warnings` 에도 안 남는다
  (걸러진 이미지는 조용히 SKIP 된다 — `plan_log/이미지-경로.md` 의 열린 미결과 같은 자리다)
- **HWPX 판을 안 쟀다.** 이번은 `--format pdf` 하나다. 포맷 비교는 두 판을 다 가진 3그룹으로
  제한해야 성립하고, 다음 회차 몫이다
- **고정 설정으로 파싱한 결과를 `--check` 쪽에서는 못 봤다.** `corpus.py` 의 캐시 키가
  파일명뿐이라 설정이 바뀌어도 옛 캐시를 쓴다. `--dense` 는 캐시를 안 타므로 이번 수치는
  영향이 없다 — 미결로 `plan_log/평가-세트.md` 에 있다
- **`usage` 가 0 이라 비용 축을 못 쟀다.** 캐시 없는 머신에서 이 실행이 얼마인지는 여전히
  추정치다(전 문서 139,438토큰 ≈ $0.003, `verify_log/2026-08-18-embedding.md`)
- **23건이 왜 안 잡히는지 안 봤다.** 이 회차는 러너가 옳게 도는지까지다
