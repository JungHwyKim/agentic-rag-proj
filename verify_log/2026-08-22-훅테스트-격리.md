# 훅 테스트 격리 — 탈출구를 켠 환경에서도 검사가 도는가

- 검증일: 2026-08-22
- 대상: [task_log/2026-08-22-훅테스트-격리.md](../task_log/2026-08-22-훅테스트-격리.md)
- 비용: 외부 API 호출 없음

## 1. 확인하려 한 것

**"규칙이 도는가"쪽이다. 임계값이 없다.**

훅은 전부 `main()` 첫머리에서 자기 탈출구 환경변수를 보고 즉시 반환한다. 그 값이 켜진 채로
테스트를 돌리면 **검사 대상이 아예 안 돈다.** 그때 결과가 두 갈래로 갈리는데, 조용히
통과하는 쪽이 더 나쁘다 — 검사가 있는 줄 알았는데 없는 상태가 아무 신호 없이 유지된다.

이 검증은 실파일이 필요 없다. 입력이 환경변수 여섯이라 전수로 돌릴 수 있다.

## 2. 가상 데이터

무엇을 고립시켰나: **환경변수 하나씩.** 훅 테스트 스위트 전체를 각 탈출구를 켠 채 돌린다.

```bash
# 탈출구 목록은 훅 소스에서 뽑는다 (test_hook_wiring.py 가 쓰는 것과 같은 정규식)
#   grep -o 'os\.environ\.get("[A-Z_]*"' .claude/hooks/*.py
for v in SKIP_PLANINTERVIEW ALLOW_PAID_TESTS SKIP_TASKLOG SKIP_PLANLOG SKIP_AUTOTEST SKIP_PRECOMMIT; do
  env "$v=1" ./.venv/Scripts/python.exe -m pytest tests/hooks -q
done
```

|---|---|---|---|---|
| `SKIP_PLANINTERVIEW=1` | 전부 통과 | **13 failed** | 136 passed | 고쳐짐 |
| `ALLOW_PAID_TESTS=1` | 전부 통과 | **2 failed** | 136 passed | 고쳐짐 |
| `SKIP_TASKLOG=1` | 전부 통과 | 통과 (우연) | 136 passed | 유지 |
| `SKIP_PLANLOG=1` | 전부 통과 | 통과 (우연) | 136 passed | 유지 |
| `SKIP_AUTOTEST=1` | 전부 통과 | 통과 (우연) | 136 passed | 유지 |
| `SKIP_PRECOMMIT=1` | 전부 통과 | 통과 (우연) | 136 passed | 유지 |
| 여섯 개 동시 | 전부 통과 | (안 쟀음) | 136 passed | OK |

**뒤쪽 넷이 고치기 전에 통과한 것은 규칙 덕이 아니라 우연이다.** `test_record_hooks.py` ·
`test_paid_test_check.py` 는 `main()` 을 아예 안 부르고(`grep -c "\.main()"` 이 0),
`test_auto_test_check.py` 의 유일한 `main()` 호출은 탈출구 테스트 **안**에 있다. 그 파일들에
`main()` 을 부르는 테스트가 하나 생기면 같은 구멍이 되살아나고, 그때는 **조용히 통과하는
쪽**이다.

### 2-1. 커버리지 테스트가 실제로 무는가

목록이 조용히 낡는 것을 막는 테스트 둘을 넣었다. 한 항목을 빼서 확인했다.

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `ESCAPE_HATCHES` 에서 `SKIP_PRECOMMIT` 제거 (영역 실행) | 실패 | `['SKIP_PRECOMMIT'] 가 ESCAPE_HATCHES 에 없다` | OK |
| 같은 것, **전체 실행** | 실패 | 같은 메시지 | OK |
| 목록에 죽은 이름 추가 | 실패 | `어느 훅도 안 읽는다` | OK |

**전체 실행에서도 무는지를 따로 잰 이유가 4절에 있다.**

## 7. 재지 못한 것

- **실제 세션에서 훅이 도는 것은 사람이 확인해야 한다.** 이 검증은 `main()` 을 직접 부르거나
  subprocess 로 돌린 것이고, 하네스가 실제로 배선대로 부르는지는 별개다
  (`test_hook_wiring.py` 가 배선을 보지만 실행을 보지는 않는다)
- **`SKIP_PRECOMMIT` 은 `pre_commit_check.py` 것인데 그 훅의 테스트가 `tests/hooks` 에
  따로 없다.** 목록에는 넣었고 커버리지 테스트가 짝을 확인하지만, 그 훅이 탈출구를 켠 채
  어떻게 도는지는 안 쟀다
