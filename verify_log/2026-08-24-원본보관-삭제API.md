# 원본이 맞는 이름으로 남고, 경로 탈출이 막히고, 삭제가 둘을 함께 지우는가

- 검증일: 2026-08-24
- 대상: [task_log/2026-08-24-원본보관-삭제API.md](../task_log/2026-08-24-원본보관-삭제API.md) · 미커밋 (기준 `025f91c`)
- 비용: **외부 API 호출 없음.** 임베딩·생성·LlamaParse·Vision 을 한 번도 안 부른다 — 라우트 테스트는 `index_document()` 자체를 갈아끼우고, 실서버 확인은 원본 파일을 손으로 심어 서빙·삭제만 왕복시켰다

## 1. 확인하려 한 것

**"규칙이 도는가"** 다. **임계값이 하나도 없다** — 이번 변경에 고른 수가 없다.

1. **저장 이름이 `document_id` 만으로 계산되는가** — 그리고 예약 문자 치환 뒤에도
   충돌하지 않는가. 이게 깨지면 **한쪽 문서의 "원문 보기"가 남의 파일을 에러 없이 보여준다**
2. **경로 탈출이 막히는가** — 경로 파라미터는 사용자 입력이다
3. **삭제가 색인과 원본을 함께 지우는가** — 그리고 BM25·답변 캐시를 색인 라우트와
   **다르게** 다루는가
4. **테스트가 개발자의 실제 보관함을 안 건드리는가**

## 2. 가상 데이터

무엇을 고립시켰나: **`document_id` 하나.** 같은 라우트·같은 파일로 보내면서 문서 키만
바꾼다. `originals_dir` 은 `tests/api/conftest.py` 의 autouse 픽스처가 `tmp_path` 로 돌린다.

```python
# tests/api/conftest.py — 이 폴더의 모든 테스트에 걸린다
@pytest.fixture(autouse=True)
def originals_dir(tmp_path: Path, monkeypatch: pytest.MonkeyPatch) -> Path:
    directory = tmp_path / "original_files"
    # Settings 가 pydantic-settings 라 필드 이름이 곧 환경변수 이름이고,
    # get_settings() 가 매번 새로 만들기 때문에(lru_cache 없음) 이 한 줄이 모든 호출부에 먹는다
    monkeypatch.setenv("ORIGINALS_DIR", str(directory))
    return directory
```

기대값을 먼저 적었다.

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `_stored_name("보고서:1.pdf")` vs `_stored_name("보고서_1.pdf")` | **달라야 함** | `..._1__17511a.pdf` vs `..._1__0aa3b7.pdf` | OK |
| `_stored_name()` 을 예약문자 4종에 | `< > : " \| ? * \ /` 가 하나도 안 남음 | 안 남음 | OK |
| 같은 `document_id` 로 두 번 | 같은 이름 | 같음 | OK |
| 확장자 없는 이름 | 안 죽고 `이름__해시` | `확장자없음__df3dd1` | OK |
| 색인 성공 | 파일 1개 · 이름이 `_stored_name()` · 본문 동일 | 그대로 | OK |
| **색인 실패** | **파일 0개** | 0개 | OK |
| `POST /documents/upload`(파싱 전용) | **파일 0개** | 0개 | OK |
| `.pdf` 서빙 | 200 · `application/pdf` · inline · nosniff | 그대로 | OK |
| `.hwpx` 서빙 | 200 · **attachment** | 그대로 | OK |
| 원본 없는 문서 | 404 · 안내 문구에 "업로드" | 그대로 | OK |
| **경로 탈출 5종** | 404 · 폴더 밖 내용 유출 0 | 그대로 | OK |
| 삭제 | 204 · `HX-Trigger` · `delete_by_document_id` 호출 · 파일 삭제 | 그대로 | OK |
| 삭제 뒤 `app.state.bm25` | `None` | `None` | OK |
| 삭제 뒤 답변 캐시 | **같은 객체 · `clear()` 0회** | 그대로 | OK |
| 원본 없는 문서 삭제 | 204 · 색인은 지워짐 | 그대로 | OK |
| 삭제로 경로 탈출 | 404 · 바깥 파일 **생존** | 생존 | OK |

경로 탈출은 `../../.env` · `..%2F..%2F.env` · `....//....//.env` · `/etc/passwd` ·
`C:\Windows\win.ini` 다섯을 넣었다. **한 종류만 넣으면 안 되는 이유**: `document_id_for()` 의
`PurePath(...).name` 이 잡는 것과 `resolve()` 봉쇄가 잡는 것이 다르다.

## 3. 실제 데이터

**실파일 파싱은 이번 변경과 무관하다** — 고친 것이 전부 업로드 수명·서빙·삭제라
`tests/fixtures/` 가 답할 질문이 없다. 대신 **실제로 도는 서버**에 왕복시켰다.

원본 하나를 손으로 심고(색인은 유료라 안 돌린다) 서빙·삭제만 확인했다. 이름은
`_stored_name()` 규칙을 손으로 재현해 만들었다 — **규칙이 코드 밖에서도 계산된다는 것이
곧 매핑 파일이 필요 없다는 증거**다.

```
심은 이름 : 실증용 문서_테스트___9d876d.pdf   (원본 이름 = "실증용 문서:테스트?.pdf")
```

| 항목 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 서빙 상태·타입 | 200 · `application/pdf` | 그대로 | OK |
| disposition | inline + **원본 이름** | `inline; filename*=utf-8''...%EB%AC%B8%EC%84%9C%3A...pdf` | OK |
| nosniff | 있음 | `nosniff` | OK |
| 본문 | 심은 바이트와 동일 | 동일 | OK |
| 삭제 | 204 · `HX-Trigger` · 파일 사라짐 | 그대로 | OK |
| 사이드바 조각 | `/original` · `hx-delete` · `hx-confirm` · `doc-delete` · `원본` | 5/5 있음 | OK |
| 옛 문서(원본 없음) | 404 + 안내 | `이 문서의 원본이 저장돼 있지 않습니다. 파일을 다시 업로드하면 저장됩니다.` | OK |
| 실서버 경로 탈출 3종 | 404 · `.env`·`win.ini` 내용 유출 0 | 유출 0 | OK |

**`filename*=utf-8''` 인코딩이 이 표의 요점 하나다** — 내려받을 때 디스크의
`..._테스트___9d876d.pdf` 가 아니라 **원래 이름**으로 저장된다. `filename` 을 안 주면
Starlette 이 `Content-Disposition` 헤더를 아예 안 단다(4절의 실패 참고).

## 7. 재지 못한 것

- **실파일을 끝까지 색인해 원본이 남는 것은 못 봤다.** 임베딩이 유료라 `index_document()` 를
  갈아끼운 상태로만 확인했다. 실서버 확인도 원본을 **손으로 심어** 서빙·삭제만 왕복시킨
  것이라, *"진짜 업로드 → 진짜 색인 → 원본 보관"* 한 줄은 **안 밟혔다**
- **브라우저에서 안 눌러봤다.** `hx-delete`·`hx-confirm` 이 렌더된 HTML 에 있는 것과 서버가
  `DELETE` 를 받는 것은 확인했지만, **확인창이 실제로 뜨는지 · 취소하면 요청이 안 가는지**는
  브라우저가 있어야 안다. 출처 태그의 `#page=N` 이 PDF 뷰어를 그 쪽으로 보내는지도 마찬가지다
- **큰 파일의 `shutil.move` 는 안 쟀다.** 13MB 스캔본에서 같은 볼륨이면 rename 이라 비용이
  없다고 봤지만 **재보지 않았다.** `%TEMP%` 가 다른 볼륨이면 실제 복사가 일어난다
- **동시 업로드는 안 봤다.** 같은 `document_id` 로 두 요청이 겹치면 `shutil.move` 가 서로를
  덮는다. 지금은 사용자가 하나뿐이라 안 밟히는 경로다
