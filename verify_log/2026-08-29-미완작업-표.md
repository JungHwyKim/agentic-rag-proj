# 미완 작업 수집기(`openwork/`) — 규약대로 뽑는가, 실제 저장소에서 얼마인가

- 검증일: 2026-08-29
- 대상: [task_log/2026-08-29-미완작업-표.md](../task_log/2026-08-29-미완작업-표.md) · 설계는 [plan_log/미완-작업.md](../plan_log/미완-작업.md) 1회차
- 비용: **외부 API 호출 없음** (`-m integration` 안 돌림 · LLM 단계를 아예 안 지난다)

## 1. 확인하려 한 것

둘이고 답하는 성질이 다르다.

- **규칙이 도는가** — 절을 정확히 뽑나 · 취소선을 빼나 · 구조가 어긋나면 시끄러운가. 가상으로 답한다
- **실제 저장소에서 값이 얼마인가** — 열린 항목 수 · 라벨률 · 출력 크기. 실제 기록으로만 답한다

**임계값은 이 판에서 하나도 안 정했다.** 접기 기본값(뒷정리 0개 보임)은 관측이 아니라
「근거 없이 안 정한다」 쪽 선택이라 아래 표에 안 넣는다.

## 2. 가상 데이터

무엇을 고립시켰나: **규약의 각 조각 하나씩**. 실제 기록 형식과 같은 모양의 최소 저장소를 만들어,
취소선·절 경계·이어지는 줄·회차 날짜·파일 링크를 축 하나씩만 건드렸다.

```python
# tests/openwork/test_collect_openwork.py 의 fake_repo 픽스처. 돌리면 같은 입력이 나온다
plan = tmp_path / "plan_log"; task = tmp_path / "task_log"
plan.mkdir(); task.mkdir()
(plan / "INDEX.md").write_text("# 색인\n", encoding="utf-8")
(task / "INDEX.md").write_text("# 색인\n", encoding="utf-8")

(plan / "검색.md").write_text(
    "# 검색 설계\n\n"
    "## 확정된 것\n\n- 여기 것은 안 센다\n\n"
    "## 미결\n\n"
    "- **임계값을 정한다** (2회차) — 정하려면: 같은 뜻 다른 말 쌍이 필요하다\n"
    "- ~~**옛 항목**~~ → **3회차에서 닫혔다.** 더 볼 것 없다\n"
    "- 굵은 머리가 없는 줄 — `retrieve()` 가 먼저다\n\n"
    "## 안 하기로 한 것\n\n- 여기 것도 안 센다\n\n"
    "---\n\n"
    "## 1회차 — 2026-08-01 · 처음\n\n본문\n\n"
    "## 2회차 — 2026-08-05 · 두 번째\n\n본문\n\n"
    "## 3회차 — 2026-08-09 · 세 번째\n\n본문\n",
    encoding="utf-8",
)
(task / "2026-08-07-검색-배선.md").write_text(
    "# 검색 배선\n\n관련 설계: [plan_log/검색.md](../plan_log/검색.md)\n\n"
    "## 7. 남은 것\n\n"
    "- **캐시를 안 붙였다** 다음에 잰다\n"
    "- ~~**이미 했다**~~ 닫힘\n",
    encoding="utf-8",
)
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `## 미결` 절 뽑기 | 이웃 절(`확정된 것`·`안 하기로 한 것`) 안 딸려옴 | 안 딸려옴 | 통과 |
| 없는 절 | 빈 문자열 (예외 아님) | 빈 문자열 | 통과 |
| 들여쓴 이어지는 줄 | 앞 불릿에 붙어 2건 | 2건 | 통과 |
| `~~취소선~~` 2건 | 항목에서 빠지고 `closed_skipped` 로 셈 | `plan_log:1 · task_log:1` | 통과 |
| 취소선 없는 항목 | 코드 유무와 무관하게 남음 | 남음 | 통과 |
| `**굵은 머리**` | 그대로 `what` | `임계값을 정한다` | 통과 |
| 굵은 머리 없음 | 첫 조각, 강조 표시 벗김 | `1회차 몫은 없음` | 통과 |
| `정하려면:` 있음 | `why_basis="quote"` | `quote` | 통과 |
| `정하려면:` 없음 | `why=None` (지어내지 않음) | `None` | 통과 |
| 220자 넘는 인용 | 자르고 `why_truncated=True` | `True` · 길이 220 | 통과 |
| 불릿에 `(2회차)` | 그 회차 날짜 | `2026-08-05` | 통과 |
| 회차 표시 없음 | 최신 회차 날짜 | `2026-08-09` | 통과 |
| task_log 가 `plan_log/검색.md` 링크 | `group="검색"` · `basis="file"` | 그대로 | 통과 |
| 아무것도 안 가리킴 | `group=None` (아무 데나 안 붙임) | `None` | 통과 |
| `task_log/` 폴더 없음 | `OpenWorkConfigError` | 발생 · 메시지에 `task_log` | 통과 |
| 모르는 기록 폴더(`design_log/` + `INDEX.md`) | 경고 1건 | 경고 1건 | 통과 |
| `NOT_A_SOURCE` 의 `verify_log/` | 경고 없음 | `[]` | 통과 |
| `INDEX.md` 없는 보통 폴더(`data/`) | 경고 없음 | `[]` | 통과 |
| 절 이름을 `## 열린 질문` 으로 바꿈 | 경고 1건 | 경고 1건 | 통과 |
| 기본 접기 | `followups=[]` · 수는 남음 | `count 1 · folded 1` | 통과 |
| `--group 검색` | 그 묶음만 펼침 | 1건 펼침 | 통과 |
| `(묶음 미상)` | 맨 뒤 | 맨 뒤 | 통과 |
| CLI 를 `PYTHONIOENCODING=cp949` 로 호출 | UTF-8 JSON | UTF-8 JSON | 통과 |
| 설정 어긋난 채 CLI | `rc=2` · stderr 에 사유 | `rc=2` | 통과 |

가상만으로는 **「이 규칙이 실제로 필요한가」에 못 답한다.** 그 답은 3절이다.

## 7. 재지 못한 것

- **취소선 없이 닫힌 항목이 몇 건인가** — 이 도구가 닫힘을 판정하지 않기로 했으므로 **원리적으로
  못 잰다.** 표본은 `plan_log/frontend.md` **1건**뿐이고(그 미결이 가리키는 배선은
  `backend/app/templates/_answer.html` 에 이미 있다) 비율은 사람이 훑어야 나온다
- **`group_basis="file"` 로 붙은 220건이 *맞게* 붙었는가** — 붙는 **비율**만 쟀다. 여러 기능을
  가리키는 `task_log` 파일이 18개라 그중 일부는 틀렸을 것이지만, 몇 건인지 안 세어 봤다
- **`(묶음 미상)` 171건 안에 살아 있는 것이 얼마나 되는가** — 안 훑었다
- **접기 기본값이 맞는가** — 관측이 아니라 「근거 없이 안 정한다」로 0을 골랐다. 몇 번 써 본
  뒤에만 답이 나온다
- **여러 세션이 동시에 부를 때** — 재는 도중 트리가 움직이는 것은 관측했지만(226 → 232),
  그것이 표를 실제로 틀리게 만든 사례는 못 봤다
