# 골든 답변 라벨 필드 넷을 더해도 기존 세트가 안 움직인다 — 103건 로드·43건 도장 불변

- 대상: [task_log/2026-08-29-골든답변-라벨링-착수.md](../task_log/2026-08-29-골든답변-라벨링-착수.md)

  라벨 데이터만 건드렸고 채점 코드를 안 돌렸다

## 1. 확인하려 한 것

**"규칙이 도는가" 쪽이다.** 임계값을 정하는 회차가 아니다.

`QAItem` 에 필드 넷(`must_values`·`must_points`·`must_reviewed_by`·`must_reviewed_hash`)을
더하면서 셋을 물었다.

1. **기존 103건이 그대로 로드되나** — `from_json` 이 모르는 키를 `ValueError` 로 막으므로,
   기본값이 없으면 세트가 통째로 죽는다
2. **기존 43건의 `reviewed_hash` 가 안 움직이나** — 13회차가 *"`must_*` 를 `content_hash` 에
   안 넣는다"* 로 정한 것의 실측 확인이다. 움직이면 재검수를 강요하고,
   `plan_log/검색-생성.md` 56회차가 피한 *"혼동행렬 여섯 판이 못 견주게 된다"* 를 밟는다
3. **모르는 키 가드가 헐거워지지 않았나** — 필드를 넷 더하면 오타(`must_value` 단수)가
   통과할 여지가 생긴다

## 2. 가상 데이터

무엇을 고립시켰나: **라벨이 붙은 레코드와 안 붙은 레코드를 같은 질의·같은 `gold_spans` 로
만들어, 갈리는 축을 `must_*` 하나로 남겼다.** 실제 세트로는 이 대조가 안 된다 — 커밋된
레코드는 라벨 유무와 내용이 함께 다르다.

```python
from evaluation.qa_set import QAItem, content_hash

base = {
    "query_id": "x-12", "query": "질문", "source_doc": "시행령-개정안-안내서",
    "gold_spans": ["어떤 정답 문장"],
}
bare = QAItem.from_json(dict(base))
labeled = QAItem.from_json({**base, "must_values": ["6개월"], "must_points": ["ㄱ"]})

print(content_hash(bare.query, bare.gold_spans))
print(content_hash(labeled.query, labeled.gold_spans))
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 라벨 없는 레코드 | `must_values == []` · `must_points == []` | 그대로 | 통과 |
| 〃 | `must_reviewed_by == "pending"` · `must_reviewed_hash == ""` | 그대로 | 통과 |
| 라벨 있는 레코드 | 두 리스트가 **따로** 실린다 | 그대로 | 통과 |
| 라벨 유무만 다른 두 레코드 | `content_hash(query, gold_spans)` 가 **같다** | 같다 | 통과 |
| `must_value`(단수 오타) | `ValueError: 모르는 키` | 그대로 | 통과 |

### 값 후보 추출 — 정규식만으로는 5건 중 2건이 가짜였다

`must_values` 후보를 정규식으로 뽑고 사람이 걸렀다. **뽑기와 거르기의 차이가 이 표다.**

| 질의 | 정규식이 뽑은 것 | 사람 판정 |
|---|---|---|
| `hsih-04` | `11` · `제3조제12호` | `11` 은 **목록 머리 번호** — 버림 |
| `hsch-10` | `1` | `[별표1]` 의 조각 — **전부 버림** |
| `hsih-02` | `2020년` · `2` | `2020년 기록관리 지침` 은 **문서 이름** — 전부 버림 |
| `hsih-07` | `6개월` · `2020.10.1.` | 둘 다 유효 |
| `hbas-06` | `206개` · `58개` | 둘 다 유효(`206개교`·`58개교` 로 확장) |

- **span 에 숫자가 있는 질의는 5건**(`hsih-02`·`hsih-04`·`hsih-07`·`hsch-10`·`hbas-06`)
- **실제로 `must_values` 가 된 것은 3건**이다 — `hsih-04`·`hsih-07`·`hbas-06`
- 즉 «값이 있는 span» 을 그대로 세면 **18건 중 5건(28%)** 인데, 실제 결정적 축의 분모는
  **3건(17%)** 이다. 이 회차에는 그중 2건이 실렸다(`hbas-06` 은 아직 미라벨)

**목록 머리 번호는 이 저장소가 `judge_probe` 에서 이미 배운 함정이다**(*"답변이 주장하는
사실을 하나도 안 바꾼다"*). 라벨링 쪽에서 같은 모양으로 되풀이됐고, 기계 추출만 믿었으면
가짜 `must_value` 둘이 들어갔다.
