## 1. 확인하려 한 것

물음은 둘인데 성격이 다르다.

- **«혼동행렬이 `local-gpu` 인데 운영은 `cohere` — off/fuse 비교에 영향을 주나»** — 이것은
  **재는 문제가 아니라 코드를 읽으면 답이 나오는 문제**다(3-A). 그래서 임계값을 안 정한다
- **«새로 연 축이 실제로 검색에 닿나 · 계단 세 판이 서로를 안 덮나»** — 이것은
  **«규칙이 도는가»** 라 가상으로 답한다(2절). 임계값이 없는 자리다

이 회차는 **도구만 고쳤다.** 판정 수치는 한 줄도 안 생겼다.

## 2. 가상 데이터

무엇을 고립시켰나: **재작성 축 하나만.** 검색·저장소·판정을 전부 가짜로 갈아끼워
(`tests/evaluation/test_verdicts.py` 의 기존 `_wire()` 결 그대로) `rewrite` 인자만 바꾼다.
리랭커는 `None` 고정이라 순위가 개입하지 않는다.

`tests/evaluation/test_verdicts.py` 에 더한 셋이 그 입력이다.

```python
# **`--rewrite` 가 실제로 검색에 닿아야 한다**
def test_rewrite_profile_reaches_retrieve(mocker, qa_path) -> None:
    _wire(mocker, _FakeEvaluator({}), {})
    rewriter = _FakeRewriter(api_calls=2, cache_hits=1)
    mocker.patch("rag_pipeline.retrieval.get_rewriter", return_value=rewriter)
    seen: list[object] = []
    mocker.patch(
        "rag_pipeline.retrieval.retrieve",
        side_effect=lambda query, **kw: seen.append(kw.get("rewriter", "안 넘김")) or [],
    )

    _, meta = score_verdicts(label="run", fmt="pdf", top_k=5, qa_path=qa_path, rewrite="fuse")

    assert seen == [rewriter, rewriter]
    assert meta["rewrite_profile"] == "fuse"
    assert (meta["rewrite_calls"], meta["rewrite_cache_hits"]) == (2, 1)

# 진짜 `off` 프로필이 None 을 내는 것까지가 계약이다
def test_rewrite_off_passes_none_instead_of_stopping(mocker, qa_path) -> None:

    assert meta["rewrite_calls"] is None
    assert meta["rewrite_warnings"] == []


# **이름이 안 갈리면 계단 세 판이 서로를 에러 없이 덮는다** — 13회차가 그렇게 표를 잃었다
def test_report_name_splits_on_rerank_and_rewrite() -> None:
    base = {"label": "h", "evaluator": "mini", "prompt_version": "v3"}
    ladder = (("local-gpu", "off"), ("cohere", "off"), ("cohere", "fuse"))
    names = {report_name(**base, rerank=r, rewrite=w) for r, w in ladder}

    assert len(names) == len(ladder)
    assert (
        report_name(**base, rerank="cohere", rewrite="fuse")
        == "h-verdicts-mini-cohere-fuse-v3.json"
    )
```

`kw.get("rewriter", "안 넘김")` 이 요점이다 — **«None 을 넘겼다» 와 «아예 안 넘겼다» 가
`kw.get("rewriter")` 로는 안 갈린다.** 기본값을 안 두면 축을 지워도 두 번째 테스트가 통과한다.

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `rewrite="fuse"` · 가짜 재작성기 | `retrieve` 가 그 객체를 받고 meta 에 `(2, 1)` | 질의 2건 모두 그 객체 · `("fuse", 2, 1)` | 통과 |
| 인자 없음(기본 `off`) | `retrieve` 가 **`None` 을 받는다**(SystemExit 아님) | `[None, None]` · `rewrite_calls` `None` · `rewrite_warnings` `[]` | 통과 |
| 계단 세 조합의 리포트 이름 | 서로 다른 이름 3개 | 3개 · `h-verdicts-mini-cohere-fuse-v3.json` | 통과 |

### 3-A. 물음의 답 — 두 자[尺]가 아직 안 만난다

| 항목 | 기준(물음) | 이번 실측 | 판정 |

| `top_k` | 기대 *충분* | 기대 *불충분*(=죽은 판정자 점수) | 정답을 물어온 긍정 |

## 5. 판정

- **«혼동행렬이 off/fuse 비교에 영향을 주나» — 아니다.** 두 자[尺]가 아직 안 만난다(3-A).
  **확인 완료 · 코드로 확정되는 종류라 임계값이 없다**
- **재작성 축이 실제로 검색에 닿는다 · 꺼짐이 합법이다.** 변이 검사로 확인. **의도한 변화**
- **리포트 이름이 계단 세 판을 가른다.** 변이 검사로 확인. **의도한 변화**
- **회귀 없음** — 기본 인자(`--rerank off --rewrite off`)에서 `retrieve()` 가 `rewriter=None`
  을 받으므로 검색 경로가 지금까지와 같다. 전체 스위트도 전건 통과
- **판정 수치는 한 줄도 안 생겼다** — 계단 세 판은 유료라 승인 대기다.
  **어긋난 축 넷은 그대로 열려 있다**

## 7. 재지 못한 것

- **계단 세 판 자체** — 유료(판정 `mini` 86호출/판 · `cohere` 리랭킹 86호출/판 × 2판)라
  승인 전에 안 돌렸다. **그래서 «운영에서 판정이 얼마나 맞나» 는 여전히 모른다**
- **재시도 루프의 발화율** — 이 도구는 판정만 잰다. 그쪽은 `retry_diff.py` 자리다
- **LLM 60건 세트에서의 같은 표** — 부정이 0이라 혼동행렬의 절반이 원리적으로 안 선다
- **옛 넷과의 직접 비교** — 라벨·프롬프트 판이 함께 움직여 계단 1판도 재현이 아니라
  **새 기준선**이다. 옛 파일들은 이름이 달라 덮이지 않는다(그것이 이번 이름 변경의 부수 효과다)
- **`--rewrite fuse` 의 실호출** — 가짜 재작성기로만 확인했다. 진짜 `QueryRewriter` 가
  이 경로에서 도는 것은 계단 3판이 처음이다
