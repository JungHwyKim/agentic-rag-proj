## 1. 확인하려 한 것

"규칙이 도는가"가 아니라 **"표의 값이 제 열에 들어 있는가"** 다. 그래서 실파일이 본문이고,
가상은 실파일이 못 만드는 경계(가로 병합)를 채우는 데만 썼다.

판정 자[尺]는 **행마다 칸 수가 같은가** 하나다. HWPX 는 병합에 가려진 칸을 `tc` 로 내보내지
않으므로, 칸 수가 들쭉날쭉하면 그 행은 값이 왼쪽으로 밀렸다는 뜻이다.

## 2. 가상 데이터

무엇을 고립시켰나: **한 표 안에 세로 병합과 가로 병합을 하나씩만** 두고 나머지를 없앴다.
실파일에는 가로 병합이 섞여 있어 두 규칙(세로는 되풀이 / 가로는 빈 칸)을 따로 확인할 수 없다.

```python
# tests/conftest.py 의 hwpx_merged_cells — 표 하나만 든 .hwpx 를 zip 으로 조립한다
def cell(col, row, text, col_span=1, row_span=1):
    return (
        f'<hp:tc><hp:cellAddr colAddr="{col}" rowAddr="{row}"/>'
        f'<hp:cellSpan colSpan="{col_span}" rowSpan="{row_span}"/>'
        f"<hp:subList><hp:p><hp:run><hp:t>{text}</hp:t></hp:run></hp:p></hp:subList></hp:tc>"
    )

rows = (
    f"<hp:tr>{cell(0, 0, '구분', row_span=3)}{cell(1, 0, '항목')}{cell(2, 0, '담당')}</hp:tr>"
    f"<hp:tr>{cell(1, 1, '가')}{cell(2, 1, '김')}</hp:tr>"          # 첫 칸의 tc 가 없다
    f"<hp:tr>{cell(1, 2, '비고 전체', col_span=2)}</hp:tr>"
)
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 세로 3행 병합 아래 행들 | 세 행 모두 첫 칸이 `구분` | 그대로 | 일치 |
| 가로 2칸 병합 | 값은 첫 칸, 다음 칸은 `""` | `['구분','비고 전체','']` | 일치 |
| 모든 행의 칸 수 | 3으로 동일 | 3 | 일치 |
| `cellAddr` 없는 표(기존 `hwpx_file`) | 예전대로 `tc` 순서 | 기존 테스트 전부 통과 | 일치 |
