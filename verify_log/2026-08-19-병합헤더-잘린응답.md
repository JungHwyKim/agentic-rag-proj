### 제보 1 — 10쪽 플로차트는 Vision 이 아니라 **OCR** 로 갔다

원본은 `<행정정보 데이터세트 기록관리 실행절차>` 순서도다(시작 → 관리대상 시스템 선정 →
대상/제외 분기 → 운영·보존기간 확인 → 만료/영구보존 분기 → 평가·폐기 / 보존·추출·이관).

우리 결과는 `image_source=ocr` 이고 본문이 이렇다.

```
관 Gat ae / 시작 eee 행정데이터세트 운영 평가 — 페기 / [때상락인] 선정 관리기준표작성|
^ `보존기간확있 령 / co / UENCE) 27/012 처분지원 도구 / [처분 결과서] / 기록관리 제외
보존/추출 / 으 저 / 시4 | SIARD_KR / [이관 권장 규격/도구] / wie Ane SE 영구기록관이관
```

**분기 조건과 화살표가 통째로 없다.** 사용자 지적이 정확하다.

원인은 임계값이 아니라 자[尺]다 — 이 도형은 **글자 225 · 신뢰도 78.1** 로 hybrid 조건
(10자 / 60점)을 여유 있게 넘는다. 12개 중 **신뢰도가 제일 높은 것이 하필 Vision 이 제일
필요한 도형**이다. 후보 신호 분포는 `plan_log/이미지-경로.md` 4회차 표에 그대로 남겼다.
**이번에 안 고쳤다** — 밀도로 갈라도 이 도형이 3.58 로 OCR 무리 한복판이라 못 잡는다.

### 제보 2 — 병합 헤더가 하위 열 이름을 삼켰다

24쪽 표는 67행 6열이고 다섯 조각으로 나뉜다. 헤더가
`['영역', '항목', '', '', '내용', '구분']` 이라 **2·3열에 이름이 없다.**

| | 이름 있는 열 | 본문이 통째로 빈 열 |
|---|---|---|
| **수정 전** | `[0, 1, 4, 5]` (다섯 조각 모두) | 3열이 4/5 조각에서 |
| **수정 후** | `[0, 1, 2, 3, 4, 5]` (다섯 조각 모두) | 그대로 (표 전체 기준 판정) |

헤더가 `['영역','항목','항목','항목','내용','구분']` 이 된다. 3열은 표 전체로 보면 4행
(종류·포맷·구동SW·저장방법)에서 값을 가지므로 **버리지 않는다** — 버리면 그 값이 사라진다.

### 제보 3 — 잘린 Vision 응답이 본문을 오염시켰다

`max_completion_tokens=1500` 을 넘긴 응답은 JSON 이 미완성이라 파싱이 깨지고, 옛 폴백이
**문자열 전체를 `description` 으로** 썼다.

```
전: '{\n  "description": "이 이미지는 SiardGui 2.1.1.12 프로그램 창의 …
후: '이 이미지는 SiardGui 2.1.1.12 프로그램 창의 일부분을 보여준다. 좌측에는 …
```

| | 값 |
|---|---:|
| 오염된 청크 (수정 전) | **6** |
| 오염된 청크 (수정 후) | **0** |
| 재검증에 쓴 새 Vision 호출 | **0** |
| 캐시에서 찾은 누출 응답 | 4 |

캐시에 저장된 값은 *파싱 결과*라 옛 오염이 그대로 남아 있었다. 저장된 원문을 다시 파싱해
**제자리에서 고쳤다** — 파생 캐시라 재계산과 결과가 같고 과금이 없다.
