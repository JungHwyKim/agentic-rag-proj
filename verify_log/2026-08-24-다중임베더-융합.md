# 두 임베더를 RRF 로 합쳐 봤다 — 천장 +2건에 실측 −7건

- 검증일: 2026-08-24
- 대상: [task_log/2026-08-24-다중임베더-융합.md](../task_log/2026-08-24-다중임베더-융합.md)

- 비용: **실제 청구 $0.00.** 사용자 승인을 받고 돌렸고 OpenAI 호출을 예상했으나
  **한 건도 안 났다** — 질의 임베딩까지 캐시에 있었다(7절)

## 1. 확인하려 한 것

둘이다. **(1) 규칙이 도는가** — `fuse()` 를 경로 둘 고정에서 N개로 넓힌 것이 기존 dense+BM25
산출을 안 바꾸는가. **(2) 임계값이 아니라 판정** — 상용(`baseline`) dense 와 로컬(`kure-v1`)
dense 를 합치면 KURE 단독보다 나은가.

(2)의 천장은 착수 전에 이미 쟀다 — 오라클 합집합이 60건 `0.883` vs KURE 단독 `0.850` 이라
**여지가 +2건**이었다(`2026-08-24-로컬임베더-비교측정.md` 3-4).

## 2. 가상 데이터

무엇을 고립시켰나: **경로 수 한 축만** 바꿨다. 저장소·임베더·BM25 가 전부 가짜라 키 없이 돈다.

전문은 `tests/retrieval/test_fuse_paths.py` 이고, 핵심 가짜는 이것이다.

```python
class FakeStore:
    def __init__(self, collection: str, results=None) -> None:
        self._collection = collection
        self.results = results or []
        self.top_ks: list[int] = []

    @property
    def collection(self) -> str:      # retrieve() 가 경로 이름을 여기서 얻는다
        return self._collection

    def search(self, query_vector, top_k=5):
        self.top_ks.append(top_k)
        return self.results
```

## 5. 판정

| 항목 | 판정 |
|---|---|
| `fuse()` 일반화가 기존 산출을 안 바꾼다 | **의도한 변화** — `test_rrf.py` 기대값을 한 줄도 안 고치고 통과 |
| `--bm25` / `--hybrid` 별칭 | **의도한 변화** — 라벨만 바꿔 재실행하니 `0.8167 / 0.5455 / 0.6156` 과 구간 구조까지 동일 |
| **다중 임베더 융합** | **기각.** 천장 +2건에 실측 **−7건**. 미리 박은 판정표의 *"깎인다"* 칸 |
| **BM25 융합의 구간 구조** | **확인 필요 → 새 갈래** — 총합은 −2건인데 `hit@1` +4건 · `MRR`·`nDCG`·`hit@20` 이 전부 올랐다. 아래 |

**융합이 진 기제는 RRF 가 순위만 쓴다는 데 있다.** `baseline`(0.483)과 KURE(0.850)에
**같은 무게**를 주므로 약한 쪽이 강한 쪽을 끌어내린다. 점수 단위가 달라 정규화를 못 해서
순위를 쓰는 것인데(`fusion.py`), 그 대가가 **검색기 품질 차이를 못 반영하는 것**이다.

**BM25 융합은 한 줄로 못 적는다.** 겹침 낮은 구간에서 −0.250(맞은 답 9건이 top-10 밖으로
밀림), 나머지 두 구간에서 +0.100·+0.050. **낱말이 겹치면 순위를 잘 매기고, 없으면 맞은 답을
밀어낸다.** 어휘겹침 회차가 baseline 임베딩에서 본 것(±0.000)과 같은 기제인데 **KURE 가 그
구간에서 강해진 만큼 손실이 커졌다.** 그룹으로도 갈린다 — 시행령 +1건 vs AI 가이드 −3건.

## 7. 재지 못한 것

- **OpenAI 과금을 예상했는데 안 났다.** 질의 임베딩이 `.cache/embedding` 에 있었다 —
  `axis-check` 실행이 같은 60건·20건을 `baseline` 프로필로 이미 임베딩해 뒀기 때문이다.
  **캐시를 비우면 과금이 난다**(질의 80회). 이번 값을 *"다중 임베더 융합은 공짜"* 로 읽으면
  안 된다
- **`candidate_k`·`rrf_k` 를 안 흔들었다** — 축을 하나만 바꾸는 규칙을 따랐다. 지난 격자
  30점의 폭이 `hit@10` 0.6667~0.7333(4건)이었고, 그것은 **baseline 임베딩 위에서 잰 값**이라
  KURE 위에서 다시 재면 다를 수 있다
- **BM25 융합이 왜 `hit@1` 을 +4건 올리는지** 안 봤다. 순위 재배치가 어디서 오는지는
  질의별로 읽어야 한다
- **`ai-04`·`ai-06`·`hsih-03` 의 원인** — 여전히 안 봤다. 융합의 천장이 정확히 이 셋이었고
  융합으로는 못 회수한다는 것만 확인됐다
- **8-2 교차**(리랭커 풀 밖 7건 × 겹침 0 구간) — 그 기록이 `query_id` 를 안 적었고, 물어본
  세션에서 답을 못 받았다
