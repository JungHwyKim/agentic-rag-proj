# 1단계 loader — 영역별 리뷰 기준

`rag_pipeline/ingestion/loader/**` 를 건드린 변경에 적용한다. 공통 규약은 `contracts.md` 에 있다.

## 같이 읽어야 하는 곳

변경된 파일만 읽으면 "잘 짰네요"밖에 못 쓴다. 그 파일이 지키기로 한 계약이 적힌 곳을 같이 읽는다.

| 바뀐 곳 | 같이 읽어야 하는 곳 |
|---|---|
| `loader/document/*.py` | `loader/document/base.py`, `loader/registry.py`, `schemas/document.py` |
| `loader/content/*.py` | `loader/content/router.py`, `loader/content/base.py` |
| `loader/detect.py` | `schemas/document.py` 의 `FileFormat`, `loader/registry.py` |
| 아무 핸들러나 | 그 핸들러를 덮는 `tests/` 파일 |

## 1. 아키텍처 경계 (최우선)

라우팅은 2단계다.

```
detect_format()  →  get_loader()  →  BaseDocumentLoader.load()
                                       ├ detect_regions()     포맷별 구현
                                       ├ promote_headings()   글자 크기 → TITLE 승격
                                       └ route_all()          ContentType → 핸들러
```

**문서 로더는 "어디에 무엇이 있는가"만 답한다.** `ContentRegion` 목록을 돌려주는 게 전부다.
**콘텐츠 핸들러만 "어떻게 텍스트로 만드는가"를 안다.**

이 경계가 있어야 "표를 LlamaParse 로 볼지 로컬로 볼지"를 `router.py` 와 설정만 고쳐서 바꿀 수
있다. 로더 안에서 OCR 을 부르기 시작하면 포맷 수 × 핸들러 수만큼 분기가 퍼지고, 비용 정책을
한 곳에서 못 바꾸게 된다.

### 잡아야 할 위반

- `loader/document/` 안에서 `image_ocr` / `image_vision` / `table_llamaparse` / `table_vision` / `pytesseract` /
  `openai` / `llama_cloud` 를 import 하거나 호출한다
- 로더가 `Element` 를 직접 만들어 반환한다 (핸들러의 일이다)
- `detect_regions()` 말고 다른 추상 메서드가 늘었다 — 포맷 로더가 져야 할 책임이 늘어난 것이므로,
  정말 공통 뼈대에 들어갈 일인지 따진다
- `route()` 의 `ContentType` 분기가 아니라 파일 확장자·포맷 이름으로 핸들러를 고른다
- `pipeline.py` 나 로더가 HTTP/FastAPI 를 안다 (`ingest()` 는 스크립트에서도 쓴다)
- `backend/app/api/routes/documents.py` 가 파싱 로직을 직접 한다 → `backend.md` 참고

경계 위반은 발견하면 **반드시 Critical 로 올린다.** 지금 안 잡으면 다음 포맷을 추가할 때 복사된다.

## 1-2. 제목 승격 — 되돌리면 조용히 깨지는 것들

`loader/document/headings.py` 가 글자 크기를 보고 문단을 `TITLE` 로 올린다. 이게 있어야
splitter 가 청크를 끊을 경계를 얻는다(`splitter.md` 1절). 로더는 관측한 크기를
`metadata["font_sizes"]` 로 싣기만 하고 **판정은 이 파일에서만** 한다 — 포맷 로더가 직접
`TITLE` 을 결정하기 시작하면 같은 규칙이 포맷 수만큼 복제된다.

되돌리면 안 되는 것 넷이다. 전부 실측으로 정해졌고 근거는 그 파일 docstring에 있다.

- **`min(sizes) > body` 다. `max` 로 바꾸면 안 된다.** 문단 안에 본문 크기 이하 글자가 섞이면
  제목이 아니라 강조다(`작성 [큰글씨]홍길동[/] 수석`). `max` 로 바꾸면 강조가 제목이 된다
- **본문 크기는 문서별 최빈값이다.** 절대 임계값으로 바꾸면 문서마다 결과가 뒤집힌다
  (본문이 HWPX 949 / 1500 / 1200, PDF 9.5)
- **배율이 아니라 부등호 하나다.** 1.2배 같은 임계값을 넣으면 제목 1600 / 본문 1500 인
  문서에서 제목 19개가 통째로 사라진다
- **번호·기호 머리(`□` · `1.` · `제N조`)로 승격하지 않는다.** 기각된 안이다 — 큰 글씨와
  마커가 겹치는 문단이 0/74 · 0/54 였고, 마커만 보면 시행령에서 158개를 오인한다

그리고 **호출 위치가 `detect_regions()` 밖이라는 점**을 지킨다. `regression/baseline.json` 이
`detect_regions()` 출력을 기준선으로 재므로, 안으로 옮기면 같은 결과를 내면서 기준선만 흔든다.

`font_sizes` 가 `Element.metadata` 로 새는지도 본다 — 판정에만 쓰고 버려야 한다.

## 2. 폴백 사슬

규약(예외 금지·경고·재계산 금지)은 `contracts.md` 2절에 있다. loader 의 구체적인 사슬은 둘이다.

```
표    : table_llamaparse (blob 있고 table_pdf_handler="llamaparse") → 실패/키없음 → table_native
표(승급): table_vision (blob 있고 table_pdf_handler="hybrid" 이고 region.mark_cells > 0)
        → 실패/크기 불일치/채운 것 0 → table_native
이미지: classify() → SKIP(로고·아이콘 크기 필터) / OCR / Vision → Vision 실패 → classify 가
        이미 돌린 OCR 결과(decision.ocr) 재사용
```

- Vision 실패 후 OCR 을 **다시** 돌리는 변경은 이미 낸 비용을 버리는 것이다
- **OCR 이 Tesseract 예외를 삼키는 것은 `contracts.md` 2절 때문이 아니다.** 그 규약은 유료
  외부 API 것이고 "내려갈 층이 있어서" 성립하는데, OCR 은 **사슬의 맨 아래**라 아래에 층이
  없다. 여기서 삼키는 이유는 폴백을 살리기 위해서가 아니라 이미지 하나가 적재 전체를 멈추는
  것을 막기 위해서다 — 계약 위반이 아니라 **계약 밖 강인화**다. 이걸 근거로 "OCR 도 폴백
  규약 대상"이라고 일반화하는 지적은 틀렸다. 반대로 `run_ocr()`·`extract_text()` 가
  `ctx` 를 **선택** 인자로 받는 것도 의도다 — `classify()` 는 `LoadContext` 가 없어 경고를
  못 남기고, 대신 `Decision.reason` 이 흔적을 남긴다(2026-08-22)
- **`table_vision` 이 원본 값을 덮으면 Critical 이다.** 이 핸들러의 계약은 *비어 있던 칸만
  채운다* 하나다. 값이 있던 칸을 모델 응답으로 갈아끼우면 `_fill_merged_cells()` ·
  `_merge_split_tables()` · `_merge_across_pages()` · `_join_split_cells()` 가 각각 실측으로
  오검출 0 을 확인한 결과가 조용히 뒤집힌다 — **에러가 안 나서 아무도 모른다**
- **격자 크기가 다를 때 자리를 맞추려 드는 변경도 Critical 이다.** 열 이름으로 대응시키는
  안은 HWPX 병합 셀에서 겪은 자리 밀림(373행)과 같은 종류다. 계약은 **통째로 버리고 폴백**이다
- 승급 트리거(`pdf.py:_mark_cells`)를 종횡비·채움색으로 바꾸는 변경은 근거를 요구한다.
  면적비를 고른 이유는 그것이 임계값이 아니라 **의미의 경계**이기 때문이다(칸을 통째로 덮으면
  배경, 일부면 그려진 것). 다른 축은 문서마다 다시 정해야 한다
- **판정 단위는 실제 셀 사각형 + 격자 구멍이고, 병합에 덮인 자리는 뺀다.** 셋을 한 덩어리로
  묶는 변경은 Major 다 — 실측(PDF 4개)으로 병합 자리 514개에서 새 표시가 **0건**이고, 그
  자리는 *"가로 연장은 빈 칸으로 둔다"* 가 일부러 비워둔 곳이라 옆 칸 값이 이미 덮는다.
  두 겹(`_MARK_INSIDE_RATIO` · `_MARK_AREA_RATIO`)은 합성 격자 칸에서도 **그대로 쓴다** —
  안쪽 조건을 빼면 6, 면적 조건을 빼면 30, 둘 다 빼면 251 로 쏟아진다(현재 1)
- **`table_vision` 이 아는 서명을 다시 부르면 비용 누수다.** `ContentRegion.mark_signature`
  가 있고 `LoadContext.mark_symbols` 에 그 서명이 있으면 **호출 없이** 기하로만 메운다
  (실측: AI가이드 PDF 표 6개 → 호출 1회). **문서당 flat 1회로 바꾸자는 제안은 기각한다** —
  "문서 안에서 기호가 하나"는 재본 적 없는 가정이고, 서명 축이 그것을 실측으로 대체한다.
  **기호를 실제로 얻었을 때만 기억하는지** 본다 — 실패·거절한 서명을 기억하면 그 문서의 남은
  표가 전부 빈 기호로 죽는다(못 쓸 응답을 캐시에 안 넣는 것과 같은 형태다)
- 표 Vision 캐시 키 salt 에 **모델명과 프롬프트 해시**가 둘 다 있는지 본다. 프롬프트가
  빠지면 규칙 문구를 고쳐도 옛 답이 **에러 없이** 돌아온다(해상도·격자에 이어 같은 형태의
  구멍 셋째였다). 키 본문은 PNG + 격자다 — `region.blob` 을 쓰면 안 된다(생성 시각이 들어가
  매번 다른 바이트가 나와 캐시가 한 번도 안 든다)
- 표 승급이 `max_vision_calls_per_doc` 를 이미지와 **공유**하는지 본다. 표 전용 상한을
  새로 두면 둘 다 예산이 남았는데 한쪽만 막히는 상황이 생긴다
- hybrid 이미지 판정(`loader/content/classify.py`)이 무료·로컬 Tesseract 를 **먼저** 돌리는
  순서가 깨졌는지 본다. 이 순서가 유료 Vision 호출을 아낀다. 200페이지 스캔본을 전부 Vision 에
  보내면 감당이 안 된다

## 3. 정렬 계약 — `route_all()` 이 두 번 정렬하는 이유

`loader/content/router.py` 의 `route_all()` 이 **두 번** 정렬한다 — 먼저 regions 를 `order` 로,
핸들러를 다 돌린 뒤 결과 elements 를 다시 `order` 로. 리전 하나가 여러 Element 로 늘어나기
때문이다.

- **앞 정렬**은 **직렬로 남은 핸들러**(텍스트·표·유료 Vision)의 호출 순서를 결정론적으로
  만든다 → 그쪽 비용 카운터가 재현된다
- **뒤 정렬**은 늘어난 Element 를 문서 순서로 다시 합친다. **병렬 실행의 전제가 이것이다**

둘 중 하나를 지우는 변경은 되돌리게 한다. 특히 **뒤 정렬을 지우면 요소 순서가 완료 순서로
흐트러지는데, 짧은 문서에서는 우연히 맞아 테스트를 통과할 수 있다.**

**2026-08-24 에 좁아졌다가 2026-08-25 에 되돌아왔다.** 무료 OCR 이 병렬로 돌면서 하루 동안
`ctx.warnings` 순서가 완료 순서였는데, 자식 컨텍스트(3-1절)로 문서 순서를 되찾았다.
**지금은 경고 순서도 결정론적이고 문서 순서다** — 직렬 핸들러의 경고와도 제자리에 섞인다.
`route_all()` 의 조립 루프에서 `ctx.absorb()` 를 옮기거나 빼면 이게 조용히 깨진다.

## 3-1. 병렬 경계 — 되돌리면 과금이 샌다

`route_all()` 은 **무료 OCR 만** 스레드로 돌리고 유료 핸들러는 직렬로 남긴다. 실측
(2026-08-24, 47쪽 통짜 스캔 PDF)으로 `ingest()` 237.5초 중 Tesseract 가 213.9초였고,
워커 8에서 51.8초가 됐다(요소·본문 자수·회귀 기준선 전부 동일).

리뷰에서 볼 것은 셋이다.

- **유료 핸들러를 병렬 구간에 넣는 변경은 Critical 이다.** `image_vision` · `table_vision` 의
  상한 검사가 `if ctx.vision_calls >= cfg.max_vision_calls_per_doc:` 와 증가로 **갈라져**
  있고 `ctx.mark_symbols` 메모도 조회와 기록이 갈라져 있다. 병렬이면 상한을 넘겨 과금되고
  "서명당 1회"(표 6개 → 호출 1회)가 여러 번이 된다 — **키 없는 기본 pytest 는 그걸 못 잡는다.**
  올리려면 검사와 증가를 한 임계구역으로 묶어야 하고, 그건 `LoadContext` 의 락을 넓히는 것과
  **다른 일**이다
- **`classify()` 에 `ctx` 를 들이는 변경은 이 병렬화의 전제를 깬다.**
  `classify(image, config, bbox=)` 가 `LoadContext` 를 안 받아 공유 가변 상태를 한 톨도 안
  건드리는 것이, 판정을 병렬 구간 안에 둘 수 있는 유일한 근거다. 판정은 비용의 **절반**
  (108.0초)이라 직렬로 내려오면 이득이 반으로 준다. 경고가 필요하면 `Decision.reason` 을 쓴다
- **`absorb()` 를 안 거치고 워커가 공유 `ctx` 에 바로 쓰게 되돌리면 두 가지가 한꺼번에
  깨진다.** 하나는 경고 순서(3절)이고, 다른 하나가 더 크다 — `absorb()` 가 자식의
  `vision_calls` · `llamaparse_calls` · `mark_symbols` 가 비었는지 검사하는 것이 **유료가
  병렬 구간에 들어오지 않았다는 유일한 실행 시점 증거**다. 빼면 위 첫 항목의 Critical 이
  주석과 테스트로만 지켜지는 상태로 되돌아간다
- **판정 결과를 모아 두고 나중에 처리하는 모양으로 되돌리면 메모리가 터진다.** 여는 것 ·
  판정 · 무료 OCR 이 한 워커 안에서 이어지는 이유다 — `Image.open` 은 게으르지만 `classify()`
  안의 `preprocess()` 가 `load()` 를 강제해, 47쪽이면 디코드된 픽셀 **약 1.2GB** 가 동시에
  산다(2500x3535 RGB × 47, 계산값). 유료로 갈린 리전에 이미지를 딸려 보내는 변경도 같은 축이다

## 4. 알려진 함정

리뷰 중 이 근처를 건드렸다면 특별히 본다. 아래 수치는 전부 실측이다.

### OCR 한국어

- `ocr_psm=6` 을 쓴다. 기본 3 은 한글 한 줄을 세로로 오인식한다
  (실측: "대한민국 서울특별시" → `[ 완 ro 소 mo`, PSM 6 으로 바꾸니 신뢰도 93%)
- `preserve_interword_spaces=1` 이 없으면 "주식회사"가 "주 식 회 사"로 쪼개져 임베딩·검색이
  망가진다
- **`image_to_data` 는 이 옵션을 무시**하므로 용도가 분리돼 있다 — **신뢰도는 `image_to_data`,
  최종 텍스트는 `image_to_string`.** 상자 간격으로 재조립하는 방법은 실측으로 불가능이 확인됐다
  (한글 음절 내부 간격 0.26~0.56 과 영문 단어 경계 0.48~0.59 가 겹쳐 임계값 하나로 못 가른다).
  **이 둘을 합치는 변경은 되돌리게 한다**

### 이미지 전처리

600px 미만일 때만 확대한다. 이미 큰 이미지를 늘리면 보간 흐림 때문에 인식률이 떨어진다
(실측: 900→1000px 미세 업스케일에서 원본 7토큰 → 전처리 후 0토큰).

### HWPX

- **쪽 번호**: `hp:tbl` 의 `hp:sz height` 를 믿으면 안 된다. 쪽을 넘기는 표는 이 값이 **시작
  쪽에 남은 공간으로 잘려서** 저장돼 있다(실측: 43행 표가 선언 34206 / 실제 98326). 실제 높이는
  `hp:cellSz height` 를 `hp:cellSpan rowSpan` 으로 나눠 복원해야 나온다. vertpos 만 보고 쪽을
  세면 쪽 넘긴 표 뒤로 쪽 번호가 전부 밀린다
- **레이아웃 표**: 한글은 제목·인용을 그릴 때 표를 쓴다. 내용 든 칸이 2개 이하이고 9칸 이하인
  표는 `_is_layout_box` 가 본문 문단으로 강등한다(`metadata["layout_table"]` 로 표시).
  그림이 든 상자는 캡션-그림 관계가 끊기므로 표로 남기고, **표가 든 상자도 남긴다** —
  강등하면 안쪽 표가 문단으로 뭉개진다. **세는 대상은 `_table_rows()` 의 격자가 아니라 실제
  `tc` 목록이다**(`_table_anchor_cells()`). 격자는 병합 칸을 펴므로 그걸 세면 임계값의 뜻이
  달라진다 — 되돌리면 시행령 안내서 표가 9→13개가 된다
- **병합 셀**: 병합에 덮인 자리는 `hp:tc` 가 아예 안 나온다. `hp:cellAddr` 를 안 보고 순서대로
  담으면 값이 왼쪽으로 밀린다(실측 373행). `_table_rows()` 가 `cellAddr`·`cellSpan` 으로
  격자를 채우고, **세로 연장은 값을 되풀이 / 가로 연장은 빈 칸**이다 — splitter 가 행 단위로만
  쪼개기 때문이다. **되돌리면 열 이름과 값이 틀리게 짝지어진 표가 색인된다.**
  직계 `tr`/`tc` 만 보는 것도 규칙이다 — `_text_of()` 가 재귀라 중첩 표 텍스트는 부모 칸에
  이미 있고, `iter` 로 훑으면 같은 내용이 두 번 들어간다
- **가로 쪽**: 한컴은 가로 쪽에서도 `hp:pagePr@width/height` 에 물리 용지(세로) 치수를 그대로
  넣고 방향은 `landscape` 속성으로만 표시한다. **이름과 반대로 `NARROWLY` 가 가로, `WIDELY` 가
  세로다**(실측: 시행령 개정안 안내서 가로쪽 판 — 두 방향 모두 width=59528 height=84188 인데
  WIDELY 섹션의 vertpos 가 69898 까지 올라가 71435=height-여백 에 육박한다. 가로였다면 46775 를
  넘을 수 없다). 가로 섹션의 본문 높이는 `width` 에서 얻어야 한다 — 안 가르면 53% 과대평가해
  쪽 넘긴 표를 한 쪽으로 세고 이후 쪽 번호가 밀린다
- 실제 한컴 파일 회귀 테스트(`tests/ingestion/loader/document/test_hwpx_real.py`)는
  `tests/fixtures/` 에 파일이 있을 때만 돌고 없으면 조용히 skip 한다

### LlamaParse SDK

`llama-parse` 와 `llama-cloud-services` 는 **둘 다 deprecated** 다
(`llama-cloud-services` 는 2026-05-01 유지보수 종료, 이미 지났다).
`llama-cloud>=1.0` 의 `Client.parsing.parse()` 를 쓴다.

### 레거시 포맷

`.hwp`/`.doc`/`.ppt` 는 감지만 하고 `UnsupportedLegacyLoader` 가 변환 안내와 함께 415 로
거부한다. 정확한 안내를 주려면 업로드 자체는 받아야 하므로 **`SUPPORTED_EXTENSIONS` 에 남아
있어야 한다** — 여기서 빼는 변경은 안내를 망친다.

### zip bomb

`loader/detect.py:MAX_UNCOMPRESSED_BYTES`(500MB). 새 zip 계열 포맷을 추가하면서 이 검사를
우회하지 않았는지 본다.

### 포맷 판별

확장자를 믿지 않고 매직바이트로 판별한다(zip/ole 는 내부 구조까지 봐야 갈린다).
확장자로 분기하는 코드가 새로 생겼으면 지적한다.

### PDF 스캔 판정

10자 미만을 스캔으로 본다. 20자로 올리면 제목만 있는 표지·간지가 전부 OCR 로 넘어가 비용을
낭비한다.

### PDF 표 — 되붙이기와 병합 셀

둘 다 **되돌리면 조용히 검색 품질이 나빠지는** 자리다.

- **리전 되붙이기**(`pdf.py:_merge_split_tables`): `find_tables()` 가 한 표를 여러 개로 내놓는다.
  splitter 는 각 조각의 첫 행을 헤더로 되풀이하므로 실제 열 이름이 첫 조각에만 남는다.
  조건 셋(**세로 간격 12pt 미만 · 좌우 끝 ±2pt · 열 수 동일**)을 **모두** 만족할 때만 붙인다 —
  하나라도 빼면 서로 다른 표가 붙는다(실측: 열 수 조건이 2026 중등 계획 31쪽을 걸러낸다).
  임계값 12 는 관측값이 아니라 **분포의 틈**에서 나왔다(조각 6.8 vs 별개 18.8 이상)
- **병합 셀 채우기**(`pdf.py:_fill_merged_cells`): `extract()` 만 보면 병합 자리와 빈 칸이
  구분되지 않는다. **`row.cells[j] is None` 과 겹쳐 봐야 갈린다.** 규칙은 HWPX 와 같지만
  (세로 되풀이 / 가로 빈 칸) **판정은 좌표 스캔이 아니라 기하**다 — 격자 칸 중심점을 덮는 셀을
  찾아 그 셀의 왼쪽 열이면서 위에 있을 때만 채운다. "같은 열 위에 값이 있으면" 으로 되돌리면
  **위 칸이 실제로 여기까지 안 내려오는 자리까지 채운다**(실측 897칸 중 13칸 오염).
  격자 경계는 **모든 칸 모서리의 합집합**에서 얻는다 — 그 행의 칸들만 보면 범위가 부푼다.
  격자 계산은 `pdf.py:_grid_of()` 하나뿐이다. 되살려 복제하는 변경은 Major 다
- **격자 구멍**(`pdf.py:_grid_holes` · `_fill_grid_holes`): `row.cells[j] is None` 은 **한
  가지 뜻이 아니다.** 격자 칸 중심을 덮는 셀이 있으면 병합에 덮인 자리이고, 없으면
  `find_tables()` 가 셀 사각형을 아예 안 낸 구멍이다. 표 안에서 사라지던 행 라벨(AI가이드
  17쪽 `책임성`)이 후자였다. 구멍 글자를 되살릴 때 **표 전체가 빈 열을 빼는 가드를 지우면
  Major 다** — 표 바깥 여백을 열로 삼킨 자리의 쪽 번호가 표에 들어간다(실측 2건 중 1건).
  그 잣대는 splitter 의 *"표 전체에서 비어 있는 열은 버린다"* 와 같은 것이고 새 축이 아니다.
  **구멍 채우기가 "표가 살아남을지 판정한 뒤"에 오는 순서도 계약이다** — 앞으로 옮기면 구멍
  글자만으로 빈 표가 되살아나 리전 수가 움직이고 기준선이 재는 것이 정확히 그 수다
- **쪽 경계 되붙이기**(`pdf.py:_merge_across_pages`): 같은 쪽 규칙과 **축이 다르다** —
  세로 간격은 쪽이 바뀌면 사라지므로 **두 리전 사이에 한글을 가진 텍스트 블록이 0개**인지를
  본다(좌우 끝 ±2pt · 열 수 동일은 그대로). **헤더 반복으로 바꾸자는 제안은 기각한다** —
  실측으로 오검출 4 · 미검출 3 이다(AI가이드 12~17쪽이 헤더가 같은 별개 표 다섯).
  기하 띠로 머리말을 거르는 안도 **틈이 1.0%p** 라 기각됐다. 이어 붙인 표는 **`blob` 을
  지운다** — 단일 쪽 크롭으로 표현할 수 없어 남겨 두면 유료 경로가 조각 하나만 보낸 결과를
  전체로 안다. 앵커 이어받기는 **빈 칸이 이어지는 구간까지만**이고, 여기서 멈추지 않으면
  위 897칸 중 13칸 오염 규칙으로 되돌아간다
- **쪽을 넘긴 요소의 끝 쪽은 `metadata["page_end"]` 로만 남긴다.** HWPX·PDF 가 같은 키를
  쓰고 splitter(`_element_page_end`)와 indexing 이 그것을 읽는다. 새 키를 만들면 그 포맷만
  조용히 빠지므로, 리뷰에서 `page_span` 같은 이름이 보이면 지적한다
- **갈린 셀 잇기**(`pdf.py:_join_split_cells`): 쪽 경계가 셀 하나를 가로지른 것을 잇는다.
  **`rows` 의 값 반복으로 판정하자는 제안은 기각한다** — `선택`/`선택` 같은 값이 병합처럼
  보여 실측 오검출 2건이다(기하 판정은 0건). 판정용 셀 행 수는 `metadata` 사설 키로 나르고
  `detect_regions()` 가 지운다 — **그 키가 공개 스키마로 새면 지적한다**
- **이 둘을 외부 API 로 대신하자는 제안이 나오면 기각한다.** 핸들러가 리전 하나의 blob 만
  보내 LlamaParse 는 조각 하나밖에 못 본다. 근거는 `plan_log/표-경로.md`
