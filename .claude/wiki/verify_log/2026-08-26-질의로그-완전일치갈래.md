## 1. 확인하려 한 것

셋이고 성격이 다르다.

- **규칙이 도는가** — `ANSWER_CACHE_MODE=exact` 가 임베딩 없이 조회하고, 표기가 다른 같은
  질문을 잡고, 다른 문자열은 미스이고, 무효화가 그대로 무는가
- **값이 얼마인가** — exact 히트가 실제로 얼마를 아끼는가. 이건 실서빙에서만 나온다
- **전제가 참인가** — 넘겨받은 *"운영 `.qdrant` 의 KURE 컬렉션 0건"* 이 지금도 참인가

**임계값을 정하는 검증이 아니다.** 이 축에는 정할 값이 없다(완전 일치의 성질).

## 2. 가상 데이터

무엇을 고립시켰나: **qdrant 클라이언트**. `retrieve()` 가 **id 가 맞을 때만** 돌려주는 가짜를
써서 *"다른 문자열은 미스"* 를 실제로 잴 수 있게 했다 — 기존 `query_points()` 가짜처럼 무조건
주면 그 계약이 검증되지 않는다.

```python
# tests/answer_cache/test_answer_cache.py 의 _FakeClient 에 더한 것
def retrieve(self, collection_name: str, ids: list[Any], **_: Any) -> list[_Point]:
    if self._point is None or str(self._point.id) not in {str(i) for i in ids}:
        return []
    return [self._point]
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| exact · 같은 문자열 | 히트 · `embed_query` 0회 | 히트 · 0회 | 통과 |

| exact · `"유예 기간은 언제까지죠?"` (뜻 같음) | **미스** · 임베딩 0회 | 미스 · 0회 | 통과 |
| exact 히트의 `cached_from.score` | 1.0 | 1.0 | 통과 |
| exact · 근거 청크가 사라짐 | 미스 + 항목 삭제 | 미스 + `delete` 호출 | 통과 |
| exact · `put()` | 진짜 벡터 저장 · 임베딩 1회 | `[0.1,0.2,0.3]` · 1회 | 통과 |
| `semantic` + threshold `None` | `get_answer_cache()` 가 `None` | `None` | 통과 |
| `exact` + threshold `None` | 캐시 객체 · `mode="exact"` · `threshold=None` | 그대로 | 통과 |

## 7. 재지 못한 것

- **완전 일치의 적중률** — 이 회차가 만든 것이 그것을 재는 도구다. **로그가 비어 있어
  아직 분자도 분모도 없다.** 실사용이 쌓여야 나오고, 그것이 캐시를 켤지 정하는 유일한 근거다
- **다른 생성 모델과의 비교** — 사용자가 나중에 `gpt5.6luna` 로 견주겠다고 밝혔다.
  이번 수치는 전부 `gpt-4.1-mini` 기준이고 **그 비교는 안 했다.** 왕복 시간의 대부분이
  검색·모델 적재라 생성 모델을 바꾸면 1회차 수치만 움직인다(2회차 0.008초는 생성을 안 탄다)
- **화면에서 `shadow_missing` 배지 확인** — 두 컬렉션의 `document_id` 가 같은 것으로
  구조 확정했고 눈으로는 안 봤다
- **멀티워커에서의 로그 경쟁** — 모듈 레벨 `Lock` 은 프로세스 하나를 전제한다.
  지금 실행 형태가 `--reload` 단일 프로세스라 안 쟀다
- **`qa_cache` 컬렉션을 지워도 디렉터리가 남는다** — `delete_collection()` 뒤에도
  `.qdrant/collection/qa_cache_.../storage.sqlite`(32KB)가 남아 손으로 지웠다.
  qdrant 가 컬렉션 목록에서는 빼므로 무해하지만, **`QdrantAnswerCache.clear()` 가 색인마다
  같은 일을 한다** — 캐시를 켠 뒤 디스크가 실제로 회수되는지는 안 쟀다
