# `replace` 로 반례를 찾으려 했는데, **새 판이 한 건도 안 나온다 — 원리적으로다**

- 검증일: 2026-08-28
- 대상: 접기 판정의 반례 찾기. **제품 코드·평가 도구 변경 0** — `evaluation/retry_diff.py` 를
  `--rewrite replace` 로만 바꿔 부른 측정 회차다
- 비용: **유료(사용자 승인)** — **재작성 0회(전량 캐시 히트)** · Cohere 리랭킹 37회 ·
  판정 67회(추정, 7절) · 생성 0회. `-m integration` 미실행. 색인 재실행 0

## 1. 확인하려 한 것

접기 판정의 누적이 **판 2건 · 잃음 1 · 살림 0 · 그대로 1** 이라 규칙(3판 이상 · 잃음 > 살림)에
못 미친다. 판을 늘리는 길 셋 중 둘이 이미 닫혔다 — 재시도 상한(33회차 실측으로 무효)과
코퍼스 확대(41회차에 기각). 남은 둘 중 **`replace` 반례 찾기**를 골랐다.

**비대칭을 알고 시작했다** — 다음 회차가 한 번이라도 정답을 살리면 「근거가 같으면 항상
접는다」는 **전역 규칙을 기각**할 수 있지만, **0건이어도 운영 모드 `fuse` 에서 안전하다고는
못 한다.**

33회차와 **같은 코퍼스**(`h-cohere-18w3` · 4문서 414청크 · PDF)에 재작성 모드만 바꿔
축을 고립시켰다.

## 2. 가상 데이터

**없음.** 재는 것이 *규칙이 도는가* 가 아니라 *다른 모드가 다른 판을 내는가* 라, 합성
입력이 답할 질문이 없다.

## 3. 실제 데이터

### 3-A. 회계 게이트

| 항목 | `fuse`(33회차) | `replace`(이번) |
|---|---|---|
| 검색 | 67 | 67 |
| 재작성 | api 49 + cache 18 = 67 ✔ | **api 0 + cache 67 = 67** ✔ |
| 리랭킹 | api 67 + cache 0 = 67 ✔ | **api 37 + cache 30 = 67** ✔ |
| 경고 | 없음 | 없음 |

**재작성이 0원인 것은 설계가 값을 한 것이다** — `rewrite_cache_salt` 에 `rewrite_mode` 를
일부러 안 실어 두 모드가 캐시를 나눠 쓴다(*"둘 다 만들어 재본다"* 의 근거였다).
**리랭킹 api 37회는 모드가 실제로 먹었다는 증거다** — 후보 집합이 37회 달랐다는 뜻이다.

### 3-B. 회차 67개 전수 대조 — 거의 전부 같다

| 대조 축 | 같은 회차 |
|---|---|
| **재작성 질의** | **67 / 67** |
| 판정(`real_verdict`) | 66 / 67 |
| **근거 목록(`chunk_ids`)** | **64 / 67** |

근거가 갈린 3회차 중 **순위가 실제로 움직인 것은 하나뿐**이다.

```
hsih-02 [0]  rank None -> None   (판정은 sufficient -> insufficient 로 갈렸다)
hsih-10 [2]  rank 4    -> 3      <= 유일하게 순위가 움직인 회차
hsch-12 [0]  rank None -> None
```

### 3-C. 요약 지표가 한 칸도 안 갈린다

| 항목 | `fuse` | `replace` |
|---|---|---|
| 근거 동일 회차 | 9 (질의 8) | 9 (질의 8) |
| 짝지음 · 못 봄 | 4 · 5 | 4 · 5 |
| 접었으면 놓쳤다 · 안 도왔다 | 0 · 4 | 0 · 4 |
| 실사용이 닿았을 회차 | 2 | 2 |

### 3-D. 판이 **같은 판**이다 — 두 번 세면 안 된다

두 실행 모두 판은 `hbas-01` **하나**이고, `(query_id, N, rank_n, rank_next)` 가 같다.

```
fuse    판: [('hbas-01', 2, 1, None, '안 도왔다')]
replace 판: [('hbas-01', 2, 1, None, '안 도왔다')]

hbas-01 회차 대조
  [0] rank 4 / 4 · 근거 동일 · 질의 같음
  [1] rank 1 / 1 · 근거 동일 · 질의 같음
  [2] rank 1 / 1 · 근거 동일 · 질의 같음   <= N
  [3] rank None / None · 근거 동일 · 질의 같음
  stop retries_exhausted / retries_exhausted · 근거동일 [2] / [2]
```

**네 회차가 질의·근거·순위까지 전부 같다.** 그러므로 이 실행은 **새 판을 0건 만들었고**,
누적은 그대로 **판 2건 · 잃음 1 · 살림 0 · 그대로 1** 이다.

### 3-E. 왜 같은가 — 우연이 아니라 **구조**다

`retrieve()` 안에서 재작성기는 `rewrite(current_query, 1차 pool)` 로 불린다. 그 **1차
pool 은 `_branches_for(current_query)` 라 모드와 무관**하고, 합류(`fuse` 4갈래 /
`replace` 2갈래)는 **그 호출 뒤에** 일어난다. 루프의 `step_rewrite` 는 `last_rewritten` 을
`current_query` 로 승급하기만 하므로,

- 0회차 재작성 입력이 모드와 무관 → 1회차 `current_query` 가 같다
- 1회차 재작성 입력도 모드와 무관 → 2회차 `current_query` 가 같다 → 귀납

즉 **재작성 질의 열이 원리적으로 모드와 무관하다.** 실측 67/67 이 그 귀결이다.
갈릴 수 있는 것은 **근거 집합 → 판정 → 정지 시점** 뿐인데, 근거 집합은 리랭커가 흡수했다
(후보가 37회 달랐는데 top-5 는 64/67 같다). 35~39회차의 *"리랭커가 재작성을 흡수한다"* 가
**재시도 루프 안에서도 재현됐고**, 이번에는 지표가 아니라 **근거 목록 동일성**으로 잰 것이
다르다.

## 4. 테스트 스위트

코드 변경이 0이라 회귀 대상이 아니다. 같은 세션의 41회차 실행 직후 값이
`ruff All checks passed!` · `pytest 1606 passed, 8 skipped, 7 deselected` 였다.

**그 직후 `tests/evaluation` 4건이 실패 상태였는데 이 회차와 무관했고, 이미 해소됐다.**
다른 세션이 `evaluation/answer_eval.py` 의 `report_name()` 에 `rerank`·`top_k` 를 더하는
중이었고(같은 라벨에서 `--top-k` 만 5→10 으로 바꾼 판이 **에러 없이 덮이는** 것을 막는
변경이다) 테스트가 잠깐 안 따라온 창에 이 회차의 훅이 걸린 것이다. 그쪽이 짝 테스트 둘
(`test_the_rerank_profile_splits_the_report` · `test_the_top_k_splits_the_report`)까지
더해 `tests/evaluation` 은 **337 passed, 6 skipped** 다. 손대지 않았다.

**그래서 위 1606 을 이 저장소의 현재 기준선으로 읽으면 안 된다** — 그 세션이 테스트를
늘리고 있어 올라간다.

## 5. 판정

| 항목 | 판정 | 근거 |
|---|---|---|
| 「`replace` 가 반례를 낸다」 | **기각** | 살림 0 · 새 판 0. 판이 33회차와 글자까지 같다 (3-D) |
| 「`replace` 로 판을 늘릴 수 있다」 | **기각 — 원리적으로** | 재작성 질의 열이 모드와 무관하다 (3-E) |
| 모드가 실제로 먹었나 | **의도한 변화** | 리랭킹 api 37회 = 후보 집합이 37회 달랐다 (3-A) |
| 리랭커의 재작성 흡수 | **재현됨** | 후보가 달라도 근거 목록이 64/67 같다 (3-E) |
| 접을지 | **확인 필요(불변)** | 누적 판 2건 그대로. 규칙 미달, 보류 |

**「살림 0」을 「접어도 안전하다」로 읽지 않는다.** 시작 전에 적은 비대칭 그대로다.

## 6. 재현

```powershell
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe -m evaluation.retry_diff `
  --qa-set evaluation/qa_set_human.jsonl `
  --label h-cohere-18w3 --format pdf `
  --rewrite replace --rerank cohere --evaluator mini `
  --top-k 5 --max-retries 3 --json
```

대조는 `h-cohere-18w3-retry-diff-{fuse,replace}-pdf.json` 두 파일을 회차 단위로 zip 해
`query` · `real_verdict` · `chunk_ids` 를 견준다.

## 7. 재지 못한 것

- **판정(Evaluator) 호출 수** — 41회차와 같은 이유다. `retry_diff` meta 에 Evaluator usage
  칸이 없어 67회는 *회차마다 1회* 라는 구조에서 나온 **추정**이다
- **리랭커를 끈 `replace`** — 흡수가 리랭커 때문이라면 `--rerank off` 에서는 갈릴 수 있다.
  다만 그것은 운영 조합이 아니라 접기 판정의 모집단이 못 된다(41회차에 같은 이유로 기각)
- **판정이 갈린 한 회차의 기전** — `hsih-02` [0] 이 `sufficient` → `insufficient` 로 갈렸는데
  둘 다 `rank None` 이라 순위로는 설명이 안 된다. 표본 1이라 안 팠다
- **접기 결정 자체** — 판 2건. 규칙대로 보류다
