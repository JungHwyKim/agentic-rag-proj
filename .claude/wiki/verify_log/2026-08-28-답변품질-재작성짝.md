## 1. 확인하려 한 것

`off × cohere` 와 `fuse × cohere` 는 검색 지표가 여섯 k 축에서 소수점까지 같은데 최종 근거
목록이 다르다(35회차). **그 차이가 답변까지 가나**를 물었다. 「임계값이 맞는가」가 아니라
**「조건이 답을 바꾸는가」**라 실파일(운영 코퍼스 색인) 쪽에 힘이 실린다.

가상 쪽에서 물은 것은 따로다 — **새로 만든 도구와 고친 가드가 실제로 무엇을 막는가**(2절).

## 2. 가상 데이터

무엇을 고립시켰나: **제품 코드에 변이를 하나씩 넣고 테스트가 빨개지는지**. 리포트 두 개를
짝짓는 도구는 유료 호출이 0이라 위험이 «비싸다»가 아니라 **«싸게 틀린다»** 다 — 축이 어긋난
두 리포트를 짝지어도 표는 멀쩡히 나온다.

```python
# 스크래치패드. TARGET 의 한 줄을 바꾸고 그 영역 테스트를 돌린 뒤 반드시 되돌린다.
# **try/finally 가 요점이다** — 34회차가 되돌리기 없이 죽어 파일이 변이된 채 남았다
import subprocess, sys
from pathlib import Path

TARGET = Path("evaluation/answer_diff.py")
MUTATIONS = [
    ("군 나누기가 순서를 안 본다 (집합 비교)",
     'return list(self.a["chunk_ids"]) == list(self.b["chunk_ids"])',
     'return set(self.a["chunk_ids"]) == set(self.b["chunk_ids"])'),
    ("범위 밖 인용 번호를 안 뺀다",
     'inside = [n for n in row.get("cited", []) if 1 <= n <= len(chunk_ids)]',
     'inside = list(row.get("cited", []))'),
    ("재작성이 같은 짝을 안 막는다",
     'if a_meta.get("rewrite_profile") == b_meta.get("rewrite_profile"):', "if False:"),
    ("짝 없는 질의를 조용히 버린다", "if only_a or only_b:", "if False:"),
    ("축 목록에서 top_k 가 빠진다", '    "top_k",', ""),
    ("재현 게이트가 어긋나도 통과한다", "if same_n == expect_same:", "if True:"),
]
original = TARGET.read_bytes(); text = original.decode("utf-8")
try:
    for name, old, new in MUTATIONS:
        assert text.count(old) == 1, name
        TARGET.write_bytes(text.replace(old, new).encode("utf-8"))
        p = subprocess.run([sys.executable, "-m", "pytest",
                            "tests/evaluation/test_answer_diff.py", "-q"],
                           capture_output=True, text=True, encoding="utf-8", errors="replace")
        TARGET.write_bytes(original)
        print(("O " if p.returncode else "X ") + name)
finally:
    TARGET.write_bytes(original)
```

|---|---|---|---|
| 군 나누기가 순서를 안 본다 | 빨강 | 빨강 | 잡힘 |
| 범위 밖 인용 번호를 안 뺀다 | 빨강 | 빨강 | 잡힘 |
| 재작성이 같은 짝을 안 막는다 | 빨강 | 빨강 | 잡힘 |
| 짝 없는 질의를 조용히 버린다 | 빨강 | 빨강 | 잡힘 |
| 축 목록에서 `top_k` 가 빠진다 | 빨강 | 빨강 | 잡힘 |
| 재현 게이트가 어긋나도 통과한다 | 빨강 | 빨강 | 잡힘 |
| `control_partner` 를 «완전 일치» 로 되돌린다 | 빨강 | 빨강 | 잡힘 |
| `control_partner` 의 근거 가드를 없앤다 | 빨강 | 빨강 | 잡힘 |

**첫 판에서 한 변이가 «자리를 못 찾음» 으로 헛돌았다** — `'    "top_k",\n'` 로 찾았는데
파일이 CRLF 라 0건이었다. `hits != 1` 을 세기만 하고 넘어가게 짜 두어 **X 도 O 도 아닌 `?`
로 찍혔고**, 그 줄이 없었으면 «6개 중 5개 잡힘» 을 그냥 통과로 읽을 뻔했다.

## 5. 판정

- **재현 게이트 두 판 다 일치 — 의도한 변화.** 49·34 가 35회차 수치와 정확히 같고 캐시 델타가
  0이라, 이 네 판은 그때 그 순위 위에서 잰 것이다. **이 확인이 없으면 아래 표를 못 읽는다**
- **재작성은 정답 근거의 인용을 안 바꾼다 — 의도한 변화.** 신호군에서 8→8 · 24→24 이고,
  유일하게 움직인 한 건은 바닥 군에 있다. 즉 35~38회차의 「리랭커가 재작성을 흡수한다」가
  **생성 단계에서도 유지된다**
- **다만 「아무것도 안 바뀐다」는 아니다.** 인용 청크 집합이 갈린 비율이 신호군에서 바닥의
  1.8배(k=5) · **3.1배**(k=10)다. 바뀌는 것이 **정답이 아닌 자리**일 뿐이고, 이것은 35회차가
  검색에서 본 모양(상위 10이 26건 갈리는데 25건은 정답 자리 그대로)과 같다
- **지지 축은 240/240 전부 `supported` — 변별력 0.** 판 1(사람 43건)에 이어 두 번째다.
  이 자[尺]는 **정상 파이프라인 답변에서는 아무것도 안 가른다**
- **`ai-01` 의 대조군 누출은 회귀가 아니라 계기 결함이었다.** 고쳐서 k=10 두 판은 0/60 이다
- **k=5 신호군은 11건이다.** 인용 정합성이 0.533 → 0.471 로 내려가 보이지만 **분자가 8로
  같고 분모가 15→17 로 는 것**이라, 방향을 말할 수는 있어도 규칙은 못 세운다 — 미리
  적어 둔 대로 세우지 않는다

## 6. 재현

```powershell
$env:PYTHONIOENCODING = "utf-8"

# 네 판. 같은 컬렉션을 쓰므로 반드시 순차로 돌린다(qdrant 배타 잠금)
```

## 7. 재지 못한 것

- **`sih-06` 의 대조군 판정이 왜 `supported` 였나** — `AnswerRow` 가 대조군의 **판정 사유를
  안 싣는다**(`control` 한 칸뿐). 겹침 0인데 빌린 근거에 `행정정보 데이터세트` 가 있다는
  것까지만 확인했고, 채점자가 그것을 근거로 삼았는지는 못 봤다
- **k=5 의 대조군을 고친 계기로 다시 재는 것** — 못 한다. 생성에 캐시가 없어 재실행이
  재현이 아니라 **새 표본**이다(답변이 달라지면 판정도 대조군도 달라진다). 그래서
  k=5 두 판은 옛 계기, k=10 두 판은 고친 계기로 남는다
- **`replace` 모드 · `local-gpu` 위에서의 같은 물음 · 사람 세트 짝** — 안 돌렸다
- **«답이 맞나»** — 골든 답변이 없어 여전히 못 잰다. 이 판이 잰 것은 *근거에 충실한가* 이고,
  그중에서도 실제로 변별한 것은 **인용 정합성 하나**다
