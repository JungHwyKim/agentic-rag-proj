# 재작성을 화면에 이었다 — 사슬은 통과, 다만 **떠 있던 서버는 옛 코드였다**

- 검증일: 2026-08-27
- 대상: `answer_question(rewriter=...)` 배선 · `plan_log/검색-생성.md` 25회차
- 비용: **외부 API 재작성 호출 0회**(`.cache/rewrite` **78 → 78**). 실사용 확인 질의를 한 번
  보냈고 그것이 생성·리랭킹을 태웠지만(6.5초) **재작성은 안 돌았다** — 아래 3.2 가 그 이유다

## 1. 확인하려 한 것

**`.env` 의 `REWRITE_MODEL`·`REWRITE_MODE` 가 실제로 질의 경로에 닿는가.**
24회차에 그 두 줄을 적었지만 읽는 곳이 없어 **죽은 줄**이었다. 배선이 그것을 살렸는지를 본다.

**규칙이 도는가**를 묻는 것이지 임계값을 정하는 것이 아니다.

## 2. 가상 데이터

무엇을 고립시켰나: **사슬의 고리를 하나씩** 끊어 보고 이어 보는 것. 실제 저장소도 실키도
안 쓴다 — `answer_question` 과 라우트를 각각 모킹으로 고립시킨다.

```python
# tests/test_query.py — answer_question 이 넘겨주기만 하는가
def test_rewriter_is_passed_through_to_retrieve(mocker, config):
    retrieve = mocker.patch.object(query_module, "retrieve", return_value=[_chunk()])
    mocker.patch.object(query_module, "generate_answer", return_value="답변")
    rewriter = object()
    answer_question("질문", store=object(), embedder=object(),
                    config=config, rewriter=rewriter)
    assert retrieve.call_args.kwargs["rewriter"] is rewriter

# tests/api/test_query_route.py — .env 값이 라우트까지 닿는가
def test_config_rewrite_reaches_the_route(mocker):
    asked = mocker.patch("backend.app.api.routes.query.answer_question", ...)
    client = _client()
    object.__setattr__(client.app.state.ingest_config, "_rewrite",
        RewriteConfig(rewrite_model="gpt-4.1-mini", rewrite_mode="fuse",
                      openai_api_key="sk-x"))
    client.post("/api/v1/query", data={"query": "질문"})
    assert asked.call_args.kwargs["rewriter"].mode == "fuse"
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `answer_question(rewriter=X)` | `retrieve` 에 그대로 X | 그대로 | 통과 |
| `answer_question()` (안 넘김) | `retrieve` 에 `None` | `None` | 통과 |
| `rewriter` 를 넘겼을 때 `retrieve` 가 받는 질의 | **원 질의 그대로** | 그대로 | 통과 |
| 답변 캐시 히트 + `rewriter` | `retrieve` 자체가 안 불림 | 안 불림 | 통과 |
| 라우트에 질의 2회 | `get_rewriter()` **2회 호출**(질의마다) | 2회 | 통과 |
| `RewriteConfig(model=..., mode="fuse")` 를 꽂고 질의 | `answer_question` 이 mode `fuse` 인 객체를 받는다 | 받는다 | 통과 |
| `rewrite_model=None` | `answer_question` 이 `None` 을 받는다 | `None` | 통과 |

**「원 질의 그대로」가 이 표에서 제일 중요하다** — 여기서 질의를 미리 다시 쓰면 `run_eval` 이
`retrieve()` 를 직접 부르므로 **평가가 그 경로를 안 밟는다**(7회차 기각 항목). 배선을 넣으며
제일 밟기 쉬운 자리라 계약으로 박았다.

## 3. 실제 데이터

### 3.1 실제 `.env` 로 만든 설정

`backend` 가 `app.state.ingest_config` 에 두는 것과 같은 객체로 확인했다.

```
get_rewriter(IngestConfig().rewrite)  ->  QueryRewriter
  mode      : fuse
  context_k : 10
```

**평가 쪽은 여전히 안 바뀐다**(재현성 장치가 그대로 산다):

```
eval_config().rewrite.rewrite_model  ->  None
get_rewriter(eval_config().rewrite)  ->  None
eval_config(rewrite="fuse")          ->  gpt-4.1-mini · fuse
```

### 3.2 실사용 질의 한 번 — **재작성이 안 돌았고, 이유는 배선이 아니었다**

`urllib` 로 새 질문 하나를 보냈다(셸 `curl` 은 한국어를 cp949 로 보내 깨뜨린다 — CLAUDE.md).

| 항목 | 값 |
|---|---|
| 응답 | 200 · 9,369자 · **6,543ms** |
| 질문 왕복 대조 | **일치**(전송 계층 정상) |
| `.cache/rewrite` | **78 → 78 (증분 0)** |

**증분 0 이 곧 재작성이 안 돌았다는 뜻이다.** 그런데 원인은 코드가 아니라 **프로세스**였다.

```
uvicorn 프로세스 CreationDate : 2026-08-27 13:42:59  (--reload 켜짐)
내가 고친 파일 LastWriteTime  : rag_pipeline/query.py           20:54:00
                                backend/app/api/routes/query.py 20:55:29
                                .env                             20:40:11
확인 시각                      : 21:03:30
```

**`--reload` 가 켜져 있는데도 프로세스가 한 번도 재시작되지 않았다.** 그래서 그 응답은 배선
이전 코드가 낸 것이고, 24회차의 `.env` 두 줄도 그 프로세스에서는 애초에 안 읽혔다.

**여기서 배웠어야 할 것은 신호를 하나만 보면 안 된다는 것이다** — `.cache/rewrite` 증분 0 을
그대로 읽으면 *"배선이 틀렸다"* 가 되는데, 실제로는 **배포가 낡은 것**이었다. 가른 것은
프로세스 생성 시각과 파일 수정 시각의 대조 하나다.

**미해결**: `--reload` 가 왜 안 물었는지는 안 봤다. 워처가 죽었는지, `watchfiles` 가 없어
statreload 로 떨어졌는지, 감시 디렉터리가 좁은지는 **재현 조건을 안 잡았다.**

## 5. 판정

- **의도한 변화** — `.env` 두 줄이 질의 경로에 닿는다. 사슬 네 고리가 전부 테스트로 잠겼다
- **의도한 변화** — 재작성기는 **질의마다** 만든다(Evaluator 와 같은 자리). `ResultCache` 가
  축처럼 보였으나 **경로 + 불리언뿐**이라 축이 아니었다
- **회귀 없음** — 평가 경로는 그대로다(`eval_config()` 가 `.env` 를 계속 이긴다).
  `rewriter` 를 안 넘긴 경로도 그대로다
- **확인 필요 → 배포 문제로 확정** — 실사용 질의에서 재작성이 안 돌았다. **코드가 아니라
  떠 있던 서버가 옛 것이었다**(13:42 기동 · 재시작 0회)
- **재지 못함** — 재작성이 실제로 도는 화면의 지연. 서버를 재시작해야 잰다
