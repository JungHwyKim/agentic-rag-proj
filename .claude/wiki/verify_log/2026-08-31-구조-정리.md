## 1. 이동 전 실측 — 왜 폴더 이름을 안 바꿨나

기록끼리의 상호참조가 어떤 모양으로 쓰여 있는지 셌다. **이 표가 「부모만 씌우기」와
「이름까지 바꾸기」의 비용을 가른다.**

| 참조 모양 | plan_log | task_log | verify_log | 합계 |
|---|---|---|---|---|
| 마크다운 상대링크 `](../xxx/yyy.md)` | 47 | 131 | 71 | **249** |
| 마크다운 같은폴더 `](yyy.md)` | 30 | 113 | 152 | **295** |
| 산문 경로 `xxx_log/yyy.md` | 237 | 382 | 295 | **914** |
| | | | | **1,458** |

세 모양 전부 **부모 폴더를 씌우는 데는 안 깨지고**(셋이 함께 움직여 상대 거리가 유지되고,
산문 경로는 폴더 이름이 저장소에서 유일하다) **폴더 안을 다시 나누면 전부 깨진다**(깊이가
바뀌고 형제가 아니게 되고 경로 중간이 는다).

저장소 전체의 경로 참조 규모(`.venv`·`.git`·`tmp`·`data`·`.cache` 제외):

| | 산문 참조 | 진짜 런타임 결속 |
|---|---|---|
| 기록 3폴더 | 2,584 | **6곳** |
| 소스 6폴더 | 2,406 | **25파일 / 71곳** (전부 `PROJECT_ROOT` 소비자) |

추적 파일 **581개 중 기록이 266개(45%)** · 소스 145개.

## 2. 이동 후 대조 — 기록은 바이트까지 그대로인가

`git diff --cached -M` 으로 잰 값이다.

| 항목 | 값 |
|---|---|
| rename 으로 잡힌 기록 파일 | **266** |
| 그중 유사도 **100%** | **266** |
| rename 중 내용이 바뀐 파일 | **0** |
| 디스크 파일 수 (plan/task/verify) | 21 / 110 / 136 — 이동 전과 동일 |

**중간에 한 번 잘못 쟀다.** `git diff --cached --stat -- '.claude/wiki'` 로 보니 266개가
전부 «추가 60,775줄» 로 나와 내용이 바뀐 것처럼 보였다 — pathspec 이 **삭제 쪽(옛 경로)을
범위에서 빼서** rename 이 짝을 못 찾은 것이고, 측정 도구가 만든 착시였다. pathspec 없이
다시 재서 위 값을 얻었다.

도구라, 「돌았다」가 「맞게 돌았다」를 뜻하지 않는다.

## 7. 실수 하나 — 이중 접두사

훅 산문을 일괄 교체할 때 `LOG_PREFIX = _hookutil.WIKI_ROOT + "plan_log/"` 의 `"plan_log/"`
까지 물어 **`WIKI_ROOT + ".claude/wiki/plan_log/"`** 를 4파일에 만들었다. 앞 `"` 가
가드(`(?<!wiki/)`)에 안 걸린 것이다.

**교체 직후 상수를 찍어 본 것이 잡았다** — 테스트는 이걸 못 잡는다(`tests/hooks` 가
`LOG_PREFIX` 를 **상수에서 받게** 방금 고쳐 놓아, 상수가 틀려도 테스트와 구현이 함께
틀려 초록으로 통과한다). 되돌린 뒤 전역 훑기로 0건을 확인했다.
