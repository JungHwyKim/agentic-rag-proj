# GPU 축을 열었다 — 지연 21.4배, 순위는 글자 그대로 같다

- 검증일: 2026-08-26
- 대상: Phase 3 리랭커의 **지연 축**. 앞 회차가 *"CPU 라서인지 모델이라서인지 안 갈렸다"* 로
  남긴 자리다 (`task_log/2026-08-25-리랭커-진질의-해부.md` 7절)
- 비용: **외부 API 호출 0**(로컬 cross-encoder · 임베딩은 캐시 적중).
  환경 변경 1건 — `torch` cu130 빌드 재설치 1.8GiB (사용자 승인)

## 1. 확인하려 한 것

셋이다. 앞 둘은 *"규칙이 도는가"*, 셋째는 *"값이 얼마인가"* 다.

1. **RTX 5060(Blackwell)에서 torch 가 도는가** — sm_120 을 담은 빌드가 있는가
2. **GPU 로 돌린 실행이 CPU 캐시를 안 읽는가** — 앞 회차의 salt 수정이 실제로 먹는가.
   안 먹으면 *"GPU 가 순식간에 같은 품질"* 이라는 거짓 결론이 나온다
3. **질의당 지연이 얼마인가** — 51초가 몇 초가 되는가

## 2. 가상 데이터

없음. 이 회차는 실측 위 측정이다(salt 가 device 로 갈리는 규칙 자체는 앞 회차의
`tests/retrieval/test_rerank.py::test_device_is_in_the_cache_key` 가 이미 잠갔다).

**인덱스를 고르는 것이 이 단계의 유일한 판단이었다.** 버전을 안 내리는 것이 조건이다 —
`sentence-transformers` 가 그 위에 얹혀 있다.

| 인덱스 | 해상 결과 | 판정 |
|---|---|---|

### 3-2. 실행 신원 — 리랭커가 진짜로 GPU 에서 돌았는가

**폴백은 예외가 아니라 조용한 RRF 순서다.** `_load_model()` 이 CUDA 실패 시 `None` 을
돌려주므로, 이 확인이 없으면 *"GPU 가 품질을 안 바꿨다"* 와 *"GPU 가 안 잡혀 CPU 순서가
나왔다"* 가 구분되지 않는다.

| 항목 | E4 (`local`, cpu) | E5 (`local-gpu`, cuda) |
|---|---|---|
| `rerank_warnings` | `[]` | **`[]`** |
| `reranked` | 2,300 | **3,000** (60 × 50) |
| `rerank_cache_hits` | 14 | **0** |
| 청크 | 118 / 71 / 103 / 122 | 동일 |
| `vision_calls` | 0 | 0 |

**`cache_hits = 0` 이 salt 수정의 실증이다.** 안 고쳤으면 3,000쌍이 전부 적중해 실행이
순식간에 끝나고 지표가 같게 나왔을 것이다 — **에러 없이 수치로만** 거짓이 되는 자리였다.

### 3-3. 품질 — 다른 것이 하나도 없다

| 대조 | 실측 |
|---|---|
| 지표 49개(`summary` + `by_k` 전량) | **다른 것 0개** |
| `per_query` 60건의 `rank` | **다른 질의 0건** |
| `hit@1` / `MRR` / `nDCG@10` / `hit@50` | 0.5833 / 0.6816 / 0.7327 / 0.9833 (양쪽 동일) |
| 그룹별 `hit@10` | 0.8000 / 0.7333 / 1.0000 / 0.9333 (양쪽 동일) |

`rerank_device` 의 주석은 *"CPU 와 GPU 가 미세하게 다른 점수를 낸다"* 라고 못 박고 있는데,
**이 모델·이 풀에서는 순위를 안 흔든다.** 점수 자체가 같은지는 안 봤다(순위만 대조했다).

### 3-4. 지연 — 같은 입력에 두 장치

**앞 회차 값은 파생값이었다.** 쌍당 1.03초는 두 실행의 벽시계 차 `(2,383 − 21) / 2,300` 에서
나온 것이라 색인·채점·러너 오버헤드가 쌍에 분산돼 있다. 여기서는 풀 60개를 미리 만들어
두고 **`rerank()` 만 감싸** 재고, **캐시를 껐다**(켜면 아무것도 안 재고 통과한다).

후보 청크 분포: 자수 **중앙 370 · p95 1,189 · 최대 1,197** (3,000개).

| 장치 | 표본 | 총시간 | 질의당 | 쌍당 | 경고 |
|---|---:|---:|---:|---:|---:|
| cuda | 60질의 | 179.3초 | **2.988초** | 0.0598초 | 0 |
| cpu | 5질의 | 319.3초 | 63.862초 | 1.2772초 | 0 |

**21.4배**(질의당·쌍당 동일). 60질의 환산으로 cpu 3,832초 · cuda 179초다.

**직접 잰 CPU 값이 파생값보다 24% 높다**(1.2772 vs 1.03). 파생값이 낮게 나오는 방향이 맞고
(오버헤드를 쌍에 분산했다), CPU 표본이 **앞 5질의라 무작위가 아니다**. 그래서 이 둘의 차를
"측정 오차"로 읽지 말 것 — 자[尺]가 다르다.

### 3-5. 첫 질의는 따로 비싸다 — **값이 흔들린다**

게으른 적재가 계약이라(`local_ce.py`) 서버 기동 뒤 **첫 질의가 이 값을 낸다.**
위 지연 표본에서는 뺐지만 운영에서는 못 뺀다.

**한 번만 재고 45.1초로 적을 뻔했다.** 켜고 나서 다시 재니 재현이 안 됐다.

| 관측 | 조건 | 값 |
|---|---|---:|
| 1 | `latency.py` 안에서 (KURE 임베더·qdrant·풀 60개를 이미 든 프로세스) · 후보 50 | **45.1초** |
| 2 | 갓 띄운 프로세스 · 후보 3 | **11.1초** |
| 3 | 갓 띄운 프로세스 · 후보 50 | **11.9초** |
| 4 | 위와 같은 입력 재실행 | **0.0초** (캐시 적중) |

**범위는 11.9~45.1초이고 대표값을 못 정했다.** 관측 3이 관측 1과 후보 수·모델이 같은데
3.8배 빠르므로 **후보 수 축이 아니다.** 남은 차이는 프로세스가 이미 들고 있던 것(임베더
2.27GB·qdrant 클라이언트)뿐인데 **그것이 원인인지는 안 갈랐다**(표본 1건씩이다).
별도 탐침에서 `CrossEncoder(...)` 생성만 떼면 13.9초였다.

**관측 4가 따로 중요하다** — 같은 질의·같은 풀이면 캐시가 통째로 덮어 0.0초다.
운영에서 첫 질의 비용을 무는 것은 **프로세스당 한 번**이고 그 뒤로도 반복 질의는 공짜다.

### 3-6. 실제 `.env` 로 E2E — 켠 뒤 확인

`RERANK_PROVIDER=local` · `RERANK_MODEL=BAAI/bge-reranker-v2-m3` · `RERANK_DEVICE=cuda` 를
`.env` 에 넣고 `IngestConfig().rerank` 로 만들었다.

| 확인 | 결과 |
|---|---|
| 구현체 | `LocalCrossEncoderReranker` |
| 융합 2위였던 **관련 청크**(`행정정보 데이터세트란…`) | rerank **1.0000** → **1위** |
| 융합 1위였던 무관 청크(`예산 집행 내역…`) | rerank **0.0000** → 2위 |

## 5. 판정

- **GPU 축이 열린다 (의도한 변화)** — `sm_120` 지원 · 버전 다운그레이드 없음.
  `cu130` 이 유일한 무손실 경로였다
- **salt 수정이 실제로 먹는다 (의도한 변화)** — `cache_hits = 0`. 이 회차가 그 수정의
  실증이고, 순서를 바꿨으면(먼저 고치고 나중에 해부) 앞 회차 해부가 캐시를 못 썼다
- **장치가 순위를 안 바꾼다 (확인)** — 지표 49개·질의 60건 전건 동일. `rerank_device` 주석의
  경고가 **이 모델·이 풀에서는** 발화하지 않는다. 그래도 salt 는 유지한다 —
  *같다는 것을 확인한 것*과 *다를 수 없다는 것*은 다르다
- **로컬 CE 의 탈락 사유가 사라졌다 (판정 전환)** — 질의당 51초(파생) / 63.9초(직접)가
  **2.988초**가 됐다. 품질은 무료 칸 넷 중 최고였으므로, **유료 갈래가 더 이상 "로컬이
  느려서" 필요한 것이 아니다**
- **감수 사항 — 첫 질의 11.9~45.1초, 대표값 미정.** 갓 띄운 프로세스에서는 12초 안팎이고
  45초는 재현이 안 됐다. **프로세스당 한 번**이고 같은 질의는 캐시가 0.0초로 덮는다
- **회귀 아님** — pytest·ruff 통과, 적재 청크 수 불변

`LocalCrossEncoderReranker(rerank_cache_enabled=False)` 에 두 장치로 물렸다.

## 7. 재지 못한 것

- **점수 자체가 같은지** — 순위만 대조했다. 점수가 미세하게 달라도 순위가 같으면 이 표는
  같게 나온다. 그래서 *"장치가 점수를 안 바꾼다"* 가 아니라 *"순위를 안 바꾼다"* 로 적었다
- **CPU 를 60질의 전량으로** — 3,832초 환산이라 5질의로 잘랐다. **앞 5질의라 무작위가 아니다**
- **화면 왕복** — `answer_question()` 은 리랭커에 더해 생성 LLM 을 부른다. 사용자 체감은
  2.988초가 아니라 그 합이고 **안 쟀다**
- **첫 질의 비용이 왜 11.9~45.1초로 흔들리나** — 프로세스가 이미 든 것(임베더 2.27GB·
  qdrant 클라이언트)이 원인으로 보이지만 **표본이 각 1건이라 안 갈랐다.** 그것이 맞다면
  운영 프로세스는 임베더를 들고 있으므로 45초 쪽에 가깝다 — **그때는 미리 적재할지가
  설계 결정이 된다**(`local_ce.py` 의 게으름 계약과 정면으로 걸린다)
- **유료 칸 E1·E3** — 다른 세션이 사용자 승인으로 돌렸고 **이 세션은 안 돌렸다**(중복 과금).
  수치는 `verify_log/2026-08-26-리랭커-유료칸.md` 에 있다. 이 세션이 보탠 것은 **폴백 10건을
  캐시 키 존재로 특정한 것** 하나다(`_predict()` 가 성공했을 때만 캐시에 쓴다 · API 안 부른다) —
  그 10건을 빼고 견주면 `nDCG@10` 이 로컬 0.6992 vs 유료 **0.7070** 으로 **부호가 뒤집힌다.**
  즉 로컬이 총합(0.7327 vs 0.7241)에서 이기는 것은 품질이 아니라 **유료가 17%에 리랭킹을
  못 건 결과**다. 폴백 원인은 **입력 길이가 아니다**(풀 총자수 중앙 26,076 vs 26,293 으로 겹친다).
  **이 부분집합 값은 `scoring.score_query(k=10)` 로 냈다** — 러너와 같은 자[尺]다. 다른 세션이
  `1/log2(rank+1)` 근사로 같은 수에 닿았는데 **우연이 아니라 이 세트의 성질이다**: 60건 중
  `gold_spans` 가 여럿인 질의가 `ai-01` **하나뿐**이고 그것이 양쪽 다 top-10 밖이라 k=10 에서
  둘 다 0 이다. **다른 k·다른 세트에 그 근사를 대면 안 된다**
- **`ko-reranker`** — 안 쟀다. GPU 가 열려 이제 몇 분짜리다
- **VRAM 여유** — 8GB 중 얼마를 쓰는지 안 봤다. 임베딩까지 GPU 로 올릴지 정할 때 필요하다
