import sys


class _BlockTavily:

### 5-1. 유출: 기본 pytest 가 Tavily 를 실제로 2회 호출했다

핀을 구현보다 **먼저** 넣었는데도 샜다. 초판이

```python
monkeypatch.delenv("TAVILY_API_KEY", raising=False)
```

였는데 **pydantic-settings 는 환경변수와 `.env` 파일을 둘 다 읽는다.** 환경변수를 *지우는*
것은 파일 쪽을 안 건드려서, 지운 자리를 `.env` 가 곧바로 채웠다.

실측(같은 머신 · 같은 구현):

| 픽스처 | `WebSearchConfig().tavily_api_key` | `tests/agent` |
|---|---|---|
| `delenv(...)` | **키가 실린다** | 2 failed · **4.89초** |
| `setenv(..., "")` | 비었다 | 87 passed · **0.85초** |

**시간 차 자체가 왕복의 증거다.** 그리고 실패 메시지가 두 번 다 서버가 준 것이었다 —
`chunk_id='web:https://www.kdca.go.kr/...'` 와 `BadRequestError: Query is too short.`

**`tests/api/conftest.py` 선례를 그대로 베낀 것이 함정이었다** — 저쪽 `ORIGINALS_DIR` ·
`QUERY_LOG_PATH` 는 **덮어쓰기**라 환경변수가 파일을 이기고, 이쪽은 **지우기**라 파일이
남는다. 자리도 모양도 같아 보이는데 방향이 반대다.

**가짜 키를 넣는 안은 더 나빴다** — `_make_client()` 가 클라이언트를 실제로 만들어
네트워크까지 간 뒤 401 로 죽는다. 막으려던 것이 호출인데 호출이 나간다.

**`paid_test_check.py` 는 이것을 원리적으로 못 막는다** — 그 훅이 막는 것은 `-m integration`
이고 이건 기본 마커다. 즉 **유료 호출이 기본 pytest 로 새는 두 번째 경로**이고, 지금 이
자리를 막는 것은 훅이 아니라 픽스처 하나다.

## 7. 재지 못한 것

- **`search_depth` 의 `fast` · `ultra-fast`** — SDK 는 받는데 크레딧·품질을 안 쟀다.
  그래서 설정에 안 열었다(합법값을 설명 못 할 설정은 안 만든다)
- **웹 근거가 답변 품질을 바꾸는가** — 잴 수가 없다. `agent/router.py` 가 이 도구를 안 골라
  답변 경로에 웹 근거가 실리지 않고, 애초에 답변 품질 자[尺]에 골든 답변이 없다
- **`web_search_max_results=5` 가 맞는 값인가** — 위와 같은 이유로 못 정했다. 임시값이다
- **내 변경 전 전체 pytest 기준선** — 트리에 다른 세션 둘이 동시에 쓰고 있었다(4-1절)
- **호출 캐시를 붙였을 때의 이득** — 안 붙이기로 해서 잴 대상이 없다. TTL 을 정하려면
  「웹 결과가 얼마 만에 낡나」를 재야 하는데 그 자[尺]가 없다
