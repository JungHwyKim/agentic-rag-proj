- 검증일: 2026-08-18
- 대상: [task_log/2026-08-18-indexing-단계.md](../task_log/2026-08-18-indexing-단계.md)
- 비용: **외부 API 호출 없음.** 임베딩은 `_make_client()` 를 가짜로 갈아끼웠고, qdrant 는
  로컬 파일 모드라 과금 경로가 아예 없다. `-m integration` 2건은 작성만 하고 안 돌렸다

## 1. 확인하려 한 것

**"규칙이 도는가"와 "설계서가 원한 동작이 실제로 되는가" 둘이다.** 임계값을 정하는 검증이
아니다 — 이번 단계에서 새로 정한 수치는 없고(`top_k=5` 는 임시값이라 재지 않았다),
확인해야 할 것은 계약이 지켜지는지다.

가설 셋.

1. **`document_id` 를 파일명에서 뽑아야 재색인이 성립한다.** 내용 해시면 문서를 고칠 때
   키가 바뀌어 옛 청크를 못 찾는다. 이건 **실파일로는 못 잰다** — 문서를 고친 판이 없다
2. **`zip(chunks, vectors)` 가 청크 수백 개에서도 안 밀린다.** 이건 반대로 **가상으로는
   못 잰다** — 합성 문서는 청크가 서너 개라 밀려도 우연히 통과한다
3. qdrant 가 문자열 point ID 를 거부한다는 전제가 사실이다

## 2. 가상 데이터

무엇을 고립시켰나: **실파일이 만들 수 없는 입력 넷** — 문서 수정(재색인), NFD 파일명,
모델 교체, 청크/벡터 개수 불일치. 축마다 한 가지만 바꿨다.

```python
# 전문: scratchpad/probe_indexing.py — 아래는 축을 만드는 부분만
DIM = 4
BEFORE = ["가", "나", "다", "라", "마"]   # 고치기 전 문서
AFTER  = ["가", "나", "라"]              # 다·마가 사라진 판

def chunks(texts, document_id="안내서.pdf"):
    return [
        Chunk(
            chunk_id=f"{document_id}:{i:04d}", document_key=document_id, chunk_index=i,
            type=ChunkType.TEXT, text=t, source_name=document_id,
        )
        for i, t in enumerate(texts)
    ]

def vectors(n):
    return [[1.0 if j == i % DIM else 0.0 for j in range(DIM)] for i in range(n)]

# 축 1 — 파일명 정규화
nfc = unicodedata.normalize("NFC", "안내서.pdf")
nfd = unicodedata.normalize("NFD", "안내서.pdf")

# 축 4 — 재색인. 대조군(delete 없이 upsert 만)과 실험군을 나란히 돌린다
s.upsert(to_records(chunks(BEFORE), vectors(5), document_id="안내서.pdf"))
s.upsert(to_records(chunks(AFTER),  vectors(3), document_id="안내서.pdf"))   # 대조군
# 실험군은 사이에 s.delete_by_document_id("안내서.pdf") 를 넣는다

# 축 6 — 차원은 같고 모델만 다르게
small = EmbeddingConfig(embedding_model="text-embedding-3-small", embedding_dimensions=1536)
large = EmbeddingConfig(embedding_model="text-embedding-3-large", embedding_dimensions=1536)
```

| 입력/축 | 기대 | 실측 | 판정 |
|---|---|---|---|
| NFD/NFC 파일명 → 같은 키인가 | 같다 | 같다 | 일치 |
| 정규화 전 두 표기가 실제로 다른가 | 다르다 (그래서 정규화가 필요) | 다르다 | 일치 |
| 같은 `chunk_id` → 같은 point | 같다 | 같다 | 일치 |
| **qdrant 가 문자열 point ID 를 받는가** | ValueError (거부) | `ValueError` | 일치 |
| 길이 계약 — 청크 3 / 벡터 2 | `IndexingError` | `IndexingError` | 일치 |
| 길이 계약 — 청크 3 / 벡터 3 | 정상 | 정상 | 일치 |
| 길이 계약 — 청크 3 / 벡터 4 | `IndexingError` | `IndexingError` | 일치 |
| **대조군: upsert 만 — 5개를 3개로 줄인 뒤 남는 수** | **5 (다·마가 남는다)** | **5** | 일치 |
| 실험군: delete→upsert — 남는 수 | 3 | 3 | 일치 |
| 실험군: 남은 본문 | 가·나·라 | `['가', '나', '라']` | 일치 |
| 문서가 빈 문서가 됐을 때 남는 수 | 0 | 0 | 일치 |
| 차원 같고 모델 다를 때 컬렉션 이름 | 다르다 | 다르다 | 일치 |
| `dimensions=None` 일 때 이름 꼬리 | `_default` (salt 규칙과 동일) | `_default` | 일치 |
| 모델 바꾼 뒤 옛 벡터가 보이는가 (직전 1건) | 0 (안 보인다) | 0 | 일치 |
| 같은 컬렉션에 다른 차원 | `IndexingError` | `IndexingError` | 일치 |
| 빈 컬렉션 검색 | `[]` (오류 아님) | `[]` | 일치 |
| `top_k=0` | `IndexingError` | `IndexingError` | 일치 |
| `top_k=-1` | `IndexingError` | `IndexingError` | 일치 |
| 컬렉션이 아예 없을 때 검색 | `IndexingError` | `IndexingError` | 일치 |

**19축 전부 기대와 일치했다.** 스크립트의 자동 판정은 18/19 로 나오는데, 갈린 한 행은
"남은 본문" 의 기대를 집합 리터럴로 적고 실측이 정렬 리스트로 찍혀서 문자열 비교가 실패한
것이다 — 내용은 같다. 판정 코드의 문제이고 제품 동작이 아니다.

**대조군 줄이 이 표의 핵심이다.** `upsert` 만으로는 5가 남는다는 것을 실제로 찍어 뒀으므로,
나중에 누가 `delete_by_document_id()` 를 "중복이니 빼자"고 지울 때 근거가 남는다.

uuid5 예시: `안내서.pdf:0007` → `24cec624-8502-52ee-82a3-8ce5d97a2f26` (UUID 파싱 성공)

`__del__` 경고 하나를 관측했다. 탐침 스크립트에서 **닫지 않은** `QdrantClient` 가 인터프리터
종료 중에 `__del__` → `close()` 를 타면서 `ImportError: sys.meta_path is None` 을 찍는다.
제품 경로에서는 `index_document()` 의 `finally` 와 테스트 픽스처가 항상 닫으므로 안 나오지만,
**저장소를 열고 안 닫으면 이 모양으로 나온다**는 것은 남겨 둔다. 실패가 아니라 종료 중
잡음이라 조용히 지나가기 쉽다.
