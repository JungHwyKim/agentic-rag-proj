## 2. 가상 데이터

무엇을 고립시켰나: **원본 격자와 모델 응답의 관계 하나.** 실파일에는 "모델이 다른 크기를
돌려준다"·"응답이 잘린다" 같은 입력이 우연히도 없고, 유료 호출로도 일부러 만들 수 없다.

```python
# tests/ingestion/loader/content/test_table_vision.py 의 입력
_ROWS = [
    ["원칙", "기획", "데이터"],
    ["투명성", "", ""],      # 2·3열이 비어 있다 — 체크 표시가 들어올 자리
    ["책임성", "", ""],
]
# 모델 응답은 SimpleNamespace 로 OpenAI 모양을 흉내낸다
#   choices[0].message.content = json.dumps({"rows": [...]})
#   choices[0].finish_reason   = "stop" | "length"
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 빈 칸 2개에 `○` | 그 둘만 채워짐, `filled=2` | 일치 | OK |
| 값 있는 칸을 `투명성(수정됨)`·`다른 값` 으로 덮어 보냄 | **원본 유지** | `투명성`·`책임성` 유지 | OK |
| 행 수 2 (원본 3) | 빈 리스트 + 경고 | 빈 리스트, `다른 크기` 경고 | OK |
| 한 행만 열 수 2 (원본 3) | 빈 리스트 | 빈 리스트 | OK |
| 채운 칸 0개 | 빈 리스트 (native 와 같다) | 빈 리스트 | OK |
| `finish_reason="length"` | 빈 리스트 + `vision_calls=1` | 일치 | OK |
| 키 없음 | 빈 리스트, 호출 0 | 일치 | OK |
| API 예외 | 빈 리스트, `vision_calls=0` | 일치 | OK |
| 상한 도달(`vision_calls=2`, 상한 2) | 클라이언트 안 만듦 | `assert_not_called` | OK |
| `rows` 없음 / `blob` 없음 | 클라이언트 안 만듦 | `assert_not_called` | OK |
| 400×500pt · 750×270pt 를 굽기 | 둘 다 긴 변 ≈1600px | 1597 · 1604 | OK |
| `blob_kind="png"` | `None` (PDF 만 굽는다) | `None` | OK |

**경계값 둘은 실파일이 못 만든다** — 잘린 응답과 크기 불일치. 여기가 가상이 유일하게

### 3-9. 재검증이 드러낸 결함 — 캐시가 한 번도 든 적이 없다

3회차에서 캐시가 하나도 안 들었다(호출 8회). 원인을 재보니 키가 문제였다.

```
_crop_pdf() 가 낸 blob 의 sha256, 같은 표를 두 번 뽑아 비교
  1회차: 811627d3ba5b d58bb4595aa9 e4774c19c73b aa412e673a1f 24ed0dde7ce2 74d08351aaf8
  2회차: 6aa2015c40a3 7b07739b49d8 25bb2945d8e0 ce88ea15da1f 9c60183ff65d 772134c8b107
  같은가: 6/6 전부 다르다        ← PyMuPDF 가 생성 시각·문서 ID 를 넣는다
```

`content_hash(region.blob, ...)` 이 매번 다른 값을 내므로 **`ResultCache` 가 표 경로에서
한 번도 작동한 적이 없다.** 에러가 안 나서 몰랐고, *"두 번째 실행은 0원"* 이라고 적어둔
것도 **틀린 말이었다.**

**보내는 것으로 키를 다시 만들었다** — 구운 PNG + 격자.

```
렌더 PNG 의 sha256, 두 실행    6/6 일치        ← 결정론적이다
새 키(PNG + 격자), 두 실행     6/6 일치        ← 캐시가 실제로 든다
```

격자를 키에 넣는 것도 필수다 — 프롬프트에 그것이 실려 나가므로 `rows` 가 바뀌면 다른
질문인데, 안 넣으면 옛 답이 돌아온다. **대각선 셀 수정으로 `rows[0][0]` 이 바뀐 것이
정확히 그 경우다.**

### 유료 패스 재현

**스크립트는 스크래치패드에 있어 세션이 끝나면 못 찾는다.** 그래서 여기 인라인한다 —
가상 데이터를 생성 코드로 남기는 것과 같은 이유다. 승급을 프로세스 안에서만 켜므로
`.env` 와 저장소를 안 건드린다. **캐시가 들면 호출 0 이다.**

```python
import sys; sys.path.insert(0, ".")
from pathlib import Path
from rag_pipeline.config import ContentRoutingConfig, IngestConfig
from rag_pipeline.ingestion.loader.content.base import ContentType, LoadContext
from rag_pipeline.ingestion.loader.content.router import ContentRouter
from rag_pipeline.ingestion.loader.document.pdf import PdfLoader

PDF = Path("tests/fixtures/[DNA+_2019-5]_공공기관_신뢰가능_AI_구현_실용가이드.pdf")
cfg = IngestConfig()
object.__setattr__(cfg, "_content", ContentRoutingConfig(table_pdf_handler="hybrid"))
ctx = LoadContext(config=cfg.content)
regions = PdfLoader(cfg).detect_regions(PDF, ctx)
targets = [r for r in regions
           if r.content_type is ContentType.TABLE and r.blob and r.mark_cells]
print(f"대상 표 {len(targets)}개 — Vision 최대 {len(targets)}회")

router = ContentRouter(cfg.content)
for region in targets:
    before = [list(row) for row in region.rows]
    elements = router.route(region, ctx)
    md = elements[0].metadata if elements else {}
    got = md.get("vision_filled_cells", 0)
    want = md.get("vision_expected_cells", len(region.mark_cells))
    over = [(r, c, before[r][c], md["rows"][r][c])
            for r in range(len(before)) for c in range(len(before[r]))
            if before[r][c].strip() and before[r][c] != md.get("rows", before)[r][c]]
    print(f"p{region.page}: {md.get('table_source', '(없음)')}  {got}/{want}"
          + (f"  원본이 덮였다: {over}" if over else ""))
print(f"vision_calls = {ctx.vision_calls}")
for w in ctx.warnings:
    print("  경고:", w)
```

**`원본이 덮였다` 가 한 줄이라도 나오면 계약 위반이다** — 지금까지 5회 실행에서 0건이다.

## 7. 재지 못한 것

- **캐시 키에 프롬프트 본문이 없다** (미해결, 2026-08-22). 지금 키는
  `hash(구운 PNG + 격자) + salt(모델명)` 이다. 프롬프트에는 그 둘 말고 `_PROMPT` 문자열이
  함께 실려 나가는데 **그것은 키에 없다.** 규칙 문구 하나만 고쳐도 다른 질문이 되는데
  옛 답이 그대로 돌아오고 **에러가 안 난다** — 해상도가 salt 에 없던 것, 격자가 키에 없던
  것과 **같은 형태의 구멍이 셋째**다.
  **지금은 발화하지 않는다**(이번 작업에서 프롬프트를 안 건드렸다). 안 고치고 남긴 이유는
  키를 바꾸면 캐시가 통째로 비껴가 다음 유료 실행이 6회를 새로 무는 것뿐이고, 그 값을
  치를 이유가 지금 없어서다.
  **고칠 시점**: 프롬프트를 손볼 때나, 해상도·격자를 바꿔 **어차피 캐시가 무효가 되는
  변경과 함께.** 그때 `salt` 에 `_PROMPT` 해시 앞자리를 더하면 된다

- **거절률을 못 정한다.** 표본이 6개고 그중 1건이다. 문서가 더 있어야 17% 가 실제
  비율인지, 14쪽 표의 특성(4행 8열 다단 헤더)에 딸린 것인지 갈린다
- **12쪽 2칸 미검출의 원인을 못 갈랐다.** `_TARGET_LONG_EDGE_PX` 를 올려 다시 돌리면
  해상도인지 모델인지 알 수 있다. **캐시 salt 에 해상도가 없어** 지금 값을 바꿔도 옛
  결과가 나온다 — 다시 재려면 salt 를 손보거나 캐시를 비워야 한다
- **17쪽 병합 자리 채움을 판정 못 했다.** 원본 문서를 눈으로 봐야 6열 체크가 7열까지
  걸치는지 안다
