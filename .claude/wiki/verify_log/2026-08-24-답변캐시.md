# 답변 캐시 — 컬렉션 분리·클라이언트 공유·무효화가 실제로 도는가

- 검증일: 2026-08-24
- 대상: `task_log/2026-08-24-답변캐시.md` (semantic answer cache 신설)
- 비용: **외부 API 호출 없음.** 임베딩·생성·Vision·LlamaParse 전부 0회. E2E 는 가짜
  embedder 로 단위 벡터를 직접 만들어 넣었고, `-m integration` 은 안 돌렸다

## 1. 확인하려 한 것

**"규칙이 도는가" 쪽이다. 임계값은 이번에 안 쟀다** — 그것은 패러프레이즈 쌍이 있어야
하고 임베딩 모델이 정해진 뒤라야 의미가 있어서 다음 회차로 미뤘다(7절).

이번에 확인한 가설은 넷이다.

1. 한 qdrant 클라이언트로 **두 컬렉션**을 열 때 배타 잠금에 안 걸리는가
2. 캐시 항목이 문서 열거(`iter_chunks()`·`list_documents()`)에 **안 섞이는가**
3. 근거 청크가 지워지거나 바뀌면 캐시가 **미스로 내려가고 그 항목을 지우는가**
4. 임계값이 없을 때 캐시가 **통째로 꺼지는가**

## 2. 가상 데이터

무엇을 고립시켰나: **임베딩과 qdrant 를 둘 다 가짜로 세워 캐시 논리만 남겼다.** 실제
저장소를 쓰면 무효화 시나리오(근거가 그 사이 지워졌다)를 만들기 어렵고, 재는 것이 캐시
논리가 아니라 qdrant 동작이 된다. 전문은 `tests/answer_cache/test_answer_cache.py`.

임계값 경계는 **한 축만 바꾼 세 점**으로 갈랐다 — 판정이 `<` 인지 `<=` 인지가 여기서만
드러난다.

```python
# tests/answer_cache/test_answer_cache.py 에서 발췌. threshold=0.9 고정, score 만 움직인다
def test_lookup_misses_just_below_threshold():
    store = _FakeStore(_FakeClient(point=_Point(_payload_of(_answer()), score=0.8999)), [_stored()])
    assert _cache(store, threshold=0.9).lookup("비슷한 질문", embedder=_FakeEmbedder()) is None

def test_lookup_hits_exactly_at_threshold():
    store = _FakeStore(_FakeClient(point=_Point(_payload_of(_answer()), score=0.9)), [_stored()])
    assert _cache(store, threshold=0.9).lookup("비슷한 질문", embedder=_FakeEmbedder()) is not None
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| score 0.8999 / threshold 0.9 | 미스 | 미스 | 통과 |
| score 0.9 / threshold 0.9 | 히트 | 히트 | 통과 |
| score 0.97 / threshold 0.9 | 히트 + `cached_from` 채워짐 | 히트, 원 질문·시각·점수 실림 | 통과 |
| 근거 청크가 저장소에 없음 | 미스 + 캐시 항목 삭제 | 미스, `delete` 1회 | 통과 |
| 근거 청크 텍스트만 바뀜 | 미스 + 캐시 항목 삭제 | 미스, `delete` 1회 | 통과 |
| `sources` 가 빈 답 저장 | 저장 안 함 | `put()` False, upsert 0회 | 통과 |
| 캐시에서 온 답 재저장 | 저장 안 함 | `put()` False, upsert 0회 | 통과 |
| `threshold=None` | 캐시가 안 만들어짐 | `get_answer_cache()` → `None` | 통과 |
| 저장소·임베딩이 예외를 던짐 | 예외가 안 새고 미스 + 경고 | 미스, `warnings` 채워짐 | 통과 |
| 공백·NFD 만 다른 같은 질문 | 같은 point id | 같음 | 통과 |

**NFD 단언은 한 번 헛돌았다.** 초판이 `"…".encode().decode()` 로 NFD 를 만들려 했는데
그것은 무연산이라 원본과 같은 문자열을 비교하고 있었다. `unicodedata.normalize("NFD", …)`
로 고치고 **"NFD 결과가 원본과 실제로 다른지"를 먼저 단언**하도록 바꿨다.

## 7. 재지 못한 것

- **유사도 임계값.** 이번 값 `0.90` 은 E2E 를 돌리기 위한 **임의값이고 근거가 없다.**
  코드의 기본값은 여전히 `None`(꺼짐)이고 `.env.example` 도 빈 값이다. 재려면 *같은 뜻
  다른 말* 쌍이 필요한데 **기존 세트에는 한 쌍도 없다** — `qa_set.jsonl`(60)과
  `qa_set_human.jsonl`(20)의 `gold_spans` 교집합이 **0건**임을 이번에 확인했다
- **임계값은 임베딩 모델에 딸린 값이다.** 세션 66이 모델 비교를 진행 중이라, 지금 재면
  모델이 바뀌는 순간 무효가 된다. 그 회차 뒤로 미뤘다
- **실제 임베딩으로 재는 히트율.** 위 E2E 의 0.9806 은 손으로 만든 단위 벡터라
  *코사인 계산이 맞는지*만 말하고 *한국어 패러프레이즈가 실제로 그 근처에 오는지*는 못 말한다
- **캐시 상한·퇴거.** 항목이 몇 개까지 늘지 안 쟀다. 수를 지어내지 않았다
