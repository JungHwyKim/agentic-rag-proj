# 기본 임베더를 KURE-v1 로 갈아타고 그림자 색인을 붙인 것을 검증했다

- 검증일: 2026-08-25
- 대상: [task_log/2026-08-25-임베더-전환.md](../task_log/2026-08-25-임베더-전환.md)
  (`plan_log/embedding.md` 5회차)
- 비용: **실제 청구 $0.00 에 가깝다.** 평가 2회는 `usage` 가 `tokens 0 · calls 0`(캐시 전량
  적중). 실서버 왕복에서 **그림자 임베딩이 실제로 몇 번 났다** — 세 줄짜리 문서 3건이라
  청크 3개이고, `text-embedding-3-small` 기준 100토큰 미만이다. `-m integration` 안 돌림

## 1. 확인하려 한 것

가설 넷.

1. **갈아탔는데 벡터가 안 바뀌었나** — `device` 축을 열었으므로 기본 `cpu` 에서 이전과
   같은 수치가 나와야 한다. 안 나오면 device 배선이 뭔가를 바꾼 것이다
2. **방어막이 한 겹 줄어든 대가를 실제로 치렀나** — `torch` 가 본체로 오면서
   *"기본 설치에 torch 가 없다"* 는 겹이 사라졌다. 남은 한 겹이 어디서 뚫리는지
3. **기준선 라벨이 함정을 닫았나**
4. **그림자가 두 컬렉션을 같은 문서 집합으로 유지하나** — 그리고 그림자가 죽어도 서비스가 사나

## 2. 가상 데이터

**없음 — 대신 테스트 대역이다.** 이 회차가 만든 것은 임계값이 아니라 **계약**이라
(두 컬렉션이 같은 집합 · 실패를 삼키되 드러냄) 합성 문서로 고립시킬 축이 없다.
계약은 `tests/ingestion/indexing/test_shadow_index.py` 10건과
`tests/api/test_shadow_routes.py` 6건이 잠근다.

## 3. 실제 데이터

### 3-1. 평가 두 갈래 — 갈아탔는데 수치가 그대로다

| 실행 | 지표 | 전환 전 | 이번 | 판정 |
|---|---|---:|---:|---|
| `--embedding kure-v1` | `hit@10` | 0.8500 | **0.8500** | 동일 |
| | `MRR` / `nDCG@10` | 0.5078 / 0.5938 | **같음** | 동일 |
| `--embedding baseline` | `hit@10` | 0.4833 | **0.4833** | 동일 |
| | 기준선 대조 | — | **이김 0 · 짐 0 · 그대로 60** | 동일 |

**`device` 축을 열어도 벡터가 안 바뀐다**가 이 표의 내용이다. `kure-v1` 리포트의
`settings.embedding.embedding_device` 가 `cpu` 로 실려 있고, 그 값이 실렸는데도 수치가
같다는 것이 배선이 옳다는 증거다. `usage` 는 두 실행 모두 `tokens 0 · calls 0`.

**프로필 가드가 fallback 없이 돈다** — `baseline.json` 에 `"embedding_profile": "baseline"`
이 명시로 있고(`in baseline` 이 `True`), `kure-v1` 실행에서 가드가 정상적으로 물러섰다.

### 3-2. 실서버 왕복 — 이 회차의 본 검증

`uvicorn` 을 실제로 띄우고 `curl` 로 걸었다. 문서는 세 줄짜리 텍스트다.

| # | 확인 | 기대 | 실측 | 판정 |
|---|---|---|---|---|
| 1 | 업로드 → 두 컬렉션 | 둘 다 +1 | KURE **0→1** · OpenAI **103→104** | 의도한 변화 |
| 2 | 질의 | KURE 컬렉션에서 검색 | 올린 문서가 출처로 나옴 | 의도한 변화 |
| 3 | 키를 깨고 업로드 | 색인 성공 + 표시 | **204** · 표시 **1건** | 의도한 변화 |
| 4 | 그 문서 재업로드 | 표시 사라짐 | **1 → 0** | 의도한 변화 |
| 5 | 삭제 | 두 컬렉션에서 제거 | KURE **3→0** · OpenAI **106→103** | 의도한 변화 |

5번의 103 은 **테스트 시작 전 백업본과 정확히 같다** — 남의 문서를 안 건드렸다는 증거다.

**3번에서 제 검증 설계가 한 번 틀렸다.** 처음에 *같은 내용*을 다시 올려서 표시가 안 붙었고
잠깐 버그로 봤는데, 원인은 **임베딩 캐시 적중**이었다 — 같은 내용이면 salt·해시가 같아
API 를 아예 안 부르므로 키가 깨져도 그림자가 성공한다. **캐시에 없는 새 내용으로 다시 재니
기대대로 났다.** 코드가 아니라 검증이 틀린 자리였다.

### 3-3. 방어막이 줄어든 대가 — 세 곳에서 실제로 뚫렸다

**이것이 이 회차에서 제일 값나가는 실측이다.** 기본값이 `local` 이 되자 provider 를 안 박은
자리가 전부 로컬 갈래로 샜다.

| 자리 | 증상 | 원인 |
|---|---|---|
| `tests/ingestion/embedding/conftest.py` | 폴더가 **241초 · 27 failed** | `embedding_config` 픽스처가 provider 미고정 → 가짜 OpenAI 클라이언트가 안 꽂히고 **2.2GB 실제 적재** |
| `tests/ingestion/indexing/test_indexing_real.py` | 폴더가 **120초 초과** · **Windows access violation** | `real_config` 가 provider 미고정 → 실파일 `index_document()` 가 로컬 모델을 올림 |
| `tests/conftest.py` `offline_config` | 테스트는 도는데 **컬렉션 이름만 틀림** | provider 는 박고 **model 은 안 박아** `openai` 인데 이름이 `nlpai-lab/KURE-v1` |

**가중치가 캐시에 없는 머신이었으면 셋 다 조용히 내려받았을 것이다.** 고친 뒤
`tests/ingestion/embedding` 은 **7.8초**, `tests/ingestion/indexing` 은 **34초**다.

## 7. 재지 못한 것

- **GPU 벡터가 CPU 와 얼마나 다른가** — 이 머신 torch 가 `2.13.0+cpu` 라 **못 쟀다**.
  `device` 를 캐시 salt 에 안 넣은 판단이 이 값에 걸려 있다(`plan_log/embedding.md` 미결)
- **KURE 색인 시간** — 실서버에서 세 줄짜리 문서만 올려 의미 있는 값이 안 나온다.
  실제 코퍼스 색인 시간은 안 쟀다
- **브라우저 렌더** — `비교색인 없음` 표시를 HTML 문자열로만 확인했다. htmx 가 실제로
  조각을 넣고 CSS 가 먹는지는 `TestClient` 도 `curl` 도 못 본다
- **한글 파일명 왕복** — `curl` 이 파일명을 mojibake 로 보내 저장 이름이 깨졌다.
  **curl 의 한계이지 앱 결함이 아니다**(브라우저는 UTF-8 로 보낸다). 브라우저로는 안 걸어 봤다
