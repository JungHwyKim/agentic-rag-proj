## 1. 확인하려 한 것

물음이 셋이고 성격이 다르다.

1. **SDK 기본 타임아웃이 얼마인가** — 재기 전에는 몰랐다. *발견* 이 목적이라 기대값이 없다

3. **빠진 클라이언트가 없는가** — 손으로 센 목록이 실제로 전수인가

## 2. 가상 데이터

무엇을 고립시켰나: **네트워크를 안 타는 클라이언트 생성 한 줄.** 키는 더미이고 요청을 안 보낸다.

### 2-1. SDK 기본값 탐침 (발견 — 기대값 없음)

```python
from openai import OpenAI
import openai
print(openai.__version__, openai._constants.DEFAULT_TIMEOUT, openai._constants.DEFAULT_MAX_RETRIES)

import cohere, inspect
c = cohere.ClientV2(api_key="x")
print(cohere.__version__, c._client_wrapper.get_timeout())
print("ClientV2 timeout 인자:", "timeout" in inspect.signature(cohere.ClientV2.__init__).parameters)

from tavily import TavilyClient
print("TavilyClient.__init__ timeout:", "timeout" in inspect.signature(TavilyClient.__init__).parameters)
print("TavilyClient.search timeout:", inspect.signature(TavilyClient.search).parameters["timeout"])
```

| 대상 | 실측 | 최악(재시도 포함) |
|---|---|---|
| `openai 3.0.0` 기본 | `Timeout(connect=5.0, read=600, write=600, pool=600)` · `max_retries=2` | **1800초** |
| `cohere 7.1.0` 기본 | `300` (생성자가 `timeout` 인자를 받음) | 300초 |
| `tavily` 생성자 | `timeout` 인자 **없음** | — |
| `tavily` `search()` | `timeout: float = 60` | 60초 |

### 2-2. 맨 float 이 무엇을 덮는가 (기대값 있음)

```python
import httpx
from openai import OpenAI
print(OpenAI(api_key="x", timeout=60.0).timeout)
print(OpenAI(api_key="x", timeout=httpx.Timeout(60.0, connect=5.0)).timeout)
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `timeout=60.0` | 읽기만 60 이 된다 | `60.0` — **connect 포함 전부** | **기대가 틀렸다** |
| `timeout=httpx.Timeout(60.0, connect=5.0)` | 읽기 60 · 연결 5 | `Timeout(connect=5.0, read=60.0, write=60.0, pool=60.0)` | 통과 |

**첫 줄이 이 검증의 값어치다.** 맨 float 으로 짰으면 읽기를 조이면서 **연결 실패를 5초에서 60초로 12배 늘렸을** 것이고, 그 회귀는 정상 경로에서 안 보인다(호스트가 살아 있으면 connect 가 안 걸린다).

## 7. 재지 못한 것

- **정상 호출의 지연 분포를 못 쟀다. 그래서 `60` 이 맞는 값인지 모른다.** `data/cost.jsonl` 이 토큰·호출만 담고 **걸린 시간을 안 담아서**, 이 저장소에는 «Vision 호출이 보통 몇 초인가» 를 답할 기록이 없다. 60은 질의 한 건이 생성까지 3.3~8.0초라는 관측의 여유 배수로 고른 값이라 **임시값이다**
- **그래서 재판정 조건을 «신호» 로 대신했다** — 값이 낮아 정상 호출이 잘리면 Vision→OCR · 리랭커→RRF · 재작성→원 질의로 내려가며 **경고가 남는다.** 그 경고에 timeout 이 뜨면 올린다. 반대 방향(600초)은 아무 신호가 없다는 것이 먼저 낮게 잡은 이유다
- **타임아웃이 실제로 발동하는 것을 안 봤다.** 발동시키려면 응답을 늦추는 가짜 서버가 필요한데, 이번에 잠근 것은 *값이 클라이언트에 실리는가* 까지다. `httpx` 동작 자체는 우리 코드가 아니다
- **`max_retries` 는 안 건드렸다.** SDK 기본 2 그대로라 최악은 `60 × 3 = 180초` 다. 줄일지는 «재시도가 값을 하는가» 를 재야 정해지는데 그 데이터가 없다
- **지연 칸을 비용 로그에 더할지 안 정했다.** 더하면 위 첫 항목이 다음 회차에 닫힌다
