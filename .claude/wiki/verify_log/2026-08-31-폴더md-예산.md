## 1. 확인하려 한 것

앞 판은 훅이 **돌았는데도** 지침이 모델에 안 닿았다. 하네스가 큰 `additionalContext` 를
2KB 프리뷰로 자르고 나머지를 파일로 뺐기 때문이다. 그래서 물은 것이 둘이다.

1. **임계값이 얼마인가** — 앞 판은 `8,889` 와 `27,457` 사이라는 것까지만 알았다
2. **하네스가 무엇을 세는가** — 앞 판의 표가 전부 **바이트**로 적혀 있는데, 보고된
   `30.5KB` 가 실린 바이트(27,457)보다 **크다.** 단위가 바이트가 아닐 가능성이 그때 이미
   표에 드러나 있었는데 안 읽혔다

둘째가 먼저다 — **단위를 모르면 임계값을 좁혀도 쓸 수 없다.**

## 2. 가상 데이터

무엇을 고립시켰나: **크기 한 축.** `.cache/mdprobe/pNNNNN/` 폴더마다 `CLAUDE.md` 하나와
빈 파일 하나를 두고, `CLAUDE.md` 의 길이만 바꿔 `cat …/f.txt` 를 돌렸다.

**여기서 가상이 맞는 이유를 밝혀 둔다.** 이 스킬의 0단계는 *"가상 수치로 임계값을 정하지
않는다"* 인데, 그 규칙이 겨누는 것은 **문서 도메인의 임계값**이다(합성 문서는 만든 사람의
기대를 그대로 갖고 있어 자기 확인이 된다). 여기서 재는 것은 **하네스의 상수**라 문서 내용과
무관하고, 오히려 같은 0단계의 *"실파일이 못 만드는 입력은 가상이 만든다"* 에 해당한다 —
실제 폴더 지침 일곱은 `5,128` 다음이 `11,538` 이라 **그 사이에 관측점이 하나도 없다.**

**폴더마다 경로가 달라 마커 네임스페이스도 달라진다** — 그래서 한 세션에서 아홉 번 잴 수
있었다(같은 폴더면 두 번째부터 침묵한다).

```python
# 탐침 폴더를 만든다. 채움이 ASCII 라 문자 수 = 길이이고, 끝에 표식을 둬서
# 전문이 왔는지 눈으로 가른다
from pathlib import Path
import sys

ROOT = Path(r"C:\agentic-rag-proj")
sys.path.insert(0, str(ROOT / ".claude" / "hooks"))
import folder_md_check as fmc

for target in [8192, 9216, 10000, 10239, 10240, 11264, 12288, 16384, 24576]:
    folder = ROOT / ".cache" / "mdprobe" / f"p{target:05d}"
    folder.mkdir(parents=True, exist_ok=True)
    (folder / "f.txt").write_text("probe\n", encoding="utf-8")

    doc = folder / "CLAUDE.md"
    tail = f"\nEND-SENTINEL-ZQX-{target}\n"
    filler_len = 1
    for _ in range(40):                       # 훅이 실을 때의 길이가 target 이 되게 맞춘다
        doc.write_text(("x" * filler_len) + tail, encoding="utf-8")
        # **`compose()` 로 재면 안 된다** — 예산을 넘는 탐침은 포인터로 떨어져 길이가
        # 117자에서 멈추고 루프가 영영 안 맞는다. 재는 것은 «전문으로 실렸을 때의 길이» 다
        got = len(fmc.HEAD) + 2 + len(fmc.block_for(doc))
        if got == target:
            break
        filler_len += target - got
```

### 2-1. 하네스가 세는 단위

일곱 폴더를 한 명령이 다 문 경우를 훅과 하네스 양쪽에서 쟀다.

| 재는 쪽 | 값 |
|---|---:|
| 훅이 실은 `additionalContext` (UTF-8 바이트) | 102,464 |
| 훅이 실은 `additionalContext` (문자) | 55,150 |
| 하네스가 보고한 크기 | `53.9KB` |

`55,150 / 1024 = 53.86…` → **`53.9KB` 와 일치한다.** 바이트로 세면 `100.1KB` 라 안 맞는다.
**하네스는 문자를 센다.** 이 문서들은 바이트당 0.54자라, **바이트로 재면 임계값을 두 배로
잘못 잡는다** — 앞 판의 표가 통째로 그 상태였다.

context 10,000 → stdout 10,086 < 10,240, context 10,239 → 10,325 > 10,240),
**context 기준 가설과 못 갈랐다.** 2회차가 그것을 닫았다.

**상수는 정확히 10,000자다** — 인접한 두 탐침(10,000 전문 / 10,001 잘림)이 못 박는다.
`> 10000` 이면 자른다.

**두 가설이 실측으로 죽었다.**

- **바이트 가설** — 10,075자가 10,217바이트라 «10,240바이트 상한» 처럼 보였는데,
  10,011자는 **10,153바이트**인데도 잘린다. 바이트 상한이면 통과했어야 한다
- **stdout(JSON) 가설** — 10,154자에서 stdout 이 정확히 10,240 이 되는 것이 **10 KiB 라는
  그럴듯한 상수**를 만든다. 그런데 stdout 이 10,097자뿐인 10,011자 탐침도 잘린다

**둘 다 그럴듯했던 이유가 보고 형식에 있다** — 보고되는 크기가 문자수/1024 라
(10,011자 → `9.8KB`) `10KB` 근처 숫자가 늘 눈에 띄고, 그러면 «10 KiB 가 상한» 으로 읽게
된다. **상한은 2진수가 아니라 10진수 10,000이다.**

### 3-0. 사람이 새 세션에서 한 최종 확인 (2026-09-01)

**두 판을 돌렸고 첫 판은 무효였다.** 무효인 이유가 이 절의 값어치다.

| | 1차(무효) | 2차 |
|---|---|---|
| `cat` 시킨 파일 | `…/loader/document/pdf.py` (49,346바이트) | `…/loader/registry.py` (3,400바이트) |
| `cat` 결과 | **48.2KB → 2KB 프리뷰**(본문 대부분 안 옴) | 통째로 옴 |
| 모델이 한 일 | `Read` 로 **본문을 다시 읽음** → 네이티브가 두 지침 자동 적재 | **쪽지를 따라 `loader/CLAUDE.md` 를 열었다** |
| 판정 | **무효** — 쪽지의 몫이 0인 경로다 | **통과** |

**1차가 무효인 이유** — `cat` 이 잘려서 모델이 `pdf.py` 를 `Read` 로 되읽었고, 그때 네이티브
지연 로드가 `ingestion`·`loader` 를 **둘 다** 실었다. 정답이 나왔지만 **쪽지가 없었어도 똑같이
나온다.** 탐침 파일이 커서 재려던 축이 지워진 것이다 — 2차는 `cat` 이 성공하는 3,400바이트
파일로 바꿔 «쪽지 말고는 길이 없는» 상태를 만들었다.

**2차에서 밝혀진 것 — 모델은 쪽지를 따라갔지만 `Read` 가 아니라 `cat` 으로 열었다.**
auto mode 가 `cat` 을 지시하므로 그쪽이 쪽지 문구를 이긴다. **그런데도 통했다** —
`loader/CLAUDE.md` 가 23,197바이트라 셸 출력 상한 아래였기 때문이다(재현 확인: 그 파일을
`cat` 하면 12,522자가 통째로 온다).

### 3-0-1. 그 우연이 안 통하는 자리 — `evaluation`

| 포인터 대상 | bytes | `cat` 으로 열면 |
|---|---:|---|
| `backend/CLAUDE.md` | 21,048 | 통째로 온다 |
| `rag_pipeline/ingestion/loader/CLAUDE.md` | 23,197 | 통째로 온다(2차가 여기 걸렸다) |
| `evaluation/CLAUDE.md` | 37,141 | **36.3KB → 2KB 프리뷰. 조용히 실패** |

즉 «쪽지를 따라간다» 가 참이어도 **제일 큰 폴더에서는 내용이 안 닿는다.** 2차가 통과한 것은
셋 중 통하는 자리를 우연히 골랐기 때문이다. 처방은 쪽지가 **`cat` 으로 열면 잘린다고
경고**하고 **크기를 함께 주는 것**이다(회귀 테스트 둘로 잠갔다).

**셸 출력 채널은 바이트를 센다** — `pdf.py` 49,346바이트가 `48.2KB`(=49,346/1024),
`evaluation/CLAUDE.md` 37,141바이트가 `36.3KB`(=37,141/1024)로 보고된다. 문자로 세면
후자는 19,683자=19.2KB 라 안 맞는다. **`additionalContext` 는 문자를 세는데(2-1 절) 이쪽은
바이트다** — 같은 `KB` 글자가 두 채널에서 다른 것을 센다. 상한도 달라서, 셸 쪽은
**23,197바이트는 통과하고 37,141바이트는 잘린다**(그 사이 정확한 값은 안 쟀다).

| 나머지 pytest | 회귀 없음(1956 → 1961, 늘어난 5가 전부 새 검사) |
