# heredoc 훅의 PowerShell 오탐을 후보 둘로 재고 고친 판을 검증했다

- 검증일: 2026-09-01
- 대상: [task_log/2026-09-01-heredoc훅-오탐.md](../task_log/2026-09-01-heredoc훅-오탐.md) ·

- 비용: **외부 API 호출 없음.** 이 훅은 정규식만 돌린다(subprocess·git 호출 없음)

## 1. 확인하려 한 것

*"규칙이 도는가"* 가 아니라 ***"어느 규칙이 옳은가"*** 다. 오탐이 실재하는 것은 이 세션이
커밋을 하려다 실제로 막혀서 이미 안다 — 물은 것은 **어디를 고치면 그 부류가 없어지나** 이고,
후보가 둘이라 **같은 케이스 세트에 나란히 대는 것**이 방법이다.

## 2. 가상 데이터

무엇을 고립시켰나: **명령 문자열 하나만** 바꾼다. 판정 함수를 직접 부르므로 셸도 파일시스템도
안 탄다.

### 2-1. 원인을 짝으로 갈랐다 — 트레일러 하나만 다르다

```python
import sys
from pathlib import Path

sys.path.insert(0, str(Path(r"C:\agentic-rag-proj") / ".claude" / "hooks"))
import heredoc_write_check as h

TRAILER = "Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>"

for label, command in [
    ("트레일러 없음", "git commit -m @'\nfix: 무언가를 고친다\n'@"),
    ("트레일러 있음", f"git commit -m @'\nfix: 무언가를 고친다\n\n{TRAILER}\n'@"),
]:
    hit = h._FILE_REDIRECT_RE.search(command)
    print(label, "막힘" if h.powershell_reason(command) else "통과",
          repr(hit.group(0)) if hit else "—")
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 트레일러 없음 | 통과 | 통과 | 통과 |
| 트레일러 있음 | 통과 | **막힘** (리다이렉트로 본 것 `">\n'@"`) | **실패** |

`_FILE_REDIRECT_RE`(`>>?\s*(?!&)[^\s|&;<>]+`)에서 `>` 뒤의 `\s*` 가 줄바꿈을 먹고, here-string
종료 기호 `'@` 가 **대상 파일명 자리**에 들어간다.

### 2-2. 증상이 `>` 하나가 아니다 — 범위 문제라는 증거

| 입력(본문만 다르다) | 기대 | 실측(고치기 전) | 판정 |
|---|---|---|---|
| 본문에 `<noreply@anthropic.com>` | 통과 | 막힘 | 실패 |
| 본문에 `Set-Content` 라는 낱말 | 통과 | 막힘 | 실패 |
| 본문에 `` `cat > f.md` `` 예시 | 통과 | 막힘 | 실패 |

뒤 둘은 트레일러와 무관하다. **「트레일러만 예외 처리」로는 셋 중 하나만 없어진다.**

### 2-3. 후보 둘을 같은 케이스 세트에 나란히 댔다

케이스는 기존 테스트의 `BLOCKED_PS`(4)·`ALLOWED_PS`(3)에 **실사용을 닮은 넷**을 더한 15개다 —
트레일러 붙은 진짜 커밋 · `Set-Content` 산문 · `cat > f.md` 산문 · 공백 있는 따옴표 경로
(`@'…'@ > "out file.md"`).

    후보 A  `>` 뒤에 경로꼴을 요구      _A_REDIRECT = r">>?\s*(?!&)[\w./\\~-]+"
    후보 B  here-string 본문 밖만 본다  본문을 `@@` 로 치환한 뒤 기존 정규식을 댄다

| 규칙 | PS 누락 | PS 오탐 | Bash 누락 | Bash 오탐 |
|---|---:|---:|---:|---:|
| 고치기 전 | 0 | **3** | 0 | 0 |
| A. 경로꼴 요구 | **1** | **2** | 0 | 0 |
| **B. 본문 밖만** | **0** | **0** | 0 | 0 |

**A 의 누락 1건이 탈락 사유다** — `@'…'@ > "out file.md"` 가 안 막힌다. `'@` 를 거르려면
경로꼴에서 따옴표를 빼야 하는데 그러면 따옴표 친 진짜 경로도 함께 빠져, **진짜 파일 쓰기가
새는 쪽으로 틀린다.** 덤으로 `_FILE_REDIRECT_RE` 는 Bash 와 **공유**라 그쪽까지 움직인다
(이번 케이스에서는 안 갈렸지만 위험은 남는다).

### 2-4. B 의 경계 10개

| 입력 | 기대 | 고치기 전 | B |
|---|---|---|---|
| 끝 구분자 없음 + 본문에 `>` | 통과(판단 안 함) | 막힘 | **막힘** |
| 끝 구분자 없음 + 진짜 쓰기 | 통과(셸이 죽는다) | 막힘 | **막힘** |
| here-string 둘 · 하나만 파일 | 막아야 | 막힘 | 막힘 |
| here-string 둘 · 둘 다 산문 | 통과 | 막힘 | 통과 |
| 닫는 구분자 뒤 공백 | 통과 | 막힘 | 통과 |
| 본문 안에 `'@` 가 있다 | 막아야 | 막힘 | 막힘 |
| 한 줄 here-string 아님 | 통과 | 통과 | 통과 |
| 본문 없이 바로 닫음 | 통과 | 통과 | 통과 |
| CRLF 줄끝 | 통과 | 막힘 | 통과 |
| 진짜 쓰기 · 본문 여러 줄 | 막아야 | 막힘 | 막힘 |

**앞 둘이 남았다** — Bash 는 `_heredocs()` 가 닫힌 것만 모아 «판단이 서지 않으면 막지 않는다»
를 지키는데, PowerShell 은 **여는 자리만** 봐서 안 닫혀도 here-string 으로 셌다. **B 가 만든
문제가 아니라 원래 있던 어긋남**이라 같은 방향으로 함께 고쳤다.

### 2-5. 고친 뒤 — 배포된 코드로 다시 잰다

| 축 | 막아야 | 통과해야 | 누락 | 오탐 |
|---|---:|---:|---:|---:|
| PowerShell | 6 | 6 | **0** | **0** |
| Bash | 9 | 13 | **0** | **0** |

훅을 **서브프로세스로도** 돌렸다(판정 함수가 맞아도 배선이 틀리면 소용이 없다).

    트레일러 붙은 진짜 커밋     deny=False   기대 False   통과
    진짜 파일 쓰기              deny=True    기대 True    통과
    안 닫힌 here-string         deny=False   기대 False   통과
