## 1. 확인하려 한 것

두 가지다.

1. **형식이 실제로 채워지는가.** 빈 폴더에 규격만 두고 끝내면 반드시 안 맞는다. 첫 회차를
   진짜로 써서 칸이 비는 곳과 명령이 안 도는 곳을 찾는다
2. **가상 데이터가 실파일의 빈자리를 실제로 메우는가.**
   `tests/ingestion/splitter/test_splitter_real.py::test_split_table_pieces_keep_header` 는
   `if not by_source: pytest.skip(...)` 으로, 실파일에 '쪼개진 표'가 없으면 스스로 건너뛴다.
   그 규칙이 정말 도는지는 지금 아무도 모른다

둘 다 "규칙이 도는가"이지 "임계값이 맞는가"가 아니다. 그래서 2절에 힘이 실린다.

## 2. 가상 데이터

무엇을 고립시켰나: **표의 데이터 행 수 한 축만** 바꿨다. 헤더·열 수·셀 문구는 고정이다.
상한(1200자) 아래 / 근처 아래 / 위 세 지점을 잡았다.

```python
CAP = 1200
HEADER = ["구분", "추진내용", "담당부서", "예산"]

# 데이터 행 n개짜리 표 하나만 든 문서. 헤더는 항상 같다
def make_doc(n: int) -> ParsedDocument:
    rows = [HEADER] + [
        [f"항목{i:02d}", f"세부 추진내용 {i:02d}", "정보화담당관", f"{i * 100}백만원"]
        for i in range(1, n + 1)
    ]
    return ParsedDocument(
        metadata=DocumentMetadata(
            source_name=f"합성-{n}행.hwpx", file_format=FileFormat.HWPX, size_bytes=0
        ),
        elements=[
            Element(
                type=ElementType.TABLE, text=rows_to_markdown(rows),
                order=1, page=1, metadata={"rows": rows},
            )
        ],
    )

config = SplitterConfig(max_chunk_chars=CAP, chunk_overlap_chars=150)
for n in (8, 20, 60):
    chunks = split(make_doc(n), config)
    headers = {tuple(c.metadata["rows"][0]) for c in chunks}
    # 기대: len(headers) == 1, 모든 조각 rows >= 2, max(len(c.text)) <= CAP
```

기대값을 먼저 적고 돌렸다.

| 입력 | 표 자수 | 기대 | 실측 (조각 / 헤더 종류 / 최대 자수) | 판정 |
|---|---:|---|---|---|
| 8행 | 371 | 조각 1, 헤더 1종 | 1 / 1 / 371 | 기대와 같음 |
| 20행 | 862 | 조각 1, 헤더 1종 | 1 / 1 / 862 | 기대와 같음 |
| 60행 | 2502 | **조각 2 이상**, 헤더 1종, 최대 ≤ 1200 | **3** / 1 / **1199** | 기대와 같음 |

60행에서 처음으로 분할이 발화했고, 조각 3개가 **모두 같은 헤더 행**을 갖고 각각 데이터 행을
1개 이상 가졌다. 상한도 1199 로 지켜졌다 — 제목 머리를 예산에서 미리 빼는 `_body_budget()`
이 표 조각에도 걸려 있다는 뜻이다.

**이 구간은 실파일이 만들지 못한다.** `EXPECTED` 에 든 세 문서 어디에도 상한을 넘는 표가
없어 위 규칙은 지금까지 한 번도 실행되지 않았다.
