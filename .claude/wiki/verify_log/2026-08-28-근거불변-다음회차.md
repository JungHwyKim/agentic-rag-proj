## 1. 확인하려 한 것

앞 회차(`verify_log/2026-08-28-근거불변-재시도.md`)가 `evidence_unchanged_at` 을 만들고 실물에서
한 번 확인했는데, **접기 판단에는 0비트를 얻었다** — 표본 1 · 예고된 질의 · 그리고 근거 동일
회차가 하필 **마지막 회차**라 볼 다음 회차가 없었다.

그래서 이번 물음은 하나다: **근거가 같았던 회차 N 을 접었다면, N+1 회차가 찾았을 것을 놓쳤나.**

임계값을 정하는 검증이 **아니다** — 순위 비교는 `scoring.hit_rank()` 가 이미 정한 자[尺]를 쓰고,
새로 정할 수는 없다.

## 2. 가상 데이터

무엇을 고립시켰나: **짝짓기 규칙과 강제 래퍼의 계약만 남기고 외부를 전부 끊었다.** 회차 목록을
손으로 지어 넣어 `pair_rows`·`production_stop`·`summarize` 를 고립시킨다.

```python
# tests/evaluation/test_retry_diff.py — 회차 하나를 짓는 헬퍼
def _round(retry_count, rank=None, *, verdict="insufficient", chunk_ids=None):
    return RetryRound(
        retry_count=retry_count, query=f"질의{retry_count}",
        chunk_ids=["c1"] if chunk_ids is None else chunk_ids,
        rank=rank, real_verdict=verdict, succeeded=True,
    )
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| N=1 의 순위 12 → N+1 이 4 | `접었으면 놓쳤다` | 같음 | 통과 |
| N+1 이 같거나 나쁨(12·20·못 찾음) | `안 도왔다` | 같음 | 통과 |
| N 에서 못 찾다가 N+1 이 9위 | `접었으면 놓쳤다` | 같음 | 통과 |
| 근거 동일이 **마지막 회차** | `못 봤다` · `seen=False` | 같음 | 통과 |
| 한 질의에 동일 회차 둘(`[1,2]`) | 줄이 둘 | 같음 | 통과 |
| 0회차가 *충분* 인데 N=2 가 *불충분* | `would_run_in_production=False` | 같음 | 통과 |
| 끝까지 *불충분* 이고 N=2 | `True` | 같음 | 통과 |
| 도구가 실패한 회차 | `_wants_more` → `None` · `production_stop` → `None` | 같음 | 통과 |

| `--no-record-verdict` | 진짜 판정을 **한 번도 안 부른다** | `calls == 0` | 통과 |
| 회차 수 ≠ `retry_count+1` | `RuntimeError` | 같음 | 통과 |
| 부정 예시만 있는 세트 | 저장소를 열기 전에 `SystemExit` | 같음 | 통과 |

**여섯 번째 줄이 이번에 규칙을 고치게 한 자리다** — 3-1절 참고.

## 3-1. 재는 도중에 규칙을 두 번 고쳤다

**둘 다 «측정이 아니라 짐작이 되는 자리»였다.**

1. **도구가 실패한 회차는 판단 불가다.** `record_tool_call()` 이 실패 시 `retrieved_chunks` 를
   아예 안 건드려, Router 가 그때 본 것은 **앞 회차 근거**이지 0건이 아니다. 그런데 이 도구는
   실패 회차의 `chunk_ids` 를 `[]` 로 적으므로 «0건이면 다시 찾는다»(규칙 5)를 **거꾸로** 읽는다
2. **회차 N 자신의 판정으로 «실사용 회차» 를 세면 안 된다.** 그 판정이 답하는 것은 *N 다음으로
   갔을까* 이고, 물어야 할 것은 *N 에 **닿았을까*** 다 — 닿으려면 0~N-1 이 전부 *불충분* 이어야
   한다. 고치기 전 규칙은 **닿지도 않았을 회차를 실사용으로 셀 수 있었다**

**둘째 것이 이번 실행의 결론을 바꿀 수 있었다.** 저장된 원자료(회차별 `real_verdict`·`succeeded`)로
새 규칙을 다시 먹여 보니 **수치는 같았다**(둘 다 0 · 판단 불가 0). 원자료는 안 건드렸고, 파생값만
다시 계산했다:

```python
from evaluation.retry_diff import RetryRound, RetryRun, pair_rows, summarize
runs = [RetryRun(..., rounds=[RetryRound(**rd) for rd in r["rounds"]]) for r in saved["runs"]]
print(summarize(runs, pair_rows(runs)))
# {'unchanged_rounds': 26, 'paired': 10, 'unseen': 16, 'helped': 0, 'no_help': 10,
#  'would_run_in_production': 0, 'would_run_unknown': 0}
```

**저장된 JSON 의 `summary`·`pairs` 는 고치기 전 코드가 쓴 것이다**(값은 같다). 원자료를 남겨 둔
덕분에 되짚을 수 있었던 자리라 그대로 둔다.

## 7. 재지 못한 것

- **실사용 회차에서의 근거 동일 — 표본이 여전히 0이다.** 이 코퍼스·이 세트에서는 판정이

  질의**가 필요하다(사람 세트 긍정 18건, 또는 운영 색인)
- **`replace` 모드는 안 쟀다** — `fuse` 하나로만 돌렸다. 재작성 모드가 «어절만 바꾸는» 빈도를
  가를 수 있지만 이번 물음의 축이 아니다
- **HWPX 판은 안 쟀다** — PDF 컬렉션 하나다
- **왜 «이미 1위인 질의»에서 근거가 안 바뀌나** 는 관찰이지 기전이 아니다. 짝지은 10 중 8이
  `1 → 1` 인 것이 그 방향을 가리키지만, 3-B절의 반례(`retries_exhausted` 인데 근거 동일)가 있어
  «이미 답을 찾았을 때만 난다» 로 일반화하면 안 된다. **이 코퍼스에서 제목 가설이 세 번 기각된
  것과 같은 종류의 유혹이다**
