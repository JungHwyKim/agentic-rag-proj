# 판정(verdict)을 화면·질의로그에 이었다 — 배지 넷의 상태와 로그 한 칸

- 검증일: 2026-08-27
- 대상: 화면 배선 (`task_log/2026-08-27-판정-화면배선.md`) · 미커밋
- 비용: **외부 API 호출 없음.** 판정은 `EVALUATOR_MODEL` 이 비어 꺼진 채 돌았고
  `answer_question` 은 전부 모킹이다. `-m integration` 안 돌림

## 1. 확인하려 한 것

**"규칙이 도는가"** 쪽이다. 임계값을 정하는 회차가 아니다.

1. `Answer.verdict` 의 네 상태(없음 / `sufficient` / `insufficient` / `failed`)가 화면 조각에서
   **각각 무엇을 그리는가** — 특히 *충분* 과 *꺼짐* 이 둘 다 "줄 없음" 인지
2. 모델 사유가 **`title` 밖으로 새지 않는가**
3. `query_log` 레코드의 칸 집합이 계약대로 일곱인가, 판정이 꺼졌을 때 `verdict` 가 `null` 인가

## 2. 가상 데이터

무엇을 고립시켰나: **`Answer.verdict` 한 축만** 바꾼 네 변종이다. 질문·답변·근거 청크는 전부
같게 두고 verdict 만 갈았다 — 배지 유무가 다른 것(근거 수·캐시 여부)에서 오지 않는다는 것을
보이려면 나머지가 고정돼야 한다.

`tests/conftest.py` 의 생성 방식을 쓸 자리가 아니다(파일이 아니라 `Answer` 객체가 입력이다).
그래서 스키마 객체를 직접 만들고 라우트를 통해 렌더했다.

```python
# scratchpad/probe_verdict.py — 저장소에 아무것도 안 쓴다
# QUERY_LOG_ENABLED=false 로 질의 로그를 끄고 ORIGINALS_DIR 을 임시 폴더로 돌린다
# (둘 다 기본값이 PROJECT_ROOT 아래라 안 돌리면 개발자 파일에 샌다)
import os, tempfile
os.environ["QUERY_LOG_ENABLED"] = "false"
os.environ["ORIGINALS_DIR"] = tempfile.mkdtemp()

CHUNK = RetrievedChunk(
    chunk_id="계약서.pdf:0007", document_id="계약서.pdf", text="제12조 …",
    metadata={"source_name": "계약서.pdf", "page": 4}, dense_score=0.812,
)
REASON = "근거가 기입용 빈 서식이다"
CASES = {
    "verdict 없음(꺼짐/캐시)": None,
    "sufficient":   EvaluatorVerdict(verdict="sufficient",   reasoning="충분하다"),
    "insufficient": EvaluatorVerdict(verdict="insufficient", reasoning=REASON),
    "failed":       EvaluatorVerdict(verdict="failed", reasoning="판정을 얻지 못했습니다"),
}
for label, verdict in CASES.items():
    answer = Answer(query="질문", text="답변", sources=[CHUNK], verdict=verdict)
    with patch("backend.app.api.routes.query.answer_question", return_value=answer):
        body = _client().post("/api/v1/query", data={"query": "질문"}).text
    # badge-row verdict-* 조각을 잘라 클래스·사유 위치·문구를 센다
```

기대는 돌리기 전에 적었다(설계에서 정한 것 그대로다).

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `verdict` 없음 | 배지 없음 | 배지 없음 | 통과 |
| `sufficient` | 배지 없음 | 배지 없음 | 통과 |
| `insufficient` | 배지 · `verdict-insufficient` · 사유는 title 만 | 배지 · `verdict-insufficient` · title만 · "충분하지 않다" | 통과 |
| `failed` | 배지 · `verdict-failed` · 사유는 title 만 | 배지 · `verdict-failed` · title만 · "판정하지 못했습니다" | 통과 |

**둘째 행이 이 표의 요점이다** — *충분* 과 *꺼짐* 이 화면에서 **같아 보이는 것이 의도**다.
그 대가를 알고 고른 것이고(면담 라운드 1), 가른 근거는 캐시 배지의 *"빈 배지가 남으면
사용자는 그 기능이 켜져 있다고 읽는다"* 다.

`query_log` 쪽은 pytest 가 잠갔다(5절) — 칸 집합 일곱 · 꺼졌을 때 `null` · `reasoning` 미포함.

- **혼동행렬** — `56fb382` 로 `hbas-06` 이 정답 쪽으로 돌아와 세트가 **정답 21 · 부정 22** 다.
  기존 표(K=5 28/43 · K=10 30/43)는 20/23 분해로 잰 값이라 낡았다. 다시 재는 것은
  `.cache/evaluator` 가 살아 있으면 사실상 무료지만 **이번 회차의 축이 아니다**
- **기본 pytest 가 실제 임베딩을 만든다 (선재 · 원인 미확정)** — 이번 변경과 무관하지만
  재는 동안 걸려서 여기 남긴다.

  | 잰 것 | 값 |
  |---|---|
  | 전체 pytest 뒤 `.cache/embedding` | 1983 → **1990** (+7) |
  | 그 벡터의 차원 | **1024** (= KURE-v1). 실수값이라 가짜가 아니다 |
  | 임시 캐시 폴더로 돌린 전체 실행 | **7건** 재현 (매 실행) |

  | 폴더별 단독 실행(`tests/*/`·최상위 파일, 임시 캐시 폴더) | 캐시 **전부 0건** |
