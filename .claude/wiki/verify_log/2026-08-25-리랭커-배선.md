# 리랭커 배선 — 계약이 도는가 (품질은 아직 안 쟀다)

- 검증일: 2026-08-25
- 대상: Phase 3 리랭커 구현 (`task_log/2026-08-25-리랭커-배선.md`)
- 비용: **외부 API 호출 없음.** 두 구현체 모두 가짜로 갈아끼워 돌렸다 —
  OpenAI 는 `_make_client()`, 로컬은 `_load_model()` 이 그 이음새다

## 1. 확인하려 한 것

**"규칙이 도는가" 다. "리랭커가 값을 하는가" 는 이 회차에서 안 쟀다.**

가르는 이유가 있다 — 뒤엣것은 실파일 색인 + 유료 실행이 필요하고
(`plan_log/검색-생성.md` 5회차의 2×2 비교표), 그 표는 **아직 한 칸도 안 찼다.**
여기서 답하는 것은 넷이다.

1. `reranker=None` 이면 예전과 글자 그대로 같은가 (대조군이 안 움직이는가)
2. 리랭커가 `top_k` 가 아니라 **후보 풀**을 보는가
3. 응답이 부족·손상일 때 **통째로 버리고** RRF 순서로 내려가는가
4. 기본 pytest 가 키도 네트워크도 없이 통과하는가

## 2. 가상 데이터

무엇을 고립시켰나: **후보의 순위 하나만** 바꾼다. 저장소·임베더·BM25·모델이 전부 가짜라
검색 품질이 결과에 안 섞인다.

핵심 탐침은 *"`top_k` 밖의 후보를 리랭커가 되살리는가"* 다. 후보 60개를 만들고 30번째에만
높은 점수를 주면, 리랭커가 `top_k=10` 만 봤다면 그 후보는 결과에 못 온다.

```python
# tests/retrieval/test_rerank.py 에서 그대로 발췌
store = FakeStore([_result(f"c{i}", 1.0 - i / 100) for i in range(60)])
reranker = FakeReranker({"c29": 99.0})          # 30번째 후보만 높은 점수

hits = retrieve("질의", store=store, embedder=FakeEmbedder(), top_k=10,
                reranker=reranker, config=RetrievalConfig(candidate_k=50))
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `reranker=None` · dense 만 | 저장소 점수 순 그대로 · `rerank_score` 전부 `None` | 같음 | 통과 |
| `reranker=None` · 저장소 `top_k` | `[5]` (안 넓힌다) | `[5]` | 통과 |
| `reranker` 있음 · 저장소 `top_k` | `[5, 50]` (`candidate_k` 로 넓힌다) | `[5, 50]` | 통과 |
| 30번째에만 높은 점수 · `top_k=10` | `c29` 가 1위 · 리랭커가 본 후보 50개 | 1위 `c29` · 50개 | 통과 |
| 항목 수 부족 (`2` 중 `1`) | RRF 순서 유지 · `rerank_score` 전부 `None` · 경고 1 | 같음 | 통과 |
| 깨진 JSON / `None` / 자리 중복 / 범위 밖 `i` / 점수가 문자열 | 5건 모두 폴백 · 예외 없음 | 같음 | 통과 |
| API 예외(`RuntimeError`) | 폴백 · 경고에 원인 문자열 | `"503"` 포함 | 통과 |
| 키 없음 | 호출 안 함 · 경고 | `OPENAI_API_KEY` 경고 | 통과 |
| 후보 1개 | 호출 안 함 | `client.calls == []` | 통과 |
| 못 쓸 응답 두 번 | 캐시 안 함 → 호출 2회 | 2회 | 통과 |
| 쓸 만한 응답 두 번 | 캐시 → 호출 1회 · `cache_hits=1` | 1회 | 통과 |
| 로컬 CE 점수 `[1.0, 9.0]` | 순서 뒤집힘 · `reranked=2` · `api_calls=0` | 같음 | 통과 |
| 로컬 모델 적재 실패 3회 질의 | `_load_model` 1회만 호출 · 경고 1건 | 1회 · 1건 | 통과 |
| 로컬 점수 개수 불일치 | 통째로 버림 | 같음 | 통과 |
| 동점 `[5.0, 5.0]` | 들어온(=fused) 순서 유지 | 같음 | 통과 |
| 프롬프트 버전 `v1` vs `v2` | 캐시 salt 가 다름 | 다름 | 통과 |

**가상으로 못 답하는 것**: 위 어느 줄도 *"리랭커가 검색을 좋게 하는가"* 를 말하지 않는다.
가짜 점수는 내가 정한 값이라 **자기 확인**이다.

## 5. 판정

- **의도한 변화** — 위 2절 전부. 특히 *동등성*(`reranker=None` 이 예전과 같다)과
  *풀을 먹는가*(30번째 후보 회수) 둘이 이 회차의 계약이다
- **의도한 변화** — skip 2건 신설. 새 로컬 리랭커 프로필이 `rerank_device` 를 빠뜨리면
  실패하는 검사이고, 지금은 해당 프로필이 하나(`local`)라 나머지 둘에서 건너뛴다
- **회귀 아님 (한 번 회귀로 오인했다)** — 첫 전체 실행이 `5 failed` 였다.
  `test_indexing_real.py::test_every_chunk_finds_itself` 넷과
  `test_indexing_pipeline.py::test_collection_name_is_reported` 하나이고, 원인은
  `shapes (103,1024) and (8,) not aligned` — **저장 벡터 1024차원(KURE) vs 질의 벡터 8차원**
  이다. 그 실행이 35분 걸렸고 stderr 에 `Loading weights: 391/391` 이 찍혔다.
  **다른 세션이 그 35분 동안 `tests/conftest.py` 를 고쳤고**(`_embedding` 에
  `embedding_model="text-embedding-3-small"` 추가 — provider 만 박으면 모델 이름이 로컬
  기본값으로 남는 앞뒤 안 맞는 설정이 된다), 내 실행이 **고치기 전 상태를 스냅샷으로 잡았다.**
  같은 트리에서 다시 돌리니 `1062 passed` 이고 **99초**다. 35분 → 99초가 그 진단의 근거다

## 7. 재지 못한 것

- **리랭커의 검색 품질** — 2×2 비교표(`plan_log/검색-생성.md` 5회차)가 **한 칸도 안 찼다.**
  절차는 `evaluation/README.md` 의 「리랭커를 재려면」에 있다
- **KURE 위 후보 풀 50의 상한과 "풀 밖" `query_id`** — 0단계이고 무료인데 아직 안 돌렸다.
  기존 상한 0.883 은 **baseline 임베딩** 위 값이라 지금 바닥에서 다시 서야 한다
- **로컬 cross-encoder 의 CPU 지연** — 후보 수에 선형인데 **한 번도 안 쟀다.** 가짜 모델은
  즉시 답하므로 위 2절이 이 값을 전혀 말해주지 않는다. 화면에 못 쓸 만큼 느리면 그 사실
  자체가 비교표의 결과다
- **한국어 cross-encoder 모델 비교** — `BAAI/bge-reranker-v2-m3` 는 **탐침값**이고
  `Dongjin-kr/ko-reranker` 와 견줘본 적이 없다
- **유료 갈래의 실제 청구** — E1·E3 이 사용자 승인 대기다. 리포트 `usage.rerank_tokens` 로
  읽도록 배선은 해 뒀다. **다만 캐시가 이 값을 가린다** — 같은 (질의, 후보 집합)을 다시
  돌리면 API 를 안 탄다. 비용·실패 경로를 볼 때는 캐시에 없는 입력으로 재거나
  `.cache/rerank` 를 비운다(다른 세션이 그림자 색인 실패를 만들려다 임베딩 캐시가 적중해
  성공해 버린 사례가 있다)
- **혼자 못 서는 질의에서의 리랭커** — `qa_set` 질의는 사람이 문서를 앞에 두고 던진 것이라
  전부 혼자 선다. 앞말 없이 도착해 지시어가 안 풀리는 축은 **이 세트에 아예 없고**, 리랭커는
  `(질의, 청크)` 를 함께 보므로 그 어려움을 그대로 떠안는다. 여기서 나올 수치는
  *"혼자 서는 질의에서의 이득"* 이다 (`evaluation/README.md` 「리랭커를 재려면」 8절)
