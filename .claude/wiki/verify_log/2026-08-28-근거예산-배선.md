# 예산으로 자른 근거가 생성까지 가는지 잰다 — 「죽은 설정」이 살아났다

- 검증일: 2026-08-28
- 대상: `task_log/2026-08-28-근거예산-배선.md` (미커밋)
- 비용: **외부 API 호출 없음** · `-m integration` 미실행 · `.qdrant` 미개방 · 서버 미기동

## 1. 확인하려 한 것

**「규칙이 도는가」뿐이다. 정할 임계값이 없다.** 이번 작업은 `context_budget_chars` 의 *값*을
정하는 것이 아니라 **있는 손잡이를 배선하는 것**이라, 잴 것은 «자른 목록이 생성까지 가나»
하나다(값을 정하는 것은 미결로 남아 있다 — `agent/context.py` 의 *"자를 값을 아직 안 쟀다"*).

가설: `step_generate()` 가 `final_context` 는 잘라 만들면서 생성기에는 자르지 않은
`retrieved_chunks` 를 넘긴다. 그러면 ① 예산이 죽은 설정이고 ② 상태에 적힌 근거와 모델이
실제로 본 근거가 갈린다.

## 2. 가상 데이터

무엇을 고립시켰나: **근거 3건을 고정하고 예산 한 축만 바꿨다.** 청크 내용은 배선에 아무
영향이 없어 `_loop_stubs.chunk()` 의 기본 본문(5자)을 그대로 썼다 — 예산을 5로 두면 정확히
한 건이 남는다.

```python
from _loop_stubs import QUERY, StubEvaluator, StubGenerate, StubRetriever, chunk
from rag_pipeline.agent.loop import run_agent_loop

generate = StubGenerate()          # 받은 근거의 chunk_id 를 회차마다 기록한다
three = [chunk("c1"), chunk("c2"), chunk("c3")]

state = run_agent_loop(
    QUERY,
    retriever=StubRetriever(chunks=three),
    evaluator=StubEvaluator("sufficient"),
    generate=generate,
    context_budget_chars=5,        # 청크 하나 분량
)
print(generate.chunk_ids, state.final_context, [c.chunk_id for c in state.retrieved_chunks])
```

**기대를 먼저 적고 돌렸다.**

| 입력 | 기대 | 고치기 전 | 고친 뒤 | 판정 |
|---|---|---|---|---|
| 예산 5 · 근거 3건 → 생성기가 받은 것 | `[["c1"]]` | **`[["c1","c2","c3"]]`** | `[["c1"]]` | 의도한 변화 |
| 같은 회차 → `final_context` | `c1` 만 | `c1` 만 | `c1` 만 | (원래 맞았다) |
| 같은 회차 → `retrieved_chunks` | `c1,c2,c3` 그대로 | 그대로 | 그대로 | 회귀 없음 |
| 예산 없음 → 생성기가 받은 것 | `[["c1","c2","c3"]]` | 3건 | 3건 | **동작 불변** |
| 그래프 경로 · 예산 1 | while 과 같은 상태 · `답변(0건)` | **`답변(1건)`** | `답변(0건)` | 의도한 변화 |

**두 번째 줄이 이 회차가 잰 것의 핵심이다** — `final_context` 는 **원래부터 맞았다.**
틀린 것은 생성 입력이라, `final_context` 만 보는 검사로는 **원리적으로 못 잡는다.**

**그래프 축은 `StubGenerate` 가 답변에 근거 수를 싣는 것이 이음새다**(`답변(N건)`).
그래서 상태 비교 하나로 «두 경로가 같은 목록을 봤나» 까지 걸린다 — 이 이음새가 없으면
`_comparable()` 이 `final_context` 만 보고 통과시킨다.

**「실패할 수 있었나」를 먼저 확인했다.** 고치기 전 코드에 테스트를 얹어 돌렸더니
**4 failed, 83 passed** 다(`test_budget_trims_what_the_generator_sees` + 그래프 3 시나리오).
이 확인을 안 했으면 이 테스트들이 배선을 재는지 `select_within_budget()` 을 다시 재는지
갈리지 않았다 — 그쪽은 `tests/agent/test_context_builder.py` 가 이미 잠갔다.
