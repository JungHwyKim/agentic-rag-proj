## 2. 가상 데이터

무엇을 고립시켰나: **두 표 사이에 한글 본문이 있는가 하나만** 바꿨다. 열 수·좌우 끝·헤더
내용·행 구성은 두 변종이 완전히 같다 — 그래서 결과 차이는 그 한 축에서만 온다.

`tests/conftest.py` 에 픽스처로 승격했다(`pdf_page_crossing_table_file` ·
`pdf_separate_tables_file`). 생성 코드는 이렇다.

```python
_CROSSING_HEADER = ["구분", "항목", "내용"]


def _draw_ruled_table(page, top, cells, left=72.0, col_w=140.0):
    row_h = 28.0
    cols, rows = len(cells[0]), len(cells)
    for r in range(rows + 1):
        y = top + r * row_h
        page.draw_line((left, y), (left + cols * col_w, y))
    for c in range(cols + 1):
        x = left + c * col_w
        page.draw_line((x, top), (x, top + rows * row_h))
    for r, row in enumerate(cells):
        for c, value in enumerate(row):
            if value:
                _write_korean(page, (left + c * col_w + 8, top + r * row_h + 19), value, size=11)


def _build_two_page_table_pdf(path, separator):
    document = pymupdf.open()

    first = document.new_page()
    _draw_ruled_table(first, 560.0, [
        _CROSSING_HEADER, ["가 영역", "첫째 항목", "첫째 내용"], ["가 영역", "둘째 항목", "둘째 내용"],
    ])
    _write_korean(first, (280.0, 800.0), "- 1 -", size=10)   # 쪽 번호: 한글이 없다

    second = document.new_page()
    if separator is not None:
        _write_korean(second, (72.0, 90.0), separator, size=12)
    _draw_ruled_table(second, 120.0, [
        _CROSSING_HEADER, ["", "셋째 항목", "셋째 내용"], ["나 영역", "넷째 항목", "넷째 내용"],
    ])

    document.save(str(path))
    document.close()
    return path
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| `separator=None` (사이에 쪽 번호만) | 표 리전 1개 | 1개 | 통과 |
| 같은 입력, 행 수 | 3 + 3 − 되풀이 헤더 1 = **5행** | 5행 | 통과 |
| 같은 입력, 2쪽 첫 데이터 행의 빈 첫 열 | `가 영역` 으로 채워짐 | `가 영역` | 통과 |
| 같은 입력, 그 다음 행의 첫 열 | `나 영역` — **값이 있으면 안 덮는다** | `나 영역` | 통과 |
| 같은 입력, 합쳐진 리전의 `blob` | `None` | `None` | 통과 |
| 같은 입력, `metadata["page_end"]` | `2` | `2` | 통과 |
| `separator="2. 다음 절 제목입니다."` | 표 리전 **2개**(안 합쳐짐) | 2개 | 통과 |
| 같은 입력, 각 표의 행 수 | 3행 · 3행 | 3 · 3 | 통과 |
| 같은 입력, `page_end` | 둘 다 없음 | 둘 다 `None` | 통과 |

**쪽 번호 줄(`- 1 -`)이 픽스처에 꼭 있어야 한다.** 실파일에서 참 연속 4건 사이에 있던 것이
정확히 이것뿐이라, 이 줄이 없으면 "한글이 없는 블록은 안 센다"는 부분이 발화하지 않는다.

### 3-1. 두 규칙의 오검출·미검출 (표본 11쌍)

후보는 PDF 5개에서 **쪽을 가로지르는 인접 표 쌍** 중 열 수 동일 + 좌우 끝 ±2pt 를 만족하는
것 전부다. 정답은 HWPX 판의 행 수로 잡았다.

| 규칙 | 검출 | 오검출 | 미검출 |
|---|---:|---:|---:|
| 헤더 반복 + x ±2pt + 열 수 (7회차 유력안) | 5 | 4 | 3 |
| 사이에 한글 텍스트 블록 0 + x ±2pt + 열 수 | 4 | **0** | **0** |

쌍별 원자료. `A아래`/`B위` 는 두 리전 사이에 낀 텍스트 블록 수이고 괄호 안이 한글을 가진 것이다.

```
정답  문서       쌍        헤더반복  A아래(한글)  B위(한글)  새 규칙
참    시행령      13->14    False     1 (0)       0 (0)     병합
참    시행령      24->25    True      1 (0)       0 (0)     병합
참    학교기록물   23->24    False     1 (0)       0 (0)     병합
참    학교기록물   30->31    False     1 (0)       0 (0)     병합
거짓  시행령       8->9     False    13 (12)      0 (0)     제외
거짓  2026중등    26->27    False     2 (1)       1 (1)     제외
거짓  AI가이드      4->5     False     1 (0)       3 (3)     제외
거짓  AI가이드    13->14    True     11 (10)      4 (4)     제외
거짓  AI가이드    14->15    True     11 (10)      4 (4)     제외
```

참 4건 사이에 있는 것은 전부 쪽 번호 하나다 — `- 13 -`·`- 24 -`·`- 19 -`·`- 26 -`,
**6자에 한글 0자.** 거짓 7건은 최소 한글 블록 2개(2026중등 12자·20자)를 갖는다.

기하 띠 안을 기각한 근거도 같은 표본에서 나왔다.

```

                     → 틈 1.0%p
```

### 3-4. `page_end` 가 청크까지 흐르는가

시행령 PDF 를 `split()` 까지 태우니 청크 108개 중 쪽을 넘긴 것이 20개이고, 그중 **표 청크
10개가 `p13->14` · `p24->25`** 다. 병합 전에는 표 청크에 `page_end` 가 하나도 없었다
(HWPX 만 그 키를 실었다).
