## 1. 확인하려 한 것

넷이고, **셋은 「규칙이 도는가」이고 하나는 「우리 이해가 맞는가」다.**

1. RAGAS 지표 셋이 **정말 `reference` 를 필수 칸으로 받나** — 이름을 지어냈으면 유료 판이
   통째로 헛돈다
2. `AnswerCorrectness` 가 **성분 둘의 가중합인가** — 계획 §3 이 *"한 판은 세 지표를 다 돌려
   대조하고, 맞으면 이후 성분 둘만 돌리고 합은 계산한다"* 로 유료 절감을 걸어 둔 자리다
3. 재료가 **골든을 싣고 갈래를 가르나** — 부정 25와 pending 1을 한 칸에 담으면 「17/18」이
   재료에서 안 보인다
4. **도장이 안 깨졌나** — 이번 변경은 세트 스키마를 안 건드리므로 `--check` 가 **글자 그대로**
   같아야 한다. 달라지면 export 가 세트를 건드린 것이다

## 2. 가상 데이터

무엇을 고립시켰나: **저장소도 세트 파일도 없이 `build_material()` 의 판정만.**
`FakeStore`(순서를 일부러 뒤집어 돌려준다)와 `qa_for()`(세트를 손으로 짓는다)로 축 하나씩만
흔들었다. 실파일로는 «골든이 빈 긍정» 이 지금 `hsih-10` 하나뿐이라 갈래를 못 가른다.

```python
# tests/evaluation/test_ragas_export.py 의 헬퍼 — 긍정에는 골든이 기본으로 차고
# 부정은 빈 채로 둔다(`validate_items()` 가 금지하는 자리라 그 모양이 실제와 같다)
def qa_for(rows: list[dict], **reference_by_id: str) -> dict[str, QAItem]:
    out: dict[str, QAItem] = {}
    for r in rows:
        qid = r["query_id"]
        answerable = r.get("answerable", True)
        default = f"{qid} 의 산문 골든입니다." if answerable else ""
        out[qid] = QAItem(
            query_id=qid,
            query=r["query"],
            source_doc=r.get("source_doc", "안내서"),
            gold_spans=[],
            answerable=answerable,
            reference=reference_by_id.get(qid, default),
        )
    return out

# 갈래를 가르는 입력 — 부정 하나 · 라벨 안 찬 긍정 하나 · 라벨 찬 긍정 하나
rows = [
    row("neg",  query="부정",    answer="문서에서 찾지 못했습니다.", chunk_ids=["c1"], answerable=False),
    row("pend", query="라벨 전", answer="답",                        chunk_ids=["c2"]),
    row("ok",   query="라벨 참", answer="답",                        chunk_ids=["c3"]),
]
made, dropped = build_material(payload(rows), store, "r.json", qa_for(rows, pend=""))
```

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 부정 1 · pending 1 · 정상 1 | `negative=[neg]` · `reference_pending=[pend]` · self `[ok]` | 같음 | 통과 |
| 세트에 골든이 실림 | `made[0].reference == "공포 후 6개월입니다."` | 같음 | 통과 |
| 리포트에 있는데 세트에 없는 질의 | `SystemExit` + "짝이 아닙니다" | 같음 | 통과 |
| 대조군 (긍정 둘) | 골든만 남의 것 · 질문·답변·근거는 자기 것 · `reference_from` 참 | 같음 | 통과 |
| 골든 없는 행이 짝 후보 | 대조군을 아예 안 만든다 | `[self]` 하나 | 통과 |
| 근거가 겹치는 짝 | 대조군 0 | 0 | 통과 |
| 짝이 없는 행 | 대조군 0 | `[self]` | 통과 |
| 재료 meta | `control_axis == "reference"` | 같음 | 통과 |
| **답할 수 있는데 기권한 행** | 재료에 남고 `abstained=True` · 골든도 남는다 | 같음 | 통과 |
| 인용 붙은 기권 (`abstained: false` 저장) | 다시 판정해 `True` | `True` | 통과 |
| 저장된 `abstained: true` 인데 실제 답변 | 다시 판정해 `False` | `False` | 통과 |
| 절대 경로 | 우리가 쓴 칸에 `:\`·`:/` 0건 | 0건 | 통과 |
| `check_readable` — 옛 조합 | 통과 (`control_axis` 없음 = 옛 재료) | 통과 | 통과 |
| `check_readable` — 다른 지표 | `SystemExit`, 두 이름이 사유에 | 같음 | 통과 |
| `check_readable` — «남의 골든» 축 | `SystemExit`, "남의 골든" 이 사유에 | 같음 | 통과 |

**한 건이 처음에 실패했고 그것이 제 실수다** — `test_the_material_declares_its_control_axis`

## 3. 실제 데이터

### 3-1. 실제 라이브러리 — 격리 환경 dry-run (유료 0)

`ragas 0.4.3` · python 3.11.9 · `OPENAI_API_KEY` 없음(스크립트가 `False` 를 찍었다).
`evaluate()` 를 안 부르고 클래스와 소스만 읽었다.

| 물음 | 실측 | 판정 |
|---|---|---|
| `ResponseRelevancy` 필수 칸 | `{user_input, response}` | `reference` 를 **안 읽는다** |
| `SemanticSimilarity` 필수 칸 | `{response, reference}` | 이름이 맞다 |
| `FactualCorrectness` 필수 칸 | `{response, reference}` · `mode='f1'` · `atomicity='low'` · `coverage='low'` | 이름이 맞다 |
| `AnswerCorrectness` 필수 칸 | `{user_input, response, reference}` · `weights=[0.75, 0.25]` | 이름이 맞다 |
| 점수 컬럼명 | `metric.name` = `answer_relevancy` / `semantic_similarity` / `factual_correctness` / `answer_correctness` | 유료 판에서 `frame.columns` 로 다시 대조한다 |
| `EvaluationDataset` 이 `reference` 를 받나 | `features() == ['user_input','retrieved_contexts','response','reference']` | 받는다 |
| `get_token_usage_for_openai` 가 임베딩을 세나 | 소스가 `llm_result.llm_output["token_usage"]` 만 읽는다 | **안 센다** |

**`AnswerCorrectness` 는 성분 둘의 가중합이 아니다.** `_ascore` 가
`np.average([f1_score, similarity_score], weights=self.weights)` 인데,

```
similarity_score  ← AnswerSimilarity(embeddings=self.embeddings)
                    (SemanticSimilarity 와 같은 모듈 ragas.metrics._answer_similarity 의 형제.
                     `AnswerSimilarity is SemanticSimilarity` 는 **False** — 별칭이 아니다)
f1_score          ← StatementGeneratorPrompt + CorrectnessClassifier (TP/FP/FN → fbeta_score)
FactualCorrectness ← ClaimDecompositionPrompt + nli_prompt
```

즉 factual 쪽 **분해기가 다른 물건**이다. 클래스 소스에 `FactualCorrectness` 라는 문자열이
한 번도 안 나온다.

|---|---|---:|---:|---:|---|
| `hbas-06` | 2/2 | 0.310 | 0.539 | 0.576 | 검출 |

**후보는 `hsch-10` 하나이고, 읽으니 RAGAS 가 우리 자를 안 이겼다.**
`must_values=['별표1']` 인데 답변에 `별표1` 도 등록번호 표기방법도 **아예 없다** — 어휘 대조가
**옳게** 놓친 것이고 FC 0.400 도 함께 깎였다. 즉 «바꿔 쓴 표현을 메웠다» 가 아니다.

> 질의 — 전자결재 시스템을 안 거치고 비전자로 생산된 문서는 어떻게 등록·보존하나요?

> 답변 — …반드시 등록해야 하며, 원본은 기관에서 보존·관리해야 합니다…(등록번호 이야기 없음)

**규칙의 글자대로는 기각이다.** 다만 그 기각의 강도를 정하는 것은 분모 **4**이고,
CLAUDE.md 가 이미 *"값 축의 분모가 6이다 … 수치를 인용하면 안 된다"* 로 적어 둔 자리다.
**«RAGAS 가 아무것도 안 더한다» 와 «더하는지 볼 표본이 없다» 를 이 판은 못 가른다.**

#### 규칙 밖에서 나온 것 — **FC 가 기권에 0.670 을 준다**

`hsch-12` 는 답변이 `문서에서 찾지 못했습니다.` 인데 **FC 0.670** 이다. 골든이 부분 답이라
*"…무단 파기·유출에 대한 구체적인 처벌 내용은 **제시되어 있지 않습니다**"* 로 **없음을
