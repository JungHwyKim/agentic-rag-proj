## 1. 확인하려 한 것

물음이 둘이고 **답하는 데이터가 다르다.**

- **규칙이 도는가** — 실패가 제3의 상태로 나가나, 정상 경로 둘을 건너뛰나, 캐시가 본판과
  대조군을 가르나, 회계 게이트가 어긋남을 지표보다 먼저 소리 내나 → **가상**
- **자[尺]가 실제로 무엇을 잡는가** — 답이 코퍼스에 없는 질의에서 모델이 무엇을 하고,
  그것을 이 자[尺]가 어떻게 읽는가 → **실파일(운영 코퍼스 색인 + 사람 검수 세트)**

임계값은 정하지 않는다. 이 도구에 정할 임계값이 없다 — 인용 정합성은 *번호가 가리키는
청크가 정답을 담나* 라 의미의 경계이고, 지지 판정은 이산 라벨이다.

## 2. 가상 데이터

번에 하나씩만 바꿨다. 키가 없어도 전부 돈다.

**「실패할 수 있었나」를 테스트마다 물었다.** 통과가 보장된 관측은 잰 것이 아니므로,
제품 코드에 변이를 넣고 테스트가 빨개지는지 확인했다. 아래가 그 하네스 전문이다.

        'return SupportVerdict(verdict="unsupported", reasoning="판정을 얻지 못했습니다")',
    ),
    "부정 예시에도 인용 분모를 준다": (
        "        row.cited_gold_hits = None\n        return",

        "        if not other.chunk_ids or other.chunk_ids == me.chunk_ids:",
        "        if not other.chunk_ids:",
    ),
    "범위 밖 번호를 인용 분모에 넣는다": (
        "    inside = [n for n in row.cited if 1 <= n <= len(chunks)]",
        "    inside = list(row.cited)",
    ),
    "생성 회계 검사를 뺀다": ("    if generated != expected_generations:", "    if False:"),

try:

finally:

### 3-A. 회계 게이트 — **처음 돌린 판은 스스로 무효를 선언했다**

읽는 순서를 안 뒤집었다. 지표보다 게이트가 먼저다.

```
[회계 게이트]
  판정 호출 60 · 캐시 0 · 토큰 156336 · 생성 43
  ✗ 음성 대조군이 2건에서 supported 로 답했습니다 ['hsih-05', 'hbas-12'] — 채점자가
    남의 근거로도 «뒷받침된다» 고 말하므로 이 회차의 지지 수치는 못 씁니다
  → 아래 지표를 실력으로 읽지 않는다
```

**원인은 채점자가 아니라 기권 규칙이었다.** 두 답변이 글자 그대로 이것이다.

```
문서에서 찾지 못했습니다. [1][2][3][4][5]
```

`is_abstention()` 이 `text.strip() == NO_EVIDENCE_ANSWER` 로 재는데 **인용 번호가 붙어
일치하지 않아** 판정 대상이 됐다. *"못 찾았습니다"* 는 **어떤 근거로도 뒷받침되므로** 음성
대조군이 `supported` 를 내는 것이 당연하다. 즉 게이트는 제대로 울렸고, 가리킨 곳이 채점자가
아니었을 뿐이다.

**빈도는 2/43(4.7%)이고 둘 다 부정 예시다.** 기전은 프롬프트 안에 있다 — `SYSTEM_PROMPT`
규칙 2가 *"정확히 이렇게만 답합니다"* 인데 규칙 3이 *"[1], [2] 형식으로 표시합니다"* 라,
모델이 **둘 다** 따랐다.

### 3-B. 고친 규칙으로 다시 낸 수치 — **유료 재실행 없이**

`is_abstention()` 을 *인용 번호를 걷어낸 뒤 완전 일치* 로 고치고, 리포트에 저장해 둔
**원자료(답변 원문 · `chunk_ids` · 판정)** 에 새 규칙을 먹여 다시 계산했다. 30회차가
`retry_diff` 에서 밟은 길이고, 이 도구가 답변 원문을 싣는 이유가 이것이다.

| 기권 (부정 25건) | 11 | **13** | 오분류 2건이 판정으로 샜다 |
