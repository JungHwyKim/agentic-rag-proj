# 근거가 안 바뀐 재시도를 세는 규칙이 도는가

- 검증일: 2026-08-28
- 대상: `task_log/2026-08-28-근거불변-재시도.md` (미커밋) · `plan_log/검색-생성.md` 「다음 승인 단위 A」
- 비용: 단위 테스트는 **외부 API 호출 없음**. **3절 실물 프로브는 유료다**(사용자 승인) —
  다만 **실제로 나간 호출은 생성 1회뿐이다**: 재작성·리랭킹·판정이 **3/3 전부 캐시 히트**였다.
  `-m integration` 은 안 돌렸다

## 1. 확인하려 한 것

**"규칙이 도는가" 하나다. 임계값을 정하는 검증이 아니다** — 이 변경은 제어 흐름 계층에
관측 하나를 얹는 것이라 정할 임계값이 없고, 견주는 축(`chunk_id` 목록이 순서까지 같은가)은
동치 판정이지 문턱이 아니다.

넷을 갈라 물었다.

1. 근거가 그대로인 재시도가 **세어지는가** — 그리고 **접히지 않는가**(흐름이 그대로인가)
2. 근거가 실제로 달라진 재시도는 **안 세어지는가**
3. **도구가 실패한 회차**가 안 세어지는가 (`record_tool_call()` 이 결과를 안 건드려 앞뒤가
   자동으로 같아지는 자리)
4. 첫 검색(`retry_count == 0`)이 안 세어지는가

## 2. 가상 데이터

무엇을 고립시켰나: **가짜 넷으로 외부를 전부 끊고 「검색 결과가 회차마다 달라지는가」한
축만 바꿨다.** 27회차가 만든 `tests/agent/_loop_stubs.py` 를 그대로 쓰고, 거기에 회차마다
다른 목록을 낼 선택 인자 하나만 더했다(기본 동작 불변 — 기존 81건이 그대로 통과한다).

```python
# tests/agent/_loop_stubs.py — StubRetriever 에 더한 것이 이것뿐이다
def __init__(self, *, chunks=None, chunks_per_call=None, rewriter=None, fails=False):
    self._chunks = [chunk()] if chunks is None else chunks
    self._chunks_per_call = chunks_per_call
    ...

# 이번 회차가 낼 목록. `chunks_per_call` 을 안 주면 늘 같은 것이다
def _chunks_for_this_call(self) -> list[RetrievedChunk]:
    if self._chunks_per_call is None:
        return self._chunks
    index = min(len(self.queries) - 1, len(self._chunks_per_call) - 1)
    return self._chunks_per_call[index]
```

**기본값이 「질의와 무관하게 같은 목록」인 것이 요점이다** — 실물에서 재작성이 어투만 바꿨을
때가 정확히 그 모양이고(`verify_log/2026-08-28-재시도루프-langgraph.md` 3절), 그래서 기본
stub 이 곧 이 규칙의 양성 표본이다. 음성 표본만 인자가 필요했다.

네 입력 전부 `run_agent_loop(QUERY, ...)` · `StubRewriter` · `StubGenerate` 이고 아래 축만 다르다.

| 입력 | 기대 | 실측 | 판정 |
|---|---|---|---|
| 같은 목록 · `insufficient` · `max_retries=3` | `evidence_unchanged_at == [1, 2, 3]` · `retry_count == 3` · `stop_reason == "retries_exhausted"` · 검색 4회 | 같음 | 통과 |
| `chunks_per_call=[[c1],[c2],[c3],[c4]]` · `insufficient` | `== []` · `retry_count == 3` | 같음 | 통과 |
| `fails=True` · `last_rewritten` 을 손으로 놓아 재시도 1회 | `== []` · 검색 `[Q, "다시 쓴 질의"]` · `retry_count == 1` | 같음 | 통과 |
| 같은 목록 · `sufficient` (한 방에 끝남) | `== []` · `retry_count == 0` | 같음 | 통과 |

**셋째 입력이 손으로 `last_rewritten` 을 놓는 이유**: `fails=True` 면 1차 검색이 예외로 죽어
`note_retrieval()` 이 아예 안 돌고, 그러면 승급할 질의가 없어 **재시도가 한 번도 안 돈다** —
그 상태로는 `retry_count > 0` 가드가 혼자 막아 `output.success` 가드를 못 잰다. 즉 이 한 줄이
없으면 **테스트가 규약 2를 검증하는 척만 한다.**

**첫 입력의 검색 4회가 「접히지 않았다」의 증거다** — 접었으면 2회에서 끝난다.
