# 2단계 cleaner — 영역별 리뷰 기준

`rag_pipeline/ingestion/cleaner/**` 를 건드린 변경에 적용한다. 공통 규약은 `contracts.md` 에 있다.

이 단계는 코드가 짧아서 리뷰가 쉬워 보이지만, **깨져도 예외가 안 나고 테스트도 안 터지는**
종류의 회귀가 모여 있다. 텍스트가 조용히 나빠지고 임베딩·검색에서 나중에 드러난다.
게다가 여기 규칙은 **본문을 지우는 쪽**으로 움직이므로, 잘못된 규칙 하나가 문서를 훼손한다.

## 규칙이 두 종류다

```
문자 수준 (characters, whitespace)  요소 안의 글자만 고친다. 요소별로 독립
문서 수준 (headers)                 문서 전체를 봐야 판정할 수 있고 요소를 지운다
```

`clean()` 이 **문자 수준을 먼저** 돌린다. 공백만 다른 머리말을 같은 것으로 보려면 정규화가
앞서야 하기 때문이다. 이 순서를 뒤집는 변경은 되돌리게 한다(실측으로는 결과가 같았지만
그건 이 픽스처에서 그랬을 뿐이다).

## 같이 읽어야 하는 곳

| 바뀐 곳 | 같이 읽어야 하는 곳 |
|---|---|
| `characters.py` · `whitespace.py` | `__init__.py` 의 `_text_rules()`·`_clean_element()`, 각각의 `tests/ingestion/cleaner/test_*.py` |
| `headers.py` | `__init__.py` 의 `clean()`, `schemas/document.py` 의 `DocumentMetadata`, `tests/ingestion/cleaner/test_headers.py` |
| `__init__.py` | `pipeline.py` 의 `ingest()`, `schemas/document.py` 의 `Element` |
| 규칙을 추가·변경 | `tests/ingestion/cleaner/test_real.py` — 실측 기대값이 상수로 박혀 있다 |
| `config.py` 의 `CleanerConfig` | `.env.example`, `tests/conftest.py` 의 `offline_config` |

## 1. 단계 계약 (최우선)

`clean()` 은 `ParsedDocument` 를 받아 `ParsedDocument` 를 돌려준다. 이 타입을 바꾸면 `ingest()`
의 순차 합성이 깨지고, 뒤에 splitter/embedding 을 붙일 때 단계를 떼었다 붙였다 할 수 없게 된다.

### 잡아야 할 위반

- `clean()` 이 다른 타입(`list[Element]`, 튜플, dict)을 돌려준다
- cleaner 가 HTTP·FastAPI·외부 API 를 안다. 이 단계는 순수 로컬이고 비용이 0 이다.
  외부 호출이 새로 들어오면 `contracts.md` 2·3절(예외 금지·카운터·상한·캐시)이 전부 적용되므로
  **Critical 로 올리고** 그 규약을 다 지켰는지 따로 센다
- 로더가 해야 할 일(파싱·리전 판별)이 cleaner 로 넘어왔다
- `config` 인자 없이도 동작해야 한다 (`clean(document)` → `CleanerConfig()` 기본값)
- 규칙마다 끄는 설정이 있고 실제로 먹는지. 전부 끄면 **입력을 그대로** 돌려줘야 한다
- **새 문자 수준 규칙을 `_text_rules()` 에 등록하지 않았다** — 함수만 만들고 조립부에 안 넣으면
  아무 데서도 안 불린다. 테스트가 함수를 직접 부르면 통과해버리므로 특히 잘 샌다

## 2. 원본 객체 반환 규약 — 이 영역에서 제일 잡기 어려운 회귀

**세 층 모두가 안 바뀌었으면 인자로 받은 객체를 그대로 돌려준다.**

```
strip_control_chars() / normalize_whitespace()   안 바뀌면 인자로 받은 str 그대로
_clean_element()                                 text·rows 둘 다 그대로면 인자 Element 그대로
clean()                                          바뀐 요소가 0개면 model_copy 를 아예 안 한다
```

상위가 `is` 비교로 변경 여부를 판단하기 때문이다(`_clean_element` 의 `text is element.text`,
`clean()` 의 `before is not after`). 값 비교가 아니라 **동일성 비교**라는 게 핵심이다.

**새 문자 수준 규칙도 이 규약을 져야 한다.** 규칙은 `_clean_element` 안에서 체인으로 엮이므로
(`for rule in rules: text = rule(text)`), 규칙 하나가 항상 새 `str` 을 돌려주면 그 뒤 규칙과
무관하게 체인 전체가 "바뀜"으로 물든다.

### 깨지는 방식

- 규칙 함수가 항상 `"".join(...)` / `re.sub(...)` 결과를 돌려주도록 "단순화"한다 → 내용이 같아도
  새 `str` 객체라 `is` 가 False → 모든 요소가 바뀐 것으로 집계된다. **`cleaned_elements` 가
  요소 수만큼 부풀고**, 깨끗한 문서에서도 요소 746개가 통째로 복사된다
- `_clean_element` 나 `clean()` 이 무조건 `model_copy()` 한다 → 같은 결과

**예외가 안 나고 텍스트도 똑같아서 일반 테스트로는 안 잡힌다.** 이걸 잠그는 건 `test_real.py`
의 HWPX 0개 기대값뿐인데, 그 테스트는 `tests/fixtures/` 가 없으면 skip 된다. 즉 이 규약을
건드리는 변경은 **fixtures 없는 환경에서 전부 통과한다.** 그래서 리뷰에서 봐야 한다.

각 규칙 함수 마지막 줄(`return text if cleaned == text else cleaned`)에 달린 주석을 지우는
변경도 같이 지적한다 — 그 한 줄이 이 규약의 유일한 설명이다.

## 3. 표의 두 표현을 함께 고치는가

표 요소는 같은 내용을 `text`(마크다운)와 `metadata["rows"]`(2차원 셀 배열) 두 곳에 갖는다.
**한쪽만 고치면 같은 표의 두 표현이 어긋난다**(실측: AI 가이드 PDF 에서 `text` 202개 요소 ·
`rows` 셀 26개가 함께 고쳐졌다).

- 새 문자 수준 규칙은 `_text_rules()` 에 넣기만 하면 `_clean_rows` 에도 자동으로 실린다.
  **규칙을 `_clean_element` 안에서 직접 부르는 형태로 우회했으면** `rows` 가 빠지므로 지적한다
- `_clean_rows` 는 `list[list[str]]` 이 아닌 `rows` 를 만나면 `None` 을 돌려주고 조용히 넘어간다.
  이 방어를 지우면 로더가 다른 모양으로 넣은 `rows` 에서 터진다
- `rows` 를 제자리에서 수정(mutate)하지 않는지 본다. 입력 문서를 변형하면 안 된다

## 4. 문자 수준 규칙 — 무엇을 지우고 무엇을 남기나

### characters.py

- 기준은 코드포인트 목록이 아니라 **유니코드 범주** — `Cc`(제어)와 `Cf`(서식).
  개별 코드포인트 하드코딩 목록으로 바꾸는 변경은 후퇴다. `Cf` 에는 U+200B(zero-width space)·
  U+FEFF(BOM)·U+00AD(soft hyphen) 처럼 눈에 안 보이면서 단어를 갈라놓는 문자가 들어간다
- **`_KEEP` 에서 `\n` 을 빼는 변경은 Critical 이다.** 실측 560개가 전부 표 요소에 있는 마크다운
  표의 행 구분자다. 지우면 표가 한 줄로 뭉개진다
- **`\r` 은 지우지 않고 `\n` 으로 바꾼다.** 치환 줄을 지워 `_STRIP_CATEGORIES` 에 맡기면 앞뒤
  줄이 서로 붙는다. 치환이 필터보다 **먼저** 와야 한다는 순서도 본다
- ZWJ(U+200D)가 `Cf` 라 이모지 결합이 쪼개지는 것은 **알고 감수한 것**이다. 지적하지 않는다

### whitespace.py

- `_RUNS` 는 `[ \t]+` 다. **`\s+` 로 넓히는 변경은 Critical** — `\s` 는 `\n` 을 포함하므로 표가
  한 줄로 뭉개진다. characters.py 가 `\n` 을 지키는 것과 같은 이유이고, 여기서 더 새기 쉽다
- 줄 단위로 나눠 처리한 뒤 개행으로 다시 잇는 구조를 통짜 `sub` 로 바꾸는 변경도 같은 사고다
- 빈 셀 마커가 `|  |` → `| |` 로 바뀌는 것은 **알고 감수한 것**이다. 둘 다 유효한 빈 셀이다

## 5. 문서 수준 규칙 — headers.py

여기가 이 단계에서 유일하게 **요소를 지우는** 곳이라 사고의 대가가 제일 크다.

### 판정 기준을 '등장 비율'로 되돌리는 변경 — Critical

`(마지막 쪽 - 첫 쪽 + 1) / 전체 쪽수` 인 **걸친 폭**을 쓴다. "전체 쪽수의 N% 이상에 등장"인
등장 비율은 **한 번 시도했다가 폐기한 안**이다. 되돌리자는 제안이 오면 근거를 요구한다.

이유는 **분모를 못 믿기 때문**이다. 로더가 같은 문서를 HWPX 97쪽 / PDF 28쪽으로 센다
(CLAUDE.md "HWPX 쪽 수를 분모로 쓰지 말 것" 참고). 그래서 등장 비율이 25.8% ↔ 89.3% 로
요동쳤고, 쪽 계산을 고치면 표 머리행 문구가 6.2% → 21.4% 로 뛰어 임계값을 넘었다. 걸친 폭은
분자와 분모가 함께 부풀어 이 오류에 강하다(실측: 진짜 머리말 93.8%/89.3%, 오탐 후보
29.9~45.4%, 임계값 60%).

**쪽 수를 분모로 새로 쓰는 판정이 다른 데서 생기면 같은 이유로 지적한다.**

### 안전장치 넷 — 하나라도 빠지면 본문이 사라진다

1. **문단만 본다** (`_page_first_paragraphs` 가 `ElementType.PARAGRAPH` 로 거른다).
   표를 대상에 넣으면 양식·체크리스트처럼 같은 표가 여러 쪽 반복되는 문서에서 **진짜 데이터
   표가 통째로 지워진다.** 이 필터를 넓히는 변경은 Critical
2. **쪽의 첫 요소인 것만 지운다.** `doomed` 를 `id()` 집합으로 잡는 게 핵심이다 —
   **텍스트 비교로 "단순화"하면 본문 한가운데 나온 같은 문구까지 사라진다**
3. **전부 지워지면 무른다.** `kept` 가 비면 아무것도 안 지우고 `warnings` 에 남긴다.
   이 분기를 지우는 변경은 짧은 문서의 본문을 통째로 날린다
4. **`order` 를 재부여하지 않는다.** 남은 요소의 원본 `order` 를 유지한다 — 계약상 용도가
   정렬 하나뿐이라 연속성이 필요 없고, `elements` 에는 이미 빈틈이 있다(핸들러가 요소를 0개
   만든 자리). 번호를 다시 매기면 앞뒤 단계가 참조하던 값이 조용히 달라진다

### 지운 내역을 어디에 남기나

- **정상 제거는 `removed_texts` 에, 이상 징후는 `warnings` 에.** 둘을 합치는 변경은 지적한다 —
  정상 제거는 파싱 '문제'가 아니라서, 같은 칸에 넣으면 파싱 경고를 보는 쪽이 노이즈에 묻힌다
- 개수만 남기고 **무엇을 지웠는지**를 안 남기는 변경도 지적한다. 개수로는 오탐을 알아차릴 수 없다
- `removed_elements` 와 `cleaned_elements` 는 의미가 다르다(지운 것 vs 고친 것). 한 칸에
  합산하면 두 값을 못 가른다. 둘 다 **누적**(`기존 + 이번`)이라, `= 이번` 으로 바꾸면 규칙이
  늘었을 때 앞 규칙의 집계가 지워진다

## 6. 실측 근거가 있는가

이 단계의 규칙은 **전부 재서 넣었다.** 임계값 60% 도, 제어문자 제거도, 공백 정규화도 픽스처로
세어보고 넣은 것이다. 심지어 폐기한 안(등장 비율 20%)까지 수치로 기각했다.

새 규칙이나 새 임계값에 근거 수치가 없으면 **지적이 아니라 "확인 필요"로 올린다** —
"어느 문서에서 몇 건 나왔습니까, `tests/fixtures/` 로 재봤습니까"라고 묻는다. 근거 없는 규칙은
멀쩡한 텍스트를 조용히 깎아먹고, 깎였다는 사실을 아무도 모른다.

`test_real.py` 의 기대 상수(`AI_GUIDE_PDF_CLEANED_ELEMENTS`, `AI_GUIDE_REMOVED_HEADERS` 등)를
**테스트를 통과시키려고** 고친 흔적이 있으면 반드시 짚는다. 그 값은 사람이 세어 확인한 실측이라,
코드가 아니라 값이 바뀌었다면 파싱 결과가 달라졌다는 뜻이다.

## 7. 설정 3곳

새 설정은 세 곳이 맞아야 한다.

1. `rag_pipeline/config.py` 의 `CleanerConfig`
2. `.env.example`
3. `tests/conftest.py` — 외부 호출을 부르는 설정이면 `offline_config` 에서 꺼야 한다

규칙마다 켜고 끄는 스위치가 하나씩 있다(`remove_control_chars`·`normalize_whitespace`·
`remove_repeated_headers`). 새 규칙을 스위치 없이 넣으면 끌 방법이 없어지므로 지적한다.
임계값 설정(`header_min_pages`·`header_min_span_ratio`)은 **주석에 근거 수치가 붙어 있어야
한다** — 이 저장소의 관례다.

`IngestConfig.cleaner` 는 `content` 와 같은 lazy 프로퍼티다. 테스트에서
`object.__setattr__(config, "_cleaner", CleanerConfig(...))` 로 덮어쓰므로, 이 프로퍼티를
`__init__` 에서 만드는 형태로 바꾸면 기존 테스트 패턴이 깨진다.
