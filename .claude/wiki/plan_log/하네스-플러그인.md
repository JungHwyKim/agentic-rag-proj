# 하네스 플러그인 설계

상태: 구현됨 (1회차 — 저장소 밖 `C:\my-harness`) · **일부 기각 (2회차 — 이 저장소에서 들어내는 것은 되돌렸다)**
관련 기록: [task_log](../task_log/2026-09-10-하네스-플러그인-되돌리기.md)

## 확정된 것

- **이 저장소의 `.claude/hooks|skills|agents` 는 그대로 둔다**(2회차) — 근거: 요청이
  *「다른 프로젝트에서도 쓴다」* 였다. 플러그인은 **여기를 비워야 성립하는 것이 아니다** —
  다른 프로젝트에서 켜면 되고, 여기는 지금까지처럼 `.claude/hooks/` 가 돈다.
  1회차의 «한 벌로 모은다» 는 모델이 목표를 바꿔 읽은 것이지 사용자가 정한 것이 아니었다
- **하네스를 비공개 GitHub 저장소 하나로 뽑고, 그 저장소를 마켓플레이스로 쓴다** — 근거:
  마켓플레이스는 중앙 등록소가 아니라 `marketplace.json` 을 가진 저장소일 뿐이라, 비공개
  저장소에 두면 아무에게도 안 보인다. `claude plugin marketplace add --scope project` 와
  `claude plugin install --scope project` 가 **어느 프로젝트가 무엇을 켰는지를 그 프로젝트
  `.claude/settings.json` 에 글로 남긴다** — 지금은 그 사실이 어디에도 안 적혀 있다
- **플러그인은 셋으로 가르고, 경계는 「설치할지 말지가 갈리는 단위」로만 긋는다** —
  `harness-core`(훅 9 + 기록·도구 스킬 6) · `harness-rag`(RAG 스킬 3 + 에이전트 4) ·
  `quiz`(저장소가 아니라 `~/Documents/면접준비/` 를 읽는다). 근거: `rag-code-review` 는
  `rag_pipeline` 을 17번 지목해 그 폴더가 없는 저장소에서는 가리킬 곳이 없다
- **훅 9개는 한 플러그인에 다 담는다** — 「기록」과 「안전장치」로 쪼개면 `_hookutil.py` 가 두
  벌이 되는데, 그것이 `.codex/hooks/` 를 갈라놓은 그 모양이다. 켜고 끄는 것은 플러그인 경계가
  아니라 설정이 한다
- **프로젝트마다 갈리는 값은 `.claude/harness.json` 한 파일이 답한다** — 테스트 매핑표 22행 ·
  소스 접두사 · 위키 뿌리 · 린트·테스트 명령 · 산문 검사 대상이 훅에서 빠져나온다
- **설정 절이 없으면 그 검사는 안 돈다. 기본값으로 조용히 돌지 않는다** — 근거: 기본값으로
  돌면 남의 저장소 경로로 pytest 를 돌리거나, 반대로 *검사가 도는 줄 알았는데 안 도는* 상태가
  아무 에러 없이 생긴다. 꺼져 있다는 것은 세션에 한 번 알린다(막지 않는다) —
  `prose_style_check.py` 가 이미 쓰는 «막지 않고 알린다» 모양(`exit 0` + `additionalContext`)이다
- **`harness.json` 자신이 `harness_paths` 에 들어간다** — 안 넣으면 그 파일만 고친 세션이
  `task_log_check` 의 기록 대상에서 조용히 빠진다
- **훅의 뿌리를 런타임에 찾는다** — `_hookutil.py` 의 `PROJECT_ROOT = parents[2]` 는 플러그인에서
  저장소가 아닌 곳을 가리킨다(`__file__` 이 플러그인 설치 경로다). `CLAUDE_PROJECT_DIR` →
  훅 입력의 `cwd` → `os.getcwd()` 순으로 찾고 셋 다 실패하면 막지 않는다
- **훅 인터프리터를 프로젝트 venv 에서 떼어낸다** — 훅 9개는 전부 표준 라이브러리만 쓴다(확인함).
  venv 가 필요한 것은 훅이 아니라 훅이 부르는 pytest·ruff 이고, 그것은 `harness.json` 의
  `python` 이 답한다
- **`tests/hooks/` 10파일 2,112줄을 플러그인 저장소로 함께 옮긴다** — 훅과 그 테스트가 갈리면
  «훅의 값어치는 그 테스트가 지킨다」가 깨진다. 대가는 이 저장소의 pytest 가 더 이상 훅을 안
  지키는 것이고, 훅을 고칠 때 플러그인 쪽 pytest 를 돌리는 것이 새 규약이 된다

## 미결

- **`.codex/`·`.agents/` 미러를 어떻게 할지** — [구조-정리.md](구조-정리.md) 1회차 미결이
  그대로 열려 있다. 이번 일이 그 미결의 성질을 바꾼다: `.claude/hooks/`·`.claude/skills/` 가
  비면 미러는 **원본이 없는 사본**이 된다 — 정하려면: 미러를 버릴지, 플러그인에서 생성할지
- **`cost/` 를 플러그인으로 옮길지** — `task_log/2026-08-29-비용로그-핸드오프.md` 가
  *"경계는 테스트로 잠갔지만 실제로 옮겨 본 적은 없다"* 로 열어 둔 것이다. 이번에는 `verify-log`
  스킬이 `harness.json` 의 `cost_report_command` 를 읽고 없으면 비용 절을 건너뛰는 것으로 미룬다 —
  정하려면: 두 번째 프로젝트가 실제로 비용 로그를 쓸 때
- **한국어 게이트 문구를 설정으로 열지** — `plan_interview_check.py` 의 `OPEN_PHRASE`
  ("설계서 작성해줘")와 `plan_log_check.py` 의 `_DESIGN_PHRASES` 는 한국어 전용이다 —
  정하려면: 영어로 쓰는 프로젝트가 생길 때
- **`python` 이 PATH 에 없는 머신에서 훅이 도는지 안 쟀다** — 지금 머신은 3.12.5 가 PATH 에 있다 —
  정하려면: 두 번째 머신이 생길 때
- **플러그인 훅이 실제로 발화하는지 아직 못 봤다** — 문서로는 담을 수 있다고 확인했지만 이
  머신에서 도는 것을 본 적이 없다 — 정하려면: `claude --plugin-dir` 로 설치 전에 한 번 돌린다.
  여기서 안 되면 나머지 결정이 전부 무의미하다

## 안 하기로 한 것

- **이 저장소에서 하네스를 들어내는 것**(2회차에 기각. 1회차에 확정했다가 실행까지 하고
  되돌렸다) — 이유: **요청이 아니었다.** 「다른 프로젝트에서 쓴다」와 「여기서 지운다」는
  다른 일인데 1회차가 둘을 한 덩어리로 묶었다. 두 벌이 갈린다는 대가는 사실이지만
  **그것이 지우는 근거는 아니다** — 갈리면 그때 손으로 맞추면 되고, 지우는 것은 되돌리기가
  훨씬 비싸다(실제로 42파일을 지웠다가 복구했다) / 다시 볼 조건: 이 저장소와 플러그인이
  실제로 어긋나서 **다른 프로젝트에서 옛 동작을 보게 될 때**. 그때도 먼저 볼 것은 지우기가
  아니라 «둘을 어떻게 맞출까» 다
- **사본을 하나 더 만든다(지금 방식을 새 프로젝트에 되풀이)** — 이유: 이미 관측된 결과가 있다.
  2026-08-27 커밋 `5a89c9f` 가 Codex 사본을 *"훅은 그대로이고 갈리는 것은 경로 표기다"* 로
  만들었는데, 지금 재면 `.codex/hooks/` 7개 중 **5개가 다르고** `heredoc_write_check.py`·
  `prose_style_check.py` 둘은 **아예 없다**. `.agents/skills/` 도 10개 중 **6개가 다르다**.
  사본이 프로젝트 수만큼 늘면 같은 일이 그만큼 난다
- **`~/.claude/skills/` 에 두는 skills-dir 방식** — `claude plugin init` 이 만들어 주는 자리이고
  마켓플레이스도 설치도 없이 **다음 세션부터 모든 프로젝트에서 자동**이라 제일 빠르다.
  이유: 자동이라는 것이 곧 **프로젝트별로 끄는 스위치가 없다**는 뜻이다 — `myproj` 처럼 구조가
  다른 저장소에서도 훅이 다 돈다. 저장소도 버전도 없어 되돌릴 이력이 안 남는다 /
  다시 볼 조건: 시험 삼아 굴려 볼 때. 구조가 같아서 나중에 마켓플레이스로 올려도 안 버린다
- **`--plugin-dir` 만 쓰기** — 이유: 그 실행 한 번에만 붙는 세션 플래그라, 명령줄을 직접 안 치는
  데스크톱 앱에서는 매번 못 붙인다 / 다시 볼 조건: 설치 전 검증에는 이것을 쓴다
- **플러그인을 「기록」과 「안전장치」 둘로 쪼개기** — 이유: `_hookutil.py` 가 두 벌이 되어
  이 일이 없애려는 바로 그 드리프트를 새로 만든다. 켜고 끄는 것은 설정이 한다
- **플러그인 매니페스트의 `userConfig` 로 프로젝트별 값을 주기** — `claude plugin install
  --config key=value` 로 값을 넣는 자리가 실제로 있다. 이유: 22행짜리 매핑표 같은 구조를 못
  담고, 담을 수 있는 몇 개만 거기 두면 **설정 자리가 둘이 된다** / 다시 볼 조건: 스칼라 한둘만
  남았을 때
- **환경변수·`settings.json` 의 `env` 로 주기** — 이유: 매핑표를 문자열 한 줄에 못 담아 값이
  작은 것에만 맞는다. 절반만 쓰면 위와 같은 문제가 난다

## 1회차 — 2026-09-10 · 하네스를 다른 프로젝트에서 쓰기

**물은 것**

*"지금 스킬·훅·에이전트에 기어 있는 것들을 다른 프로젝트에서도 쓰고 싶은데 플러그인으로
만드는 게 좋을까?"*

**먼저 잰 것**

물음이 「다른 프로젝트」 하나로 보였는데, 재 보니 사본 문제는 이 저장소 안에 이미 있었다.

| 무엇을 쟀나 | 결과 |
|---|---|
| `.codex/hooks/` 와 `.claude/hooks/` 대조 | 이름이 겹치는 7개 중 **5개가 다르다**. `heredoc_write_check.py`·`prose_style_check.py` 는 `.codex` 에 없다 |
| `.agents/skills/` 와 `.claude/skills/` 대조 | 10개 중 **동일 4 · 다름 6** |
| `.agents/` 가 gitignore 인가 | **아니다 — 19파일이 추적 중**이다(`.gitignore` 는 `.codex/` 와 `/AGENTS.md` 만 무시한다). `tests/test_docs.py` 가 *"gitignore 된 사본"* 이라 적어 둔 것이 사실과 어긋난다 |
| 훅이 프로젝트 의존성을 쓰나 | 안 쓴다 — 9개 전부 표준 라이브러리뿐이다 |
| `settings.json` 배선 지점 | 16곳, 전부 `${CLAUDE_PROJECT_DIR}/.venv/Scripts/python.exe` 를 부른다 |
| 훅 테스트 크기 | `tests/hooks/` 10파일 2,112줄 |
| 다른 프로젝트가 실재하나 | `C:\myproj` — 멀티모달 RAG, `.venv` 있음, `.claude/` 없음, `AGENTS.md` 있음 |

**플러그인이 담을 수 있는 것도 함께 확인했다** — 스킬·서브에이전트·훅(`hooks/hooks.json`)은
담기고, `settings.json` 의 `permissions`·`env` 와 `CLAUDE.md` 는 못 담는다. 훅 명령에서
`${CLAUDE_PLUGIN_ROOT}`·`${CLAUDE_PROJECT_DIR}` 를 쓴다. `claude plugin validate --strict` 로
검사하고 `claude --plugin-dir` 로 설치 없이 띄운다.

**선택지 — 배포 형태**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| `~/.claude/skills/` (skills-dir) | 마켓플레이스·설치 0, 다음 세션부터 자동 | 프로젝트별로 끄는 스위치가 없다. 이력이 안 남는다 | `myproj` 는 구조가 달라 `auto_test` 매핑이 안 맞는데, 자동이면 거기서도 훅이 다 돈다 |
| 비공개 GitHub 마켓플레이스 | 프로젝트별 on/off · 켠 사실이 `settings.json` 에 남는다 · 갱신·되돌리기 경로가 명시적 | 손이 한 겹 더 들고 저장소를 새로 만들어야 한다 | 이 저장소가 「두 번째 진실」을 도처에서 막아 온 것과 방향이 같다 |
| 지금처럼 복사 | 아무것도 안 고쳐도 된다 | 사본이 갈린다 | 위 표가 그 결과다 |

**고른 것과 이유**

비공개 GitHub 마켓플레이스. 사용자가 *"마켓플레이스에 올리고 나만 사용하고 싶은데
다른 사람들에겐 비공개로"* 라고 물었고, 마켓플레이스가 등록소가 아니라 저장소라서 그게 그대로
된다. skills-dir 은 **더 빠른데도 기각했다** — 프로젝트별로 끌 수 없는 것이 이 하네스에서는
결함이다(`auto_test_check` 는 매핑표가 안 맞는 저장소에서 돌면 안 된다).
`--plugin-dir` 은 세션 플래그라 데스크톱 앱에서 매번 못 붙여 기각했고, 설치 전 검증용으로만 남긴다.

**선택지 — 프로젝트별 값을 어디에 두나**

사용자가 「프로젝트 안 설정 파일 하나」를 골랐다. 환경변수 안은 매핑표를 문자열에 못 담아
값이 작은 것에만 맞고, 플러그인마다 복사해 상수를 고치는 안은 `.codex` 결과를 되풀이한다.

**선택지 — 훅 테스트를 어디에 두나**

사용자가 「플러그인 저장소로 함께 옮긴다」를 골랐다. 이 저장소에 남기면 테스트가 플러그인
설치 경로를 가리켜야 하는데 그 경로가 머신마다 달라, 커밋 `5a89c9f` 가 이미 적어 둔 실패
(*"절대경로라 이 머신 밖에서는 훅이 침묵으로 안 돈다"*)와 같은 모양이 된다.

**남은 질문**

위 「미결」 다섯이 그대로 남는다. 그중 **플러그인 훅이 실제로 발화하는지**가 먼저다 —
안 되면 나머지 결정이 전부 무의미하고, 그때는 skills-dir 이나 지금 방식으로 되돌아간다.

## 2회차 — 2026-09-10 · 「이 저장소에서 들어낸다」를 기각한다

**물은 것**

*"난 이 프로젝트에서 하네스를 지우는 건 원치 않았어. 그냥 사용하는 하네스를 다른
프로젝트에서 적용하고 싶은거였는데."*

**무엇이 어긋났나**

1회차가 요청을 바꿔 읽었다.

| 실제 요청 | 1회차가 세운 목표 |
|---|---|
| 이 하네스를 **다른 프로젝트에서도** 쓴다 | 하네스의 진실을 **한 벌로 모은다** |

**둘은 겹치지 않는다.** 앞엣것은 플러그인을 만들면 끝나고, 뒤엣것은 거기에 더해
**이 저장소를 비우는 일**이 붙는다. 1회차는 뒤엣것을 목표로 잡고 선택지를 짰고, 그래서
면담의 문항이 처음부터 *"훅 테스트는 어디로 갈까요"* 처럼 **이동을 전제로** 나갔다.

**멈출 기회를 한 번 놓쳤다.** 사용자가 *"수술은 해야되는 이유 알려줘"* 라고 되물었는데,
그것을 «근거를 더 대라» 로 읽고 표까지 만들어 설득했다. **되물음은 설득 요청이 아니라
멈춤 신호로 먼저 읽는다** — 특히 그 일이 되돌리기 비싼 쪽일 때.

**고른 것과 이유**

이 저장소를 **세션 시작 상태로 되돌린다.** 지운 42파일은 커밋 전이라 그대로 살아났고,
`settings.json` 은 손대기 전 사본으로 되돌렸다. 고친 문서 넷은 **`git checkout` 을 안 썼다** —
그 사이 다른 세션이 커밋 4개를 했고, 파일째 되돌리면 남의 작업이 사라진다. 제 편집만 뺐다.

**복구가 무손실인지는 대조로 확인했다** — 지우기 직전에 떠 둔 사본과 복구본을 줄끝 무시하고
9쌍 대조해 **전부 같았다**(다르게 보였던 것은 CRLF↔LF 였고, 크기 차가 줄 수와 정확히 같았다).

**기각한 안**

| 안 | 왜 안 골랐나 |
|---|---|
| 기록까지 지워 완전히 되돌리기 | 이 저장소 규칙이 *「기각한 안을 지우지 않는다」* 다. 지우면 **왜 안 했는지가 어디에도 안 남아** 다음에 같은 제안이 다시 올라온다 |
| 두 벌을 그대로 두기(플러그인도 여기 켜 둔 채) | 훅이 두 벌 돈다 — 세션 마커가 서로 다른 곳에 있어 **「세션당 한 번만 막는다」가 깨지고 두 번 막힌다**. 관측으로 확인했다 |
| 플러그인을 지우고 원점으로 | 원래 요청(다른 프로젝트에서 쓰기)이 그대로 남는다. 플러그인은 실제로 돌고 테스트도 통과하므로 버릴 이유가 없다 |
