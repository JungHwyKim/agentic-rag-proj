# 위키 — 세 계층

이 위키는 세 물음에 답하도록 갈라져 있다.

| 계층 | 답하는 물음 | 어디 |
|---|---|---|
| **Overview** | 어디에 무엇이 있나 | `overview/` |
| **Knowledge** | 지금 어떻게 동작하나 | `knowledge/` |
| **History & Reasoning** | 왜 이렇게 됐나 | `plan_log/` · `task_log/` · `verify_log/` |

## History 는 폴더 이름을 안 바꾼다

**`history/` 디렉터리가 없다.** 계층 이름은 이 문서 안에만 살고, 기록은 지금 자리 그대로다.

| 폴더 | 제안 구조의 무엇에 해당하나 | 무엇이 들어 있나 |
|---|---|---|
| `plan_log/` | Decisions | 만들기 **전**의 논의. 기능당 한 파일에 회차가 쌓인다 |
| `task_log/` | Failures + Decisions | 만든 **뒤**의 회고. 세션당 한 파일 |
| `verify_log/` | Evaluations | **재는 동안** 나온 수치. 세션당 한 파일 |

**이름·자리를 안 바꾼 이유가 셋이다.**

1. **경로 참조가 2,102건**이다(위키 내부 1,408 · 밖 694). 훅 5개 · `openwork/collect.py` ·
   스킬 · `CLAUDE.md` · `AGENTS.md` 가 그 이름에 매달려 있다
2. **`task_log/` 는 decisions/failures 로 못 가른다** — 121개 중 **117개가 `## N. 설계 결정` 과
   `## N. 실패 분석` 을 둘 다** 갖는다. 파일이 «결정» 도 «실패» 도 아닌 **세션**이라, 쪼개면
   한 판의 서사가 갈린다
3. **기록 안의 옛 경로는 안 고치기로 한 것**이라(그때의 사실이다) 이름을 바꾸면 2026-08-18
   기록이 그날 없던 경로를 가리킨다

근거는 `CLAUDE.md` 의 「기록」 절과 `plan_log/구조-정리.md` · `plan_log/문서-최신성.md` 16회차.

**나눌 값어치가 생기면 파일이 아니라 각 폴더의 `INDEX.md` 를 나눈다** — 탐색은 좋아지고
경로는 한 건도 안 깨진다.

## `overview/`·`knowledge/` 에는 `INDEX.md` 를 두지 않는다

진입 파일이 **`README.md`** 다. `openwork/collect.py:check_config()` 가 *"`INDEX.md` 를 품은
위키 하위 디렉터리"* 를 **모르는 기록 폴더**로 보고 경고하는데, 이 둘은 기록 폴더가 아니다 —
이름도 정직하고 `collect.py` 를 한 줄도 안 고친다.

## 크기 상한이 있다

`overview/`·`knowledge/` 의 문서는 **20,000자**를 넘기면 안 된다. `Read` 가 호출당
25,000토큰에서 자르는데 **잘렸다는 신호가 사람에게 안 가서**, 모델이 앞부분만 읽고 답한다.
넘기면 파일을 폴더로 승격한다(`x.md` → `x/README.md` + 갈래별 파일). 갈래는 크기가 아니라
**의미**로 고른다. 검사는 `tests/test_docs.py:test_wiki_docs_fit_one_read` 이고 예외는
사유와 함께 적는다. **기록 3폴더는 이 상한 밖이다** — 파일이 곧 세션/기능이라 크기로 못 가른다.

## 무엇을 어디에 적나

- **지금 어떻게 도나** → `knowledge/`. 과거·기각한 안을 여기 길게 적지 않는다
- **왜 그렇게 골랐나** → `plan_log/`(정하는 중) · `task_log/`(정하고 난 뒤)
- **얼마가 나왔나** → `verify_log/`
- **코드가 못 말하는 실측·함정** → `CLAUDE.md`

가르는 기준은 **떼어냈을 때 문장이 성립하는가** 하나다 — `pytest 337 passed` 는 `verify_log/`,
*큰 글씨와 마커가 겹치는 문단이 0/74 라 마커 승격을 기각했다* 는 떼면 문장이 죽으므로
`task_log/` 다.
