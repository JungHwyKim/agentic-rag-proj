# 재작성 흔적을 Answer·화면·query_log 에 싣는다 — 그리고 가짜 한 줄을 치운다

- 작업일: 2026-08-27
- 검증 방법: 단위 테스트(가상 재작성기·가짜 OpenAI 클라이언트) + 띄워 둔 서버에 라이브 질의.
  **유료 4호출**(재작성 2 · 생성 1 · Cohere 리랭킹 1). `-m integration` 은 안 돌렸다.
  수치 전문은 [verify_log/2026-08-27-재작성-흔적.md](../verify_log/2026-08-27-재작성-흔적.md)

## 1. 무엇을 바꿨나

- `rag_pipeline/schemas/answer.py`
  `RewriteTrace(query, mode)` 와 `Answer.rewrite` 를 더했다. **덩어리인 이유가 2절 첫 항목이다.**
- `rag_pipeline/retrieval/rewrite.py`
  `QueryRewriter.last_rewritten` 을 열었다. `rewrite()` 가 **맨 앞에서 그것을 지운다.**
- `rag_pipeline/query.py`
  `retrieve()` 뒤에 재작성기에서 읽어 `Answer` 에 싣는다. 넘겨주기만 하던 자리에 **읽기가 하나 늘었다.**
- `backend/app/core/query_log.py`
  `rewritten`·`rewrite_mode` 두 칸. 안 걸렸으면 `null` 이고 **키는 늘 있다.**
- `backend/app/templates/_answer.html`
  Phase 4~5 자리표시(`관련 조항 재검색 중 (1 / 3)`)를 지우고 그 자리를 실물로 바꿨다.
- `backend/app/static/app.css`
  `.rewrite-row` 를 실제 값이 담기는 줄로 고치고 `.dots`(자리표시 전용)를 지웠다.
- `backend/preview.py`
  샘플 `Answer` 에 `rewrite` 를 넣었다. **안 넣으면 미리보기에서 이 줄이 아예 안 보인다.**
- 테스트 5개 파일 — 2절·5절 참조.

## 2. 설계 결정

### 흔적을 문자열이 아니라 `RewriteTrace(query, mode)` 덩어리로 실었다

버린 것: `Answer.rewritten: str | None` 하나.

**화면 문구가 `mode` 에서 갈린다.** `fuse` 는 원 질의 갈래를 남긴 채 재작성 갈래를 더한
것이라 *"…로 바꿔 검색했습니다"* 가 거짓이고, `replace` 는 갈아끼운 것이라 *"…도 함께"* 가
거짓이다. 문자열만 실으면 템플릿이 문구를 고를 근거가 없고, 나란한 두 필드로 쪼개면
*질의는 있는데 mode 가 없는* 못 쓰는 조합이 생겨 템플릿이 매번 방어해야 한다.

`cached_from` 이 `query`·`created_at`·`score` 셋을 한 덩어리로 묶은 것과 **글자 그대로 같은
잣대**다. 이 저장소가 같은 선택을 세 번째로 한 셈이다(앞의 둘은 `RetrievedChunk` 의 경로별
점수를 `float | None` 로 둔 것과 `StoredChunk`/`SearchResult` 를 가른 것).

### 다시 쓴 질의를 `retrieve()` 반환이 아니라 **인스턴스**에서 읽는다

버린 것: `retrieve()` 가 `(chunks, rewritten)` 을 돌려주게 넓히기.

`retrieve()` 의 반환은 공개 계약이고 `evaluation/run_eval.py` 를 포함한 모든 호출부가 그
모양에 맞춰져 있다. **재작성 한 줄을 화면에 보이자고 검색의 반환 타입을 넓히는 것은 값이 안
맞는다.** 반대로 `warnings`·`usage` 가 이미 인스턴스에 사는 자리라 새 관행도 아니다 —
리랭커도 같다.

이 선택에 딸린 위험이 하나 있고 그것이 4절의 마지막 항목이다.

### 캐시 히트에도 값을 싣는다

버린 것: 캐시 히트면 `None`.

재작성이 **걸린 것은 같고** 갈리는 것은 과금뿐이다. 여기서 `None` 을 주면 캐시가 도는
순간 화면 표시가 사라져 *켜 놓고도 안 보이는* 상태가 되는데, 그것이 에러 없이 일어난다.

### `query_log` 에 재작성 질의 **전문**을 싣는다 — `reasoning` 은 뺐는데

사용자가 고른 것이고, 근거는 `reasoning` 과 축이 다르다는 것이다.

- `verdict.reasoning` 은 **읽는 도구가 이미 있어서**(`evaluation/verdicts.py --wrong`) 여기
  쌓을 이유가 없었다. 재작성은 그런 도구가 없고, **여기가 유일한 기록이다** —
  `.cache/rewrite` 는 내용 해시가 키라 *어떤 질의가 무엇으로 바뀌었나* 를 못 되짚고
  원 질의를 아예 안 담는다
- 길이도 다르다. `reasoning` 은 모델이 마음대로 쓰는 산문이고 재작성 질의는 질문 한 문장에
  `rewrite_max_tokens`(256) 상한이 걸려 있다 — 바로 옆 `query` 칸이 이미 같은 급을 싣는다

`rewrite_mode` 를 함께 실은 이유는 위와 같다: 없으면 같은 줄이 두 뜻을 갖는다.

### 화면은 **있던 자리를 실물로** 바꿨다 — 새 배지를 만들지 않고

사용자가 고른 것이고, 버린 것 둘은 (a) `cached_from`·`verdict` 와 나란한 `.badge-row` 를
새로 만들고 자리표시는 유지 (b) 화면에 아예 안 그리고 로그만.

(a) 를 버린 결정적 이유는 **재작성에 관한 줄이 둘이 되고 그중 하나가 거짓**이라는 것이다.
자리표시는 *재시도 루프*(Phase 4~5)의 모형인데 우리가 만든 것은 검색 앞 1회 PRF 라 뜻도
다르다. 게다가 색을 새로 골라야 하는데 라벤더(캐시)·sunken(불충분)·danger(실패)는 이미
임자가 있고, 이 줄은 *"잘못됐다"* 가 아니라 *"이렇게 검색했다"* 라 새 색을 만들 이유가 없다.

그래서 배지가 아니라 **흐린 한 줄**로 뒀다 — 답변보다 먼저 읽히면 안 된다.
잘리는 것은 질의뿐이고 꼬리말은 `flex:none` 이다: 꼬리말이 잘리면 `fuse` 와 `replace` 가
화면에서 안 갈려 이 줄이 뜻을 잃는다.

### `.dots` 는 지우고 `.is-placeholder` 는 남겼다

`.dots`(자리표시의 가짜 진행 점 셋)는 쓰는 곳이 사라져 지웠다. `.is-placeholder` 도 마지막
사용처가 없어졌지만 **남겼다** — 배지 테스트 셋이 *이 클래스가 안 붙었음* 을 단언해
"진짜 값이 흐려지는" 회귀를 막고 있어서다. 규칙을 지우면 그 세 단언이 **영원히 참**이 되어
조용히 죽는다. CSS 한 줄과 산 가드 셋 중 뒤를 골랐고, 이유를 CSS 주석에 적었다.

## 4. 실패 분석

### 서버가 두 벌 떠 있었고, 그것을 **코드 배선 문제로 두 번 의심했다**

시작은 *"재시작하고 질의를 넣었는데 `.cache/rewrite` 가 78 그대로"* 였다. 배선을 읽고
설정을 실제로 해석해 봐도(`get_rewriter(IngestConfig().rewrite)` 가 진짜 객체를 돌려준다)
멀쩡했고, 재작성 API 를 격리해서 찔러도 정상이었다(4.71초 · `api_calls=1`).

원인은 제품이 아니라 **uvicorn 이 두 벌 살아 있는 것**이었다.

```
PID  7856 / 32672 / 34612   13:42:59 기동  ← 낡은 서버. 자식 PID 가 13:42 그대로다
PID 41080 / 40912 / 43252   21:14:38 기동  ← 사용자가 새로 띄운 것
```

**둘 다 127.0.0.1:8000 에 바인딩돼 있었다.** Windows 는 `SO_REUSEADDR` 로 같은 포트 중복
바인딩을 허용해서 두 번째가 **에러 없이** 뜬다. 그래서 질의가 그때그때 다른 쪽으로 갔고,
낡은 쪽은 `rewrite.py` 가 존재하지도 않던 13:42 코드였다.

가른 증거는 둘이다.

- `Get-NetTCPConnection -LocalPort 8000` 을 두 번 불렀더니 소유 PID 가 **40912 → 32672 로
  바뀌어** 나왔다
- 낡은 쪽 **자식 프로세스의 생성 시각이 13:42 그대로**다 — `--reload` 가 20:55 의 편집에
  한 번도 안 걸렸다는 뜻이다(걸렸으면 자식이 새로 태어난다)

**앞 세션이 같은 함정의 절반을 이미 밟았다**(`verify_log/2026-08-27-재작성-화면배선.md` 3.2절:
*"실사용 확인 전에 프로세스 생성 시각부터 본다"*). 이번에 드러난 나머지 절반은
**프로세스가 하나라는 보장이 없다**는 것이다 — 생성 시각을 봐도 *어느 쪽이 답했나* 는
포트 소유자를 봐야 갈린다.

**RSS 로 갈라 보려다 한 번 더 헛짚었다.** 낡은 자식이 205MB 라 *모델을 안 올렸으니 질의를
안 받았다* 고 읽었는데, Windows 는 유휴 프로세스의 워킹셋을 트리밍한다. RSS 는 이 판정에
못 쓴다.

**막지 못했다.** 단위 테스트로 재현할 대상이 아니고(운영 환경의 프로세스 상태다) 제품
코드로 막을 수도 없다. CLAUDE.md 함정 절에 올렸다.

### 스크립트 편집이 `answer.py` 를 CRLF → LF 로 바꿨다

`read_text()` 가 universal newlines 로 `\r\n` 을 `\n` 으로 접고, `write_text(newline="")` 이
그대로 썼다. **`git diff` 로는 안 보인다** — 인덱스가 LF 라 정규화 후 비교하면 같기 때문이다.
드러난 것은 `git diff --stat` 이 낸 *"LF will be replaced by CRLF"* 경고 한 줄뿐이었다.

되돌리고, 이후 편집은 **바이트로 읽어 줄끝을 감지하고 같은 것으로 되쓰는** 헬퍼로 했다.
이 저장소는 인덱스 LF · 워킹카피 CRLF 가 기본인데 **파일마다 다를 수 있어**(이 사고 직전
`answer.py` 만 워킹카피가 LF 로 보였다) 파일별로 감지해야 한다.

### `object()` 스텁이 깨졌다 — 그리고 방어 코드로 덮지 않았다

`answer_question()` 이 `rewriter.last_rewritten` 을 읽기 시작하자, 재작성기를 맨 `object()` 로
넘기던 기존 테스트 둘이 `AttributeError` 로 죽었다. 자동 테스트 훅이 편집 몇 초 만에 잡았다.

`getattr(rewriter, "last_rewritten", None)` 으로 덮을 수 있었지만 **안 덮었다.** 그러면
재작성기가 계약을 안 지켜도 조용히 통과하고, 그때 화면과 로그는 *재작성이 안 걸린 것처럼*
보인다 — 이 작업이 없애려던 상태와 정확히 같다. 대신 `_FakeRewriter` 를 만들어 스텁 쪽을
고쳤다.

**한 자리만 맨 `object()` 로 남겼다** — 캐시 히트 테스트다. 거기는 *재작성기의 무엇도 안
읽는다* 가 재는 것이라, 흔적을 읽는 줄이 캐시 검사 위로 올라가면 `AttributeError` 로 터지는
편이 낫다.

### 미리보기에서 그 줄이 통째로 사라졌다

자리표시를 지우고 `preview.html` 을 다시 만들었더니 재작성 줄이 **아예 없었다.** 실물은
값이 있을 때만 그리는데 샘플 `Answer` 에 `rewrite` 가 없어서다. 즉 자리표시를 지운 순간
미리보기가 *그 자리를 잃었다* — 자리표시의 유일한 값어치였던 것을 실물로 안 되돌린 것이다.

샘플에 값을 넣되 **일부러 길게** 넣었다. 이 줄에서 사람이 볼 것이 말줄임이라, 짧은 값이면
미리보기가 그 자리를 확인해 주지 못한다.

### 남은 위험 — 인스턴스 상태를 읽는 것

`last_rewritten` 은 **호출 사이에 살아 있는 상태**다. 되돌리기를 빼면 폴백으로 내려간
질의가 앞 질의의 재작성을 자기 것으로 보고하는데, **에러가 안 나고 값도 그럴듯하다.**
라우트는 질의마다 재작성기를 새로 만들어 안전하지만 `run_eval` 은 재사용한다.
회귀 테스트로 박았다(5절).

## 7. 남은 것

- **재작성을 켠 화면 지연을 아직 안 쟀다.** 라이브 세 회차(9223 · 11601 · 7336ms)는 캐시
  상태도 서버 프로세스도 제각각이라 기준선이 아니다. 다음 작업이 이것이고, 재작성 X 조건을
  만들려면 `.env` 의 `REWRITE_MODEL` 을 주석 처리하고 서버를 다시 띄워야 한다
  (**빈 값은 안 된다** — 파싱하다 죽는다)
