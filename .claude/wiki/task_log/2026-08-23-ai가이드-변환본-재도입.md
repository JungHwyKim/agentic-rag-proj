## 2. 설계 결정

### 사용자 요청의 조건이 성립하지 않아, 먼저 대조하고 계층을 갈랐다

요청은 *"PDF 랑 대조해서 다른 부분 없으면 포함"* 이었다. 대조해 보니 **본문은 다르지
않았고 오히려 좋아졌다** — 요소 텍스트 겹침이 옛 판 98.5% → **100%** 이고, PDF 쪽
미검출 10개는 **전부 `TABLE` 요소인데 그 셀 내용은 문단으로 100% 살아 있다.**

**다른 것은 구조였다.** `hp:tbl` 이 **0개**이고 `vertpos` 888개가 **전부 0** 이라 쪽이
1로 붕괴한다. 그래서 "전부 포함"도 "제외"도 답이 아니었고, 계층 넷 중 어디까지 넣을지를
사용자에게 물었다. **파싱 회귀(①②③)까지만** 넣고 평가 코퍼스(④)는 뺐다 —
①②③의 단언 중 쪽·표를 쓰는 것이 하나도 없고, ④만 `gold_page` 를 사람이 열 수 있는
값으로 요구한다. 넣었으면 15건이 전부 1쪽이 되어 2026-08-22 검수 60/60 의 전제가 깨진다.

### 결함이 있는 표본을 빼는 대신 결함을 잠갔다

2026-08-20 에 같은 문서를 뺐을 때의 문제가 이것이다 — **빼고 나면 `_is_layout_box` 나 쪽
계산을 고쳐도 아무 신호가 안 난다.** 그래서 넷을 명시적으로 단언했다: 표 리전 0 ·
`layout_table` 강등 0 · `page_count` 1 · 머리말 28 + 꼬리말 27 잔류.

**강등 0 을 함께 잠그는 것이 요점이다.** 표 0 만 보면 "`_is_layout_box` 가 다 강등했나"와
"표가 아예 없나"가 안 갈린다. 실제로 이 문서의 배제 사유가 전자로 기록돼 있었는데
(`evaluation/README.md` — *"한컴이 이 문서의 표를 레이아웃 상자로 그려서"*) zip 을 열어 보니
`hp:tbl` 자체가 0이라 **후자**였다. 둘을 함께 세면 다음 사람이 이 오해를 반복하지 않는다.

### 옛 판을 교체하지 않고 공존시켰다

`cleaner/test_real.py:test_running_header_removed_in_both_formats` 가 옛 판에서만 성립한다.
그 짝은 로더가 **HWPX 97쪽 / PDF 28쪽으로 분모를 3.5배 갈리게 세는데도 제거 개수가 25로
같다** — 이것이 `cleaner/headers.py` 가 등장 횟수 비율 대신 '걸친 폭'을 고른 근거 자체다.
변환본은 쪽이 1이라 **0건**이므로 이 자[尺]를 대신할 수 없고, 다른 세 문서 짝은 두 포맷
모두 제거 0건이라 옮길 곳도 없다. 2026-08-20 에 이 테스트만 남긴 판단과 같은 이유다.

버린 안: **변환본으로 교체**(자[尺] 상실) · **평가 코퍼스 편입**(`gold_page` 전부 1) ·
**쪽 폴백 구현**(`vertpos` 전부 0인 표본이 1건뿐이라 임계값을 못 정한다).

### 잔챙이 청크 상한을 전역으로 낮추지 않고 그 문서만 덮었다

`test_merging_removes_tiny_chunks` 의 10% 상한을 변환본이 **8/68 (11.8%)** 로 넘겼다.
규칙을 낮추면 **다른 문서에서도 안 울린다** — 옛 판 0/47 · PDF 6/70 이라 지금 아슬아슬한
것이 PDF 다. 대신 `EXPECTED` 에 `tiny_max: 8` 을 사유와 함께 적었다.

사유를 적을 수 있었던 것은 **8개를 실제로 열어 봤기 때문**이다 — 3개가 못 지운 머리말,
4개가 `[붙임]` 의 위험도 2x2 상자(표가 아니라 각각 별개 도형), 1개가 목차 줄이다.
**7/8 이 이미 잠근 두 결함의 파생**이라, 이 숫자는 느슨함이 아니라 대가의 크기다.

## 4. 실패 분석

### 기준선 파일을 통째로 다시 포맷할 뻔했다

`json.dumps(indent=1)` 로 다시 써서 **421 insertions / 401 deletions** 가 났다. 원본은
`indent=2` 다. 되돌리고 `indent=2` 로 다시 쓰니 **21 / 1** 이 됐다. 값이 하나도 안 바뀌었는데
diff 가 800줄이면 리뷰에서 "무엇이 실제로 바뀌었나"가 안 보인다. 같은 이유로 편집한 파일의
줄 끝도 CRLF 로 되돌렸다(`test_hwpx_real.py` 가 한 번 LF 로 바뀌었다).

### `근거` 에 검증 안 한 수치를 적었다

옛 판의 리전 수를 `plan_log/splitter.md` 표에서 본 **949** 로 적었다. 실제로 재보니
**774** 이고, `baseline.json` 의 2026-08-20 갱신 이력에도 774 로 적혀 있었다. 949 는 다른
축(문단 수 등)의 값으로 보인다. **다른 문서의 표에서 숫자를 옮기지 말고 재거나 같은
파일 안에서 찾아야 한다.** 고쳐서 774 로 넣었다.

### 남의 작업을 내 회귀로 오해할 뻔했다

편집 중에 자동 테스트 훅이 `tests/ingestion/loader/content` 20건 실패를 띄웠다
(`TypeError: ContentRouter() takes no arguments`). 내가 건드린 적 없는 영역이라 확인해 보니
**같은 작업 트리에서 다른 세션이** `ContentRouter` 의 생성자를 없애고 호출부를 고치는
중이었다 — 몇 분 뒤 다시 돌리니 89 passed 였다. 전체 ruff 도 한 번 `evaluation/corpus.py`
의 import 순서로 실패했다가 저절로 사라졌다.

**되돌리지 않은 것이 핵심이다.** 내 파일만 따로 lint·test 해서 내 몫이 깨끗한 것을 확인하고,
전체 수치에는 "이 증가분이 전부 내 몫이 아니다"를 붙였다. `verify_log/2026-08-22-loader-content-정리.md`
가 같은 상황을 겪고 같은 처리를 했다.
