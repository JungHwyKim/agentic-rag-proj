# 어느 판으로도 안 잡히던 긍정 3건을 읽고, 둘은 라벨이 틀린 것이었다

- 작업일: 2026-08-27
- 검증 방법: 코퍼스 전수 스캔(414청크) + 정답 span 정독 + 판정 네 판의 사유 대조.
  **외부 API 0호출** — 판정은 캐시에서 읽었다. `run_eval --check` · ruff · 전체 pytest

## 1. 무엇을 바꿨나

## 2. 설계 결정

### 라벨을 되돌린 근거는 "판정이 틀렸나"가 아니라 "답이 코퍼스에 있나"다

`hbas-06` 이 밟은 절차를 그대로 썼다 — 정답 span 이 질문에 실제로 답하는지 읽고, 답이
코퍼스 어디에도 없는지 전수로 훑는다. **판정이 셋 이상 틀렸다는 것만으로는 근거가 안 된다**
(그러면 세트가 모델을 따라가고, 자[尺]가 재는 대상에 끌려간다).

- `hbas-04` — 정답 span 이 **필수 서류 목록**이라 *동의가 필요하다* 는 뜻이지 거부 시 조치가
  아니다. 스캔에서 거부·미동의·철회·거절이 **2건뿐이고 둘 다 '학습 거부감'** 이다
- `hbas-08` — 정답 span 이 선도학교 **예산 사용 안내**의 한 줄이라 연수에 돈을 쓸 수 있다는
  뜻이지 의무 이수가 아니다. 의무·필수 연수 패턴이 **0건**이고, 연수는 전부 예산 항목이거나
  **학습지원 담당교원**(담임·교과와 다른 역할) 연수다

**판정 네 판이 모두 정확히 그 구분을 짚었다** — luna-v3 가 `hbas-08` 에 *"학습지원 담당교원
연수는 언급되지만 담임교사나 교과 담당 교사의 의무 이수 여부는 명시되어 있지 않다"* 고 답했다.
Evaluator 가 옳고 라벨이 틀렸던 자리다.

### `hai-01` 은 안 되돌렸다 — 같은 3건이지만 축이 다르다

정답 span 이 *"구현하기에 앞서 … 위험을 평가하여야 함"* 으로 **사전 의무를 실제로 말한다.**
벌어진 곳은 낱말이다 — 질문은 *안전성 검증을 받아야 하나*, 근거는 *위험 평가를 하여야 함*.
답이 코퍼스에 있으므로 부정이 아니고, **판정이 엄격했던 쪽**으로 남긴다. 사용자 결정이고,
남겨 두는 편이 프롬프트 축에 표적 하나를 준다.

### 세트는 내가 안 고치고 사용자에게 물었다

이 저장소는 라벨 되돌리기를 사람 몫으로 못 박아 뒀다(부정 25→23→22 가 전부 사람이 근거를
읽고 되돌린 결과다). 증거와 추천을 내고 결정을 받았다. **모델이 자기를 채점하는 자를 스스로
고치면 그 표가 무엇을 재는지 알 수 없게 된다.**

## 4. 실패 분석

**없음** — 되돌린 시도도 잘못 짚은 것도 없다. 다만 앞 회차가 남긴 것을 이어받아 닫은 것이라,
값어치는 이 회차보다 그쪽의 *"3건을 사람이 읽어야 갈린다"* 는 판단에 있다.

한 가지만 적어 둔다. **판정 넷이 전부 틀렸다는 신호가 실제로 세트를 가리키고 있었다.**
경계순위 회차는 그것을 *"순위와 무관하고 사슬 밖"* 이라고만 적고 판정력의 한계로 읽지 않았는데,
그 조심이 맞았다 — 셋 중 둘이 라벨이었다. **모두가 틀리는 자리는 자[尺]를 먼저 의심한다.**

## 5. 회귀 테스트

세트는 데이터라 새 테스트를 안 넣었다. 대신 **기존 가드가 이 변경을 검사한다** —
`evaluation/qa_set.py` 의 검증이 부정 레코드에 `gold_spans`·`gold_page` 가 비어 있는지,
`reviewed_by: human` 이면 `reviewed_hash` 가 지금 내용과 맞는지 본다. `--check` 로 통과 확인.

**못 막은 것**: 이 세트로 잰 **검색 지표의 분모가 조용히 바뀐다**(정답 21 → 19).
`run_eval` 은 부정을 `skipped_unanswerable` 로 빼지만, 옛 실행 JSON 과 나란히 놓으면
분모가 다른 두 수를 견주게 된다. 7절에 적었다.
