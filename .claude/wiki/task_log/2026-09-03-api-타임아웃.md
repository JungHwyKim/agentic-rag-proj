# 외부 API 클라이언트에 타임아웃을 명시한다 — SDK 기본값이 스레드를 최악 30분 잡고 있었다

- 작업일: 2026-09-03
- 검증 방법: SDK 기본값 탐침(네트워크 안 탐) · ruff · 전체 pytest. **외부 API 과금 없음** — 클라이언트 객체만 만들고 더미 키를 쓴다. `-m integration` 안 돌림

## 1. 무엇을 바꿨나

- `rag_pipeline/config.py`
  `openai_timeout_sec`(6개 설정 객체) · `cohere_timeout_sec` · `tavily_timeout_sec` 를 더하고, 연결 축을 `OPENAI_CONNECT_TIMEOUT_SEC` 상수로 못 박았다. `openai_api_key` 가 이미 6곳에 중복 선언된 그 패턴을 그대로 따랐다
- `generation/{answer,evaluate}.py` · `ingestion/embedding/openai_api.py` · `ingestion/loader/content/{image_vision,table_vision}.py` · `retrieval/reranker/openai_llm.py` · `retrieval/rewrite.py`
  `_make_client(api_key, timeout)` 로 인자를 늘리고 `httpx.Timeout` 을 먹인다. 일곱이 글자까지 같은 구현이라 한 번에 고쳤다
- `retrieval/reranker/cohere_api.py`
  생성자가 맨 float 을 받는다. SDK 기본이 300초라 여기도 구멍이었다
- `agent/tools/web_search.py`
  **생성자가 아니라 `search()` 가 받는다.** 값은 안 바뀐다(기본이 이미 60)
- `answer_cache/fingerprint.py`
  `_SKIP_SUFFIXES` 에 `_timeout_sec` 를 더했다. 안 더하면 `.env` 한 줄에 답변 캐시가 전량 미스가 된다
- `generation/citations.py`
  모듈 docstring 을 raw 로 바꿨다. 새로 만든 `ast` 검사가 잘못된 이스케이프를 드러냈다
- `tests/test_api_timeouts.py`(신규) · `tests/answer_cache/test_answer_cache.py` · `tests/ingestion/embedding/test_cache_salt.py`
- `.env.example` · `CLAUDE.md` · `.claude/wiki/knowledge/contracts.md`

## 2. 설계 결정

### 한 값(60초)을 여러 설정 객체가 각자 읽는다

갈래마다 다른 값을 주는 안을 **기각했다 — 근거가 없어서다.** Vision 이 재작성보다 오래 걸릴 것 같지만 **이 저장소에 외부 호출 지연 기록이 아예 없다**(`cost.jsonl` 이 토큰·호출만 담고 걸린 시간을 안 담는다). 근거 없이 두 번째 수를 지어내는 것은 이 저장소가 임계값에 대해 거듭 기각해 온 바로 그 모양이다.

**새 공용 모듈을 만드는 안도 기각했다.** `runtime.py` 를 후보로 봤는데 그 모듈의 존재 이유가 *"값이 프로세스 전역이라 `EmbeddingConfig`·`RerankConfig` 어느 쪽에도 못 매단다"* 이고, 타임아웃은 **각 설정 객체에 잘 매달린다.** 넣었으면 그 모듈의 근거가 깨진다.

고른 것은 **이미 있는 패턴**이다 — `openai_api_key` 가 6개 설정 클래스에 중복 선언돼 같은 `.env` 키를 각자 읽는다. 새 규칙을 만들지 않고 그 자리에 나란히 놨다.

### `connect` 은 설정으로 안 열고 상수로 못 박았다

**손잡이를 둘로 늘리지 않으려는 것이 절반이고, 나머지 절반은 이것이 «고른 수» 가 아니라는 것이다.** 5.0 은 SDK 기본과 같은 값을 그대로 옮겨 적은 것이라 재판정 조건이 없다. 값이 아니라 *안 바꾸겠다는 표시*다.

명시가 필요한 이유는 SDK 의 인자 모양이다 — 4절 참고.

### Tavily 는 값이 안 바뀌는데도 명시한다

*"기본이 이미 60이니 그대로 두자"* 를 기각했다. **그 60은 우연이다** — SDK 가 올라가며 조용히 바뀌어도 아무 신호가 없고, 이 작업이 없애려던 것이 정확히 «숨은 기본값에 기대는 것» 이다. 값이 같아도 출처를 우리 쪽으로 옮긴다.

**죽은 설정이 아니라는 것이 이 결정의 조건이다** — 실제 효과가 있는 손잡이이고 지금 값이 SDK 기본과 같을 뿐이다.

### `_timeout_sec` 를 답변 캐시 지문에서 뺀다

지문 모듈의 규칙은 **「기본은 싣고 뺄 것만 명시」**이고 그 근거는 비대칭이다(빠뜨리면 낡은 답을 서빙, 넘치면 미스 한 번). 그 규칙에 그냥 맡기면 타임아웃이 실린다.

**뺀 이유가 둘이다.** 하나는 축이 다르다는 것 — 타임아웃이 가르는 것은 *답이 무엇인가* 가 아니라 «답이 나오는가» 이고, 안 나온 회차는 **애초에 캐시에 안 들어간다.** `*_cache_dir`·`*_cache_enabled` 를 뺀 것과 같은 자리다.

둘째가 더 급하다 — 지금 `exact` 캐시는 *"`source=="user"` 50줄에서 적중률 5% 미만이면 끈다"* 의 표본을 모으는 중이다. 실었으면 `.env` 한 줄 고칠 때마다 전량 미스가 되어 **그 판정을 아래로 민다.** 같은 모듈의 `max_retries` 조각이 꺼졌을 때 안 붙는 것과 같은 이유다.

### `_make_client(api_key, timeout)` 에 기본값을 안 뒀다

`append_query_log(source=)` 가 기본값을 안 둔 것과 같은 잣대다. 두면 **새 호출부가 빠뜨렸을 때 조용히 기본값으로 돌고**, 이 작업이 없애려던 상태가 그대로 재생산된다. 없으면 `TypeError` 로 터진다.

### 검사를 파일별 테스트가 아니라 `ast` 훑기로 짰다

이름 목록으로 세는 안을 **실제로 밟아 보고 기각했다**(4절 — 그 목록이 실제로 틀렸다). `rag_pipeline/` 전체를 훑어 클라이언트 생성에 `timeout` 이 없으면 실패시킨다. 면제는 사유와 함께 표에 적는다(`auto_test_check.UNMAPPED_BY_DESIGN` 과 같은 모양).

**파일별로 잠그면 새로 생긴 클라이언트가 조용히 빠진다** — 훅의 자식 인코딩 검사가 같은 이유로 훅 전체를 `ast` 로 훑는다.

## 4. 실패 분석

### 맨 float 으로 짤 뻔했다 — 읽기를 조이려다 연결을 12배 늦출 뻔했다

`OpenAI(timeout=60.0)` 이 자연스러워 보이고 그렇게 짜려 했다. 재보니 그 인자는 `connect·read·write·pool` 을 **전부** 덮는다 — 기본 `Timeout(connect=5.0, read=600, …)` 이 통째로 `60.0` 이 된다.

그러면 **호스트가 죽었을 때 5초에 끝나던 실패가 60초 × 재시도 3회**가 된다. 조이려던 작업이 다른 축을 늦추는 것이고, **정상 경로에서는 안 보인다**(호스트가 살아 있으면 connect 가 안 걸린다).

`httpx.Timeout(읽기, connect=OPENAI_CONNECT_TIMEOUT_SEC)` 로 갈랐다. **가른 것은 값을 한 번 찍어본 것 하나다** — 문서를 읽었으면 «timeout 을 준다» 까지만 알고 지나갔다.

### `cohere.ClientV2` 를 셀 때 놓쳤다 — 그리고 그것이 검사 설계를 바꿨다

클라이언트를 세려고 `grep "OpenAI(\|TavilyClient(\|Client("` 를 돌렸다. `cohere.ClientV2(` 는 **`Client(` 를 부분 문자열로 안 갖는다**(뒤가 `V2(` 다). 그래서 **9곳으로 알고 있었고 실제는 10곳**이었다.

세션 앞부분에서 만든 면접 문서에 «9곳» 이 그대로 적혔고 나중에 고쳤다.

**교훈은 패턴을 고치는 것이 아니다** — 손으로 세는 목록은 다음 클라이언트에서 또 틀린다. 그래서 마지막 검사를 이름 목록이 아니라 `ast` 훑기로 짰다(2절).

### `runtime.py` 에 넣으려다 되돌렸다

프로세스 전역 손잡이가 사는 모듈이라 자리가 맞아 보였다. 그 모듈 docstring 을 읽으니 존재 이유가 *"값이 프로세스 전역이라 `EmbeddingConfig`·`RerankConfig` 어느 쪽에도 못 매단다"* 였고, **타임아웃은 각 설정에 잘 매달린다.** 넣었으면 그 모듈이 «전역인 것» 과 «공용인 것» 을 같이 담게 되어 근거가 흐려진다.

### 테스트가 하나 죽여서 알았다 — 새 필드가 대조에서 빠질 뻔했다

`EmbeddingConfig` 에 필드를 더하자 `tests/ingestion/embedding/test_cache_salt.py` 가 *"새 필드 `openai_timeout_sec` 의 타입 `float` 을 흔드는 규칙이 없습니다"* 로 죽었다. 그 테스트는 **모르는 타입을 조용히 건너뛰지 않고 일부러 실패**한다 — 건너뛰면 새 필드가 salt/컬렉션 대조에서 빠지는데 그것이 그 테스트가 막으려는 상황이다.

`float` 규칙을 더하는 것이 맞는 대응이었다. 더하니 «타임아웃은 salt 도 컬렉션 이름도 안 움직인다» 가 자동으로 검사된다.

### 경고를 하나 만들었다가 고쳤다

새 `ast` 검사가 소스를 **다시 파싱**하면서 `generation/citations.py` 의 `DeprecationWarning: invalid escape sequence '\['` 를 드러냈다. 모듈 docstring 안의 `\[(\d+)\]` 가 raw 아닌 문자열이었다(54행 정규식은 원래 raw 라 멀쩡).

**평소에 안 보이는 종류다** — 컴파일이 한 번뿐이고 `.pyc` 가 캐시된다. 앞으로의 파이썬에서는 `SyntaxError` 이므로 docstring 을 raw 로 바꿔 고쳤다. 검사가 덤으로 잡아준 셈이다.

## 5. 회귀 테스트

| 4절·2절의 항목 | 무엇이 막나 |

| 맨 float 이 connect 를 덮는 것 | `tests/test_api_timeouts.py::test_openai_client_gets_the_read_timeout_and_keeps_connect` — `connect == 5.0` 을 따로 단언한다 |
| 클라이언트를 세다 놓치는 것 | 같은 파일 `test_every_client_construction_passes_a_timeout` — `ast` 로 `rag_pipeline/` 전체를 훑는다 |

| cohere 갈래 | 같은 파일 `test_cohere_client_gets_the_timeout` |
| 지문이 움직이는 것 | `tests/answer_cache/test_answer_cache.py::test_fingerprint_ignores_timeouts` |
| 새 필드가 salt 대조에서 빠지는 것 | `tests/ingestion/embedding/test_cache_salt.py` — `float` 규칙을 더해 자동으로 든다 |

**못 막은 것 하나** — 타임아웃이 실제로 발동하는 것은 안 본다. 응답을 늦추는 가짜 서버가 필요하고, 잠근 범위는 *값이 클라이언트에 실리는가* 까지다. `httpx` 동작 자체는 우리 코드가 아니다.

## 7. 남은 것

- **`60` 이 맞는 값인지 모른다.** 정상 호출의 지연 분포를 못 쟀다 — `cost.jsonl` 이 걸린 시간을 안 담는다. 재판정은 값이 아니라 **신호**로 하기로 했다(잘리면 Vision→OCR · 리랭커→RRF · 재작성→원 질의로 내려가며 경고가 남는다). 그 경고에 timeout 이 뜨면 올린다
- **비용 로그에 지연 칸을 더할지 안 정했다.** 더하면 위 항목이 다음 회차에 닫히고, 갈래별로 다른 값을 줄 근거도 생긴다. 다만 «관측만 담고 파생은 볼 때 계산한다» 는 그 파일의 방침에 지연이 맞는지는 따로 봐야 한다
- **`max_retries` 는 안 건드렸다.** SDK 기본 2 그대로라 최악이 `60 × 3 = 180초` 다. 줄일지는 «재시도가 값을 하는가» 를 재야 정해지는데 그 데이터가 없다
- **LlamaParse 의 120초는 안 건드렸다.** 원래 값이 있던 유일한 갈래이고 문서 파싱이라 성격이 다르다. 다른 갈래와 나란히 볼 값인지는 안 봤다
