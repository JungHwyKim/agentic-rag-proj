# `Grep` 도구를 폴더 지침 훅에 이었다 — 미룬 근거를 전사로 세니 5분의 1이었다

- 작업일: 2026-09-01
- 검증 방법: 전사 163개 집계 · 훅을 서브프로세스로 먹임 · 실제 `Grep` 호출로 실동작 확인 ·
  `pytest tests/hooks` · 전체 `pytest -q` · `ruff check .` — **외부 API 호출 없음**

## 2. 설계 결정

### 미룬 근거를 세니 19.6%였다 — 그래서 그 결정을 **아예 안 했다**

13회차가 `Grep` 을 미룬 유일한 근거는 *"「경로 없음 = 저장소 전체」 대우가 새 결정이다"* 였다.
전사 163개에서 `Grep` **148건**을 세니 **«폴더를 안 좁힌» 호출이 19.6%**(안 줌 5.4% + 뿌리
14.2%)다. 그래서 **«안 좁혔으면 아무것도 안 싣는다»** 로 정했다 — 19.6%를 버리고 **80.4%를
얻으며, 「모든 폴더에서 조각 하나씩」을 설계할 필요가 통째로 없어진다.**

값어치는 **호출 하나가 지침을 실을 확률 35.1%**(52/148)이고 **그 전에는 전부 0**이었다.

**버린 것 둘** — ① **C(안 좁힌 호출도 싣는다)**: 19.6%를 지키는 대신 한 호출이 예산을 통째로
태운다(13회차가 「호출당 합산」으로 이미 잰 자리다). ② **B(`Glob` 까지)**: 값어치가 `Grep` 의
**6분의 1**(8건 대 52건)이라 급하지 않다.

### 「경로 없음」을 **키 유무**로 세면 절반을 놓친다

`path=<저장소 뿌리>` 21건은 키가 있지만 훅 입장에서 **똑같이 «안 좁혔다»** 이고, 바로 그 새
결정을 발동시킨다. **키로 세면 5.4%, 의도로 세면 19.6%** 다 — 셋 중 어느 안을 고를지가 이
한 칸에서 갈릴 수 있었다.

### 채널마다 판별 규칙이 **반대**다 — 통일하면 한쪽이 반드시 틀린다

셸에서는 디렉터리에 **구분자(`/`)를 요구**한다(13회차) — 맨낱말은 검색어와 못 가르기 때문이다.
`Grep` 에서는 **요구하면 안 된다** — `path` 는 명령 문자열이 아니라 **구조화된 필드**라 그 값이
경로인 것이 확실하다. 그래서 셸의 `ls backend` 는 못 잡아도 **`Grep path=backend` 는 잡는다.**
**13회차가 감수한 누락이 이 채널에는 아예 없다.**

### 배선은 matcher 를 고치는 게 아니라 **그룹을 갈랐다**

`folder_md_check` 이 `paid_test_check`·`pre_commit_check` 와 **한 matcher 그룹**에 있었다.
거기에 `Grep` 을 더하면 **나머지 둘도 `Grep` 마다 돈다** — 둘 다 `tool_input.command` 를 읽어
무동작이긴 하지만, 호출 빈도가 제일 높은 도구에 쓸데없는 프로세스 둘이 붙는다. `folder_md_check`
만 새 그룹으로 뺐다. `test_pretooluse_covers_both_shells` 는 그대로 통과한다
(`re.fullmatch("Bash|PowerShell|Grep", "Bash")` 가 맞는다).

## 4. 실패 분석

### 그럴듯한 0을 만들어 미결을 잘못 닫을 뻔했다

첫 집계 함수가 **`0/140`** 을 냈다 — *"경로를 줘도 지침을 여는 일이 한 번도 없다"* 는 뜻이고,
그대로 믿었으면 **«`Grep` 을 덮을 값어치가 없다»** 로 이 미결이 통째로 닫혔다. 원인은
**실사용 경로가 절대 경로**(`C:\agentic-rag-proj\tests`)인데 저장소 상대 경로와 비교한 것이다.
고치니 **52/140**.

**가른 것은 «0이 너무 깨끗하다»는 의심 하나다.** 이 저장소가 여러 번 적은 *"보장된 관측을
증거로 내밀면 안 잰 것이 잰 것처럼 보인다"* 의 한 얼굴인데, 여기서는 **0이 결론을 만들어
주는 방향**이라 더 위험했다. 같은 사실이 구현으로도 넘어왔다 — `grep_paths()` 가 절대 경로를
다루고, 테스트가 상대·절대를 **짝으로** 잠근다.

### `CLAUDE.md` 편집에서 문장을 한 벌 겹쳐 썼다

문단 교체에서 `old_string` 을 문장 중간부터 잡고 `new_string` 에는 앞 문장까지 넣어,
*"…12회차."* 가 **두 번** 들어갔다. `grep -c` 로 세어 곧바로 잡았다 — **읽어서가 아니라
세어서** 보였다.

### 「`Grep`·`Glob`」을 한 묶음으로 둔 미결이 애초에 틀렸다

13회차가 둘을 한 줄로 적었는데, 재보니 **읽을 필드도 다르고**(`path` 대 `pattern`) **값어치도
6분의 1**이다. 묶어 둔 채로 «덮을까» 를 물으면 `Glob` 의 작은 값어치가 `Grep` 의 결정을
끌고 다닌다. 14회차에서 두 줄로 갈랐다.
