## 2. 설계 결정

### (가) 자르는 설계를 버리고 붙이는 설계로 갔다.

초안 지시서는 "구조로 나누고 크면 자른다"였다. 실측이 뒤집었다 — tests/fixtures/
3종에서 요소 자수 중앙값이 PDF 23 / HWPX 15 / 시행령 40 이고 **1200자를 넘는
텍스트 요소가 세 문서 전부 0개**다. PDF 텍스트 블록은 707개 중 349개(49%)가
20자 미만이다. 초안대로 만들면 청크의 절반이 20자짜리가 된다.
상한 분할이 실제로 발화하는 곳은 표뿐이다(시행령의 67행 표 3,243자).

버린 것: 초안 8절 원칙 6("작은 섹션을 인접과 합치지 않는다")을 그대로 두는 안.
같은 초안 16절이 "지나치게 작은 청크가 없는가"를 검증 항목에 넣어 자기모순이었다.
대신 '섹션 안에서는 붙이고 섹션 경계는 안 넘는다'로 바꿨다.

### (나) 제목 판정 신호로 글자 크기를 골랐다. 스타일과 번호·기호 머리는 버렸다.

스타일: AI 가이드 HWPX 의 header.xml 에 스타일이 'Normal' 하나뿐이라 쓸 수 없다.
번호·기호 머리(□ · 1. · 제N조): 직관과 반대로 **큰 글씨와 마커가 겹치는 문단이
AI 가이드에서 PDF 0/74 · HWPX 0/54** 였다. 마커만 보면 PDF 75개 · HWPX 80개 ·
시행령 158개를 제목으로 오인한다. 레벨 힌트로도 아직 안 쓴다.
볼드: 재본 적이 없어서 안 넣었다.

### (다) min(sizes) > body 다. max 가 아니다.

사용자가 "큰 글씨가 사람 이름 같은 단순 강조일 수 있다"를 짚어서 갈랐다.
문단 안에 본문 크기 이하 글자가 하나라도 섞이면 강조로 본다. 실측으로 그런
'혼재' 문단의 실제 내용은 ※인용, 표지 장식, 목차 줄이었다(PDF 4 / HWPX 24·3·1).
이 문서의 `작성 [큰글씨]김동현[/] 수석` 이 정확히 이 규칙에 걸려 본문으로 남는다.

### (라) 본문 크기는 문서별 최빈값이고, 판정은 부등호 하나다.

절대 임계값 버림: 본문이 HWPX 949 / 1500 / 1200, PDF 9.5 로 문서마다 다르다.
배율 임계값 버림: 시행령은 제목 1600 / 본문 1500 으로 차이가 6.7% 뿐이라
1.2배 같은 값을 두면 그 문서의 제목 19개가 통째로 사라진다.
최빈값 동률이면 큰 쪽을 본문으로 잡는다 — 작은 쪽을 고르면 같은 빈도의 큰 본문이
통째로 제목이 되어 문서가 수백 개 섹션으로 쪼개진다. 손해가 비대칭이다.

### (마) 승격을 detect_regions() 안이 아니라 load() 에 뒀다.

regression/baseline.json 이 detect_regions() 출력(리전 수·타입별 수·쪽 집합)을
기준선으로 잰다. load() 에 두면 같은 결과를 얻으면서 기준선이 안 흔들린다.
실제로 대조해서 documents 6건 전부 동일했다.

### (바) pipeline.py 를 안 고쳤다. **누락이 아니라 결정이다.**

CLAUDE.md 의 "새 파이프라인 단계 추가" 4번은 예약 주석을 실제 호출로 바꾸라고
한다. 이번엔 안 했다. 사용자가 "청크를 버리는 구조라면 필수 단계로 넣는 게
맞나"를 짚어 계약을 확인한 결과다 — backend/app/api/routes/documents.py 가
response_model=ParsedDocument 로 ingest() 결과를 그대로 반환하므로 ingest() 의
반환 타입이 곧 공개 HTTP 응답 스키마다. 청크를 내보내는 것은 splitter 결정이
아니라 API 결정이고, 소비자(embedding)가 아직 없다.
버린 안: ingest(split=True) 같은 플래그로 반환 타입을 가르는 것. 반환 타입이
인자에 따라 달라지면 response_model 을 선언할 수 없다.

같은 절차의 설정 3곳 중 **2곳만 해당한다.** offline_config 에는 끌 것이 없다 —
splitter 는 외부 API 를 안 쓴다.

### (사) chunk_id 는 document_key 를 인자로 받고 기본값만 파싱 결과 해시다.

저장소에 document_id 가 없다(backend 는 uuid4() 임시 파일명만 만들고 버린다).
내용 해시를 id 로 못박으면 "재업로드 = 중복"이라는 **indexing 정책**을 splitter 가
앞질러 정하는 셈이 된다. 인자로 열어두면 나중에 진짜 id 를 넘기기만 하면 되고
Chunk 스키마는 안 바뀐다. content_hash 는 loader/content/base.py 것을 재사용했다
(복제하면 해시 규칙이 두 곳으로 갈린다 — contracts.md 3절).

### (아) 제목 경로를 청크 본문에 붙인다(사용자 선택).

버린 안: metadata 로만 두는 것. 표 청크 하나만 검색됐을 때 그게 어느 절 얘기인지
본문만 봐서는 알 수 없다. 대가는 임베딩 입력에 같은 문구가 반복된다는 것이고,
그 영향은 평가 세트가 생겨야 잰다.

## 4. 실패 분석

### (가) 상한을 선언해놓고 넘기고 있었다.

제목 머리를 **분할한 뒤에** 붙이도록 짰다. 그래서 1200 상한에 최대 1258자
청크가 생겼다(PDF 3개 / 시행령 7개 / 학교기록물 9개). 실파일로 분포를 찍어보다
발견했다. 예산에서 머리 길이를 미리 빼는 _body_budget() 으로 고쳤다.
다만 절반 밑으로는 안 깎는다 — 제목 경로가 상한의 절반을 먹는 문서라면 문제는
본문이 아니라 제목이고, 더 깎아봐야 청크 수만 폭발한다.
막은 것: test_cap_holds_after_heading_prefix, test_no_chunk_exceeds_cap(실파일).

### (나) HWPX 를 스타일로 풀려다 막혔다.

hh:style 의 이름(개요 1, 제목 등)으로 승격하려 했다. AI 가이드 HWPX 를 열어보니
스타일이 id=0 'Normal' **하나뿐**이었다. 한컴이 서식을 문단 스타일이 아니라
charPr 로 직접 박는 문서가 흔하다는 뜻이다. 글자 크기로 갈아탔다.
막은 것: test_missing_header_xml_is_safe — header.xml 이 없어도 죽지 않고
승격만 꺼진다.

### (다) 테스트 파일 이름이 충돌해 수집이 통째로 멈췄다.

tests/ingestion/splitter/test_real.py 를 만들었더니 cleaner/test_real.py 와
모듈명이 겹쳐 pytest 가 collection error 로 죽었다(tests/ 에 __init__.py 가 없어
basename 이 곧 모듈명이다). 영역 테스트만 돌릴 때는 안 나고 전체에서만 났다.
test_splitter_real.py 로 개명했다 — loader 쪽 test_hwpx_real.py 와 같은 관례다.
__init__.py 를 뿌리거나 importmode 를 바꾸는 안은 버렸다. 저장소 전체에 없는
구조를 이 파일 하나 때문에 들이는 값은 아니다.

### (라) 항진명제 테스트를 하나 썼다가 고쳤다.

test_split_table_pieces_keep_header 가 `rows[0] == chunk.metadata["rows"][0]` 로
자기 자신을 비교하고 있었다. 통과해도 아무것도 보장하지 않는다. 같은 원본 표에서
나온 조각들을 element_orders 로 묶어 **헤더 행이 하나인지** 보도록 고쳤다.
고치고 나니 AI 가이드 두 판에는 쪼개진 표가 없어 skip 이 됐다 — 그게 정직한 상태다.

## 7. 남은 것

- **표지·간지 장식이 제목으로 올라온다.** 실측: "DNA" · "플러스" · "2019" ·
  "2025. 1." · "- OECD 권고안의 적용 -". 그 결과 heading_path 에 표지가 조상으로
  남는다(예: [공공기관 신뢰가능 AI 구현 실용가이드 > Contents > 요약 > ...]).
  제목 스택의 pop 이 대부분 걷어내 깊이는 2~5로 잡히지만 루트 1~2개가 표지다.
  규칙을 지금 안 만든 이유는 "첫 쪽 제외"류가 표지 여러 쪽인 문서에서 깨지기
  때문이다. plan_log/splitter.md 미결에 있다.
- **AI 가이드 HWPX 는 표를 0개로 센다.** 같은 문서 PDF 판은 10개다.
  _is_layout_box 강등이 유력하지만 **확인하지 않았다.** 로더 쪽 별건이다.
- 청크 크기 상한 1200 과 겹침 150 은 **임시값이다.** 근거가 생기는 시점은
  정답 질의 세트가 생길 때다(plan_log/평가-세트.md).
- 크기 단위가 문자다. 임베딩 모델을 고르면 토큰으로 재판정해야 한다.
- excel/csv 는 못 쟀다. CSV 는 파일 전체가 표 하나, Excel 은 시트당 표 하나에
  max_excel_rows=5000 이라 행 그룹 분할이 제일 크게 걸리는 곳인데 픽스처가 없다.
- splitter 를 ingest() 에 언제 끼울지는 embedding·indexing 이 생겨야 정해진다.
