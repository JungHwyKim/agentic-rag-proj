## 2. 설계 결정

### 오리진 목록만 비우지 않고 미들웨어째 걷어냈다

미결이 *"정하려면: 이 API 의 외부 소비자가 실재하는지"* 로 열려 있었고 답은 **없다**였다 —
화면을 같은 uvicorn 이 서빙하고(`CLAUDE.md` 가 *"빈 `frontend/` 는 이 결정 이후로 쓰이지
않는다"* 로 못 박았다) `evaluation/` 은 HTTP 가 아니라 파이프라인을 직접 부른다.

버린 안은 **오리진 목록만 비우기**다. 값이 하나도 없는 미들웨어는 죽은 설정이 아니라
**죽은 코드**가 되고, 이 저장소는 "합법값이 하나뿐인 설정은 안 만든다"를 반복해 지켜왔다
(`embedding.provider` · `distance` · `qdrant_url`). 대신 되살릴 조건을 `backend.md`
"안 하기로 한 것"에 적었다.

**참조가 정말 죽어 있었다는 근거는 실측이다** — CORS 참조가 코드 4줄 + 리뷰 기준 표 1줄이
전부이고 **테스트 참조가 0** 이었다. 그래서 제거 후 `tests/api` 40개가 전부 통과하는 것이
기대값이었고 실제로 그랬다.

### 미결의 머리(색인 엔드포인트)를 일부러 안 골랐다 — 범위가 아니라 겹침이 이유다

목록의 머리는 여전히 색인 엔드포인트다. 그것은 `pipeline.py` 서명을 바꾸고
`main.py`·`chat.html`·테스트까지 번지는데, `chat.html` 은 다른 세션이 2회차에서 미리보기
생성기까지 붙여 만든 자리다. **사용자가 *"2번이랑 3번 겹치는지 확인해주고"* 로 물어 실제로
재본 뒤 갈랐다** — 그 세션 20분 유휴 · `core/config.py` 는 최초 커밋 이후 무변경 ·
CORS 참조는 코드 4줄 + 리뷰기준 1줄 · 테스트 참조 0. 겹침이 없다는 것이 수치로 나왔기
때문에 이 둘을 골랐다.

### 재는 것과 고치는 것을 미리 갈라 두었다

측정에서 무엇이 나오든 **이번 회차에서는 안 고치기로 계획에 못 박아 두었다.** 결과가
어긋남 0 이라 실제로 쓸 일은 없었지만, **첫 실행이 어긋남 5건을 냈던 시점에 이 약속이
성급한 수정을 막았다**(4절). 재는 것과 고치는 것을 한 회차에 묶으면 "무엇을 보고 그렇게
고쳤나"가 흐려진다 — 이 저장소가 `verify_log`/`task_log` 를 가른 것과 같은 이유다.

## 4. 실패 분석

**측정 첫 실행이 어긋남 5건을 냈고, 다섯 다 거짓이었다.** 코드가 아니라 **내 표본이 조잡한
것**이 원인이었다.

- `.hwpx` — 판정 마커를 `Contents/section0.xml` 로 넣었다. `detect.py:_ZIP_MARKERS` 가
  보는 것은 **`Contents/content.hpf`** 다(HWPX 패키지 매니페스트). 마커가 없으니 `unknown`
- `.doc`·`.ppt`·`.xls`·`.hwp` — OLE 헤더 8바이트 뒤를 `\x00` 512개로 채웠다. 감지는
  `olefile` 로 **스트림 이름**(`WordDocument`·`PowerPoint Document`·`Workbook`·`FileHeader`)을
  읽는데 스트림이 하나도 없으니 전부 `unknown`

**여기서 배운 것은 방향이다.** `verify-log` 0단계가 경고하는 가상 데이터의 위험은
*"합성 문서는 만든 사람의 기대를 그대로 갖고 있어 자기 확인이 된다"* — 즉 **없는 결함을
없다고** 통과시키는 쪽이다. 이번은 반대로 **없는 결함을 있다고** 보고했고, 그대로 믿었으면
멀쩡한 감지 코드를 고칠 뻔했다.

두 가지가 막았다. (1) 기대값(22종 OK)을 **돌리기 전에** 적어둬서 불일치가 눈에 띄었고,
(2) "이번엔 안 고친다"를 계획에 못 박아 둬서 원인을 찾을 시간이 생겼다. 원인을 찾자
`detect.py` 를 읽는 것으로 끝났다 — 표본을 고치니 어긋남 0 이 됐다.

레거시 4종은 고칠 수가 없어 **"못 잼"으로 갈라 남겼다.** `olefile` 이 읽기 전용이라 표본
자체를 만들 수 없다. 어긋남으로 세면 없는 결함이 기록에 박히고, 빼면 안 잰 것을 잰 척하게
된다.
