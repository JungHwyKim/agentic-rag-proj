## 2. 설계 결정

### 부정 예시를 뺀다 — 표본이 제일 많은데도 뺀다

부정 예시는 판정이 늘 *불충분* 이라 **재시도를 끝까지 돌아 회차를 제일 많이 준다.** 그런데
놓칠 정답이 애초에 없어 «다음 회차가 값을 했나» 에 **원리적으로 못 답한다.** 그래서 세트를
`qa_set.jsonl` 60건(전부 정답 실재)으로 골랐고, `run_eval` 이 검색 채점에서 빼는 것과 같은
이유라 **같은 함수(`split_scorable`)를 쓴다.**

버린 것은 **사람 세트 43건**이다. 재시도 회차는 훨씬 많이 나오지만 그 대부분이 부정 25건에서
나오고, 그 회차들은 이 물음에 답을 못 한다 — 사실상 긍정 18건만 쓰는 셈이다.

### 재시도를 강제하되 **진짜 판정을 지우지 않는다**

루프는 판정이 *불충분* 일 때만 재시도한다. 그대로 두면 잘 찾은 질의가 한 바퀴에 끝나 「표본 1」이
「표본 5」가 되고 끝난다. 그래서 `_ForcingEvaluator` 가 **진짜 판정을 부르고 그 값을 기록한 뒤**
루프에는 `insufficient` 를 돌려준다.

**그 한 줄이 «한 번 돌려 둘 다 답한다» 의 전부다.** 실제로 이번 실행의 제일 큰 수치가 거기서
나왔다 — 기록해 둔 진짜 판정으로 되짚으니 **60건 중 56건이 첫 검색에서 *충분*** 이었다.
지우고 가짜만 남겼으면 그 사실을 영원히 못 봤고, 표는 «근거 동일 26회차» 로 멀쩡해 보였을 것이다.

버린 것은 **판정 자체를 빼는 안**(`--no-record-verdict`)이다. 훨씬 싼데(212호출이 지배항이다)
그 열이 사라진다 — 플래그로는 남겨 뒀다.

### 생성은 안 부른다

측정 축이 `step_retrieve` 안이라 생성이 안 닿는다. 가짜 생성기로 질의당 한 번의 유료 호출을
없앴다(27회차 실물 프로브 선례).

### `max_retries` 는 제품 기본값 3

2로 두면 근거 동일 회차가 **마지막 회차**가 되어 짝지을 다음 회차가 없는 경우만 는다 —
28회차 단일 프로브가 정확히 그래서 0비트를 얻었다. **그래도 16/26 이 «못 봤다» 로 나왔다.**

## 4. 실패 분석

**규칙을 두 번 고쳤고, 둘 다 «재는 것이 짐작으로 바뀌는» 자리였다.**

**첫째 — 도구가 실패한 회차를 실사용으로 셀 뻔했다.** `_would_run` 이 «근거 0건이면 다시
찾는다»(Router 규칙 5)를 쓰는데, `record_tool_call()` 은 **실패 시 `retrieved_chunks` 를 아예
안 건드린다.** 그러니 Router 가 그때 본 것은 앞 회차 근거이지 0건이 아닌데, 이 도구는 실패
회차의 `chunk_ids` 를 `[]` 로 적어 **규칙을 거꾸로 읽는다.** 앞 회차를 되짚어 흉내 낼 수도
있었지만 그건 재는 것이 아니라 짐작하는 것이라 `None`(판단 불가)으로 뒀다.

**둘째가 더 컸다 — 결론을 바꿀 수 있었다.** 회차 N **자신의** 판정으로 «실사용 회차» 를 셌는데,
그 판정이 답하는 것은 *N 다음으로 갔을까* 이고 물어야 할 것은 ***N 에 닿았을까*** 다. 닿으려면
0~N-1 이 **전부** *불충분* 이어야 한다. 고치기 전 규칙은 **실사용이 0회차에서 멈췄을 질의의
2회차를 «실사용 회차» 로 셀 수 있었다.** 이번 실행에서는 두 규칙이 우연히 같은 답(0)을 냈지만,
**같은 답이 나온 것과 같은 것을 재는 것은 다르다.**

원자료(회차별 `real_verdict`·`succeeded`)를 JSON 에 남겨 둔 덕분에 **다시 돌리지 않고**
새 규칙을 먹여 확인할 수 있었다 — 유료 실행을 한 번 아낀 자리다.

**그리고 훅이 이름 변경을 잡아 줬다.** `_would_run` → `_wants_more` 로 바꾼 순간
`auto_test_check.py` 가 collection error 를 물어 왔다. 그런데 진짜 문제는 이름이 아니라
**기존 테스트 하나가 이제 틀린 것을 검증하고 있었다는 것**이라, 그 절을 통째로 다시 썼다.

**막다른 길은 없었다.** 다만 배경 실행을 `| tail -80` 으로 파이프해 둬서 **20분 넘게 진행이
0바이트였다** — 다음에는 파이프 없이 돌린다.

## 5. 회귀 테스트

`tests/evaluation/test_retry_diff.py` 에 35건. 위 4절과 이어지는 것들:

| 잠근 것 | 테스트 |
|---|---|
| 도구가 실패한 회차는 판단 불가 (4절 첫째) | `test_a_failed_round_is_not_judged` |
| **닿지도 않았을 회차를 실사용으로 안 센다** (4절 둘째) | `test_a_round_production_never_reaches_is_not_a_production_round` |
| 끝까지 불충분이면 닿는다 (그 거울상) | `test_a_reachable_round_is_counted_as_production` |
| 판단 불가를 만나면 그 아래가 전부 짐작이라 None | `test_production_stop_gives_up_at_an_unjudgeable_round` |
| 강제해도 진짜 판정이 남는다 · `failed` 도 그대로 | `test_forcing_keeps_the_real_verdict_and_still_forces_a_retry` · `test_forcing_records_failed_as_failed` |
| 마지막 회차는 «못 봤다» 이지 «안 도왔다» 가 아니다 | `test_an_unchanged_last_round_is_counted_as_unseen_not_as_no_help` |
| 부정 예시만 있는 세트는 저장소를 열기 전에 멈춘다 | `test_a_set_of_only_negatives_stops_before_opening_anything` |
| 회차 수와 `retry_count` 가 어긋나면 터진다 | `test_a_round_count_mismatch_raises_instead_of_shifting_the_pairs` |

**못 막은 것**: 이 도구가 *유료 경로에서* 제대로 도는지는 단위 테스트가 원리적으로 못 잡는다.
배선은 `--limit 1` 로 먼저 확인하는 절차가 대신한다.
