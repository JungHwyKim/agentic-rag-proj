# 기본 임베더를 KURE-v1 로 갈아타고, GPU 축을 열고, OpenAI 를 그림자로 쌓는다

- 작업일: 2026-08-25
- 검증 방법: `ruff` + 전체 `pytest` + 평가 2회 + **실서버 왕복 5종**.
  **실제 청구 $0.00 에 가깝다** — 평가는 캐시 전량 적중(`tokens 0 · calls 0`),
  실서버는 세 줄짜리 문서 3건의 그림자 임베딩뿐이다. `-m integration` 안 돌림

## 2. 설계 결정

### 갈아타기를 `.env` 가 아니라 코드 기본값으로 했고, 그래서 `torch` 를 본체로 옮겼다

`.env` 로만 바꾸는 안을 버렸다 — **"기본값이 무엇인가" 의 답이 저장소 밖에 살게 된다.**
다음 사람이 코드만 보면 OpenAI 로 읽는다.

코드 기본값을 바꾸면 `requirements-local.txt` 의 존재 이유(*"안 쓰는 사람에게 2.27GB"*)가
뒤집힌다 — **안 쓰는 사람이 없어진다.** 그래서 본체로 옮기고 그 파일을 지웠다.
**대가를 알고 치렀다**: 기본 pytest 가 가중치를 안 받는 근거가 둘에서 하나가 된다.

### 그림자를 목록이 아니라 **하나**로 뒀다

`shadow: tuple[VectorStore, Embedder] | None` 이고 `Sequence` 가 아니다.
목록으로 열면 합법값이 하나뿐인 축이 또 생기는데, **바로 그것이 이틀 전 `extra_dense` 를
죽인 이유다**(다중 임베더 융합, 호출부 0개). 셋째 모델이 실재하면 그때 연다.

### 그림자 실패를 **삼킨다** — 이 저장소에서 드문 쪽이다

embedding·indexing 은 실패를 예외로 올리고, 그 근거는 *"내려갈 폴백 층이 없다"* 이다.
**여기는 주 컬렉션이 이미 성공한 뒤라 층이 실재한다.** 그림자가 죽었다고 업로드를 막으면
OpenAI 장애가 서비스를 멈춘다 — 주 모델은 멀쩡한데도.

**대신 구멍이 드러나야 한다.** `ShadowIndexResult.error` 로 올리고 목록에 표시를 단다.
*조용히 없어지는 것*과 갈리는 자리이고, 표시가 없으면 무엇을 다시 올릴지 알 방법이 없다.

**채우는 코드는 안 만들었다** — 색인이 `delete → upsert` 라 멱등이고 `document_id` 가
파일 이름에서 파생되므로 **재업로드가 곧 채우기**다. 실서버에서 표시 1→0 으로 확인했다.

### `sibling_for()` 를 되살렸다 — 이틀 전에 지운 API 다

지운 근거는 *"호출부가 0개인 죽은 축"* 이었다. 이번엔 살아 있는 호출부가 생겼다(색인·삭제).
**잣대는 그대로고 사실이 바뀐 것이다.** 반대로 `get_store(shares_client_with=)` 는
**안 되살렸다** — 융합 회차에 `run_eval` 이 쓰던 것이고 지금 호출부가 없어, 되살리면
그 자리가 다시 죽은 축이 된다.

### `device` 를 캐시 salt·컬렉션 이름에 **안 넣었다**

같은 모델·같은 차원이고 차이가 float 오차 수준일 것으로 본다. 넣으면 GPU 로 옮기는 순간
캐시가 전량 미스가 되고 컬렉션이 갈려 **옛 색인이 통째로 고아가 된다** — `provider` 를
salt 에 안 넣은 3회차 판단과 같은 잣대다.

**다만 이건 실측이 아니다**(CUDA 머신이 없다). 미결로 열어 뒀고, 처음 GPU 를 쓸 때
CPU 벡터와의 코사인 차이를 재기로 했다. **자동 감지(`cuda if available`)는 안 한다** —
그것이 정확히 *"머신마다 조용히 갈리는"* 모양이다.

### 평가 기준선에 라벨을 박았다 — 사용자가 제 안을 고친 자리

나는 *"`DEFAULT_EMBEDDING_PROFILE` 을 `baseline` 으로 두면 함정을 안 건드린다"* 로
제안했는데, 사용자가 **"그건 피한 것이지 없앤 것이 아니다"** 로 고쳤다. 맞다 —
근본 원인은 기본값이 아니라 **`baseline.json` 에 라벨이 없어 암묵적 fallback
(`.get(k, DEFAULT)`)에 기대는 것**이다. 새 리포트는 라벨을 항상 쓰므로 라벨 없는 파일은
그 하나뿐이었다. 박으니 비교가 *실제 라벨 대 실제 라벨* 이 되어 기본값이 몇 번 바뀌든 안전하다.

## 4. 실패 분석

### 방어막이 한 겹 줄어든 대가를 **세 곳에서 실제로 치렀다**

예상은 했지만 *어디가 뚫리는지*는 몰랐다. 셋 다 provider 를 안 박고 기본값에 기댄 자리다.

| 자리 | 증상 |
|---|---|
| `tests/ingestion/embedding/conftest.py` | **241초 · 27 failed** — 가짜 OpenAI 클라이언트가 안 꽂히고 2.2GB 실제 적재 |
| `tests/ingestion/indexing/test_indexing_real.py` | **120초 초과 · Windows access violation** |
| `tests/conftest.py` `offline_config` | provider 만 박고 **model 을 안 박아** 컬렉션 이름이 `nlpai-lab/KURE-v1` — **테스트는 도는데 이름만 틀림** |

**가중치가 캐시에 없는 머신이었으면 셋 다 조용히 내려받았을 것이다.** 셋째가 특히
고약하다 — 아무것도 안 깨지고 파생 이름만 틀리므로, `test_collection_name_is_reported`
하나가 없었으면 못 봤다.

막은 방법: 세 자리에 provider(그리고 model)를 박고, **`test_local_embedder.py` 에 가드
넷**을 더했다 — 배포 기본값이 `local`/`KURE-v1` 인가 · `device` 기본이 `cpu` 인가 ·
그 device 가 `_make_model()` 까지 실려 가는가 · **핀이 실제로 기본값을 뒤집는가**.
마지막 것이 요점이다: 기본값과 핀이 같아지면 기존 테스트는 통과하는데 방어는 사라진다.

### 이름 공간 테스트가 깨졌는데, 규칙이 아니라 **대리 지표**가 깨진 것이었다

`test_the_two_name_spaces_do_not_overlap` 이 *"기본 모델 이름에 `/` 가 없다"* 로
잠그고 있었다. 규칙(*OpenAI 이름엔 슬래시가 없고 로컬은 `org/name`*)은 그대로인데,
**기본값이 반대편으로 가면서 대리 지표만 무너졌다.** provider 를 함께 읽어 방향을 정하도록
고쳤다 — 다음에 또 뒤집혀도 안 깨진다.

### 실서버 검증 설계가 한 번 틀렸다 — 코드가 아니라 내 쪽이었다

그림자 실패를 만들려고 키를 깨고 **같은 문서를 다시** 올렸는데 표시가 안 붙어 잠깐
버그로 봤다. 원인은 **임베딩 캐시 적중**이다 — 같은 내용이면 salt·해시가 같아 API 를
아예 안 부르므로 키가 깨져도 그림자가 성공한다. 캐시에 없는 새 내용으로 다시 재니
기대대로 났다. **재현 절차에 그 함정을 적어 뒀다.**

## 7. 남은 것

- **GPU 벡터가 CPU 와 얼마나 다른가** — 못 쟀다(이 머신 torch 가 `2.13.0+cpu`).
  `device` 를 캐시 salt 에 안 넣은 판단이 이 값에 걸려 있다
- **이중 색인을 언제 걷나** — *다시 볼 조건*: **새 문서에 정답 질의가 붙을 때.**
  문서 수로 안 적는 이유는 `hit@10` 도 `overlap.py` 도 **정답 span 이 있어야 돌기** 때문이다
- **브라우저 확인** — `비교색인 없음` 표시를 HTML 문자열로만 봤다
- **옛 494 point 는 되살릴 수 없다** — 원본 보관이 그 문서들보다 나중이라 재업로드가 유일한 길
- **실코퍼스 KURE 색인 시간** — 안 쟀다. CPU 라 느릴 수 있고 그것이 `device` 를 연 이유다
