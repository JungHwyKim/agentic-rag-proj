## 1. 무엇을 바꿨나

한 세션에 둘을 했고 **한 파일에 남긴다.** 건드린 코드는 다르지만 둘 다 *이 저장소가 자기

어느 문제에 딸린 것인지는 2절이 갈라 적는다.

- `.claude/hooks/_hookutil.py`
  `child_env()` 신설. 자식 프로세스에 `PYTHONIOENCODING=utf-8` 을 박는다. 두 훅이 같은
  이유로 필요해서 공용부에 뒀다
- `.claude/hooks/auto_test_check.py`
  `_run_pytest()` 가 그 환경을 넘긴다. 영역 테스트·Stop 게이트가 여기로 돈다
- `.claude/hooks/pre_commit_check.py`
  `_run()` 이 같은 환경을 넘긴다. 이 파일은 여태 `_hookutil` 을 안 썼어서 import 가 하나 는다

## 2. 설계 결정

### A-1. 잘못 붙은 라벨을 «고쳤다» — 지우지도, 두지도 않았다

`data/queries.jsonl` 64~66은 브라우저로 넣은 측정 질의인데 `X-Query-Source` 를 안 붙여
기본값 `user` 로 적혔다. 64/65가 완전 일치 반복이고 65가 `cached=true` 다.

**버린 안 ① — 지운다.** 65의 `cached=true · elapsed_ms=1`(64는 6837)은 `exact` 답변
캐시가 **화면 경로에서 실제로 문** 유일한 user-갈래 관측이다. 그리고 *«헤더를 안 붙인
측정은 다시 실사용으로 세어진다»* 가 실제로 일어났다는 흔적도 함께 사라진다 — 그 문장은
`query_log.py` docstring 이 이 칸을 만들며 **미리 적어 둔 예고**라, 예고가 맞았다는 관측을
지우는 셈이다.

**버린 안 ② — 그대로 두고 산문에만 적는다.** 옛 53줄이 그렇게 처리돼 있어 선례처럼
보이는데, **성질이 반대다.** 옛 줄은 `source` 키가 **아예 없어** README 8절 스니펫의
`r.get("source") == "user"` 에서 **자동으로 빠진다**(fail-safe). 이 3줄은 `user` 라고
**적혀 있어 자동으로 들어간다**(fail-open). 그래서 *«그 3줄은 빼고 읽으세요»* 를 어디에
적어도 스니펫은 계속 세고, 그것은 **사람이 매번 기억해야 하는 규약**이 된다 — 이 저장소가
훅마다, 픽스처마다 되풀이해 적어 온 실패 모드가 정확히 그것이다.

**고른 근거는 크기다.** 컷은 «`source=="user"` 50줄에서 적중률 5% 미만이면 끈다» 인데, 이
3줄은 그 50줄에 적중 1건을 **고정으로** 얹는다 — **+2.0%p 이고 컷 5%의 40%다.** 3줄이
이만큼 미는 것을 주석으로 감당할 수 없다.

**고쳐도 되는 근거는 `source` 가 관측이 아니라는 것이다.** `query_log.py` docstring 이
이 칸을 *«갈래를 데이터에 남기는 것»* 이라 못 박았고, 갈래를 아는 authority 는 사람이다 —
옛 53줄도 결국 손으로 갈랐다. 질의·시각·`cached`·`elapsed_ms`·`verdict` 는 한 바이트도
안 건드렸고, 되돌리면 원본과 바이트가 같은 것을 확인했다.

### A-2. `source_note` 같은 키를 새로 만들지 않았다

교정을 데이터 안에 보이게 남기는 안이 있었다. 버렸다 — 3줄만 키를 더 갖는 것은
`verdict`·`rewritten`·`rewrite_mode` 가 지키는 **«키를 늘 쓴다»** 를 어긴다(빼면 *«꺼져
있었다»* 와 *«옛 형식»* 이 집계에서 안 갈린다는 그 규약이다). `append_query_log()` 가
쓰지 않는 키가 3줄에만 있으면 읽는 쪽이 생산자를 못 찾는다. 대신 README 8절 산문에 적었다.

### A-3. 라벨을 `probe` 로 골랐다

67번이 **같은 세션(07:52~07:58)·같은 질의**인데 이미 `probe` 다 — 07:58부터 헤더를 붙이기
시작한 것이라, 새 이름을 지으면 한 측정 세션이 두 라벨로 갈린다.

### B-1. `PYTHONIOENCODING=utf-8` 을 고르고 `PYTHONUTF8=1` 을 버렸다

실측으로 **둘 다 U+FFFD 0** 이다. 가른 것은 부작용의 범위다 — `PYTHONUTF8=1` 은 자식의
**모든 파일 I/O 기본 인코딩**까지 바꿔서, *훅이 돌린 pytest* 와 *사람이 손으로 돌린 pytest*
가 다른 조건이 된다. 훅은 사람이 나중에 재현할 수 있어야 하는 검사다.

**다만 그 차이를 실제로 재지는 않았다** — 문서상의 성질로 골랐다(7절).

### B-2. `errors="replace"` 를 빼는 안을 버렸다 — 둘은 한 쌍이다

*«대체문자로 뭉개지느니 예외로 죽는 편이 눈에 띈다»* 가 그럴듯하다. 그런데 호출부가 잡는
예외는 `TimeoutExpired` 와 `OSError` 뿐이라 `UnicodeDecodeError` 는 **훅 자체를 죽인다** —
사유를 못 읽는 대신 검사가 통째로 사라진다. `errors` 는 훅이 살아남게 하고 `env` 는 사유가
읽히게 한다. 하나만으로는 둘 다 안 된다.

### B-3. 공용부에 뒀다 — 인라인 두 벌을 버렸다

`pre_commit_check.py` 는 여태 `_hookutil` 을 안 쓰고 `PROJECT_ROOT` 와 `_venv_python()` 을
**자체 복제**해 왔다. 그 관례를 따르면 import 가 안 늘어난다. 버린 이유는 값어치가 있는
것이 코드 두 줄이 아니라 **이유 주석**이기 때문이다 — 복제하면 한쪽이 반드시 낡고, 낡은
쪽을 다음 사람이 본보기로 베낀다(CLAUDE.md 가 `openai_llm.py` 에서 이미 겪은 모양이다).

### B-4. 테스트를 파일별이 아니라 «훅 전체 ast 훑기» 로 갔다

처음 계획은 호출부마다 `subprocess.run` 을 가로채 `env` 를 단언하는 것이었다. 바꾼 이유는
그러면 **새로 생긴 훅이 조용히 빠지기** 때문이다 — 검사가 있는 줄 알았는데 없는 상태이고,
이 저장소의 훅들이 공통으로 두려워하는 그 실패 모드다. `test_every_hook_script_is_wired`
와 같은 모양으로, 훅 디렉터리 전체에서 «`encoding` 은 주는데 `env` 가 없는 `.run()`» 을
찾는다.

**이 검사가 무언가를 잡는다는 것은 실측했다** — 같은 규칙을 HEAD 판(고치기 전)에 걸면
`auto_test_check.py:168` 과 `pre_commit_check.py:68` **둘 다 걸리고**, 나머지 훅 다섯은
양쪽 다 0건이다. 바이트로 받아 직접 디코드하는 `_hookutil.changed_paths()` 의 `git -z` 는
`encoding` 을 안 줘서 애초에 안 걸린다 — **규칙이 «텍스트로 받는 호출» 만 겨냥한다는 뜻**
이고, 그쪽을 예외 목록에 손으로 넣지 않아도 되는 것이 이 형태를 고른 부수 효과다.

감수 사항은 소스 구조를 본다는 것이다 — `subprocess.run` 을 다른 이름으로 감싸면 못 본다.

### B-5. 왕복 테스트에 대조군을 넣었다

`test_child_env_makes_korean_readable` 은 «`child_env()` 로 돌리면 한국어가 읽힌다» 만
재면 **`child_env()` 가 빈 dict 를 돌려줘도 통과한다** — 부모 환경이 이미 utf-8 이면 두
갈래가 똑같이 성공한다. 그래서 `cp949` 를 일부러 깔고 **안 박은 쪽이 깨지는 것까지**
단언한다. CLAUDE.md 의 *«그 테스트는 `warm_up` 을 모킹하면 안 된다 — 모킹하면 핀이 없어도
통과한다»* 와 같은 자리다.

## 4. 실패 분석

### 탐침이 `env` 를 만들고 안 넘겨, 정반대 결론을 한 번 냈다

첫 탐침 스크립트가 `env = os.environ.copy(); env.update({"PYTHONIOENCODING": "utf-8"})`
까지 해 놓고 `subprocess.run(...)` 에 **`env=env` 를 빠뜨렸다.** 두 조건이 U+FFFD **52로
똑같이** 나왔고, 거기서 *«`PYTHONIOENCODING` 은 pytest 자식에 안 먹는다 — pytest 가 자기
터미널 라이터를 따로 잡는 모양이다»* 라는 그럴듯한 기전까지 세웠다.

**두 번 돌려 같은 값이 나온 것이 오히려 확신을 줬다** — 같은 버그가 두 번 돌면 안정된
관측처럼 보인다. 가른 것은 조건을 늘려(`PYTHONUTF8=1`, `-s`) **인라인으로 다시 짠 것**이고,
그 판에서는 전부 0이 나왔다. 두 판이 어긋나서야 호출을 한 줄씩 대조했다.

교훈은 하나다 — **«A와 B가 똑같이 나왔다» 를 결론으로 쓰기 전에 B가 실제로 적용됐는지부터
본다.** 지금 재현 스크립트는 조건마다 `env` 를 인자로 받아 빠뜨릴 자리가 없다.

### f-string 안 백슬래시로 교정 스크립트가 죽었다 — 그런데 그게 다행이었다

`f"CRLF {before} -> {out.count(b'\r\n')}"` 가 Python 3.11 에서 SyntaxError 다.
**파스 단계에서 죽어 백업도 쓰기도 일어나지 않았다.** 만약 실행 중간에 죽었다면 되돌릴
diff 가 없는 파일(gitignore)이 반쯤 고쳐진 채 남고 백업도 없었다.

그래서 지금 스크립트의 순서는 **① 전체 검증(«user 라벨이 그 3줄뿐인가») → ② 백업 → ③
쓰기** 다. 검증을 백업보다 앞에 둔 것은, 대상이 아닌 파일을 백업하는 것 자체가 «고칠
파일을 잘못 짚었다» 를 감추기 때문이다.

### `errors="replace"` 를 «없는 것» 으로 알고 시작했다

권고가 `errors="replace"` 와 `PYTHONIOENCODING` 을 한 쌍으로 제안했는데, 읽어 보니
`errors` 는 이미 두 훅 모두에 있었다. **그리고 그것이 증상의 나머지 반이었다** — 없었으면
훅이 `UnicodeDecodeError` 로 죽어 눈에 띄었을 것을, 있어서 조용히 대체문자가 됐다.
«없는 걸 넣자» 가 아니라 **«있는 것이 다른 반쪽을 가리고 있었다»** 가 맞는 서술이고,
그래서 두 훅의 주석이 그 둘을 *한 쌍* 으로 적는다.

## 7. 남은 것

- **`pre_commit_check` 를 실제 커밋 경로로 안 돌렸다.** `env=` 가 붙은 것은 ast 로,
  `child_env()` 는 단위로 확인했지만 **커밋을 실제로 막는 상황에서 사유가 읽히는지는 안
  봤다.** `tests/hooks/` 에 `test_pre_commit_check.py` 가 아예 없는 것도 그대로다 — 커밋을
  막는 쪽이라 사유를 못 읽는 대가가 더 큰데 검사는 더 얇다
- **`PYTHONUTF8=1` 을 버린 근거가 관측이 아니다.** 자식의 파일 I/O 가 실제로 무엇이
  달라지는지 이 저장소에서 재지 않았다. 문서상의 성질로 골랐다
- **훅이 Claude Code 에서 뜰 때의 실제 환경을 안 찍어 봤다.** 이번 측정은 셸에서
  `PYTHONIOENCODING` 을 지운 조건을 *만들어* 잰 것이다. 증상이 났다는 사실이 방증이지만
  직접 확인은 아니다
