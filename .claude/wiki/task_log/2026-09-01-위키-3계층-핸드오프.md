## 2. 확정 안 된 것 — 그리고 이 세션이 세 번 헛짚었다

**미결은 하나다 — 2판을 (a)(b)(c) 중 무엇으로 가나.**

| 안 | 무엇을 | 무엇을 잃나 |
|---|---|---|
| **(a) CLAUDE.md 요약을 지우고 가리킨다** | 전문만 남는다 | **보장** — 뿌리 한 파일은 세션 시작에 통째로 실리는데 그것이 사라진다 |
| **(b) 둘 다 둔다 (지금)** | 요약은 보장되고 전문은 필요할 때 | 지킬 것이 «둘이 안 어긋나는가» 로 바뀐다 — **검사로 만들 수 있다** |
| **(c) knowledge 에 전문이 없는 것만 내린다** | 규모가 작다 | 규모를 **아직 모른다** |

**헛짚은 것 셋 — 다음 세션이 같은 자리를 밟지 않도록 적는다.**

1. **`wc -m` 을 문자로 믿었다.** 회차 전반부의 「자수」가 전부 바이트였고, 그 탓에
   ① *"CLAUDE.md 의 문자≈토큰은 이 캡에 쓰면 안 된다"*(정반대였다) ② *"`backend.md` 는 여유
   1.2%라 폴더로 승격해야 한다"*(실제로는 캡의 49.6%) 둘을 틀리게 말했다. **둘 다 되돌렸다**
2. **`next-stages.md` 를 「낡았다」고 판단했다.** 제목만 *"아직 구현되지 않은 단계"* 이고 본문은
   스스로 *"이 파일의 옛 전제는 더 이상 맞지 않는다"* 를 적고 현재 상태를 정확히 나열한다 —
   **그것이 곧 query 층의 본문이었다.** 게다가 자체 「승격 규칙」과 충족된 「다시 볼 조건」까지
   갖고 있었다. **파일을 낡았다고 부르기 전에 그 파일이 자기에 대해 뭐라고 적었는지 읽는다**
3. **분할 커버리지 검사가 경계 오류를 못 잡았다.** README 구간을 3줄 일찍 끊어 **답변 캐시
   문단이 통째로 빠졌는데** 「모든 줄이 어딘가로 갔다」는 통과했다(빠진 줄이 `DROPPED` 에
   들어 있었다). **커버리지는 «어디로 갔나» 만 보고 «경계가 맞나» 는 못 본다** — 각 구간 첫
   줄의 시작 문자열을 앵커로 못 박아 잡았다

## 3. 그래서 무엇을 어떻게 재나

**재는 것**: CLAUDE.md 가 *"상세는 저기 있다"* 고 가리키는 온디맨드 문서를, **그 주제를 만진
세션이 실제로 열었나.**

**제일 큰 함정을 먼저 적는다 — 읽기를 `Read` 도구로만 세면 안 된다.** 전사 표본(앞 6파일
3,200줄)에서 **`Read` 26회 vs `Bash` 224회**다. auto mode 가 `cat`·`sed` 를 지시하므로,
`Read` 만 세면 도달률이 **엉뚱한 이유로 0에 가깝게** 나온다. 15회차가 *"`Read` 가 구한 것은
9건뿐"* 으로 밟은 그 자리다.

```python
# scratchpad 에 두고 저장소에 남기지 않는다. 유료 호출 0 — 로컬 파일만 읽는다.
#
# 전사 구조(실측): 각 줄이 JSON 이고 최상위에 sessionId·cwd·gitBranch·message 가 있다.
# 도구 호출은 message.content 의 {"type":"tool_use","name":...,"input":{...}} 다.
import json, pathlib, re
from collections import defaultdict

DIR = pathlib.Path.home() / ".claude/projects/C--agentic-rag-proj"

# (주제, 그 주제를 만졌다고 볼 경로 조각, 그 주제의 «지침 포인터» 문서들)
TOPICS = {
    "loader":   ("rag_pipeline/ingestion/loader",   ["ingestion/loader/__init__.py"]),
    "cleaner":  ("rag_pipeline/ingestion/cleaner",  ["ingestion/cleaner/__init__.py"]),
    "splitter": ("rag_pipeline/ingestion/splitter", ["ingestion/splitter/__init__.py"]),
    "embedding":("rag_pipeline/ingestion/embedding",["ingestion/embedding/__init__.py"]),
    "indexing": ("rag_pipeline/ingestion/indexing", ["ingestion/indexing/__init__.py"]),
    "retrieval":("rag_pipeline/retrieval",          ["retrieval/__init__.py"]),
    "generation":("rag_pipeline/generation",        ["generation/__init__.py"]),
    "evaluation":("evaluation/",                    ["evaluation/README.md"]),
}
# **근거 포인터는 따로 센다** — 안 읽어도 정상이라 합치면 도달률이 아래로 밀린다
EVIDENCE = re.compile(r"\.claude/wiki/(verify_log|plan_log)/")

def paths_in(block):
    """도구 호출 하나가 건드린 경로 문자열 전부. **command 를 반드시 포함한다.**"""
    inp = block.get("input") or {}
    out = []
    for k in ("file_path", "path", "notebook_path"):
        if isinstance(inp.get(k), str):
            out.append(inp[k])
    for k in ("command", "pattern"):          # Bash·PowerShell·Grep — 여기가 대부분이다
        if isinstance(inp.get(k), str):
            out.append(inp[k])
    return [p.replace("\\", "/") for p in out]

WRITERS = {"Edit", "Write", "NotebookEdit"}
READERS = {"Read", "Grep"}
SHELL   = {"Bash", "PowerShell"}

touched, opened = defaultdict(set), defaultdict(set)
for f in sorted(DIR.glob("*.jsonl")):
    sid = f.stem
    for line in f.open(encoding="utf-8", errors="replace"):
        try: rec = json.loads(line)
        except Exception: continue
        msg = rec.get("message")
        if not isinstance(msg, dict): continue
        for b in msg.get("content") or []:
            if not (isinstance(b, dict) and b.get("type") == "tool_use"): continue
            name, ps = b.get("name"), paths_in(b)
            for topic, (marker, docs) in TOPICS.items():
                # 만졌나 — 편집 도구의 file_path 또는 셸 명령 안의 경로
                if name in WRITERS | SHELL and any(marker in p for p in ps):
                    touched[topic].add(sid)
                # 열었나 — Read 만이 아니라 셸의 cat/sed/head/grep 도 센다
                if name in READERS | SHELL and any(d in p for p in ps for d in docs):
                    opened[topic].add(sid)

print(f"{'주제':<12}{'만진 세션':>8}{'문서를 연 세션':>14}{'도달률':>8}")
for t in TOPICS:
    n, k = len(touched[t]), len(touched[t] & opened[t])
    print(f"{t:<12}{n:>8}{k:>14}{(k/n if n else 0):>8.2f}")
```

**`TOPICS` 의 「지침 포인터」를 무엇으로 잡을지가 이 측정의 전부다.** 위 표는 모듈 docstring 과
`evaluation/README.md` 를 넣었다 — CLAUDE.md 가 *"각 단계의 상세 계약과 실측 근거는 그 단계
`__init__.py` 모듈 docstring 에 있다"* 로 **명시적으로 가리키는** 것들이다. 넣기 전에 그
문장이 아직 CLAUDE.md 에 있는지 확인한다.

## 7. 배경 — 이 문제가 어떻게 열렸나

사용자가 3계층 위키 설계 원칙(Overview / Knowledge / History)을 가져와 *"프로젝트에 가지고
있는 정보로 이렇게 바꿀 수 있어?"* 라고 물은 것이 시작이다. 세어 보니 **History 는 이미 있고
Knowledge 도 반은 있었다** — `rag-code-review/references/*.md` 8개가 컴포넌트 단위 「현재
규칙」인데 스킬 폴더에만 있어 진입점이 없었다. 그래서 이 판이 실제로 연 것은 둘뿐이다.

**함정을 내릴지가 2판으로 밀린 것은 바로 전날(2026-09-01) 사용자가 못 박은 결정 때문이다** —
`plan_log/문서-최신성.md` 15회차의 ***"분리로는 안 줄인다"***. 채널은 다르지만(폴더 `CLAUDE.md`
= 훅 `additionalContext` 호출당 10,000자 → 15.9% 잘림 / wiki = `Read` 상한 없음) **«뿌리 한
파일은 세션 시작에 통째로 실린다» 는 보장이 똑같이 사라진다.** 즉 이 결정은 **잰 것(15.9%
잘림)과 안 잰 것(누락률)의 교환**이고, 그래서 순서를 1판 → 측정 → 2판으로 갈랐다.

**이 문서에 `## 7. 남은 것` 이 없는 것은 규약 위반이 아니다** — 핸드오프 형식이라 절 구성이
다르고, `openwork.SECTIONLESS_BY_DESIGN` 에 사유와 함께 적어 뒀다.
남은 일은 위 3·4절이 그 자리이고, 기능 축의 미결은
[.claude/wiki/plan_log/문서-최신성.md](../plan_log/문서-최신성.md) 「미결」이 갖는다 —
**둘을 함께 세면 같은 일이 두 번 잡힌다.**
