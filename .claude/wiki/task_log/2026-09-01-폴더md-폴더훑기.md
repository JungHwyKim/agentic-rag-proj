## 2. 설계 결정

### 넓히되 **구분자를 품은 토큰만** 디렉터리로 인정한다

버린 것은 **「디렉터리를 맨낱말까지 센다」**이고, 버린 이유는 취향이 아니라 실측이다.

같은 11개 명령에 규칙 셋을 대면 — 파일만(넓히기 전) **누락 5·오탐 0** / 맨낱말까지
**누락 0·오탐 4** / **구분자 요구 누락 1·오탐 0** 이다. 그런데 **오탐이 「조용히 넘치는 것」이
아니라 「밀어내는 것」**인 게 결정적이었다.

    $ grep -rn "cost" backend/app
      맨낱말 허용   cost/CLAUDE.md 만 2,286자.  backend 는 한 줄도 안 온다
      +구분자 요구  backend/CLAUDE.md (1/2) 8,317자

한 호출에 드는 조각이 **사실상 하나**라서다 — 예산이 9,500인데 큰 셋의 조각 1이
8,130·9,047·8,998 이다. `compose()` 가 얕은 폴더부터 채우는데 `cost` 와 `backend` 는
**깊이가 같아**(둘 다 2 parts) 명령의 토큰 순서가 이기고, `grep` 은 검색어를 경로보다 **먼저**
쓴다. 즉 부딪힌 폴더가 **일하는 폴더의 자리를 먹는다.**

**이 저장소에서 특히 그렇다** — 폴더 이름이 `cost`·`tests`·`data`·`evaluation` 처럼 전부
평범한 낱말이라 `grep` 패턴이 그대로 걸린다. **파일 토큰은 확장자가 그 몫을 하는데 디렉터리
에는 그런 표지가 없어, 구분자가 대신한다.**

### `ls backend` 를 놓치는 것을 감수했다

살리는 안은 **「인자 위치를 본다」**인데 그것이 셸 파싱이라, 훅 docstring 이 이미 *"여기서
정교하게 굴면 새 형태의 명령이 조용히 빠진다"* 로 경계한 자리다. **놓치는 방향은 넓히기 전과
같아 되돌아갈 뿐이라**(fail-safe) 감수 쪽이 싸다. 다만 **테스트로 그 누락을 일부러 잠갔다** —
사라지면 판별자가 바뀐 것이므로 오탐 쪽을 다시 재라는 뜻이다.

### `Grep`·`Glob` **도구**는 이 판에서 안 덮었다

**matcher 에 `Grep` 을 더하는 것만으로는 무동작이다** — 그쪽 `tool_input` 에 `command` 키가
아예 없어 `main()` 이 곧바로 exit 0 한다(먹여서 확인했다). 그리고 **「경로 없음 = 저장소
전체」를 무엇으로 대우할지가 새 결정**이다 — 모든 폴더에서 조각을 하나씩 집으면 한 호출이
예산을 통째로 태운다. 재고 정할 것이라 미결로 남겼다.

### 12회차가 이 미결에 단 반론이 낡은 것을 확인하고 지웠다

*"메우는 것만으로는 처방이 아니다 — 예산 초과는 그대로다"* 는 **쪽지 시절** 문장이다
(`verify_log/2026-08-31-폴더md-예산.md` 에 *"메워도 `evaluation` 은 여전히 예산 초과라 또
쪽지가 된다"* 로 적혀 있다). 12회차가 쪽지를 기각하고 이어싣기로 갈았으니 **지금 초과는
«또 쪽지» 가 아니라 조각이고 그것이 채택된 동작**이다. **결론이 무효화한 반론이 미결 줄에
그대로 실려 왔다** — 미결을 옮겨 적을 때 그 줄이 기대는 전제가 아직 사는지 같이 봐야 한다.

### 「`Grep` 도구 구멍」이라는 이름 자체가 틀렸다

12회차는 3차 시험이 *"그 구멍으로 빠졌다"* 고 적었는데, 3차의 `Grep` 6회 중 3~6번은
`path=.claude/wiki/…` 이고 **거기엔 `CLAUDE.md` 가 없다**(저장소 전체에 뿌리 + 일곱 폴더뿐).
즉 **어떤 폴더 지침 훅으로도 원리적으로 못 닿는 자리**라, 이 수리는 그 시험을 되살리지
않는다 — 고친 것은 **다른 구멍**이다. 진짜 이름은 「폴더를 무는데 파일 이름이 안 나오는 모든
명령」이고, Bash `grep -rn`·`ls` 도 똑같이 0자였다.

### 기록의 거짓 예시를 **코드가 고치게** 뒀다

뿌리 `CLAUDE.md`·훅 docstring·12회차가 전부 *"`grep -rn x backend/ tests/` 한 줄이면 두
폴더가 더해진다"* 고 적었는데 **넓히기 전 실측 0자**였다. 합산 주장 자체는 참이고(55,150자는
일곱 `CLAUDE.md` 를 **파일 이름으로** 부른 명령이 근거다) 예시만 틀렸는데, **하필 그 예시가
구멍을 정상 동작처럼 보이게 했다.**

**먼저 안 고친 것이 결정이다** — A 를 넣자 그 예시가 참이 되어 고칠 것이 없어졌다. 갈림길이
열려 있는 동안 문구를 고쳤으면 두 번 고치고 그 사이에 거짓이 한 번 더 커밋됐다. 대신 훅
docstring 에 *"이 판 전까지 거짓이었다"* 를 남겨 **그 사실 자체는 안 사라지게** 했다 —
«합산 주장은 참이었고 예시만 틀렸다» 는 구분이 이 항목의 값어치다.

## 4. 실패 분석

### 적어 둔 함정을 적어 둔 채로 다시 밟았다 — 개명과 호출부를 갈랐다

`files_in` → `paths_in` 개명에서 **`main()` 의 호출부를 같은 편집에 안 넣어 훅이 죽었다**
(`NameError` → exit 1). 12회차가 `POINTER_HEAD` 를 먼저 지우고 `compose()` 를 나중에 고쳐
똑같이 죽였고, 그 교훈이 핸드오프에 *"상수와 그것을 쓰는 함수는 한 편집에 간다"* 로 적혀
있었다. **읽고도 밟았다.**

가른 것은 지식이 아니라 `auto_test_check` 다 — 편집 직후 `tests/hooks` 를 돌려 **12개 실패**로
막았고, 실패가 전부 `assert code == 0` 이라 **어느 테스트도 이 개명을 몰랐는데도** 원인이
곧바로 보였다(훅이 통째로 죽으면 모든 «실린다» 테스트가 같은 모양으로 죽는다).

### 줄끝을 넘겨짚어 1,077줄을 갈아엎을 뻔했다

`grep -c $'\r' <파일>` 이 **1,077**을 돌려줘 CRLF 파일로 읽었는데, 실제로는 **LF 전용**이었다.
Git Bash 에서 `$'\r'` 이 **빈 패턴으로 확장돼 모든 줄이 매치된 것**이다. `cat -A` 로 본 것도
`$` 뿐이었는데(=LF) `^M` 이 없다는 것을 안 읽었다.

기록을 붙이는 스크립트에 **앵커가 정확히 하나인지 검사**를 넣어 둔 것이 막았다 — CRLF 로
지은 앵커가 0건이라 **쓰기 전에 죽었다.** 안 넣었으면 파일 전체가 CRLF 로 바뀌어 diff 가
1,077줄이 되고, 그 안에 실제 변경 4줄이 묻혔다.

**처방은 세지 않고 파일에서 직접 읽는 것**이다(`"\r\n" in raw`). 이 저장소의 기록 파일은 LF 다.

### 판정표의 「오탐 2」를 오탐으로 읽을 뻔했다

구분자 규칙의 성적이 처음에 **누락 1·오탐 2** 로 나왔다. 그런데 그 2건은
`grep -rn "cost" backend/app` 처럼 **명령이 `backend/app` 을 실제로 무는** 경우라
`backend/CLAUDE.md` 가 오는 것이 정답이었다 — 내가 케이스 전체에 «말아야» 라벨을 단 것이
틀렸다(라벨은 *검색어가 부딪힌다* 를 뜻했는데 표는 *지침이 오면 안 된다* 로 읽힌다).

**수를 세지 말고 이름을 찍어 확인한 것이 갈랐다.** 그대로 뒀으면 오탐 2를 없애려고 판별자를
더 좁혀 **정답까지 잘랐을 것이다.**

## 7. 남은 것

- **`Grep`·`Glob` 도구** — matcher 만으로는 무동작이고 「경로 없음 = 저장소 전체」 대우가
  새 결정이다. 정하려면 `Grep` 호출 빈도와 「경로 없음」 비율을 전사에서 센다

- **`ls backend` 꼴이 실사용에서 얼마나 흔한가** — 감수한 누락의 크기를 안 쟀다
- **커밋 안 했다.** 사용자가 시킬 때 한다. `HANDOFF-2026-09-01.md` 는 여전히 미추적이고,
  「다 쓰면 지운다」가 그 파일의 규약이다
- 12회차에서 넘어온 채 그대로인 것 — `load_reason == "compact"` 미관측 · 셸 출력 채널의
  정확한 상한 · `AGENTS.md` 미러 드리프트(**사용자가 손대지 않기로 정했다**) · 뿌리를
