## 2. 설계 결정

### 고친 곳은 정규식이 아니라 **판정 범위**다

같은 `_FILE_REDIRECT_RE` 를 Bash 는 **`opener_line` 에만** 대는데(`_writes_a_file()`),
PowerShell 은 **명령 전체**에 댔다. 즉 PowerShell 쪽만 **here-string 본문 글자를 명령으로
읽었다.** 증상은 이렇게 나왔다.

    git commit -m @'…<noreply@anthropic.com>…'@     막힘   ← 닫는 `>`
    git commit -m @'…Set-Content 를 쓰라고 적었다…'@   막힘   ← 본문의 낱말
    git commit -m @'…`cat > f.md` 가 위험하다…'@      막힘   ← 본문의 예시

첫 줄이 제일 나쁘다 — **그 트레일러는 하네스가 모든 커밋에 요구하므로 `git commit -m @'...'@`
가 사실상 늘 막혔다.** 기전은 `>` 뒤의 `\s*` 가 줄바꿈을 먹고 종료 기호 `'@` 가 대상 파일명
자리에 들어가는 것이다(`>>?\s*(?!&)[^\s|&;<>]+`).

**버린 것은 「`>` 뒤에 경로꼴을 요구」**이고 실측으로 졌다 — **누락 1 · 오탐 2**(B 는 0·0).
누락이 탈락 사유다: `'@` 를 거르려면 경로꼴에서 따옴표를 빼야 하는데, 그러면
`@'…'@ > "out file.md"` 같은 **진짜 파일 쓰기가 함께 샌다.** 오탐이 남는 것보다 **파일 쓰기를
놓치는 쪽이 이 훅의 존재 이유를 깬다.** 게다가 그 정규식은 Bash 와 공유라 그쪽까지 움직인다.

**「트레일러만 예외 처리」도 버렸다** — 위 셋 중 하나만 없앤다. 뒤 둘은 트레일러와 무관하다.

### 「끝 구분자 없으면 판단 안 함」을 함께 넣은 것이 구현을 **더 단순하게** 했다

두 고침이 같은 방향(=Bash 를 닮게)이라 한 함수에 모였다. `subn()` 이 치환 횟수를 함께
돌려주므로 **«닫힌 것이 하나라도 있나» 가 공짜로 나오고**, 그래서 여는 자리를 보던
`_PS_HERESTRING_RE` 가 **통째로 필요 없어졌다.** 고치면서 상수가 하나 줄었다.

### 본문이 **빈** here-string 을 «닫힘» 으로 세는 것이 갈림길이었다

본문 부분을 필수로 두면(`.*?\r?\n`) `@'` 다음 줄이 바로 `'@` 인 경우가 안 잡혀,
`@'\n'@ > out.md` 가 「못 찾음」으로 빠지고 **진짜 파일 쓰기가 통과한다.** 선택으로
바꿔(`(?:.*?\r?\n)?`) 잡았고 케이스로 잠갔다.

## 4. 실패 분석

### 테스트가 8일 동안 초록인 채로 실사용을 막고 있었다

`ALLOWED_PS` 에 `git commit -m @'\nmessage line\n'@` 이 **이미 있었다.** 11회차가 훅 docstring 에
*"`git commit -m @'...'@` 처럼 파일과 무관한 정상 용도가 있어 파일 쓰기일 때만 막는다"* 로
못 박은 그 명령이다. **의도는 정확했는데 케이스에 `>` 가 한 번도 안 나온다** — 실사용이 늘
갖는 트레일러가 빠져 있었다.

**즉 「기록·테스트가 둘 다 있는데 둘 다 통과하면서 거짓」인 상태였다.** 이 저장소가 여러 번
적은 *"«확인했다»와 «확인할 수 있다»는 다르다"* 의 한 얼굴이고, 여기서는 **케이스가 실사용을
안 닮은 것**이 그 자리였다.

막은 방법은 케이스에 **하네스가 요구하는 트레일러를 상수로 못 박은 것**(`_TRAILER`)이다.
그리고 **본문만 바꾸는 짝 테스트**를 뒀다 — 한쪽만 재면 «본문을 무시한다» 와 «아무것도 안
막는다» 가 안 갈린다.

### 처음에 후보 A 를 「정규식을 좁히면 된다」로 가볍게 봤다

세션 앞부분에서 후보를 *"`>` 뒤에 실제 경로꼴이 와야 한다"* 와 *"본문 밖만 본다"* 둘로 냈고,
A 를 그럴듯하게 여겼다. **재보니 A 는 오탐을 2건밖에 못 없애면서 누락을 1건 만든다** —
잰 것이 갈랐지, 읽어서 갈리지 않았다.

### 판정표를 만들 때 라벨을 틀리게 달았다 (이 세션 앞부분)

구분자 판별자를 재던 표에서 「말아야」 라벨을 *검색어가 부딪히는 케이스* 에 달았는데, 그
명령들은 다른 폴더를 **실제로 물고 있어** 지침이 오는 것이 정답이었다. 수를 세지 않고
**이름을 찍어 확인한 것**이 갈랐다 — 그대로 뒀으면 판별자를 더 좁혀 정답까지 잘랐다.
(그 판의 회고는 `.claude/wiki/task_log/2026-09-01-폴더md-폴더훑기.md` 에 있다.)
