# 포맷 비교의 목적을 바꿔 잡고, 절차를 저장소로 넘겼다

- 작업일: 2026-08-23
- 검증 방법: `ruff` · `pytest` · **핸드오프 명령을 코드와 대조**(그룹 이름·플래그).
  **외부 API 호출 없음** — 이번에 비교를 돌리지 않았다

## 1. 무엇을 바꿨나

- `evaluation/README.md`
  *"포맷 비교를 돌리려면"* 절 신설(선행 조건 · 대조군 · 비용 · 대조 방법 · 판정 기준).
  그리고 **"쓰기" 절에 있던 반쪽짜리 포맷 비교 명령을 포인터로 바꿨다.**
- `plan_log/평가-세트.md` · `plan_log/INDEX.md`
  미결의 포맷 비교 항목에 **바뀐 목적과 대조군 문제**를 담고 절차는 README 를 가리킨다.

**코드는 안 고쳤다.** 이번 산출은 실행이 아니라 핸드오프다.

## 2. 설계 결정

### 목적을 바꿨다 — 원래 질문은 행동으로 안 이어진다

사용자가 *"HWPX format comparison 왜 해야해?"* 를 물었고, 답을 놓고 보니 **원래 목적이
약했다.** `검색-생성.md` 비교 5번과 CLAUDE.md 는 *"어느 포맷이 검색에 유리한가"* 로 적어뒀는데
**그 답에는 바꿀 설정이 없다** — 파이프라인은 사용자가 올린 포맷을 그대로 받는다. 답이 나와도
기록으로만 남는다.

**"PDF 적재 결함의 검색 대가가 얼마인가"** 로 다시 잡으면 행동으로 이어진다. 해부가 남긴
"확인 필요" 10건의 원인 후보가 *적재* 인지 *검색* 인지가 갈리고 — 18덩어리 중 **13개가 비교
가능**하다(5개는 AI 가이드라 HWPX 판이 없다) — 적재 쪽이면 로더를, 검색 쪽이면 BM25·모델을
먼저 한다. 덤으로 CLAUDE.md 가 미해결로 적어둔 제목 유실 22.9~39%·낱말 공백 손실에 **처음
값이 매겨진다.**

### 대조군을 다시 만들어야 한다 — 이번 설계에서 제일 큰 것

`baseline.json` 을 PDF 대조군으로 그냥 쓰려다 막혔다. 그것은 **4그룹 414청크를 한 컬렉션**에
넣은 실행이고 HWPX 는 3그룹뿐이라, 그대로 견주면 **경쟁 집합이 다르다** — PDF 쪽 질의는
AI 가이드 청크와도 경쟁했고 HWPX 쪽은 안 했다. 같은 3그룹으로 **양쪽 다** 돌려야 성립한다.
PDF 쪽은 청크가 이미 임베딩 캐시에 있어 대가가 거의 없다.

### 핸드오프를 저장소 안에 뒀다

플랜 파일은 `~/.claude/plans/` 에 있어 **새 세션이 안 읽는다.** INDEX 셋이 새 세션의 입구라
`plan_log/INDEX.md` → `평가-세트.md` 미결 → `evaluation/README.md` 로 끊김 없이 닿게 했다.

**`plan_log` 9회차로 적는 안은 기각했다.** 회차는 *진행한 논의*를 쌓는 자리인데 이번에 정한
것은 *할까 말까와 목적* 뿐이고 일은 안 했다. 안 한 일을 회차로 적으면 계획과 기록이 섞인다.

### 명령을 두 곳에 두지 않았다

`README` "쓰기" 절에 이미 `--format hwpx --groups …` 한 줄이 있었는데 **대조군 이야기가
빠진 반쪽**이었다. 새 절을 더하면서 그 줄을 포인터로 바꿨다 — 두 곳이 같은 것을 반씩 들면
한쪽이 조용히 낡는다. 같은 이유로 `plan_log` 미결에도 명령을 복제하지 않고 README 를 가리킨다.

### CLAUDE.md 의 낡은 수치를 **지금 고치지 않았다**

*"시행령 HWPX 45청크 vs PDF 104청크(2.3배)"* 가 파싱 캐시로는 **67 vs 118(1.76배)** 로
보인다. 그런데 그 캐시는 **어느 설정으로 만들어졌는지 모른다**(캐시 키가 파일명뿐이다).
낡은 수치를 검증 안 된 수치로 바꾸는 것은 고치는 것이 아니다. 두 실행의 `indexed` 가 권위
있는 값을 내므로 그때 갱신하도록 README 6항에 적어뒀다.

## 3. 지표

**`verify_log/` 를 안 만들었다.** 잰 수치가 없다 — 이번에 나온 숫자(13/18 덩어리,
3그룹 285 vs 343청크)는 전부 **논증의 근거**라 `verify-log` 스킬의 가르는 기준
(*"떼어냈을 때 문장이 성립하는가"*)에서 이쪽이다.

- ruff 통과 / pytest 전체 통과 (코드 변경 없음)
- 핸드오프 대조: README 가 적은 그룹 이름 **3/3 이 `documents.py` 키와 일치**,
  세 그룹 모두 hwpx·pdf 두 판이 디스크에 있어 **`SystemExit` 가 안 난다**
- README 가 쓰는 플래그가 전부 `--help` 에 있다
- E2E : **안 함** — 비교 실행은 새 세션 몫이다

## 4. 실패 분석

**하나. `baseline.json` 을 대조군으로 쓰려던 것.** 처음 핸드오프 초안은 *"HWPX 만 돌려서
baseline 과 견준다"* 였다. 그러면 **60건 4그룹 대 45건 3그룹**을 견주게 되고, 경쟁 집합이
달라 차이가 포맷 때문인지 문서 하나가 빠진 것 때문인지 못 가른다. `compare_to_baseline()`
이 포맷 다르면 거부하는 가드를 왜 넣었는지 되짚다가 알아챘다 — **그 가드가 막으려던 것이
정확히 이 사고**다. 그래서 대조군을 다시 만드는 절차로 바꿨다.

**둘. CLAUDE.md 수치를 캐시 값으로 고칠 뻔했다.** 67 vs 118 이 눈에 보이니 바로 고치고
싶었는데, 그 캐시의 출처를 모른다. **낡은 값을 검증 안 된 값으로 바꾸면 낡았다는 사실만
사라지고 틀림은 남는다.**

## 5. 회귀 테스트

**없다 — 코드를 안 고쳤다.** 대신 핸드오프가 성립하는지를 명령과 코드 대조로 확인했다(3절).
이 대조는 일회성이라 테스트로 안 박았다. **README 의 그룹 이름이 `documents.py` 와 어긋나면
새 세션이 `SystemExit` 를 보고 알아챈다** — 조용히 틀리는 종류가 아니라 테스트가 덜 급하다.
