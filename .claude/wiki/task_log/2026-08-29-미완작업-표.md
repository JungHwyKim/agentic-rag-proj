# 안 끝난 일을 한 표로 — 수집은 스크립트, 묶기·순서는 스킬로 갈랐다

- 작업일: 2026-08-29
- 검증 방법: `tests/openwork` 29건 신설 + 전체 pytest + ruff + 실제 저장소 1회 수집. **외부 API 호출 없음** (`-m integration` 안 돌림 · LLM 단계를 아예 안 지난다)

  그 JSON 을 묶고 선행 순서를 매겨 표로 그리는 절차. **기록 폴더를 직접 훑지 말라**가
  이 문서의 첫 줄이다
- `.claude/hooks/auto_test_check.py`
  `_MAPPINGS` 에 `openwork/ → tests/openwork` 한 줄. 안 걸면 이 도구만 자동 테스트가

- `tests/openwork/test_collect_openwork.py`
  29건. 대부분 *조용히 틀리는* 자리를 잠근다

  설계 1회차와 색인

## 2. 설계 결정

### 스킬 하나가 아니라 **스크립트 + 스킬**로 갈랐다

세 기록 폴더 전체가 **4.36MB(약 145만 자, 파일 251개)** 이고 세 `INDEX.md` 만 합쳐도
644KB 다. 「모델이 다 읽는다」가 원리적으로 막히고, 그 길은 `plan_log/프로젝트-컨텍스트.md`
가 *"세 INDEX와 전체 로그를 기본 문맥으로 읽는 것 — 색인을 추가하는 목적과 정면으로
어긋난다"* 로 이미 기각해 뒀다.

반면 재료는 규약으로 서 있다 — `## 미결` 이 **19/19 파일**, `## 7. 남은 것` 이
**98/102 파일**, 둘 합이 전체의 **5.2%** 다. 즉 **뽑는 일이 판단이 아니다.**
그래서 수집은 결정적으로 스크립트가 하고, 묶기·선행 순서·설명만 스킬이 한다.

기각한 것은 **커밋되는 `OPEN.md`** 다. CLAUDE.md 가 *"여기에 현재 상태를 적지 않는다 —
적는 순간 낡기 때문이다"* 로 금지한 형태이고, 미결의 **네 번째 진실**이 된다. 낡은 채
커밋된 목록은 아무것도 없는 것보다 더 그럴듯하게 거짓말을 한다. 대화에 표로만 내기로 한
것이 덤으로 **「새 항목이 자동으로 들어온다」를 공짜로** 만들었다 — 동기화할 장부가 없다.

### 닫힘을 판정하지 않기로 했는데, 재보니 **절반이 공짜였다**

처음 결정은 "닫혔는지 판정하지 않는다"였다. 701건을 매번 코드와 대조할 수 없고,
**틀리는 방향이 나쁘기** 때문이다 — 놓친 판정이 「닫혔다」로 보인다.

그런데 실제로 세어 보니 `## 미결` 불릿 232개 중 **72개(31%)** 가 이미
`~~**제목**~~ → **N회차에서 닫혔다.**` 모양으로 닫힘을 표시하고 있었다. 규약이 이미 있고
지켜지므로 **모델 없이 문자열로** 빠진다(호출마다 같은 답). 표에 오르는 것은 232가 아니라
**165**다.

**나머지는 여전히 못 뺀다.** `plan_log/frontend.md` 의 `## 미결` 에 *"재시도 횟수를 화면에
싣기 … 배선은 여전히 미결"* 이 서 있는데 `backend/app/templates/_answer.html` 에 그 줄이
**이미 있다**(`검색-생성.md` 44회차). frontend.md 의 마지막 회차가 3회차라 **다른 파일이
닫은 것을 이쪽이 안 따라온** 것이고, 아무 신호가 없다. 그래서 이 도구가 내는 것은
「열린 것」이 아니라 **「열린 채로 적힌 것」**이고, 모든 항목이 출처·회차·날짜를 달고 나간다.

### 뒷정리의 기능 라벨을 **불릿이 아니라 파일 링크**에서 얻는다

처음에는 불릿 안에 기능 이름이 나오는지만 봤다. 결과는 **457건 중 374건(82%)이 묶음
미상**이었다. 원인은 `task_log` 가 `plan_log` 와 달리 **파일이 기능이 아니라 세션**이라는
것이다 — 기능은 본문의 `plan_log/<기능>.md` 링크에만 남는다. 그 링크를 물려받게 하니
미상이 **374 → 171(37%)** 로 줄었다(라벨률 63%).

감수 사항을 같이 적어 둔다 — `plan_log` 링크를 가진 `task_log` 파일 65개 중 **18개가 여럿을
가리킨다.** 지금은 제일 자주 나온 것을 고르고 동수면 이름순으로 고정한다(호출마다 안
흔들리게). **몇 건이 틀리게 붙는지는 안 쟀다.**

### 「왜」가 원문에 없으면 **지어내지 않고 `None` 을 돌려준다**

「정하려면:／이유:」 인용을 가진 비율이 `## 미결` 은 **80%**(열린 165건 기준)인데
`## 7. 남은 것` 은 **1%** 다. 없는 것을 모델이 채워 넣게 하면 인용과 요약이 한 칸에 섞이고,
**표의 절반이 호출마다 달라지는데 읽는 사람은 그걸 모른다.** 그래서 스크립트는 `why=None`
으로 비워 두고 `why_basis` 로 어느 쪽인지 밝히며, 스킬이 요약할 때 「요약」이라고 표시한다.

같은 이유로 긴 인용은 자르되 `why_truncated` 로 밝힌다 — **말없이 자르면 요약인데 표는
그것을 인용이라고 말한다.**

### 구조 정리 대비를 **양방향**으로 걸었다

폴더 이름이 스킬 산문에 박히면 이름이 바뀔 때 **표가 조용히 짧아진다**(에러가 안 난다).
그래서 경로·절 이름을 `SOURCES` 상수 한 자리에 두고 ① 설정된 폴더가 없으면
`OpenWorkConfigError` 로 죽고 ② 설정에 없는 기록 폴더(`INDEX.md` 를 품은 최상위 디렉터리)가
생기면 경고하고 ③ 설정된 절 이름이 한 파일에서도 안 나오면 경고한다.

**한 방향만 막으면 새 폴더가 생겼을 때 그대로 재현된다.** ②의 헛경보를 막으려고
`NOT_A_SOURCE` 를 뒀다 — `verify_log` 가 매번 뜨면 경고를 안 읽게 되고, 그건
`auto_test_check.UNMAPPED_BY_DESIGN` 이 있는 이유와 같다.

`verify_log/` 를 재료에서 뺀 근거도 관측이다 — `## 남은…` 절이 **0/129 파일**이다.
수치만 담는 곳이라 미완이 원래 안 적히고, 넣어도 0건이다.

## 4. 실패 분석

### 인코딩을 부르는 쪽 규약으로 뒀다가 실제로 깨졌다 — **그리고 원인이 코드 쪽으로 보였다**

CLI 테스트 둘이 `auto_test_check` 훅이 돌린 pytest 에서만 실패했다. `proc.stdout` 이
`None` 인데 `returncode` 는 0이라 코드가 이상해 보였고, **같은 파일을 따로 돌리면 29건이
전부 통과했다.** 가른 것은 환경이다 — 훅의 pytest 에는 `PYTHONIOENCODING` 이 없어 자식
프로세스가 한국어 JSON 을 **cp949 로** 내보냈고, 부모가 UTF-8 로 읽었다.

CLAUDE.md 가 「출력」 얼굴로 적어 둔 그 함정이다(`pytest -rs` 의 skip 사유가 깨지는 자리와
같은 것). 확인은 `PYTHONIOENCODING=cp949` 로 한국어를 찍어 바이트를 본 것이다 —
`"임계값"` 이 `300 323 260 350 260 252` 로 나갔다.

**처방을 부르는 쪽이 아니라 도구 쪽에 뒀다.** `main()` 이 자기 `stdout`·`stderr` 를 UTF-8 로
못 박는다 — 부르는 쪽 규약으로 두면 **안 붙인 호출에서 조용히 깨진다.**
`test_cli_output_is_utf8_regardless_of_caller_encoding` 이 `PYTHONIOENCODING=cp949` 를
일부러 넣어 이 자리를 잠근다.

### 라벨 규칙 첫 판이 82% 를 미상으로 냈다

`plan_log` 에서 통하던 「파일이 곧 기능」을 `task_log` 에 그대로 가져간 것이 원인이다.
저쪽은 파일이 **세션**이라 규칙이 성립하지 않는다. 되돌린 것이 아니라 계층을 하나 얹어
고쳤다(불릿 → 파일 링크). `test_followup_inherits_feature_from_file_link` 와
`test_followup_without_any_hint_stays_ungrouped` 가 양쪽을 잠근다.

### 굵은 머리가 없는 불릿에서 강조 표시가 표로 샜다

`1회차 몫은 **없음**` 이 `what` 에 별표째 실렸다. 떨어지는 자리에서 `**` 를 벗긴다
(`test_what_strips_emphasis_in_fallback`).

### 「전부 읽는다」를 스크립트로 옮겨 놓을 뻔했다

첫 출력이 **120,923B** 였다. 원인은 `json.dumps(indent=2)` 하나였고(같은 내용이 압축이면
79KB), `--raw` 를 켜면 148KB 다. 기본을 압축·원문 제외로 내렸다.
