# 판정을 화면과 질의로그에 잇는다 — 배지는 나쁜 소식일 때만 뜬다

- 작업일: 2026-08-27
- 검증 방법: ruff · 전체 pytest · 판정 네 상태를 화면 조각으로 렌더한 탐침.
  **외부 API 과금 없음** — `EVALUATOR_MODEL` 이 빈 채 돌았고 `answer_question` 은 전부
  모킹이다. **화면 E2E 는 안 했다**(유료 1회라 승인 대기). `-m integration` 안 돌림

## 1. 무엇을 바꿨나

  `ask()` 가 `evaluator=get_evaluator(...)` 를 넘긴다. **질의마다 새로 만든다**(2절).
- `backend/app/core/query_log.py`
  레코드에 `verdict` 한 칸. 판정을 안 돌렸어도 키는 있고 값이 `null` 이다.
- `backend/app/templates/_answer.html`
  캐시 배지 뒤 · Phase 5 자리표시 앞에 판정 배지. **불충분·실패일 때만** 그린다.
- `backend/app/static/app.css`
  `.badge-row` 변종 둘. 새 색을 안 만들고 있는 토큰으로 무게만 갈랐다.
- `tests/api/test_query_route.py` · `tests/api/test_query_log.py`
  배지 5 · 인스턴스 수명 2 · 로그 2 = **9건**. 그리고 두 헬퍼에 `_evaluator` 핀.
- `.env.example` · `CLAUDE.md`
  켜면 무엇이 나타나는지, 왜 여기만 질의마다인지.

## 2. 설계 결정

넷을 면담 두 라운드로 정했다(`plan_log/검색-생성.md` 12회차에 회차 기록이 있다).
여기에는 **코드가 그 결정을 어떻게 지키는지**만 적는다.

### 배지는 나쁜 소식일 때만 뜬다 — *충분* 과 *꺼짐* 이 화면에서 같아 보인다

버린 것은 **셋 다 그리기**다. 논거가 있었다 — 첫 혼동행렬의 오답이 전부 **거짓 *충분***
쪽이라, *충분* 배지가 있어야 사람이 그 칸을 실사용에서 만난다. 그런데 그러면 **모든 답변에
줄이 하나 늘고**, 판정 정확도를 다시 재기도 전에 화면이 판정을 단언하게 된다.

가른 것은 `cached_from` 배지가 이미 세워 둔 문장이다 — *"없으면 줄 자체를 안 그린다. 빈
배지가 남으면 사용자는 캐시가 켜져 있다고 읽는다."* 같은 잣대를 그대로 적용하면 *충분* 은
안 그리는 쪽이다. **대가는 알고 골랐다**: *충분* 과 *판정 꺼짐* 이 화면에서 구분되지 않는다.

문구에 *"아래 답변은 그대로 생성된 것입니다"* 를 넣은 것은 계약을 보이게 하려는 것이다 —
**판정이 답변을 바꾸지 않는데**, 배지만 보면 답변이 눌렸다고 읽힌다.

### Evaluator 만 질의마다 새로 만든다 — 싱글턴의 근거가 여기엔 없다

`embedder`·`bm25`·`reranker` 는 전부 `app.state` 싱글턴이다. 모양을 따라가는 것이 자연스러워
보였는데, **저 셋이 싱글턴인 이유를 하나씩 읽으니 여기엔 하나도 해당하지 않았다** — KURE
2.27GB 적재 · cross-encoder 적재 · 저장소 전량 훑기다. `OpenAIEvaluator` 는 `_make_client()`
를 호출 시점에 부르고 캐시가 디스크라 **만드는 데 드는 것이 없다.**

이유 없이 모양만 따라가면 딸려 오는 것이 있다. `warnings` 와 `usage` 가 **인스턴스에
누적**되는데, `EVALUATOR_MODEL` 은 찼고 `OPENAI_API_KEY` 가 없는 조합이면 `_call_api()` 가
질의마다 경고 한 줄을 남긴다. 싱글턴이면 그 리스트가 서버 수명 내내 자란다 — **읽는 사람도
없고 에러도 안 난다.**

버린 셋째는 **싱글턴 + 질의마다 reset** 이다. `warnings` 가 읽기 전용 property 라 라우트가
`_warnings` 를 직접 만져야 하고, 상태 소유권이 두 곳으로 갈린다.

**`run_in_threadpool` 로 안 감쌌다.** 저 셋을 감싼 이유는 만드는 자리가 곧 모델 적재여서인데
여기는 I/O 도 적재도 없다. 판정 호출 자체는 `answer_question` 안에서 이미 루프 밖이다.

### 모델 사유는 `title` 에만 — 배지에 펼치지 않는다

`reasoning` 의 길이는 모델이 정한다(`EVALUATOR_MAX_TOKENS=512` 가 상한인데 그것도 임시값이다).
배지에 펼치면 레이아웃이 길이에 끌려다니고 **답변보다 판정이 먼저 읽힌다.** 긴 원문을
`title` 에 담는 규칙은 캐시 배지(원 질문)와 소스 태그(한국어 파일명)가 이미 쓰고 있다.

버린 것은 **아예 안 내보내기**다. 사유를 읽는 도구(`verdicts.py --wrong`)가 이미 있으니
화면에서 뺄 수도 있었는데, 그러면 **실사용에서 만난 오판을 그 자리에서 못 짚는다.**

### `query_log` 에는 `verdict` 만. 키는 늘 있고 `reasoning` 은 없다

싣는 이유는 **재려는 것이 실사용 분포**여서다. `qa_set_human.jsonl` 43건은 고정된 세트라
*실사용에서 불충분이 얼마나 나오는가* 를 원리적으로 못 잰다 — 그 비율이 Phase 5(재작성)를
되살릴지 정하는 근거다. 모듈 docstring 이 *"적중률의 분모가 유일한 목적"* 이라고 못 박아 둔
자리라, 그 뜻을 넓히는 것을 결정으로 적었다.

**키를 늘 쓴다.** 판정을 안 돌렸으면 `null` 이지 키를 빼지 않는다 — 빼면 *"판정이 꺼져
있었다"* 와 *"옛 형식이라 칸이 없다"* 가 집계에서 안 갈린다.

`reasoning` 은 뺐다. 상한도 자동 정리도 없는 파일이라(`Settings.originals_dir` 과 같은 판단)
모델 문장이 질의마다 쌓인다.

### 딸려 나온 것 — 캐시와 판정은 화면에서 배타다

`qdrant_cache._to_answer()` 가 `verdict` 를 안 되살린다. 스키마 docstring 이 *"`Answer.verdict`
자체가 `None` 인 것은 판정을 안 돌렸다는 뜻이다 — 꺼져 있거나 답이 캐시에서 왔거나"* 로
의도를 못 박아 둔 자리라 **이번에 안 건드렸다.** 결과로 답변 캐시를 켜면 **히트한 질의에는
판정 배지가 영영 안 뜨고** 로그의 `verdict` 도 `null` 이다. 캐시를 켤 때 함께 볼 축이다.

## 4. 실패 분석

**되돌린 시도는 없다.** 대신 계약 하나를 **훅이 먼저 잡았다.**

`query_log` 에 칸을 더하자마자 `auto_test_check.py` 가 `tests/api` 를 돌려
`test_one_query_writes_one_line` 이 깨졌다 — 그 테스트가 `set(row) == {여섯}` 으로 **칸 집합을
계약으로 잠가 두었기** 때문이다. 고치는 데 든 것은 한 줄이지만, **잠가 두지 않았으면 칸이
늘어난 것을 아무도 안 알려줬을 것**이고 로그 형식이 조용히 갈렸을 것이다.

같은 이유로 새 테스트도 `set(row) == {일곱}` 으로 다시 잠갔다. 다음 사람이 칸을 더하면
같은 자리에서 걸린다.

**계획대로 밟은 함정 하나** — `_client()` 헬퍼 둘에 `_evaluator` 핀을 넣었다. 라우트가 이제
질의마다 `get_evaluator(config.evaluator)` 를 부르므로, 안 박으면 개발자 `.env` 의
`EVALUATOR_MODEL` 이 픽스처에 실린다. CLAUDE.md 가 임베딩 provider 에서 *실제로 뚫린 적이
있다* 고 적어 둔 그 겹이다. 이번에는 **배선보다 먼저** 넣었다.

- **화면 E2E 를 안 했다** — 유료 1회다. 볼 것 셋: 불충분 질의에서 배지 + 마우스 올려 사유 ·
  충분 질의에서 줄 없음 · `data/queries.jsonl` 마지막 줄의 `verdict` 칸
- ~~**혼동행렬이 낡았다**~~ — **이미 닫혀 있었다.** `56fb382` 를 만든 세션이 라벨을 되돌리며
  **재측정까지 마쳤다**(K=5 28/43 그대로 · K=10 30 → **31/43** · API 호출 0). 이 줄을 쓸 때
  그 사실을 못 보고 미결로 적었다 — 근거는 `verify_log/2026-08-26-evaluator-판정.md` 의
  「되돌린 뒤 다시 잰 표」이고, 2026-08-27 에 같은 명령을 다시 돌려 같은 수를 확인했다
- **실사용 *불충분* 비율** — 이제 로그가 쌓기 시작하지만 **아직 한 줄도 없다**(꺼져 있다)
- **질의당 LLM 호출 상한** — 판정이 실사용에서 도는 순간 표적이 생긴다. 정상 상태 질의
  3.0~4.3초 위에 판정 1회가 얹힌다
- **기본 pytest 가 KURE-v1 가중치를 적재하고 실제 임베딩 7건을 만든다** — 이번 변경과
  **무관한 선재 사항**이다. 전체 실행마다 `Loading weights: …/393` 1회 · 임베딩 캐시 +7 건이고,
  **어느 폴더도 단독으로는 안 만드는데 합치면 만든다.** 이 머신에서는 캐시가 차 있어 대가가
  작지만 **새 클론에서는 2.27GB 를 내려받아 적재한다.** 원인을 못 좁혔다 — 별개 세션이 필요하다.
  수치와 검출 방법(진행줄이 **stderr** 라 `2>&1 | grep` 으로는 0 이 나온다)은 verify_log 7절
- **커밋 안 했다** — 사용자가 시킬 때만 한다
