# 재색인 입구를 내고, 원본이 없는 문서에서는 버튼을 감춘다

- 작업일: 2026-08-26
- 검증 방법: ruff + 전체 pytest + OpenAPI 로 라우트 등록 확인. **외부 API 호출 없음** —
  전 테스트에서 `index_document()` 를 갈아끼웠고 `-m integration` 7건은 기본값대로 deselect
  됐다. **화면 E2E 는 안 했다**(7절)

## 1. 무엇을 바꿨나

- `backend/app/api/routes/documents.py`
  `POST /documents/{document_id}/reindex` 와, 목록이 부를 공개 함수 `original_exists()`.
- `backend/app/api/routes/query.py`
  `_mark_missing_originals()` 를 `_mark_shadow_gaps()` **옆에** 붙이고 목록 조립에 한 줄.
- `backend/app/templates/_documents.html`
  재색인 버튼과, 원본이 없을 때 그 자리에 뜨는 `원본 없음` 배지.
- `backend/app/templates/chat.html`
  진행 표시를 폼 직결에서 **body 위임**으로 바꿨다. 목록 조각이 다시 그려져도 산다.
- `backend/app/static/app.css`
  `.doc-reindex` · `.doc-original-missing` — 각각 `.doc-delete` · `.doc-shadow-missing` 과 짝.
- `tests/api/test_reindex_route.py` (새 파일)
  라우트 계약 7건.
- `tests/api/test_pages.py`
  진행 표시 가드가 스크립트를 자르는 **앵커 한 줄**. 4절이 그 사연이다.

## 2. 설계 결정

### 재색인은 새 결합이 아니라 입구다 — 그래서 이번 회차가 작다

버린 것: `document_id` 를 명시적 id 로 옮기고 문서 레지스트리(rDBMS)를 들이는 안.

근거는 부품이 이미 다 있다는 것이다. `index_document()` 는 이미
`delete_by_document_id(파일명)` → `upsert()` 순서라 **같은 키로 다시 부르는 것이 곧
재색인**이고, 7회차가 원본을 `originals_dir` 에 남기게 만들어 **입력도 이미 디스크에 있다.**
없는 것은 둘을 잇는 라우트 하나였다. 7회차가 삭제 API 의 미룸을 풀 때 쓴 논리
(*"새 결합을 만드는 것이 아니라 있는 것을 노출한다"*)가 여기서도 그대로 섰다.

### 버전 관리·문서 유효성은 셋이 한 묶음이라 갈라서 미뤘다

사용자가 선택지를 받고 *"버전관리를 고려하면 2번이고 유효함까지 고려하면 3번이지?"* 로
되짚었다. **답은 둘 다 아니었고, 그 확인이 이번 회차에서 제일 값어치 있는 부분이다.**

- **내용 해시(2번)는 버전 *감지* 이지 관리가 아니다.** "다르다"만 알 뿐 어느 쪽이 새 판인지
  모르고 옛 판을 되돌리지도 못한다
- **레지스트리(3번)는 담을 *자리* 를 만들 뿐 유효성 자체가 아니다.** 유효/폐지·시행일은 그
  위에 얹는 메타데이터 축이다

실제로 필요한 것은 **레지스트리 + payload 축(`version`/`valid`) + `search(filters=)`** 셋이고
**셋째가 병목**이다 — `retrieval/` 에 `filters` 참조가 **0건**이고
`indexing/__init__.py` 가 *"일부러 없다"* 로 적어 두었다. 여기서 처음 소비자가 생긴다.
그리고 그것을 만들면 `retrieval/` 을 건드려 **이번 트랙을 고른 이유(다른 세션과 안 겹침)가
통째로 사라진다.** 그래서 `plan_log/backend.md` 미결에 새 항목으로 세웠다.

이번에 남긴 뒷길은 하나다 — URL 의 `{document_id}` 를 **불투명 문자열**로 받는다.
7회차가 원본 서빙에서 이미 한 것과 같고, 나중에 명시적 id 로 옮겨도 공개 URL 이 안 깨진다.

### `original_name` 에 문서 키를 넘긴다 — 디스크 이름이 아니다

디스크 이름은 `_stored_name()` 이 만든 `안내서__a3f9c2.pdf` 다. 그것을 그대로 넘기면
`document_id_for()` 가 **새 키**를 만들어, `delete_by_document_id()` 가 옛 청크를 못 찾고
같은 문서가 두 벌로 색인된다. **에러가 안 나므로 알아챌 길이 없다.** 이 라우트에서 제일
조용하게 틀릴 수 있는 자리라 테스트로 `"__" not in original_name` 까지 박았다.

### 답변 캐시는 비우고, 삭제 라우트는 안 비운다 — 방향이 반대다

캐시의 무효화는 **조회 시점에 근거 청크를 되짚어** *"딛고 선 청크가 사라지거나 바뀌었다"* 를
id·텍스트 해시로 잡는다. 삭제는 바로 그 경우라 **원리적으로 잡히고**, 그래서 삭제 라우트는
`clear()` 를 안 부른다.

재색인은 반대쪽이 있다 — 파서를 고쳐 **청크가 늘어난** 경우다. 옛 답이 딛고 선 청크는
여전히 멀쩡하므로 근거 대조가 **원리적으로 못 잡는다.** 색인 라우트가 `clear()` 를 부르는
이유(새 문서 유입)와 **같은 축**이라, 재색인도 비운다. 버린 것: 삭제와 같게 맞춰 안 비우는
안 — 그러면 파서를 고친 직후에도 옛 답이 그대로 나온다.

### 그림자 색인도 함께 다시 한다

버린 것: 주 색인만 다시 하는 안(과금 없음)과, 버튼을 둘로 가르는 안.

근거는 짝이다 — 색인 라우트가 두 컬렉션을 **함께 채우고** 삭제 라우트가 **함께 지운다.**
한쪽만 다시 하면 두 컬렉션이 서로 다른 청크를 들어 `overlap.py` 가 경고하는 상태가 되는데,
**그 어긋남은 화면에 안 보인다** — 사이드바 배지는 *있다/없다* 만 본다. 버튼 둘로 가르는
안은 7회차가 삭제에서 이미 버렸고(*"문서 상태가 셋이 된다"*) 같은 이유가 여기서도 산다.
대가는 그림자가 켜진 환경에서의 OpenAI 재과금이고, 그것은 감수했다.

### 원본이 없는 문서는 버튼을 감춘다 — 404 안내가 아니라

7회차 이전에 올린 문서에는 원본이 없다. 버튼을 늘 그려두고 404 로 안내하면 **눌러야 그것을
안다** — 6회차에 사용자가 물고 온 것이 정확히 그 종류(*"되는 건지 아닌지 모르겠다"*)였다.
그래서 목록에 `original_missing` 을 실어 배지로 바꾼다. 자리와 모양은 `shadow_missing` 과
같은 것이라 새 패턴이 아니다.

저장 이름 규칙을 `query.py` 에 복사하지 않고 `documents.original_exists()` 를 부른다.
복사하면 규칙이 두 벌이 되어 한쪽만 고쳐진다 — `_reject_unsupported_extension` 을 두 라우트가
나눠 쓰는 것과 같은 이유다.

### 진행 표시는 body 위임 — 두 번째 UI 를 만들지 않는다

재색인 버튼은 **문서 목록 조각 안**에 있어 목록이 다시 그려질 때마다 사라진다. 버튼에 직접
리스너를 걸면 첫 갱신 뒤로 **조용히 안 듣는다**(그리고 갱신은 재색인 자신이 유발한다).
그래서 `document.body` 에서 듣고 `#upload-form, [data-reindex]` 만 골라낸다.

재색인은 **업로드 구간이 아예 없다** — 보낼 파일이 없으므로 `loadstart` 에서 곧바로 색인
구간으로 간다. 버린 것: 재색인 전용 진행 표시를 따로 만드는 안. 같은 상자를 쓰는 것이
*"퍼센트를 지어내지 않는다"* 규약을 한 곳에만 두게 한다.

## 4. 실패 분석

**진행 표시 가드를 함수 시그니처로 깼다.**

`chat.html` 의 `stop()` 이 이제 이벤트를 받아야 해서 `function stop(event)` 로 바뀌었다.
그런데 `tests/api/test_pages.py::test_indexing_phase_shows_time_not_a_fake_percentage` 가
스크립트를 **문자열로 잘라** 검사한다.

```python
indexing = script.split("function enterIndexing()")[1].split("function stop()")[0]
assert "Math.round" not in indexing
```

`"function stop()"` 이 더 이상 없으니 `split` 이 아무것도 못 잘라 **잔여 전체**가 `indexing`
구간이 됐고, 거기에 업로드 구간의 `Math.round` 가 들어와 단언이 터졌다. 즉 **가드가 지키려던
성질은 멀쩡한데 가드가 엉뚱한 데서 터진 것**이다 — 이 종류를 회귀로 오해하면 멀쩡한 코드를
되돌리게 된다.

고친 방향은 코드가 아니라 앵커다. `"function stop("` 까지만 잡으면 인자가 바뀌어도 같은
구간이 잘린다. 가드가 재는 성질(*색인 구간이 퍼센트를 계산하지 않는다*)은 그대로다.

**막다른 길 하나**: `stop()` 의 시그니처를 유지하려고 필터링을 밖으로 빼는 안을 생각했다가
버렸다. 그러면 이벤트 필터가 세 리스너에 흩어져, 앵커를 지키자고 실제 구조를 나쁘게 만드는
교환이 된다.

**못 막은 것**: 진행 표시의 body 위임이 **실제 브라우저에서 듣는지**는 테스트가 없다.
`test_pages.py` 는 스크립트를 문자열로 볼 뿐 실행하지 않는다 — Node 툴체인이 없다는 것이
이 저장소의 전제라 여기서 열지 않았다.

## 7. 남은 것

- **화면 E2E 는 사용자 몫이다.** 진행 표시가 실제로 뜨는지, `hx-confirm` 이 걸리는지,
  7회차 이전 문서에 버튼이 없는지는 브라우저에서만 확인된다. uvicorn 을 띄우면 `.qdrant`
  배타 잠금을 잡으므로 다른 세션과 겹치지 않을 때 해야 한다
- **진짜 재색인의 결과를 안 쟀다** — 보관된 원본으로 다시 돌렸을 때 청크 수가 그대로인지는
  `regression-test` 의 자[尺]다. 이 작업은 라우트 계약만 잠갔다
- **버전 관리·문서 유효성**은 `plan_log/backend.md` 미결의 새 항목이다. 착수 조건은
  `search(filters=)` 를 만질 세션이 `retrieval/` 과 안 겹칠 때다
- **전량 재색인과 진행률 퍼센트**는 여전히 미결이다. 둘은 같은 덩어리(작업 레지스트리·폴링)라
  따로 열면 오류 표시 배선을 두 번 고치게 된다
