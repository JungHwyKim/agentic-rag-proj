# PDF 가 쪼갠 표를 로더에서 되붙였다 — 임계값을 표본 1개에서 5개 PDF로 옮기고 나서

- 작업일: 2026-08-19
- 검증 방법: `detect_regions()` 단독 실측(PDF 5개·표 리전 103개) + `pytest` 전체 + 기준선 대조.
  **외부 API 호출 없음**

## 1. 무엇을 바꿨나

- `rag_pipeline/ingestion/loader/document/pdf.py`
  `_merge_split_tables()` · `_is_same_table()` 신설. 리전을 만들기 **전에** 되붙인다
- `tests/ingestion/loader/document/test_pdf.py` — 판정 세 조건을 각각 잠그는 테스트 4개

- `tests/fixtures/「2025년 학교기록물 관리 지침」 (1).hwpx` 삭제 (기존 파일과 바이트 동일)
- `regression/baseline.json` — 문서 5개 추가, `tests.passed` 337→478 갱신

## 2. 설계 결정

### 되붙이기는 **로더**에서 한다

splitter 나 승급(LlamaParse)이 아니라 리전을 만드는 자리다. 근거가 둘이다.

- **승급으로는 못 고친다.** `table_llamaparse.handle()` 은 리전 하나의 blob 을 보내므로 외부
  API 는 애초에 조각 하나밖에 못 본다. 실측이 이를 보여줬다 — 유료 경로에서 같은 표가 오히려
  10조각이 됐다
- **splitter 도 못 고친다.** splitter 는 리전이 왜 그렇게 잘렸는지 모르고, 알아도 bbox 를
  안 받는다. 조각의 첫 행을 헤더로 되풀이하는 것은 리전이 온전하다는 전제에서 옳은 동작이다

버린 안: splitter 에서 "앞 청크와 열 수가 같으면 헤더를 물려받기". 같은 판별자가 필요한데
splitter 에는 좌표가 없어 더 약한 근거로 같은 일을 하게 된다.

### 조건 셋을 **모두** 걸고, 임계값은 틈에서 고른다

간격 12 / x ±2pt / 열 수 동일. 1회차에서 이 규칙을 미룬 이유는 **조각난 표 표본이 1개**라
간격 임계값을 정할 근거가 없어서였다. PDF 5개로 늘리자 분포가 갈렸다 — 조각난 표는 6.8 이고
x 가 일치하는 나머지는 전부 18.8 이상이다. **2.8배 틈의 가운데를 골랐다.**

열 수 조건이 독립적으로 일한다는 것도 확인했다. 2026 중등 계획 31쪽은 x 도 맞고 간격도
36~39 로 비교적 가깝지만 열이 6→3→2→3 이라 걸러지고, 실제로 서로 다른 표다.

버린 안: 간격만으로 판정. 2026중등 31쪽을 잘못 붙인다.
버린 안: "앞 조각이 헤더만 있는 1행" 을 조건에 추가. 시행령은 잡지만 근거가 표본 하나에
다시 묶인다 — 틈으로 고른 임계값이 그보다 낫다.

### 안 붙인 것도 근거를 남긴다

학교기록물 PDF 31쪽은 한 행씩 리전이 잡혀 **조각난 것이 맞지만 안 붙였다.** 간격이 18.8~21.6
이라 임계값 밖이고, 무엇보다 **헤더 행이 없어 붙여도 되살릴 열 이름이 없다.** 시행령처럼
"열 이름이 첫 조각에만 남는" 피해가 없다. 이 판단을 `verify_log` 3절에 표로 남겼다.

### 기준선에 새 문서를 넣되 **승인된 값이 아니라고 적는다**

기존 6개의 `근거` 는 사람이 문서를 열어 확인한 값이다. 새 5개는 첫 측정값이라 각 항목에
"사람이 확인하지 않았다"를 명시했다. 특히 학교기록물 PDF 의 이미지 81개(HWPX 판은 20개)는
원인 미확인이라 **이 값을 근거로 다른 판정을 하지 말라**고 적어뒀다.

## 4. 실패 분석

### 기준선 `tests.passed` 가 337 로 낡아 있었다

2026-08-17 값이라 embedding·indexing 두 단계가 들어오는 동안 아무도 안 고쳤다. **회귀 판정의
기준이 낡으면 대조가 매번 거짓 양성을 낸다.** 478 로 맞추고 337→383→466→478 의 경위를 근거에
적었다.

### 픽스처를 늘리자 이름 충돌이 났다

새로 받은 `「2025년 학교기록물 관리 지침」 (1).hwpx` 가 기존 파일과 **바이트가 같고** 이름이
부분 문자열로 겹쳐, `_find()` 가 둘을 잡아 테스트 3개가 실패했다. CLAUDE.md 가 경고해 둔 함정이
실제로 발생한 것이다 — `_find()` 가 `pytest.fail` 로 막아준 덕에 **엉뚱한 문서에 정답을 적용하는
사고는 안 났다.** 안전장치가 설계대로 동작했다.

### 표 위주 문서가 파싱 실패로 오인됐다

`test_extracts_body_without_warnings` 가 **문단** 글자수 5,000 을 요구했는데, 새 2026중등
문서는 본문 27,431자 중 82%가 표에 있어 문단만 세면 4,653자다. 임계값이 산문 위주 코퍼스를
가정하고 있었다. 전체 요소를 세도록 고쳤다 — "본문을 뽑았는가"를 묻는 자리이므로 표도 본문이다.

### 되돌린 것: 없음

다만 `_merge_split_tables()` 를 부르는 코드를 먼저 넣고 함수를 나중에 넣어 `NameError` 로
폴백하는 중간 상태를 한 번 거쳤다. PostToolUse 훅이 즉시 잡았다.
