## 계획과 실제가 어긋난 곳

하나 있었고, 리뷰에서 잡았다. **"예외를 던진다"고 정해놓고 던지지 않는 경로가 하나 남아
있었다.** 응답 항목의 `embedding` 필드가 손상되면 `AttributeError`/`TypeError` 가 날것으로
새어 나간다 — `RagPipelineError` 가 아니라서 `_status_for()` 가 매핑표에서 못 찾고 500 을
돌려준다. `EmbeddingError` 로 감쌌다(`_as_vector()`). 계약을 세우는 것과 **모든 경로에서
지키는 것**은 다른 일이라는 것을 다시 확인했다.

나머지는 계획대로다. 특히 **결정 2(키 없으면 예외)와 결정 3(`ingest()` 에 안 끼움)이 서로를
지탱한다**는 예상이 실제로 맞았다 — 기본 pytest 383개가 키 없이 그대로 통과한다.

## 확정된 것

### 책임 경계

- embedding 의 책임은 **`str -> list[float]`** 하나다. Chunk 를 다시 자르거나 고치지 않고,
  metadata 를 벡터에 섞지 않고, Vector DB 를 모른다
- 입력은 `list[Chunk]` 가 아니라 **`list[str]`** 이다. 상위가 `[c.text for c in chunks]` 를
  넘긴다 — Embedder 가 `Chunk` 를 알면 질의 임베딩(`embed_query`)과 비대칭이 된다

### 인터페이스

```python
class Embedder(Protocol):
    def embed_documents(self, texts: list[str]) -> list[list[float]]: ...
    def embed_query(self, text: str) -> list[float]: ...
    @property
    def usage(self) -> EmbeddingUsage: ...
```

- **문서/질의 분리는 지금 아무 차이가 없다.** `text-embedding-3-*` 는 둘을 구분하지 않는다 —
  유료 호출로 `embed_query(t)` 와 `embed_documents([t])[0]` 이 **최대 원소차 0.0 으로 완전히
  같음**을 확인했다(둘 다 1개짜리 배치라 입력이 동일하다). 분리하는 이유는 **로컬 모델 대비**
  하나뿐이다(BGE·E5 계열은 질의에 접두사를 요구한다). 그렇게 정직하게 적는다 —
  "임베딩 공간이 달라서"가 아니다
- `usage` 를 Protocol 에 넣은 이유: 비용 카운터가 보여야 하는데(contracts 3절 a)
  embedding 은 `ingest()` 밖에 있어 `DocumentMetadata` 로 나갈 길이 없다. `LoadContext`
  처럼 인자로 받는 형태 대신 인스턴스에 둔다 — 승인된 시그니처 `embed_documents(texts)` 를
  지키기 위해서다. 문서당으로 읽으려면 호출부가 `reset()` 한다

### 실패 계약 — 예외를 던진다

**`len(out) == len(in)` 이 계약이고, 못 지키면 예외(`EmbeddingError`)다.**

이건 contracts.md 2절("외부 API 는 예외를 안 던지고 빈 결과 + `ctx.warn()`")을 **의도적으로
따르지 않는 것**이다. 그 규약은 **폴백 층이 있어서** 성립한다 — LlamaParse 가 죽으면
PyMuPDF 로, Vision 이 죽으면 OCR 로 내려간다. **embedding 에는 내려갈 층이 없다.**
빈 벡터를 돌려주면 그 청크는 영원히 검색되지 않는데 아무도 모른다 — contracts 2절이 막으려던
바로 그 상황("사용자는 결과가 왜 엉성한지 알 길이 없다")이 규약을 문자대로 지켜서 일어난다.

예외로 받는 경우: 키 없음 / API 실패 / 응답 개수 불일치 / 빈 문자열 입력 / 토큰 상한 초과.
전부 `EmbeddingError` 하나로 받는다 — 둘로 가르면 `_status_for()` 의 `isinstance` 순서
문제만 는다.

### 비용 통제 — contracts 3절을 embedding 모양으로

| | 로더 쪽 | embedding 쪽 |
|---|---|---|
| (a) 성공 뒤 카운터 | `ctx.vision_calls += 1` | `usage.api_calls` · `usage.total_tokens` |
| (b) 상한 | `max_vision_calls_per_doc` | `max_embedding_tokens_per_doc` |
| (c) 캐시 salt | `f"vision:{model}"` | `f"embed:{model}:{dim}"` |

**(b) 를 호출 수로 베끼면 아무것도 안 막는다.** embedding 은 배치라 청크 500개가 5회
호출이다. 돈은 호출이 아니라 **토큰**이다. `tiktoken` 으로 호출 전에 세서
`max_vision_calls_per_doc` 와 같은 사전 검사 모양을 유지한다.

**`LoadContext` 는 재사용하지 않고 `content_hash()`·`ResultCache` 는 재사용한다.**
`LoadContext` 는 `ContentRoutingConfig` 와 loader 전용 카운터(`vision_calls`·`ocr_applied`)를
들고 있어 끌어오면 loader 관심사가 샌다. 해시·캐시는 splitter 가 `content_hash` 에 대해
이미 같은 판단을 했다.

### 합성 지점 — `ingest()` 에 안 끼운다

splitter 와 **같은 이유이고 한 칸 밀린 같은 상황**이다. 벡터를 소비할 곳(indexing)이 없다.
`ingest()` 의 반환은 곧 `backend` 의 `response_model` 이라 바꾸는 순간 API 결정이 된다.
게다가 청크 285~721개 × 1536차원 float 를 업로드 응답에 실으면 수 MB 다.

부수 효과 하나가 중요하다 — **기본 `pytest` 가 embedding 을 아예 안 부른다.** 그래서
"키 없으면 예외"가 기본 테스트를 안 깬다. 결정 둘이 서로를 지탱한다.

### 모델·차원

`text-embedding-3-small` / 기본 차원(1536). **임시값이고 실측 전이다.**
모델 간 한국어 검색 품질은 **못 잰다** — 정답 질의 세트가 없다(`평가-세트.md`).
싼 쪽에서 시작하고 캐시 salt 에 모델·차원을 넣어 교체 가능하게 뒀다.
다시 볼 조건: `평가-세트.md` 가 닫힐 때.

**그 조건이 도래했고 2회차가 잴 수단까지 만들었다**(2026-08-24). 값 자체는 아직 이것이다.

**3회차가 두 번째 프로필을 골랐다**(2026-08-24) — **`nlpai-lab/KURE-v1`**(1024차원 · 8192
컨텍스트 · 2.27GB · MIT · 접두사 없음 · bge-m3 를 한국어 검색으로 파인튜닝). **운영 기본값은
`text-embedding-3-small` 그대로**이고, 로컬 모델은 평가 프로필 `kure-v1` 로만 실재한다 —
갈아탈지는 측정을 읽은 뒤 사람이 정한다. 고른 근거와 버린 셋은 아래 3회차.

### 캐시 salt 의 규칙은 구현체가 갖지 않는다 (2회차)

`base.py:cache_salt_for(embedding)` 하나가 정하고 `OpenAIEmbedder._salt` 가 그것을 부른다.
**`indexing.collection_name_for()` 의 거울**이다 — 저쪽은 벡터가 *저장되는* 자리를, 이쪽은
*캐시되는* 자리를 가른다.

근거: 원래 구현체 사설 프로퍼티였는데, 그러면 **두 번째 구현체가 salt 를 자기가 다시 짜야
하고 빠뜨려도 아무 에러가 안 난다.** 저쪽은 처음부터 모듈 수준 공개 함수라 그 위험이 없었고
이쪽에만 대칭이 없었다. 값(`embed:{model}:{dim}`)은 **한 글자도 안 바꿨다** — 동일성 실행의
`usage.tokens` 가 0 인 것이 그 실증이다(캐시 전량 적중).

규칙은 **벡터를 바꾸는 설정은 전부 여기 들어간다**이고, 지금 실재하는 축은 `(모델, 차원)`
둘이다. `tests/ingestion/embedding/test_cache_salt.py` 가 두 파생이 **같은 필드에 반응하는지**를
강제한다(값이 아니라 반응을 본다 — 문자열 모양이 원래 다르다).

### 평가 러너에 임베딩 프로필 축이 있다 (2회차)

`evaluation/config.py` 의 `EVAL_EMBEDDINGS`(이름 → 설정) + `--embedding <이름>`. 기본은
`baseline` 이라 아무것도 안 주면 지금까지와 같은 실행이다. 고정 중에 **임베딩 블록 하나만**
축이 있다.

근거: `평가-세트.md` 가 `--config-env` 를 기각한 사유 둘을 **둘 다 피한다** — 값이 둘 이상
실재해 *"합법값이 하나뿐인 죽은 설정"* 이 아니고, 저장소에 커밋된 **닫힌 집합**이라 고정을
통째로 푸는 것도 아니다. `baseline.json` 만 보고 어느 설정으로 잰 값인지 안다는 성질이 산다.

딸린 계약 둘 — 리포트가 **이름과 값을 둘 다** 싣는다(이름만 남기면 그 프로필의 내용이 나중에
바뀌었을 때 옛 결과가 무엇으로 쟀는지 모른다). `compare_to_baseline()` 이 **프로필이 다르면
물러선다**(포맷 가드와 같은 이유). 단 **키가 없으면 기본 프로필로 읽는다** — 커밋된
`baseline.json` 은 축이 생기기 전에 만들어져 그 키가 없다.

### 겹침 구간별 채점은 저장소 코드다 (2회차)

`evaluation/overlap.py`. `verify_log/2026-08-24-어휘겹침.md` 6절 인라인을 옮겼다.
**총합으로 재면 겹침 0 구간(질의의 1/3)의 변화가 나머지 3분의 2에 묻힌다** — 모델을 바꾸면
정확히 그 구간이 움직일 것으로 기대하므로, 총합은 찾으려던 것을 못 본다.

인라인으로 두지 않은 이유는 **용도가 달라졌다**는 것이다 — 이제 모델 비교의 주 판정 기준이라
복사본 둘이 갈리면 두 실행이 다른 자로 재는데 아무 에러가 안 난다.

### 로컬 갈래가 열렸다 — 셋이 한 변경이다 (3회차)

`evaluation/README.md` 8-1 이 *"셋이 한 변경"* 으로 묶어둔 것이 이번에 함께 열린다.

| 무엇 | 3회차의 결정 |
|---|---|
| `EmbeddingConfig.embedding_provider` + `get_embedder()` 분기 | **연다.** 구현체가 둘이 되어 *"합법값이 하나뿐인 죽은 설정"* 이 아니게 됐다 |
| `tests/conftest.py` 의 `offline_config` | **`embedding_provider="openai"` 를 못 박는다.** 지금 방어는 *"키를 지운다"* 인데 **로컬 모델은 키가 없어도 돈다** — 개발자 `.env` 에 `EMBEDDING_PROVIDER=local` 이 있으면 기본 pytest 가 가중치를 내려받고 **아무 에러도 안 난다** |
| `cache_salt_for()` 에 provider·질의 접두사 | **안 넣는다.** 아래 절 |

**의존성은 `requirements-local.txt` 로 가른다.** `torch`(Windows/cp311 휠 122MB, PyPI 기본이
CPU 빌드) + `sentence-transformers` 다. 본체에 넣으면 로컬 프로필을 안 쓰는 사람도 코드
~140MB 와 가중치 2.27GB 를 받는다. **부수 효과가 더 크다** — 기본 pytest 환경에 `torch` 가
아예 없으면 *"가중치를 조용히 내려받는 경로"* 가 구조적으로 없다. `offline_config` 방어와
같은 방향으로 두 겹이 된다.

### provider 는 salt 에 안 들어간다 (3회차, 2회차가 연 미결을 닫음)

`cache_salt_for()` 도 `collection_name_for()` 도 **값을 한 글자도 안 바꾼다.**

근거는 **provider 가 모델 이름을 통해서만 벡터를 바꾼다**는 것이다. `text-embedding-3-small`
과 `nlpai-lab/KURE-v1` 은 같은 자리를 볼 수 없고, 두 provider 의 이름 공간이 애초에
겹치지 않는다(OpenAI 는 `text-embedding-*`, 로컬은 `org/name` 꼴로 슬래시를 갖는다).
규칙(*"벡터를 바꾸는 설정은 전부 여기 들어간다"*)은 실질적으로 지켜진다.

**넣었을 때의 대가가 실재해서 이쪽이 이겼다** — salt 가 바뀌면 `.cache/embedding` 이 전량
미스가 되고(재임베딩 139,438토큰), 개발자 `.qdrant` 의 기존 컬렉션이 고아가 되며, 2회차가
동일성 실행으로 닫은 *"`tokens 0 · calls 0`"* 성질이 한 번 깨진다.

**질의 접두사는 여전히 죽은 축이다** — KURE-v1 의 `config_sentence_transformers.json` 이
`prompts: {}` · `default_prompt_name: null` 이라 접두사를 안 쓴다. 접두사 모델을 실제로
붙이는 날 그때 연다.

### 로컬은 차원을 못 줄인다 — 값이 오면 예외 (3회차)

`embedding_dimensions` 는 **`None` 그대로 두고**, 로컬 구현체는 값이 오면 `EmbeddingError`
를 던진다. bge-m3 계열은 MRL 미학습이라 앞 N 차원을 잘라 재정규화하면 **품질이 조용히**
나빠진다.

**필드의 뜻을 provider 마다 가르지 않으려는 것**이 이 결정이다 — `embedding_dimensions` 는
*"차원을 줄여라"* 하나이고, OpenAI 는 할 수 있고 로컬은 못 하니 거절한다. 프로필에 1024 를
적어 *"이럴 것이다"* 라는 기대값으로 쓰는 안은 그 이유로 기각했다.

**끝까지 성립한다는 것은 코드가 이미 답했다** — `pipeline.py` 가
`ensure_collection(len(records[0].vector))` 로 **실제 벡터에서** 크기를 얻고,
`qdrant_store.py` docstring 이 *"`None` 은 '모델 기본값'이라는 뜻이지 차원을 아는 값이
아니다"* 라고 적어 놨다.

곁가지로 `evaluation/README.md` 2번의 *"차원이 다르면 `embedding_dimensions` 도 함께
적는다"* 는 **범위를 좁혀야 한다** — 그 경고는 모델 이름이 같을 때를 위한 것이다.

### device 는 설정이 아니라 `cpu` 고정 (3회차)

`embedding.device` 를 만들지 않고 구현체가 `cpu` 로 못 박는다. **근거는 재현성이고,
`evaluation/config.py` 가 `.env` 를 막은 것과 같은 이유다** — 누가 cu128 torch 를 깔면 같은
명령이 머신마다 다른 벡터를 내고 *"baseline 은 재현될 때만 기준선"* 이 무너진다.

이 머신에 RTX 5060 Laptop(8GB)이 있지만 Blackwell(sm_120)은 Windows 네이티브 torch 가
PyPI 밖 `index-url` 을 요구하는 경로이고, 414청크+60질의 규모에 그 값을 치를 이유가 없다.

## 언제 하나 — 뒤에 오는 것들의 선행 조건

지시서 초안이 Vector DB·Retriever·Semantic Cache·Conversation History 를 "향후 연계"로
한데 묶었는데, **선행 조건이 전혀 다르고 하나는 embedding 과 무관하다.**

| # | 단계 | 언제 | 무엇이 있어야 하나 |
|---|---|---|---|
| 1 | embedding | 이번 | — |
| 2 | indexing / Vector DB | embedding 직후 | `qdrant-client` 설치. 여기서 **`document_id` 정책**("재업로드 = 중복인가")이 정해진다 — splitter·embedding 이 둘 다 이 미결을 열어두고 기다린다 |
| 3 | retriever | indexing 직후 | **질의 엔드포인트가 여기서 처음 생긴다.** 지금 backend 에는 업로드 하나뿐이라 "질문"이 존재하지 않는다 |
| 4 | 평가 세트 | retriever 와 함께 | retriever 가 있어야 recall@k 를 잴 대상이 생긴다. 없으면 3의 top-k·threshold 가 전부 임시값이다 |
| 5 | 생성 (LLM 답변) | retriever 뒤 | — |
| 6 | **Conversation History** | **3에서 질의 엔드포인트가 생기는 시점.** 5와 함께가 자연스럽다 | 세션·턴 개념, KV/관계형 저장소. LangGraph Checkpointer 를 쓸 거면 에이전트 그래프가 먼저 — LangGraph 는 설치돼 있지도 않다 |
| 7 | **Semantic Cache** | **제일 뒤.** 4와 5가 둘 다 선 뒤 | 캐시할 **답**(5), 질문 벡터를 담을 **저장소**(2), **유사도 임계값의 근거**(4) |

**Conversation History 는 embedding 을 기다릴 이유가 없다.** 일반 대화 히스토리는 벡터를
안 쓴다 — 최근 N턴을 그대로 넣는 것이 기본이다. embedding 을 쓰는 것은 **장기 기억**(과거
대화에서 의미적으로 관련된 것을 검색)뿐이고, 그건 History 와 별개 기능이며 7보다도 뒤다.

**Semantic Cache 를 제일 뒤로 미는 이유는 순서가 아니라 위험이다.** 나머지는 없으면 기능이
없을 뿐인데 이건 **임계값이 틀리면 다른 질문에 옛 답을 준다.** "0.95 이상이면 같은 질문"의
0.95를 정할 근거가 지금 없고, 그 근거는 4가 생겨야 나온다. 게다가 **최적화**라 없어도
시스템이 돈다. 근거 없이 먼저 넣으면 안 되는 부류의 대표다.

**이번 작업이 6·7에 실제로 남기는 것은 둘뿐이다** — `embed_query()` 가 `embed_documents()` 와
같은 모델·같은 salt 를 쓴다는 것, salt 에 모델·차원이 들어간다는 것. 초안의 "구조를 갖춘다"는
검증할 수 없는 문장이라 이 둘로 바꿔 적는다.

  밟았다. **추상화를 먼저 두고 설정을 나중에 연 것이 실제로 값을 했다** — 호출부는 안 바뀐다

  **2회차에서 같은 잣대를 캐시 키에도 적용했다**(2026-08-24) — `cache_salt_for()` 를 만들면서
  `provider` 를 파생에 넣을지 물었고 **안 넣었다.** 구현체가 하나면 파생 축도 죽은 축이다.
  대신 규칙을 함수 docstring 에 못 박고 테스트로 두 파생의 일치를 강제해, **열 때 한 곳만
  고치면 되는 상태**로 뒀다. `indexing.collection_name_for()` 도 같은 상태다
- **평가 러너에서 임베딩 말고 다른 설정까지 갈아끼우는 것** (2회차) — 이유: `평가-세트.md` 가

  기준선이다"* 라 통째로 푸는 것은 목적을 없앤다 / 다시 볼 조건: 임베딩이 아닌 축을 실제로
  비교하게 될 때. 그때도 **이름 붙인 프로필 모양**을 먼저 검토한다
- **`--model` 문자열 하나로 모델 축을 내는 것** (2회차) — 이유: 제일 작지만 로컬 갈래에서

  플래그를 다시 설계하게 된다 / 다시 볼 조건: 없다 — 프로필이 이것을 포함한다
- **로컬 embedding 구현체를 지금 만드는 것** — 이유: 두 번째 구현이 있어야 추상화가 맞는지

## 1회차 — 2026-08-17 · 지시서 초안 검토와 설계 확정

**물은 것**

사용자가 embedding 지시서 초안(18절)을 가져와 "필요한 부분·불필요한 부분"을 요청했다.
초안의 뼈대는 *"Text → Vector 로 책임을 좁히고 Vector DB·Retriever·Semantic Cache·
Conversation History 를 밀어낸다"* 였다.

**드러난 것 — 초안은 맞는 말이지만 이 저장소 것이 아니다**

뼈대는 옳다. 어긋난 곳이 셋이다.

*(1) 같은 경계 선언이 네 번 있다 (3·15·16·18절).* 그런데 이 패턴은 `splitter.md` 1회차에서
이미 기각한 것이다 — *"그 코드가 한 줄도 없어서 '변경하지 않았다' 체크박스가 항상 통과한다.
검사로서 값어치가 0이다."* Retriever·Semantic Cache·Conversation History 는 이 저장소에
한 줄도 없다. 사용자가 여기서 **"언제 해야 되는지 명시해줘"** 를 짚었고, 그게 이 절을 지우는
대신 **선행 조건 표로 바꾸는** 결론이 됐다(위 "언제 하나"). 금지를 네 번 적는 것보다 다시 볼
조건을 한 번 적는 것이 `plan-log` 형식에도 맞다.

*(2) 초안의 두 규약을 합치면 조용히 깨진다.* 초안 10절은 `list[list[float]]` 를 돌려주라
하고, 이 저장소의 contracts 2절은 실패 시 빈 결과를 돌려주라 한다. 둘을 그대로 합치면
`zip(chunks, vectors)` 가 조용히 어긋난다 — 배치 중간이 실패하면 자리가 밀려도 아무도
안 죽는다. 그리고 초안 6·7절의 `APIEmbedding` 클래스가 `__init__` 에서 클라이언트를 만들면
contracts 6절이 **Critical** 로 못 박은 `_make_client()` 모킹 이음새가 깨진다.

*(3) 비용 통제가 한 글자도 없다.* `CLAUDE.md` 에 "비용 통제" 절이 있고 contracts 3절이
카운터·상한·캐시 salt 셋을 요구하며, `next-stages.md` 는 embedding 을 콕 집어 적어놨다 —
*"캐시 salt 에 모델명·차원·버전을 넣는다. 임베딩 모델을 바꿨는데 옛 벡터가 나오면 검색이
조용히 망가진다."*

곁가지로 초안의 사실 오류 넷: `Chunk.content`(실제 `text`), `document_id`(실제
`document_key`, 그리고 그게 없는 것이 splitter 의 명시적 미결), `Preprocessor`(실제
`cleaner`), `ingestion/splitter.py`(실제 패키지). 그리고 *"차원은 모델이 정하니 코드에
고정하지 않는다"* 는 반만 맞다 — `text-embedding-3-*` 는 `dimensions` 파라미터로 줄일 수
있어 **차원은 설정값**이고, 캐시 salt 와 (나중에) 컬렉션 정의에 함께 들어간다.

**선택지 — 부분 실패 시 청크↔벡터 대응**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| 길이 보장 + 실패는 예외 | 초안 형식 유지, 상위가 `Chunk` 를 몰라도 된다 | 한 청크 실패 = 배치 전체 실패 | 폴백 층이 없어 "빈 결과"가 오용이 되는 자리 |
| `EmbeddedChunk` 로 id 를 묶는다 | 부분 성공 표현 가능 | Embedder 가 `Chunk` 를 알게 되고 `embed_query` 와 비대칭 | 초안 5절 인터페이스를 이탈 |
| 초안 그대로 (실패 시 `[]`) | contracts 2절 문자 그대로 | `zip` 이 조용히 어긋난다 | contracts 2절은 폴백이 있어서 성립하는 규약이다 |

**고른 것과 이유**

네 갈래 전부 사용자가 골랐고 넷이 서로 엮여 있다.

1. **길이 보장 + 예외.** 나머지 둘은 위 표 그대로.
2. **키 없음도 예외.** 폴백 층이 없는 자리에서 빈 벡터는 "영원히 검색 안 되는 청크"를
   조용히 만든다.
3. **`ingest()` 에 안 끼운다.** splitter 와 같은 이유. 그리고 이게 2번의 부작용을 없앤다 —
   기본 `pytest` 가 embedding 을 아예 안 부르므로 "키 없으면 예외"가 테스트를 안 깬다.
   **결정 2와 3이 서로를 지탱한다.**
4. **`text-embedding-3-small` / 1536, 임시값 표시.** 품질 비교를 못 재니 싼 쪽에서 시작하고
   salt 로 교체 가능하게 둔다.

**초안에서 덜어낸 것**

경계 선언 네 벌 → 선행 조건 표 하나, 4절(embedding 정의), 5·6·7절의 같은 다이어그램 셋,
10절 예시, 8절 `provider` 설정, 14절 Protocol 런타임 검사 테스트, 13절 `timeout`/`max_retries`.

**초안에 더한 것**

비용 통제 3종, `_make_client()` 이음새 보존, 실패 경로 테스트 6종(contracts.md:
*"이 저장소에서 제일 자주 빠지는 테스트다"* — 초안 14절 4종은 전부 성공 경로였다),
`offline_config` 에 키 차단(`EmbeddingConfig()` 가 `.env` 를 읽어 개발자 머신의 실키가
픽스처로 샐 수 있다), `auto_test_check.py` 매핑.

**남은 질문**

위 "미결" 전부. 배치 크기·토큰 상한은 이번 구현의 실측으로 닫고, 나머지는 indexing 과
`평가-세트.md` 를 기다린다.

## 2회차 — 2026-08-24 · 모델 비교 핸드오프를 인수하고 잴 수단을 만들었다

README 1번 표의 셋이 전부 통과했다. `baseline.json` 의 `settings.embedding` 이

`get_embedder()` 가 단일 분기 · `collection_name_for()` 가 이미 모델·차원을 이름에 담는다.

**선택지 — 어느 모델로 두 번째 축을 세우나**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| **로컬 한국어 모델** (고름) | 과금 0. 계열·토크나이저가 진짜 달라 **음성 결과가 결론이 된다** | `provider` 설정 + `get_embedder()` 분기 + 새 의존성이 선행. "안 하기로 한 것" 두 항목이 함께 열린다 | 겹침 0 구간은 **정의상 낱말이 아니라 뜻으로 찾아야 하는 자리**라 가능성이 제일 크다 |

**선택지 — 러너에 축을 어떻게 내나**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| **이름 붙인 프로필** (고름) | 기각 사유 둘을 다 피한다 | 프로필 하나뿐인 동안은 축이 도는지만 확인 가능 | 값이 둘 이상 실재해 죽은 설정이 아니고, **커밋된 닫힌 집합**이라 통째로 푸는 것도 아니다 |

**사용자가 열어준 갈림길 하나 — 캐시 키**

*"`--embedding` 으로 모델을 바꿔도 캐시 키가 텍스트만 기준이면 이전 모델 벡터가 그대로 튀어
나올 수 있다"* 는 지적이었다. 확인해 보니 **절반은 이미 닫혀 있었다** — salt 가
`embed:{model}:{dim}` 이라 값은 안전했다. **열려 있던 절반이 구조다**: 그 규칙이
`OpenAIEmbedder` 사설 프로퍼티라 두 번째 구현체가 다시 짜야 하고 **빠뜨려도 에러가 안 난다.**
`collection_name_for()` 는 모듈 수준 공개 함수라 그 대칭이 이쪽에만 없었다. 이 지적이
`cache_salt_for()` 승격을 만들었다.

**고른 것과 이유**

넷 다 사용자가 골랐다.

1. **로컬 한국어 모델** — 다만 *어느* 로컬 모델인지는 **계획서에 갈래로 남기고 배선 회차에서
   확정**하기로 했다. 기억 속 벤치마크 순위로 고르면 `이미지-경로.md` 1회차의 탐침값 사고를
   되풀이한다
2. **이름 붙인 프로필 레지스트리** — 위 표
3. **캐시 키를 공유 함수로 + 벡터를 바꾸는 것 전부를 같은 자에 넣는 규칙** — 지금 실재하는
   축은 (모델, 차원) 둘이고 provider·접두사는 **죽은 축이라 안 넣었다**
4. **이번 회차는 축까지** — 모델을 함께 갈아끼우면 다음에 수치가 이상할 때 *축 탓인지 모델
   탓인지* 못 가른다

**닫힌 것 — 축이 산출을 안 바꾼다**

`--embedding baseline` 2회가 대조군과 **전 항목 일치**했다. 60건 `hit@10 0.4833 ·
MRR 0.2530` 에 러너 자신의 대조가 **이김 0 · 짐 0 · 그대로 60**(순위가 한 건도 안 움직였다),
20건 `0.4000 / 0.1635`, 청크 118·71·103·122 동일. **실제 청구 $0.00**(`tokens 0 · calls 0`) —
salt 를 안 건드렸다는 실증이기도 하다. 겹침 모듈도 인라인을 재현했다(중앙 0.200/0.128 ·
이득 `+0.000/+0.300/+0.250` · 겹침 0 구간 `↑6 ↓5`).

**곁가지 — 다른 세션 셋과 겹침을 조율했다**

같은 트리에 답변 캐시 세션과 hybrid 세션이 함께 있었다. 겹치던 세 파일
(`rag_pipeline/config.py` · `.env.example` · `tests/conftest.py`)은 **범위가 좁아지면서 이번
회차에서 빠져** 저쪽이 먼저 가고 이쪽이 다음 회차에 얹기로 순서를 뒤집었다. hybrid 세션이
넘긴 *"두 판 모두 못 잡은 6건 중 5건"* 은 확인 요청 결과 **`@10` 에서 6건 전부**로 정정됐다
(5는 `@20` 관점이고 주지표가 `hit@10` 이다 — 저쪽이 커밋 `b53f935` 로 고쳤다).

**남은 질문**

위 "미결" 전부. 머리는 **어느 로컬 모델인가**이고, 그것을 고르는 순간 `offline_config` 방어와
`provider` 파생이 **함께** 열린다.

## 3회차 — 2026-08-24 · 로컬 임베더 모델을 고르고 배선을 정했다

**물은 것**

사용자가 *"`evaluation/README.md` · `plan_log/embedding.md` 2회차 · INDEX 셋 읽어보고 로컬
임베더 모델 정해보자"* 로 시작했다. 2회차가 **잴 수단만 만들고 모델은 일부러 안 고른 채**

**먼저 한 것 — 기억이 아니라 카드·파일·이 머신을 봤다**

2회차가 남긴 지시(*"실제 모델 카드를 보고 정한다"*)를 글자 그대로 따랐다. HF API 로 파일
크기를, `raw/main` 으로 `modules.json`·`config_sentence_transformers.json` 을, PyPI API 로
휠 크기를, `nvidia-smi` 로 이 머신을 확인했다.

|---|---|---|---|---|---|
| `nlpai-lab/KURE-v1` | 1024 | 8192 | 2.27 GB | **없음** | MIT |

**설치 용량은 가중치가 전부였다** — `torch` win/cp311 휠 122MB · `transformers` 11.7MB ·

**순위표로 고르지 않기로 한 것이 이 회차의 방법론이다**

KURE 저장소 표는 `KURE-v1 0.6947 > BGE-m3-ko 0.6875 > bge-m3 0.6872 > mE5 0.6637 >
openai-3-large 0.6167`(NDCG@10, 8개 한국어 검색 세트)이고, arctic-ko 카드 표는
`arctic-ko 0.740 > BGE-m3-ko 0.730 > KURE-v1 0.728` 이다. **두 표를 섞을 수 없다** — 같은
KURE-v1 이 0.695 와 0.728 로 스케일이 다르고, 뒤엣것은 저자 자신이 낸 표다. 0.012 차로
고르는 것이 정확히 `50pt 탐침값` 이다. **그래서 순위는 근거에서 뺐고, 우리 60건이 답한다.**

**선택지 — 어느 로컬 모델인가**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |

**선택지 — 의존성을 어디에 두나**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| **별도 `requirements-local.txt`** (고름) | 기본 설치 불변 | 한 줄 설치가 두 줄이 된다 | **부수 효과가 본 효과보다 크다** — 기본 pytest 환경에 `torch` 가 아예 없으면 *"가중치를 조용히 내려받는 경로"* 가 **구조적으로** 없다. `offline_config` 방어와 두 겹이 된다 |
| `requirements.txt` 본체 | 한 줄 설치 유지 | 안 쓰는 사람도 코드 ~140MB + 가중치 2.27GB | 지금 본체가 *"추후 단계 - 지금은 설치하지 않음 (없음)"* 으로 끝난다. 안 쓰는 사람에게 비용이 가는 첫 항목이 된다 |

**사용자가 열어준 갈림길 둘 — 차원과 salt**

둘 다 *"축이 무엇을 뜻하나"* 를 묻는 같은 종류였다.

*(1) `embedding_dimensions`.* 코드는 `None` 으로 끝까지 성립한다고 답했다 —
`pipeline.py` 가 `ensure_collection(len(records[0].vector))` 로 실제 벡터에서 크기를 얻고,
`qdrant_store.py` docstring 이 이미 *"`None` 은 '모델 기본값'이라는 뜻이지 차원을 아는 값이
아니다"* 라고 적어 놨다. 그런데 `evaluation/README.md` 는 반대로 *"차원이 다르면 함께
적는다"* 고 지시한다. **둘 중 하나는 고쳐야 했고**, `None` + 예외를 골랐다 — 한 필드가
provider 마다 다른 뜻(*명령* vs *기대값*)을 갖는 것이 이 저장소가 계속 경계하는 모양이다.
README 쪽은 경고의 **범위를 좁힌다**(모델 이름이 같을 때를 위한 것이었다).

*(2) salt 에 provider.* 2회차가 명시적 미결로 열어둔 것이다. **안 넣기로 했고, 결정적인
것은 대가가 실재한다는 쪽이었다** — 넣으면 `.cache/embedding` 전량 미스, 개발자 `.qdrant`
컬렉션 고아화, 그리고 2회차가 동일성 실행으로 닫은 *"`tokens 0 · calls 0`"* 이 한 번 깨진다.
얻는 것은 **이미 갖고 있다** — provider 는 모델 이름을 통해서만 벡터를 바꾸고 두 이름
공간이 안 겹친다.

**고른 것과 이유**

넷 다 사용자가 골랐다.

1. **`nlpai-lab/KURE-v1`** — 위 표. 순위가 아니라 카드의 사실로 골랐다
2. **별도 `requirements-local.txt`** — 부수 효과(기본 pytest 에 `torch` 부재)가 본 효과보다 크다
3. **`embedding_dimensions` 는 `None` 유지 + 로컬은 값이 오면 예외** — 필드의 뜻을 안 가른다
4. **salt 에 provider 를 안 넣는다** — 이름 공간이 안 겹치고, 넣는 대가가 실재한다

곁가지로 **`device` 를 설정으로 안 연다**(구현체가 `cpu` 고정). 이 머신에 RTX 5060
Laptop(8GB)이 있는데도 그렇게 한 이유는 재현성이다 — cu128 torch 를 깐 머신에서만 GPU 로
가면 같은 명령이 다른 벡터를 낸다. `evaluation/config.py` 가 `.env` 를 막은 것과 같은 잣대다.
겸사겸사 Blackwell(sm_120)이 Windows 네이티브에서 PyPI 밖 `index-url` 을 요구하는 경로라
비용도 크다.

**안 닫은 것 — 이 회차는 배선까지다**

**모델을 골랐다는 것이 갈아탔다는 뜻이 아니다.** 운영 기본값은 `text-embedding-3-small`
그대로이고, KURE-v1 은 평가 프로필 `kure-v1` 로만 실재한다. 갈아탈지는 60건·20건을
**겹침 구간별로** 읽은 뒤 사람이 정한다 — 총합 `hit@10` 으로 읽으면 겹침 0 구간(질의의
1/3)의 변화가 나머지 3분의 2에 묻힌다(2회차가 실제로 한 번 한 실수다).

**남은 질문**

위 "미결" 전부. 머리는 **갈아탈 것인가**이고, 그 답은 이 회차가 만든 프로필을 실제로 돌려야
나온다. 함께 잴 것 하나가 예약돼 있다 — `verify_log/2026-08-24-리랭커-여지.md` 가 센
**hybrid 후보 풀(50) 밖의 정답**(60건 중 7 · 20건 중 1)과 겹침 0 구간의 **교차**다.
따로 재면 *모델이 움직인 것*과 *표적이 원래 좁았던 것*이 섞인다.

## 4회차 — 2026-08-24 · 두 임베더 융합을 고르고, hybrid 의 세 뜻을 갈랐다

**물은 것**

3회차 배선을 돌려 KURE-v1 이 dense `hit@10` 을 크게 올린 직후, 사용자가 물었다 —
*"embedder 는 hybrid 로 사용할 수 없어? 어차피 로컬은 저장공간 잡아먹는 거 외 비용이 안 들고,
상용 embedder 로 돌린 결과랑 비교해서 더 좋게 나오면 그거대로 사용 못해?"*

**드러난 것 — "hybrid" 가 세 가지로 읽혔고, 하나를 내가 빠뜨렸다**

| 뜻 | 실체 | 지금 재보려면 |
|---|---|---|
| 1. dense + BM25 | 저장소가 `--hybrid` 라 부르는 것. `fuse(dense, sparse, ...)` | **명령 두 줄**(코드 있음, 무료). **KURE 위에서만 안 재봤다** |
| 2. 상용 dense + 로컬 dense | 코드 없음 | 배선 선행. 질의당 OpenAI 과금 부활 |
| 3. **모델 자체의 hybrid** | `bge-m3` 계열이 한 인코딩으로 dense + learned sparse + ColBERT 를 낸다. 모델 카드가 스스로 "hybrid retrieval" 이라 부른다 | 모델 교체 선행 |

**3번을 처음에 빠뜨렸고, 사용자가 되물어 잡혔다.** *"embedder 를 hybrid 로"* 라는 말에 제일
문자 그대로 맞는 것이 3번인데 1·2번으로만 읽고 계획서를 썼다. 되물음이 없었으면 그대로 갔다.

**3번을 확인하다 KURE-v1 의 성질 하나가 새로 드러났다.** 저장소 파일을 대조하니 —

```
BAAI/bge-m3        model.bin 2271MB · sparse_linear.pt · colbert_linear.pt   ← 셋 다
nlpai-lab/KURE-v1  model.safetensors 2271MB                                  ← 둘이 없다
```

**KURE-v1 은 dense 헤드만 파인튜닝하고 sparse·colbert 헤드를 안 실었다.** 그래서 3번은 지금
모델로 **못 한다.** 함정이 딸려 있다 — KURE-v1 에 `BGEM3FlagModel` 을 물리면 그 가중치가
**없는 채로 초기화**돼 **에러 없이 무의미한 sparse** 를 낸다. 이 저장소가 제일 싫어하는
*"도는데 틀린"* 모양이다.

**먼저 한 것 — 배선하기 전에 천장부터 쟀다**

2번을 짓기로 하기 전에 **기존 실행 JSON 만으로 오라클 합집합**을 냈다(무료). 두 실행 중
하나라도 `@10` 에 잡은 질의를 세는 것이고, 그것이 **어떤 융합이든 넘을 수 없는 값**이다.
수치는 `verify_log/2026-08-24-로컬임베더-비교측정.md`. 요점은 **`baseline` 만 잡는 질의가 60건
중 둘 · 20건 중 하나**라는 것이고, 셋 중 둘이 겹침 0.000 이다.

**선택지 — 어느 hybrid 인가**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| **2. 두 임베더 융합** (고름) | 질문의 문자 그대로. 로컬이 이미 있어 절반은 갖춰져 있다 | **천장이 60건에서 +2건** · 질의당 OpenAI 과금 부활 · `RetrievedChunk` 에 두 번째 dense 점수가 앉을 자리가 없다 | README 가 *"60건에서 5%p 는 질의 3개라 잡음과 안 갈린다"* 고 적어둔 바로 그 크기다 |
| 1. dense + BM25 | 코드가 이미 있고 무료 | *"상용과 비교해서"* 라는 말과 안 맞는다 | **대조군으로 쓴다** — 같은 RRF 를 쓰는 유일한 대조군이라, 융합이 졌을 때 *RRF 가 안 듣는 것*과 *두 번째 dense 가 신호를 안 더하는 것*을 가른다 |
| 3. 모델 자체 hybrid | learned sparse 가 지금의 bigram BM25 보다 한국어에 강할 가능성이 크다. 질의 비용 0 | **KURE-v1 에 헤드가 없다.** `bge-m3` 로 바꾸면 방금 재서 이긴 모델을 내려놓는다 | 3회차가 `bge-m3` 를 버린 것은 *"모델 비교의 실험군"* 으로서지 *"운영 모델"* 로서가 아니다 — 그 기각은 다시 볼 수 있다 |

**고른 것과 이유**

사용자가 **2번**을 고르고 *"다른 선택지는 가능성을 열어만 두자"* 로 정리했다.
**천장(+2건)과 과금 부활을 먼저 말씀드린 뒤의 선택**이다. 그래서 짓되, *"지었으니 쓴다"* 가
안 되도록 **판정을 미리 박았다** — `±1건 안이면 배선은 남기되 기본으로 안 켠다`.

배선 결정 넷은 `plan_log/검색-생성.md` 4회차에 있다(경로 목록 일반화 · `path_scores` ·
`extra_dense` · `--embedding` 쉼표 목록). **여기 복제하지 않는다** — 저쪽이 retrieval 계약의
주인이다.

**닫힌 것 — 융합은 기각이다**

배선하고 재봤다. **`hit@10` 0.8500 → 0.7333(60건, −7건)** 으로 천장(+2건)을 회수하기는커녕
크게 깎였고, 겹침 세 구간 전부에서 안 올랐다. 미리 박은 판정표의 *"깎인다"* 칸이다.
기제는 **RRF 가 순위만 써서 약한 검색기에 강한 검색기와 같은 무게를 주는 것**이고,
`baseline`(0.483)이 KURE(0.850)를 끌어내렸다. 수치는
`verify_log/2026-08-24-다중임베더-융합.md`, 배선 결정은 `plan_log/검색-생성.md` 4회차.

**~~배선은 남겼다~~ → 재고 전량 되돌렸다 (2026-08-25).** 처음에는 *"지우면 이 결론이
'안 해봐서 모른다' 로 남는다"* 로 남겼는데, 사용자가 뒤집었다. 근거 둘 — **융합이 기각됐고**,
`extra_dense` 의 **호출부가 0개**라 이 파일이 `embedding.provider` 를 2회차까지 안 만든 잣대에
그대로 걸린다. **되돌리기 범위도 한 번 넓혔다**: 처음엔 융합 코드만 빼고 곁가지로 얻은
용어(`--bm25` 개명)·가드는 남기려 했으나, 그 둘의 근거가 *"`hybrid` 가 넷이 될 뻔했다"* 라
융합을 지우면 성립하지 않는다. 자세한 것은 `plan_log/검색-생성.md` 4회차.

**곁가지로 용어를 갈랐다.** 사용자가 *"지금 hybrid 용어를 같이 사용하고 있어?"* 를 물어
확인하니 저장소에 이미 둘(적재의 핸들러 선택 · 검색의 dense+BM25)이 있었고 이번 대화가 둘을
더 얹고 있었다. 검색 쪽은 **무엇을 합치는지로** 부른다 — BM25 융합 / 다중 임베더 융합 /
모델 내장 sparse / 경로 융합. 자세한 것은 `evaluation/README.md` 의 용어 절.

**남은 질문**

위 "미결" 전부. 머리는 여전히 **갈아탈 것인가**이고, 융합이 기각되면서 그 앞에 남은 것은
**BM25 융합을 켤 것인가** 하나다 — 그런데 그것이 총합으로는 안 정해진다(`hit@10` −2건인데
`hit@1` +4건 · `MRR`·`nDCG`·`hit@20` 이 전부 오른다).

## 5회차 — 2026-08-25 · 갈아탔다, GPU 축을 열었다, OpenAI 를 그림자로 남겼다

**물은 것**

되돌리기 회차 직후 두 프로필을 재현해 격차가 확인되자 사용자가 셋을 정했다 —
*"1. kure 모델로 바꾸자. 2. 지금은 이전 측정값이 있으니까 cpu로 돌리고, gpu로도 가능하게
해줘. 3. qdrant에 kure용 컬렉션 하나 만들면 되는거 아니야? ... 그냥 매번 색인할때 두개 다
돌려서 축적하면 되지않나."*

**드러난 것 — 3번의 전제는 맞았지만 목적이 달랐다**

컬렉션이 모델별로 저절로 갈린다는 전제는 **맞다**(`collection_name_for()`). 그런데 확인해
보니 **`original_files/` 가 비어 있었다** — 원본 보관(`b2aa6e8`)이 기존 494 point 보다
나중이라 **옛 문서는 어느 쪽이든 재색인이 불가능**하다. 즉 이중 색인은 사용자가 아쉬워한
*"옛 색인 목록"* 을 못 구한다.

그래서 내가 *"KURE 만 색인하자"* 를 추천했는데 사용자가 틀을 바꿨다 —
*"아직 표본이 많이 없으니까 둘 다 색인하고, 어느정도 데이터가 생기면 그때 다시 디폴드
모델 정하는걸로."* **대조군으로 축적한다**는 틀에서는 그 컬렉션이 질의 대상이 아니라
비교군이고, 정답 세트가 60건뿐이라 일반화가 이른 것도 맞다. **내 반대 근거(*"아무도 질의
안 하는 컬렉션에 비용을 낸다"*)가 그 틀에서는 성립하지 않는다.**

**선택지 — 기본값을 어디에 두나**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| **코드 기본값 + torch 본체** (고름) | 기본값과 설치 목록의 앞뒤가 맞는다 | 모든 설치에 2.27GB | 기본값이 `local` 인데 설치가 선택이면 **기본 설치로 서버를 띄우면 첫 색인에서 ImportError** 다 |
| `.env` 로만 | 설치 구조 불변 · 되돌리기 쉽다 | **"기본값이 무엇인가" 의 답이 저장소 밖에 산다** | 다음 사람이 코드만 보면 OpenAI 로 읽는다 |
| 코드만 바꾸고 torch 는 별도 | 2.27GB 를 강제 안 함 | 위 ImportError 를 안내로 감당 | 안내로 감당하는 것은 이 저장소가 `hybrid` 기본값을 정할 때 버린 방식이다 |

**고른 것과 이유**

1. **코드 기본값 + `torch` 본체 이관.** `requirements-local.txt` 의 존재 이유가 뒤집혔다 —
   *"안 쓰는 사람"* 이 없어졌다. **대가를 알고 골랐다**: 기본 pytest 가 가중치를 안 받는
   근거가 둘(핀 + torch 부재)에서 **하나(핀)** 로 준다
2. **`EMBEDDING_DEVICE` 신설, 기본 `cpu`, 자동 감지 안 함.** `cuda if available` 이 정확히
   *"머신마다 조용히 갈리는"* 모양이라, 3회차가 device 를 상수로 못 박은 근거가 자동 감지에는
   그대로 산다. 평가는 `EVAL_EMBEDDINGS["kure-v1"]` 이 `cpu` 를 박아 안 흔들린다
3. **그림자 색인.** 실패는 **삼키고**(주 컬렉션이 성공해 폴백 층이 실재한다) 구멍을 목록에
   드러낸다. **채우는 코드는 안 만들었다** — 색인이 멱등이라 재업로드가 곧 채우기다
4. **그림자는 하나이고 목록이 아니다.** 목록으로 열면 합법값이 하나뿐인 축이 또 생기는데,
   그것이 이틀 전 `extra_dense` 를 죽인 잣대다

**사용자가 내 안을 고친 자리 — 이 회차에서 제일 값나가는 대목**

평가 기본 프로필을 *"`baseline` 으로 두면 함정을 안 건드린다"* 로 제안했더니 사용자가
**"그건 함정을 피한 것이지 제거한 것이 아니다"** 로 뒤집었다. 근본 원인은
`DEFAULT_EMBEDDING_PROFILE` 의 값이 아니라 **`baseline.json` 에 라벨이 없어 암묵적
fallback(`.get(k, DEFAULT)`)에 기대는 것**이고, 그러면 나중에 다른 이유로 기본값이 바뀔 때
같은 함정이 재현된다. 라벨을 박아 닫았다 — 새 리포트는 라벨을 항상 쓰므로 라벨 없는 파일은
그 하나뿐이었다.

**닫힌 것 — 모델 미결이 끝났다**

`plan_log/embedding.md` 를 2회차부터 끌어온 *모델·차원* 미결이 닫혔다. 운영 기본값이
`nlpai-lab/KURE-v1` 이고 근거는 `hit@10` 0.4833 → **0.8500** 이다. 갈아탄 뒤 재측정에서
수치가 **전 항목 동일**해 device 축이 벡터를 안 바꾼 것도 확인했다.

**대가도 실측으로 나왔다** — 방어막이 한 겹 준 결과가 **세 곳에서 터졌다**(폴더 241초 ·
Windows access violation · 컬렉션 이름만 틀림). 전문은
`verify_log/2026-08-25-임베더-전환.md`, 회고는 `task_log/2026-08-25-임베더-전환.md`.

2회차가 *"hybrid 후보 풀(50) 밖의 정답 7건은 리랭커로도 못 고쳐 **dense 변별력이 유일한
수단**"* 이라 적고 교차 측정을 예약해 뒀는데, 리랭커 세션이 KURE+BM25·풀 50 으로 재서

혼자 낮고 중등은 1.0000). *"진 질의 5건 중 넷이 AI 가이드"* 라는 옛 미결과 같은 쪽을
가리키는데, **여전히 우연인지 그 문서의 성질인지는 안 쟀다.**
