# 검증 기록 설계

상태: 확정 (1회차)
관련 기록: 없음 — `.claude/skills/**` 와 `CLAUDE.md` 만 고치므로 `is_recordable()` 대상이
아니다(경계를 예외로 뚫지 않는다). 첫 실사용 기록은 `verify_log/INDEX.md` 에 쌓인다.

## 확정된 것

- **검증 수치는 `verify_log/YYYY-MM-DD-<주제>.md` 에 회차로 쌓는다.** 기록 폴더가 셋이 되고
  축은 시점이 아니라 성격이다 — `plan_log`·`task_log` 가 산문이면 이쪽은 수치다 —
  근거: 지금 수치가 가는 곳 셋이 전부 검증 기록용이 아니다. `baseline.json` 은 승인된
  기대값 **하나**라 회차가 안 쌓이고, `task_log` 3절은 회고 안에 섞여 회차 간 비교가 사람
  눈이며, Stop 훅의 전체 pytest 결과는 **아무 데도 안 남는다**(성공하면 출력조차 없다)
- **`task_log` 3절에서 옮기는 것은 측정값뿐이다.** `pytest 337 passed`·파싱 실측 표는
  옮기고, 2절(설계 결정)·4절(실패 분석)·7절(남은 것) 안의 수치는 그대로 둔다 —
  근거: 저쪽 수치는 측정값이 아니라 **논증의 근거**다. `큰 글씨와 마커가 겹치는 문단이
  0/74` 을 떼어내면 "번호·기호 머리 승격을 왜 기각했나"라는 문장 자체가 죽는다.
  실제로 8개 기록을 읽어보니 수치는 3절보다 2·4절에 더 촘촘하다
- **3절을 비우지 않고 링크 + 대표 수치 한두 개로 줄인다** — 근거: 완전히 비우면 `task_log`
  만 읽을 때 논증의 근거가 사라진다. `INDEX.md` 항목이 전부 대표 수치로 끝나는 기존 관행과도
  어긋난다
- **기록은 가상 데이터와 실제 데이터를 명시적으로 가른다.** 둘이 답하는 질문이 다르다 —
  가상은 "규칙이 도는가"에만 답하고 **임계값을 정하는 데 못 쓴다**(합성 문서는 만든 사람이
  기대한 모양을 그대로 갖고 있어 자기 확인이 된다). 반대로 경계값·극단·0건은 실파일에
  *우연히* 있어야만 검증되므로 가상이 만든다 — 근거: 이 저장소 임계값은 전부 실파일에서
  나왔고 초안을 뒤집은 것도 실측이다. 반대 방향의 실증은
  `test_split_table_pieces_keep_header` 가 AI 가이드 두 판에 '쪼개진 표'가 없어 지금 skip 되는 것
- **실파일 수치에는 파일 신원(bytes + sha256 앞 12자)을 붙인다** — 근거: `tests/fixtures/`
  는 gitignore 라 이름만으로는 문서를 못 가리킨다. 실제로 사고가 났다 —
  `test_hwpx_real.py` 의 `_find()` 는 "시행령 개정안" 이 세로판·가로판 두 파일에 걸려
  26쪽 정답이 28쪽 문서에 적용될 뻔한 뒤 만들어졌다
- **기록 머리에 비용 줄을 필수로 둔다** — 근거: `vision_calls`·`llamaparse_calls` 는
  `schemas/document.py` 에 있고 `document-ingestion` 이 적으라고 지시하는데 `task_log/`
  8개 전부 0건이다. `task-log` 3절 템플릿에 담을 칸 자체가 없었다
- **기대값을 먼저 적고 돌린다** — 근거: 돌린 뒤 기대값을 맞추면 아무것도 검증하지 않는다.
  splitter 기록 4-(라) 의 항진명제 테스트(`rows[0] == chunk.metadata["rows"][0]`)가 그 실패였다

## 미결

- **회차가 쌓인 뒤 기계 대조가 필요한가.** 지금은 `.md` 뿐이고 읽는 코드가 없다 —
  정하려면: 회차가 5~10개 쌓여 "언제부터 이 수치가 움직였나"를 손으로 못 훑을 때 다시 본다
- **검색 품질 블록을 언제 채우나.** `retriever` 가 없어 `해당 없음` 이다 —
  정하려면: `plan_log/평가-세트.md` 가 정답 질의 세트를 확정해야 한다
- **`verify_log/INDEX.md` 한 줄이 `task_log/INDEX.md` 처럼 길어질 것인가.** 저쪽이 이미
  항목당 3~5줄로 번지는 중이다(`기록-형식.md` 미결) — 정하려면: 항목이 5개를 넘길 때 본다

## 안 하기로 한 것

- **새 Stop 훅으로 `verify_log/` 기록을 강제하기** — 이유: 세 번째 차단 게이트는
  `SKIP_*=1` 을 습관으로 만든다. `task_log_check.py` 주석이 이미 같은 이유로
  `.claude/skills/**` 와 `CLAUDE.md` 를 대상에서 뺐다("문서 한 줄 고칠 때마다 7절을 채우게
  만들면 SKIP_TASKLOG=1 이 습관이 되고, 그러면 정작 필요할 때도 안 걸린다"). 대신
  `task-log` 2단계가 `verify-log` 를 부르게 해서 **기존 게이트 하나가 둘 다 강제**한다 /
  다시 볼 조건: `task-log` 를 거치지 않는 검증(회귀 대조 단독 등)이 반복적으로 기록을
  빠뜨리는 게 관찰되면
- **`verify_log/*.json` 을 `.md` 와 함께 내기** — 이유: 이 저장소에는 `baseline.json` 을
  읽는 코드조차 없다(`.py` 참조 0건, 전부 문서·스킬이 사람 손으로 대조한다). 하네스 기록
  2-(i) 의 "소비자 없는 상태 파일은 실패 모드만 늘린다"가 같은 판단이다 / 다시 볼 조건:
  위 미결 첫 줄
- **`baseline.json` 에 `runs` 배열을 더해 회차를 같은 파일에 쌓기** — 이유: 기준선은
  "승인된 하나"여야 대조가 성립한다. 측정값을 섞으면 무엇이 기준인지 흐려지고
  `regression-test` 4단계의 "수치가 달라졌다고 자동으로 덮어쓰지 않는다"가 무의미해진다
- **기존 `task_log` 7건의 수치를 소급 이관하기** — 이유: 지난 기록은 그때의 관측이고,
  손대면 회고가 사후 편집된다. `기록-형식.md` 가 `.md` 전환 때 정한 "문장은 한 글자도 안
  고친다"와 같은 판단이다. 대신 `verify_log/INDEX.md` 에 "이 시점 이전은 `task_log/` 3절에
  있다" 한 줄을 적는다 / 다시 볼 조건: 없음
- **스킬에 `scripts/` 를 두어 측정을 자동화하기** — 이유: 현재 스킬 5개 중 스크립트를 가진
  것이 하나도 없고, 무엇을 세느냐는 무엇을 고쳤느냐에 따라 매번 다르다. 고정 스크립트를
  두면 그 스크립트가 세는 것만 세게 된다 / 다시 볼 조건: 같은 측정을 세 번 이상 반복하면

## 1회차 — 2026-08-17 · 검증 수치에 제 집을 준다

**물은 것**

코딩이 끝난 뒤 검증·테스트에서 나오는 데이터를 기록하는 스킬을 만든다. 테스트는 2종류 —
모델이 만드는 가상 데이터와 실제 데이터. 그리고 `task_log` 에 나오는 수치를 옮길 수 있는지.

**먼저 확인한 것**

- 수치가 가는 곳이 셋인데 셋 다 검증 기록용이 아니다(위 "확정된 것" 첫 줄)
- **비용 수치는 설계만 있고 데이터가 0건**이다. 8개 기록 전부 "외부 API 호출 없음"으로 끝난다
- `tests/fixtures/` 는 gitignore 라 실파일 수치가 저장소만으로는 재현 불가다. 반대로
  가상 데이터는 생성 코드를 남기면 완전히 재현된다 — **이 비대칭이 두 종류를 가르는 축**이다
- 탐색 중 `.txt`/`.md` 드리프트를 보고받았으나 **이미 해결돼 있었다**
  (`task_log/2026-08-17-기록형식-md전환.md`, 남은 참조 0건). 범위에서 뺐다
- `evaluation_log/` 가 빈 디렉터리로 남아 있다. 추적 파일 0개, 참조 0건

**선택지**

기록 위치를 세 안으로 좁혀 물었다.

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| `verify_log/` 신설 | `task_log` 와 1:1 로 짝지어지고 회차가 쌓인다 | 기록 폴더가 셋이 된다 | `plan_log`·`task_log` 가 이미 폴더당 한 성격이고 `INDEX.md` 관행이 그대로 재사용된다 |
| `regression/runs/` 아래 | 기준선과 물리적으로 가깝다 | `task_log` 와의 짝이 약해진다 | 기준선은 "승인된 하나"라 성격이 달라 같은 폴더에 두면 무엇이 기준인지 흐려진다 |
| `task_log` 안에 형식만 강제 | 폴더가 안 는다 | 회차 간 비교가 여전히 사람 눈이다 | 3절이 회고 산문과 섞여 있는 것이 애초의 문제였다 |

수치 이관 범위도 함께 물었다 — 3절만 / 전부 옮기고 링크만 / 이관 없이 복제.

**고른 것과 이유**

`verify_log/` 신설 + 3절 지표만 이관 + 소급 안 함 + 가상 데이터는 생성 코드 인라인.
넷 다 사용자가 골랐다.

기각한 것과 이유는 위 "안 하기로 한 것" 에 그대로 남겼다. 특히 **훅을 안 만든 것**이 이번
회차의 핵심 판단이다 — 강제 장치를 늘리는 대신 기존 게이트에 얹었다.
