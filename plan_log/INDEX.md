# 설계 논의 색인

아직 만들지 않은 단계를 **어떻게 만들지 정해가는 과정**을 기능당 한 파일에 회차로 쌓는다.
무엇을 기각했고 무엇을 아직 못 정했는지가 핵심이다.

기록 방법과 논의 진행 규칙은 `plan-log` 스킬에 있다. 설계 논의 세션이 기록 없이 끝나려 하면
Stop 훅(`.claude/hooks/plan_log_check.py`)이 세션당 한 번 막는다.

`task_log/` 와 헷갈리지 말 것 — 저쪽은 **만들고 난 뒤의 회고**, 여기는 **만들기 전의 논의**다.

`최종 갱신` 은 그 파일의 최신 회차 날짜다. 파일명에 날짜가 없으니 여기가 시점을 아는 유일한 자리다.

| 기능 | 상태 | 최종 갱신 | 요약 |
|---|---|---|---|
| [시맨틱-캐시.md](시맨틱-캐시.md) | 구현됨 (5회차) · 확정 (6회차) · **꺼진 채로 둔다 — 차선(완전 일치)은 코드에만 세운다** | 2026-08-26 | 비슷한 질문에 옛 답을 되돌려주는 캐시. **사용자 안에서 축 하나만 뒤집혔다** — *컬렉션을 가른다*는 그대로 가고(문서와 섞으면 `iter_chunks()`·`list_documents()` 가 캐시를 문서로 세는데, 가를 필터 축은 `indexing.md` 가 이미 닫았다), *질문과 답을 가른다*는 기각(qdrant 가 point 마다 벡터를 요구해 **아무도 검색 안 하는 답변에 임베딩 비용**이 붙고 쓰기가 둘로 갈려 *히트하면서 빈 답을 주는* 반쪽 상태가 생긴다). **사용자 안에 없던 축이 잠금이다** — 두 번째 `get_store()` 는 같은 uvicorn 안에서 자기 자신과 충돌해서, `QdrantStore.client` 로 **한 클라이언트가 두 컬렉션**을 본다(실제 qdrant E2E 로 잠금 오류 0 확인). 이름은 `collection_name_for(..., prefix=)` 로 파생해 모델 교체 시 옛 벡터에 새 질의를 재는 사고를 구조로 막는다. **제일 큰 결정은 임계값을 '정하지 않기로' 정한 것** — 재려 했더니 *같은 뜻 다른 말* 쌍이 **0쌍**이었다(`qa_set.jsonl` 60 · `qa_set_human.jsonl` 20 의 `gold_spans` 교집합 0). 0.95 임시값을 넣는 대신 **기본값 자체를 없애** `None` 이면 캐시가 통째로 꺼지게 했다 — 근거 없는 수가 코드에 존재할 수 없는 모양이고, 임계값은 **임베딩 모델에 딸린 값**이라 이름이 안 지켜준다. 기각: 두 컬렉션 · `kind` 로 섞기 · 캐시 전용 경로 · qdrant 밖 JSONL(저장소가 둘이 되어 ChromaDB 기각과 같은 잣대) · TTL(축이 어긋난다 — 코퍼스가 안 바뀌면 한 달 전 답도 옳다) · 컬렉션 지문(문서 하나에 캐시 전멸) · 완전 일치만 · 히트를 티 안 내기 · `AnswerCache` Protocol · 미스 시 임베딩 2회를 없애려 세 시그니처를 넓히는 것. 미결 — **임계값 값(모델 비교 뒤에 잰다)** · 캐시 상한·퇴거 · provider 파생 · backend 색인 시 무효화. **다음 세션이 이어받을 자리는 저장소 안에 있다** — 임계값 재는 절차는 `evaluation/README.md` 의 「답변 캐시 임계값을 재려면」이고, 전제 둘(모델 확정 · 쌍 사람 검수)이 안 서 있다. 미결 셋이 **캐시를 켜는 순간 함께 발화한다**: 검색 파이프라인 변화(리랭커가 붙으면 히트한 질의는 리랭킹도 건너뛴다) · `_ensure_collection()` 이 기존 차원을 안 본다 · 캐시 상한. **곁다리 교훈: 트리도 지금 이 순간의 사진일 뿐이다** — 겹칠 뻔한 파일 셋을 다른 세션에 **직접 물어** 갈랐고, 그쪽이 준 provider 파생 지적은 git 에도 트리에도 없었다 **2회차 — 쌍 사람 검수 1차(겹침 0.30 이상 6건): 통과 2 · 지적 4.** **겹침이 가리키는 자리와 실제 결함이 있는 자리가 다르다** — 제일 무거운 지적(`p-bas-08`, *비품→물품* 이라 원문 답 `비품 구입 불가` 와 패러프레이즈 답 *교구는 가능* 이 **갈린다**)은 겹침으로 안 잡히고 `gold_spans` 를 읽어야 보였다(내용어로 세면 3위→8위). 반대로 통과 하나(`p-bas-06` 0.300)는 공유 토큰 셋이 `나요`·`되나`·`비를` 로 **전부 어미**였다 — `tokenize()` 가 글자 bigram 이라 어미가 겹침에 실린다(`나요` 는 160개 질의 중 **90**). 세 번째 축도 나왔다: `p-sch-12` 는 뜻이 아니라 **자립성**이 깨졌다(`그 대장을…` — 캐시 질의는 앞말 없이 도착한다). 그래서 74건은 **문서 그룹별**로 본다. **뜻을 고치면 겹침이 오른다** — 지적 4건을 고쳐 쓰니 셋이 위로 갔고(`p-sch-12` 0.462→**0.500**), `비품`·`차시` 처럼 답을 가르는 낱말은 **일부러 그대로 뒀다**. **한 번도 발화한 적 없는 알림을 발견했다** — 테스트 `_REVIEW_HINT=0.5` 와 README `0.30` 이 어긋난 채 세트 최댓값이 0.4615 라 죽어 있었고, `overlap.py` 의 *"경계값은 인용하지 않는다"* 를 따라 README 에서 수를 빼고 `_REVIEW_HINT` 하나를 가리키게 했다(값은 안 건드림 — 이제 발화한다). 도장은 **`reviewed_hash`**(`qa_set.content_hash` 재사용) — `overlap` 은 값이 *바뀌는* 수정만 잡아 **겹침 0.0 인 20건이 구멍**이고, 실증했다. 기각: 지적 넷을 빼기(양성 표본이 준다) · `reviewed_by` 만 찍기(그 구멍이 남는다) · `note` 추가(판단 근거가 두 곳에 생긴다) · 내용어 겹침 순(df 컷이 임의값이라 근거 없는 수가 순서가 된다) **3회차 — 검수 80/80 완료, 재작성 25쌍(지적 23).** **잣대가 검수 중에 굳었다**: `ai` 의 `원칙→준칙` 넷이 통과인데 `sih` 의 `지침→안내서` 셋이 지적이라, 가르는 것이 *"gold 용어를 바꿨나"* 가 아니라 ***"바꾼 낱말이 이 문서 안에서 다른 것을 가리키나"*** 임이 강제로 드러났다(`안내서` 는 그 문서 자신의 이름이고 `준칙` 이라 불리는 것은 AI 가이드에 없다). 같은 낱말이 자리에 따라 갈린다 — `p-sch-01` 의 `**이** 문서를` 은 통과, `p-sch-03` 의 `문서 생산` 은 지적(`문서` 는 분류표에서 기록물의 한 유형). **축 셋 중 겹침이 재는 것은 하나뿐이고 23건 중 10건이다** — 나머지 13(답이 갈린다 8 · 혼자 못 선다 5)은 `gold_spans` 를 읽어야 나왔다. **`선도학교↔시범 운영교` 는 잣대가 아니라 방향으로 갈랐다** — 지어낸 이름을 두면 양성 분포가 **아래로** 밀려 *겹치면 안 켠다* 가 **살아 있는** 쪽이고, 되돌리면 착시 쪽이다(1차에 `p-bas-08` 만 되살려 엇갈려 있던 것을 맞췄다). **잣대 범위를 코퍼스로 안 넓히고 잣대가 하는 일을 둘로 갈랐다** — 라벨링은 `gold_spans` 가 한 문서 조각이라 문서 범위가 맞고, *캐시가 다른 문서와 맞물리나* 는 사람이 쌍 단위로 흉내 낼 것이 아니라 **음성 분포가 이미 코퍼스를 가로질러** 따로 잴 것이 없다(미결로 열어 임계값 회차에 붙임). **축 후보 하나를 표본 1건에서 일부러 승격 안 했다**(`p-hbas-05` 의 *발화 생략* — 2건 더 나오면 본다). **검수가 양성 분포를 위로 밀었다**: 중앙 0.111→**0.143** · 평균 0.117→**0.165**(+41%) · 0인쌍 20→**15** — **오염이 아니라 교정 때문**이라 방향만 보고 읽으면 거꾸로 해석한다. **전제 둘이 다 닫혔다** — 모델도 다른 세션이 `nlpai-lab/KURE-v1`(local·1024차원, `hit@10` 0.483→0.850)로 확정했고 **로컬이라 임베딩 과금 0**. 이제 재기만 하면 된다. **곁다리: 세션 다섯에 먼저 물었다** — 모델 확정이 오늘 닫힌 것은 git 에도 트리에도 없어 **물어야 나왔고**, 내 훅이 낸 embedding 90초 타임아웃은 남의 편집 중 상태였다(알리고 안 건드렸다). 같은 `evaluation/README.md` 를 세 세션이 고쳤는데 아무도 안 잃었다 **4회차 — 쟀고 못 정했다.** 양성 최소 **0.4917** vs 음성 최대 **0.8212**, 양성 **65/80(81%)** 이 음성 최대 아래에 잠긴다 → README 2절이 재기 전에 못 박은 *겹치면 못 정한다* 가 발화했다. **코드는 손댈 것이 없다** — `answer_cache_threshold=None` 이라 이미 꺼져 있고, 1회차가 기본값을 없앤 설계가 그대로 답이 됐다. **평균으로 판정했으면 정반대 결론이 났다**(양성 0.7355 vs 음성 0.3846) — 판정은 **양성 최소 vs 음성 최대**다. **죽인 것은 같은 문서 안의 이웃 질문**이다(`sch-08`↔`sch-09` 0.8212 — 둘 다 문서고 위치를 묻는데 답이 `지상 권고`/`내부 권고`). 음성을 문서 축으로 가르면 **같은 문서 0.8212 vs 다른 문서 0.6753** 이라, README 1절의 *같은 문서 조합을 반드시 포함한다* 가 실제로 판정을 갈랐다(걸렀으면 *틈이 있다*로 잘못 닫았다). 그래서 3회차 미결이 **예상과 반대 방향으로 닫혔다** — 위험은 코퍼스를 가로지르는 데 있지 않고 문서 **안쪽**에 있다. **재는 도구는 `evaluation/cache_threshold_probe.py` 로 따로 냈다**(사용자 판단) — `run_eval.py` 는 정답률, 이쪽은 **분리 가능성**이라 자[尺]가 다르다. `eval_config()` 는 안 빌리고 `embedding_profile()` 만 빌린다. `separability()` 가 겹칠 때 `None` 말고 낼 값이 없는 것이 이 도구의 요점이다. 기각: `cut 0.90` 의 **오적중 0/12,640** 을 임계값으로 쓰기(닫힌 코퍼스 표본이고 규칙은 재기 전에 정해졌다) · 평균으로 판정 · 같은 문서 음성 거르기. **곁다리로 캐시 구멍을 잡았다** — `cache_salt_for()` 가 `device` 를 안 실어 GPU/CPU 벡터가 같은 칸을 쓴다(다른 세션 지적을 확인). 논증 대신 **캐시를 끄고 다시 재** 소수 6자리 일치를 확인했다. 차선(완전 일치)의 발화 조건이 참이 됐지만 **실제 질의 로그가 없어 지금 켤 근거도 없다** **5회차 — 모델을 바꿔도 안 갈린다(유료 $0.0001 미만).** `--embedding baseline`(`text-embedding-3-small`)로 다시 재니 **거기서도 겹쳤고 더 심하다** — 잠긴 양성 **75/80** vs KURE **65/80**, 양성 p50 **0.3873** vs **0.7321**. **더 잘 가르는 KURE 에서도 81%가 잠긴다**는 것이 요점이라 미결 *겹침이 모델 탓인가* 를 **"코퍼스 쪽으로 크게 기운다"로 좁혀 닫았다** — 표본이 둘이라 *어떤 모델로도* 는 안 쓴다. **재기 전에 재는 대상이 깨져 있었다**: `EVAL_EMBEDDINGS["baseline"]` 이 `embedding_provider` 를 안 박아, 코드 기본값이 `openai`→`local` 로 뒤집힌 순간(`cba8e8d`) 그 프로필이 조용히 *로컬 text-embedding-3-small* 을 뜻하게 됐다(그런 HF 리포는 없다). **어느 테스트도 안 잡았다** — 이름 대조는 *있는 키*만 보고 fallback 은 키가 아예 없는 자리라 원리적으로 안 걸린다. `cba8e8d` 자신이 *"근본 원인은 baseline.json 이 암묵적 fallback 에 기대는 것"* 이라 적고 라벨은 박았는데 **프로필 쪽 fallback 은 남겨둔** 절반 상태였다. 프로필에 한 줄 + **전수 가드**(모든 프로필이 provider 를 박는가)로 닫았고, 깨지는지 손으로 확인했다. `baseline.json` 은 `settings` 에 한 필드만(**`+1/-0`**, `summary`·`per_query` 글자까지 동일) — **재생성이 아니라 기록 정정**이고 근거는 날짜다(수치 08-23, 로컬 임베더 08-24라 선택지가 없었다). 기각: 테스트 느슨하게(가드가 막으려던 것이 *라벨만 있고 값이 틀린 상태*라 거꾸로 간다) · `_meta` 경고 · 재생성 · 모든 필드 명시 · 명령줄 provider. 곁다리 — 두 모델의 **제일 어려운 음성이 다르고**(KURE `sch-08↔sch-09`, OpenAI `sih-01↔sih-08`), **눈금 경고가 처음 발화했다**(OpenAI 노름 0.999562~1.000417, 어긋남 4e-4 라 판정 무관). 미뤄둔 **전체 pytest 를 유효한 조건에서 돌려 `1096 passed, 4 skipped`**. 새 미결 — **운영 `.qdrant` 의 KURE 컬렉션이 0건**(다른 세션이 발견. `cba8e8d` 뒤 운영 색인을 안 지었고 원인 축이 같다. 재색인은 Vision 과금) **6회차 — 차선을 코드에 세우되 켜지 않는다.** 넘겨받은 미결 셋 중 **하나는 전제가 이미 바뀌어 있었다** — *운영 KURE 컬렉션 0건* 은 낡은 관찰로, 잠금을 피해 sqlite 를 `mode=ro&immutable=1` 로 먼저 읽고 실클라이언트로 다시 재니 주 **103·dim 1024** · 그림자 **103·dim 1536** 이고 둘 다 같은 문서다. **옛 컬렉션은 죽은 것이 아니라 `Settings.shadow_index_enabled` 가 쓰는 그림자라 "안 읽으니 지우자"가 애초에 성립하지 않았다**(지워도 다음 색인이 다시 만든다). 과금 전제도 약하다 — Vision 캐시 키가 `sha256("vision:{모델}" + blob)` 이라 같은 파일·같은 모델이면 재색인 Vision 비용이 0이고 `vision_calls=0` 이 그 증거다(이번엔 안 밟았지만 근거를 남겼다). **완전 일치는 임계값이 아니라 `ANSWER_CACHE_MODE` 라는 별도 축으로 냈다** — 임계값은 *같은 벡터인가*를 재는 자[尺]인데 완전 일치가 묻는 것은 *같은 문자열인가*라, `threshold=1.0` 은 한 자로 둘을 재게 되고 부동소수 보장도 없다(OpenAI 노름 실측 0.999562~1.000417). `exact` 갈래는 `lookup()` 에서 **임베딩을 아예 안 불러** *"미스 시 임베딩 2회"* 감수 사항이 1회가 된다. **세우되 켜지 않는
