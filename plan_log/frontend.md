# 프론트엔드 설계

상태: 구현됨 (1~2회차, 2026-08-23 · 커밋 73be307~a2aa31e · 4166f80)

`검색-생성.md` 와 짝이다 — 이 화면이 부르는 질의 경로가 저쪽 Phase 1~2 의 앞자락이고,
저쪽 미결 하나(`store` 수명)가 여기서 닫혔다.

**이 회차가 정한 것의 대부분은 실은 backend·생성 결정이었고 [backend.md](backend.md) 2회차가
가져갔다** — 엔드포인트 범위 · `store` 수명 · 세 번째 진입점 · `Answer.sources` 계약 ·
생성 정책이 전부 그쪽이다(항목 25개 중 18개). 여기 남은 것은 **화면 자체의 결정 다섯**뿐이다.
`---` 아래 1회차 본문은 그대로다 — 그 세션에서 실제로 일어난 일의 기록이라 옮기지 않는다.

## 확정된 것

- **FastAPI + Jinja2 + HTMX** — 근거: 이 머신에 `node`/`npm`/`pnpm` 이 **없다**(실측).
  FastAPI 가 HTML 을 직접 서빙하므로 CORS·개발 서버 이중화가 사라진다. 화면의 상호작용
  (소스 태그 펼침·문서 목록 갱신)은 전부 부분 HTML 교체로 표현된다
- **대화 히스토리·재검색 표시·유사 질문 배지는 자리만 두고 비활성** — 사용자 요청(rDBMS 는
  나중)과 Phase 예약 순서
- **소스 태그는 가로로 놓고 발췌는 그 아래 전체 폭** — 근거: 화면 구성안이 그 모양이다.
  **CSS 로는 못 고치고 마크업이 바뀌어야 했다** — 버튼과 발췌를 쌍으로 감싸면 발췌가 전체 폭을
  쓰기 위해 래퍼가 `flex:1 1 100%` 여야 하고, 그러면 버튼도 같이 세로로 쌓인다.
  토글은 `closest('.sources')` 안의 인덱스로 짝을 찾는다(id 를 안 만든다 — 답변마다 고유
  토큰을 라우트에서 넘겨야 하는데 그만한 이유가 없다)
- **배치는 예시화면 그대로, 치수는 실데이터 기준** — 근거: 예시는 문서 2개·소스 2개에 파일명이
  짧지만 실제는 문서 5개·소스 5개에 이름이 40자를 넘는다. 태그 줄바꿈·이름 잘림·사이드바 폭은
  **긴 이름에서만 드러나므로** 예시 값으로 맞추면 확인하려던 것을 정확히 못 본다.
  파일명은 `22ch` 에서 자르고 원본은 `title` 에 둔다 — **쪽 번호는 안 자른다**(태그의 요점이다)
- **미리보기 산출을 저장소 루트 `preview.html` 로, 생성기는 `backend/preview.py`** — 근거:
  스크래치패드 경로가 **123자**라 실질적으로 더블클릭이 불가능했고, 그 때문에 사용자가 두 번
  헛돌았다. 산출물은 `.gitignore` 이고 생성기만 커밋한다 — 템플릿을 고치면 곧바로 낡는 파일이라
  저장소에 두면 어느 시점의 화면인지 아무도 모르게 된다
- **템플릿을 `file://` 로 열면 배너가 이유를 말한다** — 근거: 그 화면은 "스타일이 깨진 앱" 처럼
  보여서 원인을 짐작할 수 없다(실제로 두 번 그 함정에 빠졌다). **배너 스타일은 인라인이다** —
  CSS 가 안 왔다는 것을 알리는 배너인데 그 스타일을 `app.css` 에 두면 배너까지 스타일이 없다.
  `preview.html` 도 `file://` 로 열리므로 생성기가 이 script 를 `id` 로 찾아 지운다

## 미결

- **미리보기가 낡은 것을 무엇이 알려주나** — `preview.html` 은 템플릿을 고치는 순간 낡는데
  아무 신호가 없다. 지금은 사람이 다시 돌리는 수밖에 없다. 정하려면: 실제로 낡은 것을 보고
  헷갈리는 일이 한 번 나와야 한다(이 저장소가 임계값을 정하는 순서와 같다)
- 1회차 몫은 **없음** — 다섯 중 넷이 [backend.md](backend.md) 로 갔다(`store` 분리 · 답변 품질을 무엇으로
  재나 · 문서 목록의 진짜 출처 · `GenerationError` 재시도). 나머지 하나 `top_k` 는 옮기지 않고
  **지웠다** — `indexing.md` 와 `검색-생성.md` 가 이미 같은 미결을 이고 있어, 옮기면 같은 질문의
  네 번째 자리가 생긴다

## 안 하기로 한 것

- **React + Vite + TypeScript** — 이유: 이 머신에 Node 가 없어 새 툴체인이 통째로 들어온다.
  이 저장소는 Python 하나로만 서 있고 *"두 번째 구현체가 실재할 때"* 를 반복해 지켜왔다.
  화면의 상호작용이 부분 HTML 교체로 전부 표현되는 동안은 값을 못 한다 /
  다시 볼 조건: 클라이언트 상태가 실제로 늘 때 — 대화 히스토리 멀티탭, 낙관적 갱신,
  같은 화면에서 여러 대화를 동시에 여는 것
- **Streamlit** — 이유: 매 상호작용마다 스크립트를 통째로 재실행하는 모델이라 이 화면
  (사이드바 커스텀 레이아웃·배지 클릭 이동·소스 태그 펼침)이 성립하지 않는다
- **Jinja 주석(`{# #}`)을 HTML 주석으로 바꾸기** — 이유: 직접 열었을 때 글자로 찍히는 것은
  가려지지만 **CSS 가 없는 것은 그대로**라 여전히 깨진 화면으로 보인다. 오해의 절반만 지우고
  나머지 절반을 남기는 쪽이 더 나쁘다(원인을 더 못 짚게 된다). 덤으로 주석 내용이 브라우저로
  나간다 / 다시 볼 조건: 배너로도 못 막는 오해가 나오면
- **미리보기를 바탕화면에 두기** — 이유: OneDrive 로 동기화되고 저장소 밖이라 낡은 파일이
  남아도 아무도 안 치운다. 저장소 루트도 충분히 짧다
- **미리보기를 스크래치패드에 두기(1차 결정)** — 이유: **경로가 123자였다.** 앞 라운드에서
  골랐던 것을 같은 세션 안에서 뒤집었다 — 고를 때는 "저장소를 안 더럽힌다"만 봤고 **사람이
  실제로 열 수 있는가**를 안 봤다
- **Phase 2 Retriever 부터 제대로 세우기** — 이유: 이번 회차가 프론트가 아니라 검색 단계
  착수가 된다. hybrid·reranker 설계가 줄줄이 딸려 있어 지금 정하면 `검색-생성.md` 의 논의를
  앞지른다 / 다시 볼 조건: 이 화면으로 진 질의를 눈으로 본 뒤

## 1회차 — 2026-08-23 · 화면 구성안을 받아 무엇을 진짜로 만들지 가르기

**물은 것**

사용자가 화면 구성안(스크린샷)을 들고 *"이걸 예시로 frontend 를 만들고 싶다. 대화
히스토리는 rDBMS 를 설치해야 돼서 나중에 구현하고 싶어서 일단 열어만 줘. 어느 웹을
사용하면 좋을까?"* 로 물었다.

**논의를 시작하며 깐 사실 둘**

1. **이 화면이 부를 API 가 거의 없다.** 노출된 엔드포인트는 `upload`(파싱만 하고 색인은
   안 함)와 `health` 둘뿐이고 `retrieval/` 에 `.py` 가 0개다. 화면의 "재검색 중 (1/3)"과
   "비슷한 질문에 답변한 적 있어요"는 각각 Phase 4~5 와 제일 마지막 단계로 예약된 것들이다.
   반면 dense 검색은 `run_eval.py` 가 이미 끝까지 돌려 baseline 까지 냈다
2. **이 머신에 Node 가 없다** — `node`·`npm`·`pnpm` 전부. 스택 선택에서 이것이 실제 비용이다

**라운드별 선택지와 결과**

| 라운드 | 물은 것 | 고른 것 | 떨어진 것 |
|---|---|---|---|
| 1 | 웹 스택 | HTMX+Jinja2 | React+Vite+TS · Streamlit |
| 1 | 어디까지 진짜로 | dense `/query` 까지 | 업로드만 진짜 · 화면만 |
| 1 | 히스토리 "열어만 둔다"의 모양 | 자리만 두고 비활성 | localStorage · 세션 메모리 |
| 2 | 답변 말풍선 | LLM 실호출 | 검색 결과만 표시 · 목업 |
| 2 | 문서 목록 | `QdrantStore` scroll | 목업 · 검색 결과에서 역산 |
| 2 | ADR 거처 | `plan_log/frontend.md` | `검색-생성.md` 2회차 · `DECISIONS.md` |
| 3 | 배선 거처 | `rag_pipeline` 세 번째 진입점 | backend 조립 · Phase 2 부터 |
| 3 | 환각 방지 | 프롬프트로만 | 점수 임계값 · 인용 코드 검증 |
| 3 | 스트리밍 | 안 한다 | SSE · 두 단계 |
| 4 | `Answer.sources` 원소 | `RetrievedChunk` | `SearchResult` |
| 4 | `run_eval` 리팩터 | `retrieve()` 로 나눠 태운다 | 안 건드린다 |

**사용자 분석을 코드와 대조해 보정한 셋**

사용자가 1라운드 답에 qdrant 잠금 분석을 직접 붙였고(싱글턴 (a) vs 도커 (b), (a) 추천),
**핵심은 맞았다.** 대조에서 셋이 갈렸다.

1. **`DECISIONS.md` 는 이 저장소에 없다** — 사용자가 *"ADR 한 줄 남겨둘 만한 지점"* 으로
   그 파일을 지목했는데 존재하지 않는다. 이 저장소의 그 자리는 `plan_log/` 다
2. **(b) 로 넘어가는 트리거가 "동시 쓰기"가 아니다** — 사용자는 *"적재 스크립트 등 다른
   프로세스"* 를 걱정했는데, 실제 충돌은 `index_document()` 가 `get_store()` 로 **자기
   클라이언트를 직접 열기** 때문에 **같은 프로세스 안에서** 난다. 그리고 그때 첫 후보는
   도커가 아니라 `index_document(store=...)` 주입이다
3. **문서 목록이 "읽기 전용이라 지금 바로 real" 은 절반만 맞다** — `VectorStore` 에
   `search`·`count` 는 있어도 **문서를 나열하는 메서드가 없다.** 공짜가 아니라 Protocol 을
   넓히느냐 마느냐의 결정이 딸려 있었고, 그것이 2라운드 질문이 됐다

같은 대조가 3·4라운드에서도 둘 더 나왔다. 사용자가 *"`Answer` 에 `text`,
`sources: list[{page, heading_path, chunk_text}]` 를 지금 못 박자"* 고 했는데 **그 타입이
이미 있었고**(`RetrievedChunk`), 딸려온 요청(*"dot 점수를 로깅해두면 나중에 임계값을
측정된 숫자로 정할 수 있다"*)도 `dense_score: float|None` 로 **이미 충족돼 있었다.**
그리고 *"`run_eval` 도 `answer_question()` 을 부르게 하자"* 는 **그대로는 안 된다** —
`run_eval --dense` 는 생성을 안 부르는데(부르면 60건 × LLM 이 baseline 에 붙는다) 공유되는
것은 함수 전체가 아니라 **검색 절반**이다. 그래서 `retrieve()` 로 갈랐고, 이것이 4라운드
질문이 되면서 Phase 2 Retriever 의 자리를 미리 잡는 부수 효과도 얻었다.

**계획 검토에서 사용자가 잡은 둘**

계획을 낸 뒤 사용자가 세 곳을 지적했고 **하나가 진짜였다.**

- **`run_eval` 리팩터의 `top_k` 처리가 안 정해져 있었다**(진짜). 다만 위험은 사용자가 짚은
  *"@10/@20 측정이 조용히 빠진다"* 와 조금 다르다 — `run_eval` 은 이미 *"검색은 한 번이고
  채점만 여러 번"* 구조라 `top_k=k` **한 번**이 정답이고 세 번 부르면 그 구조를 깬다.
  진짜 위험은 **`retrieve()` 의 기본값 5 가 무심코 실리는 것**이고, 그러면 `by_axis[10]`·
  `[20]` 만 조용히 낮아져 **검색 품질이 나빠진 것처럼 보인다.** 검증 절에 `by_k` 대조를 넣어
  그 증상을 잡는 자리를 명시했다
- **lazy 프로퍼티가 오타 아니냐**(아님). `IngestConfig` 에 붙이는 것이 맞고 다섯이 전부 그
  형태다. 다만 *lazy 인 이유*(테스트 덮어쓰기)와 *실키 차단*을 한 줄에 붙여 써서 오해를 샀다
  — 둘은 별개 장치이고 **순서가 있다**(lazy 여야 `offline_config` 가 꽂을 수 있다)
- **문서 절반이 잘려 보인다**(아님). 파일 235줄을 전부 읽어 대조했고 지목된 세 대목이
  모두 제자리에 있었다. 미리보기가 끊는 것이라, 해당 대목을 대화에 그대로 붙여 확인받았다

**남은 질문**

위 "미결" 다섯. 머리는 **업로드 실연결 시점의 store 분리**다 — 그때 `index_document()` 의
서명이 바뀌므로 이 회차가 남긴 결정 중 유일하게 기존 코드를 건드리게 된다.

## 2회차 — 2026-08-23 · 화면이 예시와 다르다는 제보에서 시작해 "볼 수 있게" 까지

**물은 것**

사용자가 *"chat.html 은 내가 올린 예시화면이랑 너무나도 다른데 왜 css도 없고 텍스트만 있어?"*
로 물었다. 두 갈래였고 **하나는 버그가 아니었다.**

**갈래 1 — "CSS 가 없다"는 보는 경로 문제였다**

사용자가 템플릿 파일을 브라우저로 직접 열고 있었다. `file://` 에서는 `<link href="/static/app.css">`
가 `file:///static/app.css` 로 풀려 404 이고, htmx 가 채우는 자리는 빈 채로 남고, `{# … #}` 이
글자로 찍힌다. **판정은 그 주석이다** — Jinja 주석은 서버가 렌더할 때 사라지므로, 화면에
`{# 채팅 화면 전체… #}` 가 보인다는 것은 그 화면에 렌더가 한 번도 안 일어났다는 뜻이다.
2회차 스크린샷이 정확히 그 모양이었다.

**갈래 2 — "예시와 다르다"는 맞았다**

당시 `app.css` 176줄은 실용 스타일이지 스크린샷 배치를 옮긴 것이 아니었다. 실제로 어긋난 넷:

| 예시화면 | 그때 |
|---|---|
| 소스 태그 둘이 가로로 나란히 | `.source { flex: 1 1 100% }` 라 세로로 쌓임 |
| 배지·답변 카드가 대화 영역 전체 폭 | `max-width: 78%` |
| `N개 문서 · 인덱싱 완료` 가 사이드바 맨 아래 | 문서 목록 바로 밑 |
| 히스토리 항목에 테두리 | 배경색만 |

**선택지**

| 물은 것 | 고른 것 | 떨어진 것 |
|---|---|---|
| 예시를 어느 정도로 따를까 | 배치는 그대로, 값은 실데이터 기준 | 픽셀 단위 재현 |
| 서버 없이 볼 수단 | 스크래치패드 단독 HTML | 저장소 스크립트 · 안 만듦 |
| (재논의) 미리보기 위치 | **저장소 루트 + 생성기 커밋** | 바탕화면 · 서버로만 |
| 직접 열었을 때 대비 | `file://` 안내 배너 | 주석만 HTML 로 · 안 함 |

**같은 세션 안에서 결정 하나를 뒤집었다**

미리보기를 스크래치패드에 두기로 정하고 만들었는데, 사용자가 **다시 `chat.html` 스크린샷을
보내왔다.** 미리보기를 안 연 것이다. 경로를 세어 보니 **123자**였다
(`AppData\Local\Temp\claude\…\scratchpad\preview.html`). 고를 때 본 축은 *"저장소를 안
더럽힌다"* 뿐이었고 **사람이 실제로 열 수 있는가**를 안 봤다. 저장소 루트로 옮겼다.

**구조가 원인인 것과 스타일이 원인인 것을 갈랐다**

소스 태그 가로 배치는 CSS 값 문제가 아니었다. `<div class="source">` 가 버튼과 발췌를 쌍으로
감싸는 한, 발췌가 전체 폭을 쓰려면 래퍼가 `flex:1 1 100%` 여야 하고 그러면 버튼이 함께 쌓인다.
**마크업을 바꿔야 풀리는 자리**라 `_answer.html` 의 루프를 둘로 나눴다(버튼 줄 → 발췌 묶음).

토글은 **id 를 안 만들었다.** `this.closest('.sources').querySelectorAll('.excerpt')[N]` 로
범위를 좁히면 한 화면에 답변이 여럿 쌓여도 안 섞인다. id 를 쓰면 답변마다 고유 토큰을
라우트에서 넘겨야 하는데 그만한 이유가 없다.

**배너의 스타일이 인라인인 것이 이 회차에서 제일 틀리기 쉬운 자리다**

`app.css` 에 `.file-warning` 을 두면, **CSS 가 안 왔다는 것을 알리는 배너가 스타일 없이 뜬다.**
자기 자신을 부정하는 배치라 인라인 `style=` 로 못 박고 테스트로 잠갔다.

딸린 것 하나 — `preview.html` 도 `file://` 로 열리므로 그대로 두면 *"직접 열지 말라"* 는 배너가
**정작 직접 열라고 만든 파일에** 뜬다. 생성기가 `id="file-warning"` 으로 찾아 지우고, 그 id 가
살아 있는지를 테스트가 잠근다(앵커가 빗나가면 조용히 배너가 되살아난다).

**남은 질문**

- 미리보기가 낡은 것을 무엇이 알려주나 (위 "미결")
- 화면을 기계가 판정할 방법이 없다 — 이번에도 최종 판정은 **사람이 열어본 것** 하나였다.
  테스트는 DOM 구조만 잡고 모양은 못 잡는다
