## 확정된 것

지금까지 확정된 결정만 모은다. **여기만 읽으면 현재 설계를 안다.**

- **에이전트는 담당 영역에 코드가 있을 때만 두껍게 쓴다** — `ingestion-specialist` 는
  두껍게(loader·cleaner 가 실재한다), `retrieval-specialist`·`rag-evaluator` 는 얇게 쓰고
  `plan-log` 로 라우팅한다. 근거: 이 저장소가 세 곳에서 같은 말을 못박아 뒀다 —
  `references/next-stages.md`("추측으로 만든 체크리스트로 리뷰하면 없는 규칙을 근거로 멀쩡한
  설계를 지적하게 된다"), `plan-log` 2단계, `code_reviewer_plan.md` §0
- **에이전트는 판정 기준을 복제하지 않고 `rag-code-review/references/` 를 읽는다** —
  `code-reviewer` 가 이미 쓰는 위임 구조다. 규칙이 두 벌로 갈라지면 한쪽이 조용히 낡는다
  (실측: 2회차에서 `references/cleaner.md` 가 실제로 그렇게 낡았다 — `문서-최신성.md` 2회차)
- **자동 테스트 훅은 PostToolUse 에 단다** — 취향이 아니라 강제다. `tests/hooks/
  test_hook_wiring.py:test_pretooluse_covers_both_shells` 가 PreToolUse 의 **모든** matcher 에
  `re.fullmatch(matcher, "Bash")` 와 `"PowerShell"` 을 요구하므로, `matcher: "Write|Edit"` 를
  PreToolUse 에 추가하면 그 테스트가 깨지고 → `pre_commit_check` 가 커밋을 막는다
- **테스트 범위를 두 층으로 가른다** — PostToolUse 는 변경 경로에 대응하는 **영역별** 테스트만,
  Stop 은 **전체 1회**. 근거: 기본 스위트가 210개인데 합성 문서 생성(docx/pptx/xlsx/pdf/hwpx)과
  OCR 이 섞여 있어 매 편집마다 전체를 돌리기엔 무겁다. 실제 소요는 구현 후 실측해 `task_log` 에
  남긴다 — **지금은 "무겁다"까지만 아는 상태이고 초 단위 수치는 재지 않았다**
- **매핑 누락을 테스트로 강제한다** — 새 단계 디렉터리가 생겼는데 매핑 표에 안 넣으면 그 단계는
  자동 테스트가 한 번도 안 도는데 아무 에러도 안 난다. 근거: `paid_test_check.py` 가 남긴 교훈이
  정확히 이것이다 — `-m integration` 금지가 CLAUDE.md·스킬 3개·에이전트까지 5곳에 적혀 있었지만
  *"전부 모델을 향한 설득"* 이었고, 그래서 훅으로 못박았다. 산문은 보조로만 둔다
- **훅 스크립트 하나가 두 이벤트를 처리한다** — `plan_log_check.py` 가 이미 3이벤트를
  `payload["hook_event_name"]` 로 분기하는 선례다. 파일이 늘면 배선 테스트 표면도 함께 는다
- **Skill 은 반복이 입증된 절차에만 만든다** — `document-ingestion` 은
  `task_log/routing-diff-시행령개정안.md` 가 그 절차를 손으로 한 기록이라 근거가 있다.
  `regression-test` 는 기준선 artifact 를 이번에 신설한다
- **"기록했는가"는 git 이 아니라 세션 마커로 판정한다** (2회차 추가). 근거: git 판정은
  세션을 구분하지 못해 **지난 세션의 미커밋 기록이 이번 세션을 통과시킨다.** 기록이
  밀릴수록 검사가 헐거워지니 방향이 정반대다. 발견 시점에 `plan_log/` 미커밋 3건으로
  설계 논의 검사가 실제로 무력화돼 있었다
- **다만 마커만으로는 부족하다 — 세션 시작 이후의 mtime 을 함께 본다** (4회차 추가).
  마커는 PostToolUse 의 `tool_input.file_path` 로 만드는데 **그 필드는 Write/Edit 에만
  있어** Bash 로 쓴 기록이 통째로 안 보인다. 근거: 기록을 다 남기고 커밋까지 한 세션이
  실제로 막혔다(2026-08-19). **2회차 교훈은 안 깨진다** — git 은 "커밋됐는가"를 묻고
  mtime 은 "이 세션에 쓰였는가"를 물어 분모가 다르다. 지난 세션의 미커밋 기록은 mtime 이
  세션 시작보다 옛것이라 여전히 안 통과한다
- **`tool_input.file_path` 에 기대는 훅은 전부 같은 구멍을 갖는다** (5회차 추가).
  4회차가 기록 훅 둘을 고쳤고 5회차가 `auto_test_check` 를 고쳐 셋이 다 닫혔다.
  **방향은 반대다** — 기록 훅은 오탐(막힘)이라 눈에 띄고, 자동 테스트는 조용히 안 돈다.
  판정 primitive 는 하나를 공유한다(`_hookutil` 의 세션 기준 시각)
- **오탐은 무력화의 한 형태로 센다** (4회차 추가). 일을 하고도 막히는 게이트는
  `SKIP_*=1` 을 습관으로 만든다. `검증-기록.md` 1회차가 새 훅을 기각할 때 쓴 저울과 같다
- **`plan-log` 를 부르는 기준은 "아직 없는 것"이 아니라 "정하려는 것"이다** (3회차 추가) —
  이미 정한 규칙·형식·경계·컨벤션을 바꿀지 논의하는 경우에도 부르고, 확인으로 시작한 대화가
  바꾸는 쪽으로 번지면 **그 시점에** 부른다. 근거: 스킬 호출이 곧 `plan_log_check` 의 설계
  세션 표시를 만들어 Stop 검사를 무장시키는데, 직전 세션은 "형식이 맞나 확인해줘"로 시작해
  규칙 변경으로 흘러가서 스킬이 안 불렸고 검사가 통째로 무력화됐다. **어휘 감지로는 못 잡는다** —
  그 세션의 사용자 메시지 셋 중 `_DESIGN_PHRASES` 에 걸리는 것이 하나도 없었다
- **기록 대상은 `.claude/` 중 동작이 있는 것만** (2회차 추가) — `hooks/**.py` 와
  `settings.json` 은 넣고 `skills/**`·`agents/**`·CLAUDE.md 는 뺐다. 근거: 훅에는 코드를
  읽어 알 수 없는 판단이 몰려 있어 task_log 2·4절의 몫인 반면, 문서 갱신은 `task-log`
  5단계가 이미 담당한다. 문서마다 7절을 채우게 하면 `SKIP_TASKLOG=1` 이 습관이 된다.

- **에이전트를 새로 만들지 않는다 — 바꿀 것이 있으면 스킬 쪽이다** (6회차 추가).

- **모델을 대조할 때는 입력을 먼저 고정한다** (6회차 추가). 범위를 넓게 주면 모델마다 다른

- **채점 답안지는 리포트를 보기 전에 확정한다** (6회차 추가). 나중에 만들면 사후 합리화다.

  재현에서 갈렸다. 모델을 올리는 것보다 **한 번 더 돌리는 것**이 같은 예산에서 더 잡는다
- **핸드오프는 적용하기 전에 트리와 대조한다** (8회차 추가). 감사 리포트를 받아 그대로 적용하면
  안 된다 — 실측으로 **7건 중 4건이 이미 적용돼 있었고**, 그중 둘은 핸드오프 diff 보다 나은
  형태였다(`image_ocr` 이 `preprocess` 까지 `try` 안에 넣고 `ctx` 로 경고를 남긴다). 리포트가
  들고 있던 기준선(pytest 577)도 그 사이 614 로 낡아 있었다. **대조 없이 적용하면 나은 구현을
  낡은 diff 로 덮어쓴다**
- **같은 작업 트리에 다른 세션이 있으면 범위를 파일 단위로 가른다** (8회차 추가). 브랜치가
  갈린 게 아니라 **같은 디스크**라, 저쪽이 파일을 통째로 다시 쓰면 내 편집이 **에러 없이**
  사라진다. 가르는 근거는 **mtime** 이다 — 편집 직전에 대상 파일의 mtime·해시를 찍고, 검증
  뒤 `git diff -- <대상>` 으로 내 변경만 들어갔는지 본다. `ListAgents` 가 어느 세션이 busy
  인지 알려주지만 **무엇을 만지는지는 안 알려주므로** 판정은 파일 쪽에서 한다
- **체크포인트 감사의 축은 모델이 아니라 범위다** (7회차 추가). `rag-code-review` 1단계가

## 미결

다음 논의의 시작점.

- **영역별 테스트 하나가 얼마나 걸리나** — 정하려면: 구현 후 각 매핑 대상을 실제로 돌려 잰다.
  수십 초가 걸리는 대상이 있으면 그 항목을 더 잘게 쪼갠다. 지금은 전체 210개가 무겁다는 것만
  알고 영역별 수치는 없다
- **Stop 훅 3개가 실제로 성가신가** — 정하려면: 한 세션에서 몇 번 막히는지 체감한다.
  `문서-최신성.md` 1회차가 "세 번째 훅은 한 세션의 종료를 세 번 막을 수 있고 얻는 것보다
  성가심이 크다"며 CLAUDE.md 전용 훅을 기각한 전례가 있다. 이번 훅은 *테스트가 실제로 실패할
  때만* 막으므로 평상시 0회일 것으로 보지만, 그건 예상이지 실측이 아니다
- **`regression/baseline.json` 이 fixtures 없는 환경에서 쓸모가 있나** — 정하려면: `tests/fixtures/`
  가 gitignore 라 다른 클론에는 없다. baseline 은 커밋되는데 대조할 입력이 없는 상태가 된다.
  실제로 그 상황을 만나면 정한다
  → **2026-08-23 에 답했다** (`plan_log/회귀-기준선.md` 1·2회차). 두 단계로 답이 바뀌었다.
  1회차에서 *"`tests` 블록은 수집 수라 환경 독립"* 이라고 적었는데 **2회차 실측이 그것을
  뒤집었다** — 픽스처를 안 복사한 워크트리에서 `tests/ingestion/loader/document` 가
  146 → **121** 이다. `test_hwpx_real.py` 의 `_hwpx_params()` 가 수집 시점에
  `FIXTURES.glob()` 을 불러서다(실파일 모듈 다섯 중 이 하나만). 그래서 지금의 답은
  **"영역 하나만 빼면 쓸모가 있다"** 이고, 그 하나의 값(121)을 기준선 `_meta.픽스처 없는 환경`
  에 적어 그 환경에서도 대조되게 했다. `documents` 는 픽스처가 있어야 하고 없으면 조용히
  skip 한다 — 그건 "없어도 안 깨진다"이지 "쓸모가 있다"가 아니다.
  **남은 것**: `test_hwpx_real.py` 를 나머지 넷처럼 정적 목록 + 런타임 skip 으로 바꿀지.
  바꾸면 흔들림이 사라지지만, glob 이 주던 *"새 hwpx 픽스처가 들어오면 자동으로 검사된다"*
  를 잃는다. 정하려면 그 자동 커버리지가 실제로 값어치를 한 적이 있는지 봐야 한다
- **전수 점검 모드와 중복 판정 기준을 `rag-code-review` 에 넣을지** (6회차) — 정하려면:
  이번 감사 4회를 채점해 **같은 함정에 여러 모델이 반복해 걸리는지** 본다. 한 번만 걸린
  것은 문서화 값어치가 없다. 스킬 1단계가 `git diff` 로 범위를 잡고 중복이 Minor 등급인
  것이 지금의 공백이다
  → **7회차에서 답했다.** 공백은 맞았고 **모델이 아니라 범위 문제**였다. 체크포인트 A 의
  첫 전수 실행에서 판정 기준의 첫 재료를 얻는다
- **Fable 이 이 저장소 코드에서 실제로 더 나은가** (6회차) — 정하려면: n=2 로는 못 정한다.

## 4회차 — 2026-08-19 · 기록 훅이 도구를 가려서 생긴 구멍

**물은 것**

기록을 전부 남기고 커밋까지 한 세션이 "기록이 없습니다"로 막혔다. 판정을 어떻게 고칠 것인가.

**측정 — 트리거는 멀쩡하고 만족 조건만 깨졌다**

두 기록 훅의 구조를 갈라 보면 축이 둘이다.

| | 무엇으로 판정하나 | Bash 편집에 영향받나 |
|---|---|---|
| `plan_log_check` 트리거(설계 세션인가) | Skill 호출 | 아니다 |
| `task_log_check` 트리거(소스를 고쳤나) | `git status` | 아니다 |
| **둘의 만족 조건(기록했나)** | **PostToolUse 의 `tool_input.file_path`** | **그렇다 — Write/Edit 에만 있다** |

그래서 방향은 **오탐(false block)** 쪽뿐이다. 검사가 조용히 통과하는 반대 방향은 아니다.
다만 auto mode 가 Bash 편집을 기본으로 만들면서 **상시 오탐**이 된다.

`auto_test_check` 도 같은 필드를 쓰지만 Stop 이 `changed_paths()` 로 판정해 놓치는 것은
없다 — 잃는 것은 PostToolUse 의 빠른 되먹임뿐이다.

**선택지**

| 안 | 장점 | 단점 | 이 프로젝트에서의 근거 |
|---|---|---|---|
| 세션 시작 이후 mtime 을 함께 본다 | 도구를 안 가린다. `settings.json` 불변 | 새 공용 primitive 하나 | 2회차 교훈이 안 깨진다(분모가 다르다) |
| matcher 에 `Bash\|PowerShell` 을 더해 명령줄 파싱 | 구조가 그대로 | **고치려던 실패가 남는다**(`sed -i "$f"` 는 경로가 없다) + 읽기를 기록으로 오인 | 임의 셸 파싱은 추측이다 |
| `git status` 판정으로 되돌리기 | 제일 단순 | **2회차에서 버린 그 버그다** | 미커밋 3건으로 실제 무력화됐었다 |
| "기록은 Write/Edit 로 써라"를 문서에 적기 | 코드 안 늘어남 | **훅이 존재하는 전제를 부정한다** | `_hookutil` docstring: 모델에게 시키는 일은 지켜질 때도 있고 아닐 때도 있다 |

## 7회차 — 2026-08-22 · 대조 결과로 모델을 정하고, 다섯 제안 중 넷이 범위였음을 갈랐다
