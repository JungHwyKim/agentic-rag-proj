## 2. 설계 결정

### 미뤄둔 근거를 다시 재보니 약해져 있었다

`plan_log/backend.md` 와 `indexing.md` 둘 다 삭제 API 를 *"먼저 만들면 **무엇을 지우는가**가
파일명인 채로 굳는다 / 정하려면 문서 레지스트리가 생길 때"* 로 미뤄뒀다. 재보니 **그 결합은
이미 굳어 있었다** — `index_document()` 가 재색인에서 `delete_by_document_id(파일명)` 을
이미 부른다. 같은 이름으로 다시 올리면 옛 청크가 **지금도** 지워진다.

즉 삭제 API 는 새 결합을 만드는 것이 아니라 **있는 것을 노출**할 뿐이다. 부품도 이미 있었다 —
`delete_by_document_id()` 는 `VectorStore` **Protocol 에 있어서** `list_documents()` 처럼
`getattr` 로 봐줄 필요조차 없다. 굳는 위험이 남는 곳은 URL 의 `{document_id}` 하나이고,
**불투명 문자열로 받는 것**으로 막았다.

### 저장 이름에 해시 접미사를 **항상** 붙였다

사용자는 *"원본 이름 + 안전문자 치환"* 을 골랐다. 그대로 두면 `보고서:1.pdf` 와
`보고서_1.pdf` 가 디스크에서 **같은 이름**이 된다. 색인은 둘을 다른 문서로 아는데 원문은
하나뿐이라, **한쪽의 "원문 보기"가 남의 파일을 에러 없이 보여준다.**

버린 안 둘. **해시 이름만 쓰기** — 폴더를 열면 16진수뿐이라 사용자가 고른 "손으로 열어보면
안다"를 잃는다. **부딪힐 때만 접미사** — 평소엔 깨끗하지만 **이름이 `document_id` 만으로
계산되지 않게 되어** "이 문서의 원본이 어느 파일인가"를 알려면 디스크를 뒤지거나 매핑을
들여야 한다. 두 번째 진실이다.

항상 붙이면 셋을 다 얻는다: 사람이 읽고 · 계산되고 · 안 부딪힌다.

### 저장은 색인이 **성공한 뒤**다

실패한 원본까지 남기면 **목록에 없는 파일이 디스크에 쌓여** 화면과 어긋난다. 그리고
`POST /documents/upload`(파싱 전용, 공개 API)는 아예 저장하지 않는다 — 색인을 안 하므로
저장하면 같은 어긋남이 생긴다.

`shutil.move` 를 쓴 것은 기존 `finally` 의 `unlink(missing_ok=True)` 가 **옮겨간 뒤를 이미
견디도록** 쓰여 있어서다. 복사였으면 13MB 스캔본에서 I/O 가 두 배다.

### 삭제에서 답변 캐시를 **안** 비운 것이 색인과 반대다

색인 라우트는 다른 세션이 `cache.clear()` 를 넣었다 — **새 문서 유입은 조회 시점 근거
대조로 원리적으로 못 잡기 때문**이다(사라진 것이 없어 옛 답의 근거가 여전히 멀쩡하다).
삭제는 **정확히 반대**다. 근거 청크가 실제로 사라지므로 캐시가 스스로 걸러낸다. 여기서
`clear()` 를 부르면 잡히는 것을 또 잡느라 `warnings` 만 잃는다.

BM25 는 둘 다 되돌린다 — 저장소를 전량 훑은 스냅샷이라 늘어도 줄어도 낡는다.

### 서빙 위험의 절반은 화이트리스트가 이미 막고 있었다

*"올린 파일을 그대로 되돌려준다"* 의 고전적 위험은 같은 오리진 스크립트 실행인데,
`SUPPORTED_EXTENSIONS` 에 **`.svg` 도 `.html` 도 없다.** 남은 것은 경로 탈출(2겹으로 막음)과
Content-Type 이다. 확장자로 타입을 정한 근거는 3회차의 실측이다 — 화이트리스트 22종을
`detect_format()` 에 왕복시켜 **잰 것 18 · 어긋남 0** 이라 저장된 파일의 확장자는 이미
매직바이트로 뒷받침돼 있다.

### `#page=N` 은 PDF 일 때만이다

`RetrievedChunk.metadata` 에 `page` 가 이미 실려 있어 배관이 공짜였다. 다만 HWPX 는 로더가
세는 쪽 수가 문서에 따라 크게 부풀어(신뢰가능 AI 가이드 실제 28쪽 → **97쪽**) 엉뚱한 쪽으로
보낸다. 브라우저가 HWPX 를 못 열어 실질 제약은 아니지만, 안 붙이는 이유는 그쪽이다.

## 4. 실패 분석

### 테스트가 개발자의 **실제** 원본 보관함에 파일을 썼다

원본 보관을 넣은 직후 저장소 루트의 `original_files/` 에 `안내서__48fbb1.docx`(22바이트)가
생겼다. `tests/api/test_index_route.py` 의 가짜 업로드다 — 그 테스트는 원본 보관을 모르고
`originals_dir` 을 덮지도 않는다. **아무 에러도 안 났다.**

이것은 CLAUDE.md 가 이미 경고한 함정을 **내가 새로 하나 더 만든 것**이다:

> 색인 설정은 키가 아니라 저장 위치를 덮는다 — `IndexingConfig()` 의 기본 `qdrant_path` 가
> `PROJECT_ROOT/.qdrant` 라 안 덮으면 테스트가 개발자의 실제 색인을 건드린다

**막은 방법이 요점이다.** 각 테스트에서 손으로 덮게 하지 않고 `tests/api/conftest.py` 에
**autouse 픽스처**로 걸었다 — 손으로 덮는 규약이면 새 테스트를 쓰면서 잊는 순간 다시 샌다.
환경변수(`ORIGINALS_DIR`)로 덮은 것도 같은 이유다: `Settings` 가 pydantic-settings 이고
`get_settings()` 가 **매번 새로 만들기 때문에**(`lru_cache` 가 없다) 한 줄이 모든 호출부에
먹는다. 모듈마다 `get_settings` 를 patch 하는 방식이었으면 **새 호출부가 생길 때마다
빠뜨린다** — 실제로 처음엔 그렇게 짰다가 `query.py` 것을 따로 추가해야 했다.

### `FileResponse` 가 `Content-Disposition` 을 안 달았다

`content_disposition_type="inline"` 만 주고 `filename` 을 안 줬더니 헤더가 **아예 없었다**.
Starlette 은 `filename` 이 있을 때만 그 헤더를 만든다. 테스트가 `KeyError` 로 잡았다.

고치면서 오히려 나아졌다 — `filename=document_id_for(document_id)` 를 주니 내려받을 때
디스크 이름(`안내서__48fbb1.docx`)이 아니라 **원본 이름**으로 저장된다. **없는 헤더를 채우려다
계약이 하나 생긴 셈**이라 실서버에서 `filename*=utf-8''` 인코딩까지 확인했다.

### 막다른 길 — 테스트가 `ingest` 를 `None` 으로 모킹했다

*"파싱 전용 엔드포인트는 저장 안 한다"* 를 재려고 `ingest` 를 `None` 반환으로 갈아끼웠는데,
`response_model=ParsedDocument` 가 응답 검증에서 죽었다. **라우트가 아니라 검증에서 죽으면
이 테스트가 무엇을 재는지 흐려진다** — 진짜 `ParsedDocument` 를 만들어 돌려주게 고쳤다.
