## 2. 설계 결정

"기록했는가"를 git status 가 아니라 세션 마커로 판정하도록 갈아엎었다.
버린 것은 기존의 git 검사다 — `plan_log/` 나 `task_log/` 에 변경이 하나라도 있으면
통과시키는 방식.

그 판정은 세션을 구분하지 못한다. 지난 세션이 남긴 미커밋 기록이 작업트리에 있으면
이번 세션이 한 줄도 안 써도 통과한다. 가정이 아니라 실제 상태였다 — 이번에 확인한
시점의 작업트리에 plan_log/ 미커밋이 3건(M INDEX.md, M 문서-최신성.md, ?? 평가-세트.md)
쌓여 있어서 설계 논의 검사가 통째로 무력화돼 있었다. 방향이 정반대인 것이 문제다:
기록을 안 하고 미룰수록 검사가 더 헐거워진다.

마커 방식은 plan_log_check.py 가 Skill 호출을 PostToolUse 로 잡는 수법을 그대로 한 칸
더 쓴 것이라 새 개념을 안 늘린다.

기록 대상에 .claude/hooks/ 와 settings.json 을 넣고 .claude/skills/**·CLAUDE.md 는 뺐다.
버린 것은 ".claude/ 전부를 넣는" 안이다.

넣은 쪽 근거: 훅에는 코드를 읽어서 알 수 없는 판단이 유난히 많이 박힌다(-uall 을 빼면
새 디렉터리가 "?? rag_pipeline/" 한 줄로 접혀 검사가 조용히 통과, UserPromptSubmit 에서
종료코드 2 는 사용자가 방금 친 프롬프트를 지움, stop_hook_active 는 Stop 입력 필드에
아예 없음). 정확히 task_log 2절·4절의 몫인데 지금은 전부 독스트링에 몰려 있다. 게다가
훅이 조용히 무력화되면 그 뒤 모든 세션의 기록이 안 남는다.
선례도 한쪽으로 기울어 있었다 — auto_test_check.py 의 SOURCE_PREFIXES 에 이미
".claude/hooks/" 가 들어 있고, 9004a97(유료테스트 차단훅)은 task_log 를 남겼다.
반대로 121b8b2(기록 강제 훅 자체)는 안 남겼다. 규칙이 없어서 갈렸다.

뺀 쪽 근거: 문서 갱신은 task-log 스킬 5단계가 이미 담당한다. 문서 한 줄 고칠 때마다
7절을 채우게 만들면 SKIP_TASKLOG=1 이 습관이 되고, 그러면 정작 필요할 때도 안 걸린다.
경계를 is_recordable() 로 직접 재서 11개 경로를 확인했다(3절).

tests/ 는 넣지 않았다. 테스트만 고치는 세션은 드물고, 대개 소스와 같이 바뀌어
이미 걸린다. 넣으면 오탐만 는다.

## 4. 실패 분석

계획을 세운 시점의 저장소 스냅샷을 믿고 구현에 들어갔다가 두 곳이 틀렸다.
계획과 구현 사이에 커밋 b6d3dca(적재 subagent 3종과 자동 테스트 훅)가 들어와
settings.json 과 hooks/ 가 이미 달라져 있었다.

(1) "PostToolUse 에 Write|Edit 그룹을 새로 추가한다"고 적었는데 그 그룹이 이미
    있었다(auto_test_check). 새로 만들었으면 같은 matcher 그룹이 둘이 되어,
    어느 쪽에 훅을 다는지가 취향 문제로 남고 다음 사람이 헷갈렸을 것이다.
    기존 그룹에 얹는 것으로 바꿨다.

(2) "_hookutil.py 는 손대지 않는다"고 적었는데, 필요한 경로 정규화 함수가
    auto_test_check.py 에 _relative_to_root 로 이미 있었다. 계획대로 갔으면
    같은 함수가 3벌이 됐고, 그건 _hookutil.py 모듈 docstring 이 명시적으로
    경고하는 실패 모드다("같은 코드가 훅마다 복사되면 한쪽만 고쳐져 그 버그가
    되살아난다"). 실제로 그 문서가 예로 든 BOM 교훈이 paid_test_check.py 에만
    있다가 auto_test_check.py 에서 다시 걸린 전례가 있다. 계획을 뒤집고
    _hookutil.relative_to_root 로 끌어올렸다.

막다른 길은 아니었지만 교훈은 하나다 — 계획 승인과 구현 사이에 시간이 있으면
구현 직전에 대상 파일을 다시 읽어야 한다. 이번엔 CLAUDE.md 가 바뀐 것이 눈에
띄어서 알아챘고, 안 그랬으면 (2)를 모르고 3벌째를 만들었을 것이다.

부작용 하나: (2) 때문에 auto_test_check.py 의 pathlib.Path 임포트가 미사용이 됐다.
ruff F401 이 잡기 전에 같이 제거했다.
