# 자동 테스트 훅도 도구를 안 가리게 했다 — 이번엔 조용히 안 도는 쪽이었다

- 작업일: 2026-08-19
- 검증 방법: 훅 테스트 93개(신규 3건) + pytest 전체(504 passed) + ruff. **비용 0.**
- 설계 논의: [plan_log/하네스-확장.md](../plan_log/하네스-확장.md) 5회차
- 앞선 작업: [2026-08-19-기록훅-도구비의존.md](2026-08-19-기록훅-도구비의존.md) (같은 뿌리)

## 1. 무엇을 바꿨나

- `_hookutil.py` — `marker_mtime()` · `touch_marker()` · `paths_newer_than()` 신설
- `auto_test_check.py` — `_targets_for_call()` 신설. `file_path` 가 없으면 파일 쪽에서
  변경을 찾는다. 대상이 여럿일 수 있어 `_handle_post_tool_use` 가 목록을 받는다
- `settings.json` — PostToolUse 에 `Bash|PowerShell` 그룹을 **따로** 더했다
- `tests/hooks/test_auto_test_check.py` 3건 추가

## 2. 설계 결정

### 같은 뿌리인데 방향이 반대다

기록 훅과 똑같이 `tool_input.file_path` 에 기대고 있었다. 다만 결과가 반대다 —
기록 훅은 **오탐(막힘)** 이라 눈에 띄었지만, 이쪽은 **조용히 아무 검사도 안 돈다.**
Bash 로 소스를 고치면 영역 테스트가 한 번도 안 도는데 아무도 안 알려준다.

`plan_log/하네스-확장.md` 4회차는 이것을 미결로 두면서 "고칠지 Stop 전체 실행에 맡길지 —
정하려면 되먹임이 얼마나 늦어지는지 재야 한다"고 적었다. **그 측정 없이 고쳤고, 그게 이
회차에서 계획과 어긋난 부분이다.** 재지 않은 이유는 뿌리가 이미 밝혀져 있고 `_hookutil`
쪽 primitive 도 방금 만들어 둬서, 재는 비용이 고치는 비용보다 컸기 때문이다.
지연 폭 자체는 여전히 안 쟀다.

### 기준은 "마지막으로 돌린 시각"이다

`file_path` 가 없으면 `SOURCE_PREFIXES` 아래에서 기준 시각 이후에 mtime 이 바뀐 `.py` 를
찾아 영역에 매핑한다. 기준은 `claude_autotest_checked` 마커의 mtime 이고, 없으면 세션 시작
시각이다.

**돌리기 전에 마커를 갱신한다.** 테스트가 도는 동안 들어온 다음 호출이 같은 변경을 또 잡으면
같은 테스트를 반복해서 돌린다. `GATE_NS` 를 실행 전에 잡는 것과 같은 판단이다.

### matcher 를 기존 그룹에 합치지 않고 따로 뒀다

`Write|Edit` 그룹에 `Bash|PowerShell` 을 더하면 `task_log_check` 와 `plan_log_check` 까지
**모든 Bash 호출마다** 돌아간다. 둘은 `file_path` 를 볼 뿐이라 하는 일이 없는데 Windows 에서
파이썬 프로세스가 호출당 셋씩 뜬다. 그래서 `auto_test_check` 만 담은 그룹을 새로 만들었다.

### 기각한 안

| 안 | 왜 버렸나 |
|---|---|
| Stop 전체 실행에 맡기고 안 고치기 | 놓치는 건 없지만 **되먹임이 세션 끝까지 밀린다.** 훅이 존재하는 이유가 "커밋 직전에 한꺼번에 마주치는 것보다 쉽다"인데 그게 사라진다 |
| 기존 `Write\|Edit` 그룹에 셸을 합치기 | 기록 훅 둘이 Bash 호출마다 헛돈다 |
| 명령줄에서 경로 파싱 | 기록 훅에서 이미 기각한 것과 같은 이유 — `sed -i "$f"` 를 못 잡는다 |
