## 2. 설계 결정

### 화면을 만들려 했더니 화면이 부를 것이 없었다 — 그래서 dense 경로를 함께 세웠다

사용자 요청은 "스크린샷대로 frontend 를 만들어 달라"였다. 그런데 노출된 엔드포인트가
`upload`(파싱만 하고 색인은 안 함)와 `health` 둘뿐이고 `retrieval/` 에 `.py` 가 0개였다.

**버린 안: 화면만 만들고 전부 목업.** 디자인은 빨리 확정되지만 "이 화면이 실제 데이터로
성립하는가"를 못 본다. 실제로 3-3 검증에서 성립하지 **않는** 지점이 하나 드러났다(4절).

**버린 안: Phase 2 Retriever 부터 제대로.** 이번 회차가 프론트가 아니라 검색 단계 착수가
되고, hybrid·reranker 설계가 줄줄이 딸려 있어 `검색-생성.md` 의 논의를 앞지른다.

### 스택은 HTMX — 결정적인 근거는 취향이 아니라 `node` 부재였다

이 머신에 `node`·`npm`·`pnpm` 이 **전부 없다.** React+Vite 를 고르면 이 저장소에 처음으로
Python 아닌 툴체인이 들어오는데, 화면의 상호작용(소스 태그 펼침·문서 목록 갱신·질문 전송)이
전부 부분 HTML 교체로 표현된다. **다시 볼 조건**은 클라이언트 상태가 실제로 느는 때다 —
대화 히스토리 멀티탭, 같은 화면에서 여러 대화.

**Streamlit 은 기각.** 매 상호작용마다 스크립트를 통째로 재실행하는 모델이라 이 화면이
성립하지 않는다.

### 스트리밍을 안 하는 이유는 UX 가 아니라 예외 매핑이다

SSE 는 첫 바이트에 이미 200 을 보낸 뒤라 `main.py:_STATUS_BY_EXCEPTION` 이 **못 잡는다.**
그런데 이번 변경으로 그 매핑의 세 줄(`EmbeddingError`·`IndexingError`·`GenerationError`)이
**처음으로 살아났다** — 색인이 없으면 503 + "아직 색인된 문서가 없어 검색할 수 없습니다"가
사용자에게 그대로 간다. 방금 살린 것을 스트리밍으로 다시 죽이는 것은 순서가 안 맞는다.

대가는 3~6초 스피너다. **다시 볼 조건**: 재검색 루프(Phase 4~5)가 붙을 때. 그때는 진행
표시를 나를 배관이 필요해지고, 스트림 안의 에러 이벤트 규약을 함께 정하면 된다.

### 환각을 프롬프트로만 막는다 — 임계값을 지어내지 않기 위해

`hit@10` 이 0.483 이라 절반은 무관한 청크가 온다. 점수 임계값을 두면 확실하지만 **지금 그
값을 지어내야 한다.** 이 저장소가 두 번 데인 형태다 — 이미지 표시 크기 50pt(탐침값이었고
41.4pt 짜리 진짜 문구가 나와 기각됐다) · 쪽 경계 헤더 반복(오검출 4·미검출 3).

대신 `RetrievedChunk.dense_score` 가 답변까지 실려 나가므로 **관측이 공짜로 쌓인다.**
그 첫 열매가 3절이다.

### `Answer.sources` 는 `RetrievedChunk` — 요청받은 축소 dict 를 안 만들었다

사용자가 `sources: list[{page, heading_path, chunk_text}]` 를 지금 못 박자고 했는데,
`schemas/retrieval.py` 의 `RetrievedChunk` 가 **이미 그것이었다**(`text`·`metadata`·
`dense_score`). 딸려온 요청 *"dot 점수를 로깅해 나중에 측정된 숫자로 임계값을 정하자"* 도
`dense_score: float | None` 로 **이미 충족돼 있었다** — 추가 작업 0.

`retrieval.py` docstring 은 *"dense 만 쓸 때는 `SearchResult` 로 충분하다"* 고 말하고 그건
맞다. 다만 그것은 **검색 내부**의 이야기이고 `Answer` 는 라우트·템플릿이 렌더하는 **공개
계약**이라 축이 다르다. BM25 가 붙는 날 원소 타입이 바뀌면 그 둘을 함께 고쳐야 하는데,
그것이 사용자가 피하자고 한 *"계약이 나중에 흔들리는"* 상황이다.

### `run_eval` 리팩터는 요청대로는 안 됐다 — 그래서 함수를 갈랐다

*"`run_eval` 도 `answer_question()` 을 부르게 하자"* 는 **그대로는 안 된다.**
`run_eval --dense` 는 검색만 재고 생성을 안 부르는데(부르면 60건 × LLM 이 baseline 에 붙는다)
`answer_question()` 은 생성을 포함한다. 공유되는 것은 함수 전체가 아니라 **검색 절반**이다.

그래서 `retrieve()` 를 따로 두고 `answer_question() = retrieve() + generate_answer()` 로
조립했다. 부수 효과로 Phase 2 Retriever 의 자리를 미리 잡았다.

### 문서 목록은 `QdrantStore` 에만 — Protocol 은 안 넓혔다

사용자가 *"문서 목록은 읽기 전용 조회라 지금 바로 real 로 채울 수 있다"* 고 했는데 **절반만
맞았다.** `VectorStore` 에 `search`·`count` 는 있어도 **문서를 나열하는 메서드가 없다.**
공짜가 아니라 Protocol 을 넓히느냐 마느냐의 결정이 딸려 있었다.

구체 클래스에만 달아 `검색-생성.md` 의 *"새 추상화를 안 만든다 / 두 번째 구현체가 실재할 때"*
를 지켰다. 대가는 backend 가 구체 타입을 한 군데서 아는 것인데, `getattr(store,
"list_documents", None)` 로 없으면 목록만 비도록 흡수했다(화면은 산다).

**`search()` 와 반대로 컬렉션이 없으면 예외가 아니라 빈 리스트다.** 저쪽은 "색인한 적 없음"과
"질의가 안 맞음"이 사용자가 할 일이 달라 갈랐지만, 목록은 둘 다 "보여줄 문서가 없다" 하나다.

### store 는 startup 싱글턴 — 다만 (b) 로 넘어가는 트리거가 사용자가 본 것과 달랐다

사용자가 (a) 싱글턴 vs (b) 도커를 놓고 (a) 를 추천했고 **결론은 맞았다.** 다만 근거로 든
*"적재 스크립트 등 다른 프로세스와 충돌"* 은 실제 위험이 아니다. `index_document()` 가
`get_store()` 로 **자기 클라이언트를 직접 열고 `finally` 에서 닫으므로**, 업로드 버튼을 진짜로
붙이는 순간 **같은 uvicorn 프로세스 안에서** 충돌한다.

그리고 그때 첫 후보는 도커가 아니라 **`index_document(store=...)` 주입**이다 — 훨씬 싸고
기존 계약을 안 건드린다. `plan_log/frontend.md` 미결에 그렇게 적었다.

**딸린 결정: embedder 는 startup 이 아니라 첫 질의에 만든다.** `get_embedder()` 는 키가
없으면 그 자리에서 예외라(embedding 의 실패 계약), startup 에서 만들면 **키 없는 환경에서
서버가 아예 안 뜬다** — 화면도 문서 목록도 못 본다. 미루면 그때 503 으로 떨어진다.

### 소스 태그 펼침은 서버 왕복이 아니다

계획에는 "HTMX swap"으로 적었는데 구현하며 바꿨다. **청크를 id 로 다시 가져올 방법이 없다** —
`VectorStore` 에 `search` 뿐이고, 그것 하나 때문에 Protocol 을 넓힐 수는 없다(위 결정과 같은
잣대). 발췌를 답변 조각에 함께 실어 클라이언트에서 편다. 이미 가진 텍스트라 왕복이 낭비이기도 하다.

## 4. 실패 분석

### `heading_path` 가 화면에 `&amp;gt;` 로 떴다 — 이번 작업이 만든 결함

템플릿에서 `{{ meta.get('heading_path') | join(' &gt; ') }}` 로 썼다. HTML 을 쓰는 중이니
`&gt;` 가 맞다고 생각했는데, **Jinja2 표현식 안이라 결과 문자열이 한 번 더 autoescape** 되어
`&` 가 `&amp;` 가 된다. 화면에 `머리말 &gt; 보호하고` 라는 글자가 그대로 떴다.

`join(' > ')` 로 고쳤다 — autoescape 가 알아서 `&gt;` 로 만든다. **템플릿 단위 테스트로는
안 잡혔을 것이다**(파일에 `&gt;` 가 있는지 보면 통과한다). 실제 렌더 결과를 본 E2E 에서만
드러났다.

### 유료 호출 1회를 셸 인코딩으로 버렸다

`curl --data-urlencode "query=행정정보…"` 로 첫 질의를 보냈는데, 셸이 cp949 로 내보내
서버가 UTF-8 로 읽으면서 질문이 `��������…` 로 깨진 채 도착했다. **에러가 안 났다** —
깨진 문자열도 임베딩이 되고 검색이 되고 모델이 답을 만든다. 무관한 답변(아동복지법 제3조)이
나온 것을 보고서야 알았다.

`httpx` 로 보내 다시 쟀다. 재현 명령과 함께 `verify_log` 6절에 경고로 적었다.
**막지는 못했다** — 셸에서 서버로 보내는 경로에 회귀 테스트를 걸 자리가 없다.

### 계획의 검증 항목 하나가 발화하지 않는다

계획에 *"근거를 못 찾는 질문에서 소스 영역이 안 뜨는가"* 를 적었는데 **그렇게 되지 않는다.**
dense 는 컬렉션이 비어 있지 않은 한 늘 `top_k` 개를 돌려주므로 `sources` 가 빈 경우는 빈
질의뿐이고, 그건 모델을 부르기 전에 끊긴다. 실제로 "오늘 서울 날씨 어때?"에 모델은
**"문서에서 찾지 못했습니다."** 라고 답했는데 **소스 태그 5개는 그대로 떴다.**

코드 경로 자체는 옳고(가상 테스트로 검증됨) 임계값이 없는 동안의 구조적 귀결이다.
"근거 있음"과 "근거 없음"이 화면에서 **답변 문장으로만** 갈린다. 임계값 논의의 근거가 하나 늘었다.

### 헤매지 않은 것

`bash` heredoc 으로 테스트 파일 둘을 쓰려다 파서가 깨져(`unexpected EOF`) 두 파일이 통째로
안 만들어졌다. `ls` 로 확인하고 `Write` 로 옮겨 썼다. 원인은 못 밝혔다.
