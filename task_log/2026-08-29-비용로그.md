## 2. 설계 결정

### 새 스킬을 만들지 않고 코드로 갔다

사용자가 *"이거 skill 로 만드는 게 좋을까"* 라고 물었고, 세어 보니 **스킬은 이미 그 자리에
있고 실제로 돌고 있었다.** `verify-log` 회차 템플릿이 `- 비용:` 줄을 요구하고 `verify_log/`
30여 회차가 채웠다 — `Cohere 유료 2회 ≈ 129호출` · `OpenAI listwise E1 53회 · 871,584토큰` ·
`dense baseline 약 $0.003`.

그런데 같은 목록에 이 줄이 있다.

> `- 비용: 생성 LLM(gpt-4.1-mini) **2회** (사용자 승인)`

**토큰이 없다.** 규율이 없어서가 아니라 `generation/answer.py` 에 `usage` 가 없어서 셀 것이
없었다. **스킬은 「적어라」까지 할 수 있고 「무엇을」은 못 만든다** — 새 스킬을 하나 더
만들어도 같은 자리에 선다. 그래서 새 스킬 대신 `verify-log` 의 「비용」 절 **한 곳**을 고쳐
손으로 세는 대신 `cost/report.py` 표를 붙이게 했다.

**버린 안 둘.** ① 새 스킬 `cost-log` — 위 이유. ② Stop 훅으로 강제 — CLAUDE.md 가 이미
기각해 뒀다(*"차단 게이트를 셋으로 늘리면 `SKIP_*=1` 이 습관이 된다"* 가 `verify_log` 에
훅을 안 단 이유다).

### SDK 래핑(`sitecustomize`)을 기각했다 — 셋을 잃는다

사용자가 *"코드로 만들면 `/plugin` 으로 결합 못 하지 않냐"* 고 물어 열린 갈림길이다.
`openai`·`cohere` 클라이언트를 `sys.meta_path` 로 감싸면 **저장소를 한 줄도 안 고치고**
어느 프로젝트에도 얹힌다(이 저장소는 그 트릭을 이미 안다 — 2026-08-28 langgraph 미설치 흉내).

기각한 근거 셋.

1. **stage 를 모른다.** rerank 인지 evaluate 인지 judge 인지 generate 인지를 호출 스택으로
   추정해야 하고, 리팩터링 한 번에 **조용히** 틀린다.
2. **캐시 히트를 못 본다.** 캐시가 SDK 위층이라 히트하면 호출이 아예 안 나간다 →
   「아낀 금액」과 회계 게이트가 통째로 사라지는데, **그 게이트가 429 사고의 유일한
   신호였고 저장소가 이미 두 곳에 심어 뒀다**(`run_eval` 의 `usage` 블록 ·
   `answer_eval._print()`).
3. LlamaParse·Tavily 는 SDK 모양이 다르고, `PYTHONPATH` 를 안 심은 실행은 조용히 0이 된다.

### 플러그인은 나중에 뽑되 **경계는 지금 긋는다**

플러그인이 코드를 싣는 것은 맞다 — 설치돼 있는 공식 `skill-creator` 가 자기
`skills/skill-creator/scripts/` 에 파이썬 **10개**를 넣고 다닌다. 다만 **반쪽만 옮길 수 있다**:
쓰는 쪽은 유료 호출과 **같은 프로세스 안**이어야 해서 원리적으로 못 옮기고, 읽는 쪽
(`report`·`recover`·`pricing`)만 옮길 수 있다.

지금 옮기지 않은 이유는 **안 돌려본 것을 패키징하면 남의 머신에서 처음 깨지기** 때문이고,
그때 깨질 자리가 바로 import 다 — **옮기는 날에야 안다.** 그래서
`tests/cost/test_cost_portable.py` 가 지금부터 `cost/` 가 `rag_pipeline`·`evaluation` 을
import 하지 않고 `PROJECT_ROOT`·`parents[N]` 에 안 매이는지 본다.

### 금액을 로그 줄에 안 싣는다

단가는 바뀐다. 박아 두면 바뀐 날 **이미 쌓인 줄이 조용히 거짓**이 되고 되돌릴 방법이 없다.
관측(토큰·호출)만 남기고 금액은 `cost/report.py` 가 읽을 때 곱한다 — `verdict`·`citation` 이
답변을 안 바꾸고 흔적만 싣는 것과 같은 잣대다.

**대신 낡음을 막을 수 없으니 보이게 했다** — `CHECKED_ON` 이 `None` 이면 리포트가 *"사람이
확인하지 않은 값"* 을 찍는다. 단가표에 없는 모델은 **0이 아니라 「금액 못 냄」으로 따로
센다**(0으로 채우면 안 쓴 것처럼 보이는데, 그것이 이 도구가 막으려는 종류의 거짓이다).

### 로컬·무료 갈래는 안 남긴다

로컬 임베더(KURE)를 남기면 문서 하나 색인에 수백 줄이 쌓여 상한 없는 파일이 폭주한다 —
실측으로 `.cache/embedding` 의 로컬 몫이 이틀 만에 2,451 → **2,597** 로 늘었다.
회계 게이트는 **유료 갈래를 켠 실행**에서만 쓰므로 유료만 남겨도 성립한다.
`local_st.py` 는 계약(입력 토큰 칸)만 맞추고 로그는 안 부른다.

### 임베딩 캐시 히트만 **묶어서** 한 줄이다

다른 갈래는 질의당 호출이 하나라 줄과 호출이 1:1 인데, 임베딩은 배치라
`embed_documents()` 한 번이 텍스트 수백 개를 담는다. 텍스트마다 한 줄이면 같은 폭주가
난다. 그래서 **`items` 가 그 축이다** — 이 줄이 말하는 것은 *"N개를 캐시로 아꼈다"* 이지
*"한 번 아꼈다"* 가 아니다.

### `stage` 를 `evaluate` 와 `judge` 로 갈랐다

둘 다 판정이지만 저쪽은 *근거가 충분한가*(질의당 1회)이고 이쪽은 *답변이 근거에
실렸는가*(대상당 **2회** — 본판 + 음성 대조군)다. 합치면 「판정이 왜 이렇게 비싸지」의 답이
사라진다. **`evaluation/` 이 `rag_pipeline` 밖인데도 같은 로그를 쓴다** — 비용은 계층이
아니라 돈의 문제라 평가 하네스가 쓴 돈도 같은 파일에 모여야 「이번 주에 얼마」가 성립한다.

### 과거는 되살아나는 만큼만 — 「못 가름」이 값이다

`rerank` 1,493건을 0으로 두면 안 쓴 것처럼 보이고, 전부 유료로 세면 로컬 실행이 비용으로
둔갑한다. **두 방향 다 틀리는데 에러가 안 난다.** 그래서 「못 가름」이라는 칸을 따로 뒀다 —
Evaluator 가 실패를 *충분/불충분* 이 아닌 **제3의 상태**로 뺀 것과 같은 사고다.
`generate`·`web_search` 는 캐시가 없어 **한 건도 못 되살린다**를 명시한다(0으로 찍으면
*안 썼다* 로 읽힌다).

## 4. 실패 분석

### 계획의 전제가 세 개 낡아 있었다 — 트리가 하루 만에 움직였다

설계서를 `b569018` 기준으로 썼는데 사용자가 *"설계서 작성하는 사이에 많은 변화가 있었어"*
라고 지적했고, 다시 대조하니 `42c56b1` 이었다. 뒤집힌 전제 셋.

| 계획 | 실제 |
|---|---|
| usage 클래스 **넷** | **다섯** — `JudgeUsage` 가 08-28 에 생겼다 |
| *"생성 품질은 못 잰다"* | `evaluation/answer_eval.py` 가 잰다 |
| web_search 는 backend 가 안 불러 범위 밖 | `routes/query.py` 가 `agent_max_retries > 0` 이면 부른다 → **범위 안** |

**가른 것은 `git log` 한 번이다.** 계획 안에 「착수 직전에 `git status` 를 다시 본다」를
넣어 뒀는데, 실제로 착수할 때 HEAD 가 **또** 움직여 있었다(`692eb3c` → `42c56b1`).

### 「루프가 생성을 여러 번 부른다」가 틀렸다

계획 §4에 *"재시도 루프가 `generate_answer` 를 여러 번 부르므로 **줄 수가 곧 재시도
횟수**"* 라고 적고 `generation/answer.py` 주석에까지 옮겨 썼다. **틀렸다.**
`loop.py` docstring 이 이미 답을 갖고 있었다 —
`retrieve` 1 + (`rewrite`+`retrieve`)×`max_retries` + `generate` **1** + `end` 1.
`step_generate` 가 유일한 정상 출구라 생성은 늘 1회이고, 재시도와 함께 늘어나는 것은
`step_retrieve` 안에 있는 **`evaluate`(재시도+1회)** 다.

**주석을 고치고 그 자리에 테스트를 박았다** — `tests/agent/test_retry_loop_cost.py` 가
`max_retries` 0·1·3 에서 `evaluate == N+1` 과 `generate == 1` 을 함께 잰다. 이 테스트는
**스텁을 안 쓴다**(`test_retry_loop.py` 는 `StubGenerate`·`StubEvaluator` 로 도는데,
비용 줄은 진짜 구현체 안에서 나오므로 스텁으로 바꾸면 아무것도 안 재게 된다).

### 프로퍼티화가 **독자**는 안 깼는데 **생성자**를 깼다

계획에 *"프로퍼티면 기존 독자가 한 줄도 안 바뀐다"* 라고 썼고 그건 맞았다 —
`run_eval` 의 `usage` 블록도 `max_embedding_tokens_per_doc` 상한 검사도 그대로 살았다.
놓친 것은 `pipeline.py:_usage_since()` 가 **읽는 쪽이 아니라 만드는 쪽**이라는 것이다
(`EmbeddingUsage(total_tokens=...)` → 프로퍼티는 생성자 인자가 못 된다).

**영역 테스트가 못 잡고 전체 pytest 가 잡았다** — 그 함수는 `tests/ingestion/indexing` 이
검증하는데 나는 `tests/ingestion/embedding` 만 돌리고 넘어갔다. 두 번째 교훈이 더 크다:
**`pytest -q | tail` 로 돌리면 종료코드가 파이프의 것이라 exit 0 으로 보인다.** 실제로
그 배경 실행이 「exit code 0」으로 보고됐는데 안에 실패 2건이 있었다. 그 뒤로는
`> file; echo $?` 로 돌린다.

### 첫 실행에서 테스트 둘이 제 일을 했다

- `tests/cost/test_cost_pricing.py` 가 내가 넣어 둔 `text-embedding-3-large` 를
  **저장소가 안 쓰는 죽은 줄**로 잡아냈다(그 모델을 부르는 프로필이 없다).
- `test_cost_portable.py` 를 처음에 `"PROJECT_ROOT" not in source` 로 썼더니
  *"`PROJECT_ROOT` 를 안 쓴다"* 라고 적어 둔 **주석 자체**가 걸렸다 — 규칙을 설명한
  문장이 그 규칙을 어긴 것으로 읽힌다. AST 로 바꿨다.

### 출력이 cp949 로 죽었다 — 인코딩 함정의 세 번째 얼굴

`cost.recover` 첫 실행이 `UnicodeEncodeError: 'cp949' codec can't encode character '—'`
로 **표 중간에서 멈췄고**, 그때까지 찍힌 줄은 한글이 통째로 깨져 있었다. CLAUDE.md 가
적어 둔 인코딩 함정의 *출력* 쪽이다.

`PYTHONIOENCODING=utf-8` 을 부르는 쪽에 요구하지 **않기로** 했다 — 그 요구는 잊히고,
잊히면 *비용을 보려고 돌린 명령이 비용을 못 보여준다.* `cost/use_utf8_stdout()` 이
자기 출력을 책임진다(`errors="replace"` — 사람이 읽는 표라 글자 하나가 `?` 로 보이는 것보다
표가 통째로 안 나오는 것이 나쁘다).

### 가짜 응답이 합계만 갖고 있었다 — 잠긴 적 없는 칸

`tests/generation/test_evaluate.py` 의 가짜 `usage` 가 `total_tokens` 하나뿐이었고,
`total_tokens` 를 보는 단언은 **실패 경로의 `== 0` 하나**뿐이었다. 그래서 성공 경로에서
토큰을 통째로 안 세도 **전부 통과한다.** 세 파일의 가짜를 실제 응답 모양(셋 다)으로
고치고 성공 경로 단언을 더했다.

### 피어 세션과 같은 파일을 만졌다

`evaluation/answer_eval.py` 를 피어가 작업 중이어서 **그 파일을 마지막에** 손댔다.
`CLAUDE.md` 편집은 Edit 의 유일 앵커로 넣고 뒤에 `git diff --stat` 으로 **내 것만
+5/-1** 인지 확인했다. `verify_log/INDEX.md` 도 `grep -c` 로 125 → 126 을 확인했다.
피어 파일(`evaluation/qa_set*` · `tests/evaluation/test_qa_set.py` · `plan_log/*`)은
안 건드렸다.

  대조한 날짜를 넣기 전에는 리포트가 경고를 찍고, 그 금액을 `verify_log/` 에 옮기면 안 된다.

  ② `generate` 가 실제로 찍히나 ③ 금액 자릿수가 대시보드와 맞나.
