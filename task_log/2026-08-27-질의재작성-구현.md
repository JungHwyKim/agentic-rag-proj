## 2. 설계 결정

### 합류 방식을 하나 고르지 않고 **둘 다 만들어 프로필로 갈랐다**

착수 전 대조표를 찍다가 찾았다. **21회차 상한 프로브는 「교체」를 쟀는데 7회차 로드맵은
「합류」였다** — `verify_log/2026-08-27-라벨-전수검수-재작성프로브.md` 7절이 *"프로브는 질의
문자열만 바꾼 것"* 이라고 이미 적어 뒀다. 즉 **`sih-07` 102위 → 2위 는 원 질의 갈래를
버렸을 때의 수치**이고, `fuse` 로 만들면 그 102위를 만든 dense 갈래가 RRF 에 계속 표를 던져
같은 수가 안 나온다.

「다음 승인 단위」의 *"상한은 사람이 낸 값이다"* 경고는 **어휘 축**만 짚었다 — *모델이 사람과
같은 낱말을 낼까*. 합류 방식 축은 안 짚었고, 그래서 계획대로 `fuse` 만 만들었으면 **첫 측정이
프로브와 안 맞았을 때 「모델이 못 쓴 것」과 「합류가 희석한 것」을 못 갈랐을 것**이다.

버린 것 둘. **합류만**(로드맵 그대로) — 프로브 수치가 재현 대상이 아니게 되고 얼마나
희석되는지는 또 재봐야 안다. **교체만**(프로브 모양) — 재작성이 나쁠 때 내려갈 층이 없어
PRF 의 고전적 실패(query drift)를 정면으로 맞는다.

**둘 다 만드는 비용이 사실상 0 인 것이 결정을 쉽게 했다.** 재작성 LLM 호출은 mode 가
갈리기 **전**에 일어나고 캐시 키가 `(질의, 1차 pool)` 이라, 두 프로필이 같은 캐시 항목을
읽는다 — 먼저 돌린 쪽이 값을 치르고 나머지 하나는 무료다.

### `rewrite_cache_salt` 에 `rewrite_mode` 를 **안** 싣는다 — `rerank` 쪽과 방향이 반대다

`rerank_cache_salt_for()` 는 `rerank_device` 를 **싣는다**(CPU/GPU 가 다른 점수를 내서다).
여기는 반대로 mode 를 뺐는데, 규칙이 다른 것이 아니라 **같은 규칙의 다른 답**이다 —
**출력을 가르는 것만 salt 에 넣는다.** mode 는 재작성 호출 뒤에서 갈리므로 출력을 안 가른다.

실으면 바로 위 「두 번째 프로필이 무료」가 통째로 사라진다. 그것을 테스트로 박았다
(`test_mode_does_not_split_the_cache`) — 안 박으면 나중에 *"salt 에는 설정을 다 넣는 게
안전하지"* 로 좋은 뜻으로 되돌린다.

### 리랭커에 넘기는 질의는 **원 질의**다

뜻으로도 맞다(리랭커가 재는 것은 *본문이 질문에 답하나* 이고 재작성 질의는 검색용 확장어다).
그런데 **결정을 만든 것은 캐시다** — `rerank_cache_key()` 가 query 를 싣기 때문에, 재작성
질의를 먹이면 **재작성 프롬프트를 한 줄 고칠 때마다 리랭킹 캐시가 전량 미스**가 되고
운영 `.env` 가 cohere 라 그것은 곧 유료 호출이다. 버린 것: 재작성 질의 · 둘을 이어 붙인
문자열(뒤엣것은 Cohere 의 500토큰 과금 단위에도 걸린다).

### 재작성기 출력은 **다시 쓴 질문 문장 하나**

프로브 `honest` 가 정확히 그 모양이라 **모델이 낸 문장과 사람이 낸 문장을 나란히 놓을 수
있다.** 「상한은 사람이 낸 값」과의 간격을 재는 것이 첫 측정의 목적이므로, 출력 모양이 다르면
그 비교가 성립하지 않는다.

버린 것: **원 질의 + 확장 낱말 목록**(그러면 `replace` 안에도 원 질의가 살아 있어 두 모드를
가른 이유가 흐려진다) · **문장과 낱말을 함께 내고 모드별로 고르기**(갈래가 넣어졌을 때
*재작성이 나빴나 조합이 나빴나* 를 못 가른다 — 리랭커가 *반쯤 안 채운다* 를 정한 것과 같은 종류).

### 질의는 **1개 고정** — 못 정할 근거가 있어서 안 열었다

프로브에서 `honest` 와 `honest2` 가 **1대1로 갈렸다**: `sih-07` 은 2 vs 10 으로 `honest` 가,
`ai-03` 은 3 vs 1 로 `honest2` 가 이긴다. 설정으로 열 수는 있었지만(`fuse` 때문에 `fuse_branches`
가 이미 N 갈래다) **이번 회차가 답할 것이 갈래 수에 안 실린다** — 첫 물음은 *모델이 사람만큼
쓰나* 이고 거기에 변종 수는 무관하다. 기본 1 로 열어 두면 아무도 안 재는 죽은 설정이 된다.

### 재작성기에는 `Protocol` 을 **안** 만든다

구현체가 하나뿐이라 `answer_cache` 와 같은 대우다. 리랭커가 Protocol 을 가진 것은 구현체가
**셋**이기 때문이고(`local`·`openai`·`cohere`), 그 파일 docstring 이 *"합법값이 하나뿐인
추상은 죽은 추상"* 이라고 잣대를 이미 적어 뒀다. **나란히 두면 *"검색 쪽은 다 Protocol"* 로
오해할 자리**라 `rewrite.py` docstring 에 왜 아닌지를 명시했다.

### 호출 인자는 `generation/evaluate.py` 를 따랐다 — 가까운 형제가 낡은 쪽이었다

같은 패키지의 `reranker/openai_llm.py` 가 모양이 제일 비슷해 먼저 눈에 들어오는데,
그쪽은 **luna 실측(2026-08-27) 이전 코드**라 `max_tokens=` 를 쓰고 있어 gpt-5 계열에서
**400** 이다. `evaluate.py` 만 `max_completion_tokens` + *"`temperature` 는 `None` 이면 인자
자체를 안 싣는다"* 를 반영하고 있다. **베낄 대상을 거리로 고르면 낡은 쪽을 베끼는 자리다.**

## 4. 실패 분석

### `fuse()` 를 남기려다 지웠다 — 계획이 틀렸고 ruff 가 먼저 알려줬다

계획은 두 갈래짜리 `fuse()` 를 *"`fuse_branches()` 를 부르는 이름 있는 지름길"* 로 남기는
것이었다. 근거는 `tests/retrieval/test_rrf.py::test_score_magnitude_is_ignored` 가 계약이라
살아 있어야 한다는 것이었는데, **계약을 지키는 것과 함수 이름을 남기는 것을 헷갈렸다.**

`hybrid.py` 를 `_branches_for()` 로 옮기고 나니 `fuse()` 의 **production 소비자가 0** 이
됐고, `F401`(`fuse imported but unused`)이 그것을 알려줬다. 이 저장소가 일관되게 기각해 온
*"합법값이 하나뿐인 죽은 것"* 과 같은 자리라 지우고, 계약 테스트는 같은 모양의 helper 를
자기 파일 안에 들고 `fuse_branches` 를 부른다. **계약은 이름만 옮겼고 내용은 그대로다.**

되돌리지 못하게 막은 것: 없음(테스트로 막을 성질이 아니다). 대신 `fusion.py` docstring 과
`plan_log` 확정 절에 *왜 안 남겼는지*를 적었다.

### 편집 스크립트가 파일 일곱 개를 통째로 LF 로 바꿔 놨다

여러 곳을 고칠 때 Python 스크립트로 `read_text()` → `replace()` → `write_text(newline="")`
를 썼는데, `read_text()` 가 universal newlines 로 CRLF 를 LF 로 바꿔 읽고 `newline=""` 가
그대로 쓴다. **결과가 「한 줄 고쳤는데 파일 전체가 diff」다.**

`core.autocrlf=true` 라 커밋되는 blob 은 어차피 같아서 **에러도 안 나고 `git diff --stat`
을 보기 전까지 안 보인다.** 실제로 `evaluation/config.py` 507줄 · `run_eval.py` 567줄 ·
`test_eval_config.py` 467줄 등 일곱 파일이 그 상태였다. 바이트로 다시 읽어 CRLF 로
정규화하고 `--stat` 으로 확인했다(537 insertions / 53 deletions 로 돌아왔다).

**교훈은 `newline=""` 를 쓰지 말라가 아니라, 바이트로 읽고 바이트로 쓰라는 것**이다 —
이후 `plan_log`·`INDEX` 편집은 전부 `read_bytes()` → `.replace("\r\n","\n")` 로 다뤄
→ 쓸 때 되돌리는 방식으로 했다.

### 대조표의 「운영 색인」을 표대로 못 봤다

`QdrantClient(path='.qdrant')` 가 `RuntimeError: Storage folder ... already accessed` 로
죽었다 — 서버가 떠 있었다. 표는 *"내리고 본다"* 라고 적혀 있는데, 사용자 서버를 내리는 것은
이 작업의 범위 밖이라 **그 서버의 `GET /api/v1/documents` 로 우회**했다(3문서 309청크 확인).
표에 세 번째 길로 적어 뒀다.

### 테스트 하나가 프롬프트 머리말과 부딪혔다

`rewrite_context_k=2` 를 확인하려고 `assert "조각 2" not in body` 로 썼는데, 프롬프트
머리말이 `1차 검색으로 찾은 조각 2개:` 라 **개수 표기가 본문 문자열과 겹쳤다.** 번호
블록(`[0]`·`[1]`·`[2]`)으로 세도록 고쳤다. 사소하지만 방향이 나쁜 실패다 — 통과했으면
`context_k` 가 안 먹어도 몰랐을 자리다.

## 7. 남은 것

- **유료 측정이 통째로 남았다** — 범위 5. 순서가 있다: ① `--rewrite replace` 60건
  (**프로브의 `102→2` 와 견줄 수 있는 유일한 프로필**) → ② `--rewrite fuse` 같은 세트
  (캐시를 나눠 써 사실상 무료) → ③ 사람 세트 18건. **①이 먼저인 이유**: 모델이 도메인
  낱말을 못 내면 ②·③이 둘 다 0 을 재는 실행이 된다.
  **지표를 읽기 전에 `usage.rewrite_calls + rewrite_cache_hits == 질의 수` 를 확인한다**
- **화면 배선을 안 했다** — Evaluator 가 밟은 순서(재고 나서 배선)를 그대로 따랐다.
  `answer_question()` 은 안 건드렸으므로 서버는 재작성 없이 돈다
- **재작성 질의 여러 개** — 프로브의 1대1 그대로 미결
- **줄끝 사고를 훅으로 막을 수 있나** — 안 봤다. `core.autocrlf=true` 라 커밋 blob 은 같아서
  **git 으로는 원리적으로 안 보인다**. 볼 수 있는 것은 워킹트리 바이트뿐이다
- **HWPX 판 동등성** — `--format pdf` 만 돌렸다. 리팩터가 포맷을 안 탄다는 것은 논증이지
  실측이 아니다
