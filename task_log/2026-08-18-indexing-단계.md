## 2. 설계 결정

사용자가 가져온 VectorDB 계획서를 코드와 대조해 12곳을 고쳤다. 전체 목록은
[plan_log/indexing.md](../plan_log/indexing.md) 에 있고, 여기에는 **버린 것이 있는 결정**만 적는다.

### `document_id` 를 파일명에서 뽑는다 — 내용 해시를 버렸다

계획서 9절은 `A B C D E → A B D` 재색인을 목표로 걸어놓고 `Chunk.document_id` 가 있다고
전제했다. **그 필드는 없다.** 실제는 `document_key` 이고 기본값이 파싱 결과 해시다.
그래서 계획서대로 하면 **문서를 고치는 순간 키가 바뀌어** `delete_by_document_id()` 가 옛
청크를 못 찾는다 — C·E 가 남는 게 아니라 문서가 통째로 두 벌이 된다. 막으려던 일이 계획대로
해서 일어난다.

버린 것 둘.

- **파일 내용 해시** — 지금 동작에 제일 가깝고 재업로드 중복이 공짜로 막히지만, 9절을
  포기하는 선택이다
- **업로드 시 부여하는 명시적 id** — 가장 정확하지만 "이 업로드가 그 문서의 새 판인가"를
  아는 **문서 레지스트리**가 backend 에 새로 필요하다. backend 는 지금 `uuid4()` 임시
  파일명만 만들고 버린다

감수한 것: **내용이 다른 동명 파일은 서로를 덮어쓴다.** 미결에 적었다.

### 정규화를 NFC 로 건다

한글 파일명을 macOS 는 NFD, Windows 는 NFC 로 저장한다. 안 맞추면 눈에 똑같은 이름이 다른
키가 되어 위 사고가 그대로 재현된다. 탐침에서 두 표기가 **실제로 다른 문자열**임을 먼저 찍고
(`nfd != nfc`) 정규화 후 같은 키가 되는 것을 확인했다. 한국어 코퍼스라 이론적 위험이 아니다.

### `VectorRecord.id` 는 `uuid5(chunk_id)` — 계획서의 `id = chunk_id` 는 실행 불가였다

계획서 4.2절이 *"id 는 기본적으로 chunk_id 를 사용한다"* 인데, **qdrant 는 point ID 로
unsigned int 또는 UUID 만 받는다.** 실제로 넣어보니
`ValueError: Point id 안내서.pdf:0007 is not a valid UUID` 다. 해시(`content_hash`)를 쓰지
않고 uuid5 를 쓴 이유는 "결정론적" 과 "qdrant 가 받는 형식" 을 동시에 만족하는 것이 이것뿐이라서다.
사람이 읽는 `chunk_id` 는 payload 로 보존한다 — UUID 만 남기면 결과에서 원본을 눈으로 못 되짚는다.

### 모델 혼입을 검사가 아니라 컬렉션 이름으로 막는다

계획서 11절은 **차원 불일치**만 예외로 다뤘다. 그런데 `text-embedding-3-small` 기본 1536 과
`-large` 를 `dimensions=1536` 으로 줄인 것은 **크기가 같고 벡터 공간이 다르다.** 차원 검사를
통과하고 조용히 섞여 검색 품질만 서서히 나빠진다 — 제일 늦게 발각되는 종류다.

그래서 컬렉션 이름을 `{collection_name}_{model}_{dim}` 으로 파생했다. embedding 이 캐시 salt 를
`embed:{model}:{dim}` 으로 **둘 다** 넣은 것과 같은 판단이고, 차원 부분이
`dimensions or "default"` 인 것도 salt 규칙 그대로다.

버린 것: **차원 + 모델을 둘 다 검사하는 안.** 사이드카 파일이나 예약 point 가 필요하고,
무엇보다 **검사가 통과하는 한** 혼입이 가능하다. 이름에 넣으면 아예 다른 컬렉션이라
구조적으로 불가능해진다. 대가는 모델을 바꿨을 때 옛 컬렉션이 남는 것인데, 롤백이 되는
이점과 맞바꿨다.

### 거리는 Dot 고정, 설정으로 만들지 않았다

embedding 회차에서 벡터가 단위 길이임을 유료 호출로 확인했다(0.9998~1.0005, `dimensions=256`
축소본도 0.9999). 단위 벡터에서 Cosine 과 Dot 은 같은 순위를 주고 Dot 이 더 싸다.
`distance` 설정을 만들면 합법값이 하나뿐인 죽은 설정이 된다 — `embedding.provider` 를 같은
이유로 안 만든 잣대다. `qdrant_url` · `provider` 도 같이 기각했다.

### `collection` 을 인자로 받지 않는다 — 계획서의 여섯 자리를 지웠다

계획서 5절이 "기본 컬렉션 하나"로 정해놓고 7절의 여섯 메서드가 전부 `collection: str` 을
받는다. 합법값이 하나뿐인 인자 여섯 개다. 설정으로 옮기고 store 인스턴스가 들고 있게 했다.
같은 이유로 `create_collection`/`delete_collection`/`collection_exists` 셋을
`ensure_collection()` 하나로 줄였다 — 나머지 둘은 부를 곳이 없다.

`ensure_collection()` 이 **차원을 인자로 받는** 것은 `embedding_dimensions` 가 `None`
("모델 기본값")일 수 있어서다. 설정만 봐서는 벡터 크기를 모르고, 모델→차원 표를 코드에
박으면 모델이 늘 때마다 거짓이 된다.

### `ingest()` 를 안 바꾸고 `index_document()` 를 따로 냈다

계획서 Phase 4 는 *"전체 흐름을 연결한다"* 한 줄인데, 이건 API 결정이다. 이유 둘이고
**뒤가 더 중요하다.**

1. `ingest()` 의 반환이 곧 backend 의 `response_model` 이다
2. **기본 `pytest` 가 `ingest()` 만 부르므로 임베딩이 호출되지 않는다.** 그래서 "키 없으면
   예외"라는 embedding 설계가 기본 테스트를 안 깬다. 합치면 그 지탱이 무너지고,
   `offline_config` 에 임베딩·색인을 끄는 스위치를 새로 넣어야 한다

버린 것: `IngestResult(document, chunks)` 로 반환 타입을 바꾸는 안(`plan_log/splitter.md`
가 남긴 후보 중 하나). 진입점을 둘로 두는 쪽이 공개 스키마를 안 건드린다.

### 계획서 16절의 완료 기준 8·10번을 지웠다

*"Retriever 가 구체적 구현체에 의존하지 않는다"* · *"Semantic cache 가 침투하지 않는다"* —
둘 다 그 코드가 저장소에 한 줄도 없어 **체크박스가 항상 통과한다.** `plan_log/embedding.md`
1회차가 같은 패턴을 이미 기각했다(*"검사로서 값어치가 0이다"*). 금지 선언 대신 다시 볼
조건으로 옮겨 적었다.

## 4. 실패 분석

### 훅이 integration 전용 파일을 고칠 때마다 막았다

`test_indexing_integration.py` 를 쓰자마자 `auto_test_check.py` 가 "테스트 실패"로 막았는데,
출력은 `2 deselected in 0.02s` 였다. 실패가 아니라 **pytest 가 "수집된 테스트 없음"으로
종료코드 5** 를 냈고 훅이 `returncode == 0` 만 통과로 보고 있었다.

`pyproject.toml` 의 `addopts = "-m 'not integration'"` 이 그 파일의 테스트를 전부 deselect
하므로 **integration 전용 파일은 구조적으로 항상 5가 난다.** 확인해 보니 기존
`test_embedding_integration.py` 도 똑같이 5를 낸다 — 내가 만든 문제가 아니라 이미 있던
사각지대였고, 그 파일이 세션 중에 편집되지 않아 드러나지 않았을 뿐이다.

`_OK_RETURNCODES = (0, 5)` 로 고쳤다. 5만 더하고 1(실패)·4(사용 오류)는 그대로 막는다.

### `contextlib` import 를 빠뜨려 전 테스트의 teardown 이 깨졌다

ruff 의 SIM105 지적을 받아 `try/except/pass` 를 `contextlib.suppress` 로 바꾸면서 import 를
안 넣었다. `close()` 안이라 **모든 픽스처 teardown 이 `NameError` 로 무너졌다** — 테스트
본문은 통과하는데 teardown 에서만 죽는 모양이라 실패 개수가 실제 원인보다 훨씬 커 보였다.
훅이 즉시 잡았다.

### 테스트가 코드를 잘못 예상했다 — 코드를 안 고치고 테스트를 고쳤다

`document_id_for("C:\\upload\\")` 가 예외를 낼 거라고 적었는데 `"upload"` 가 나왔다.
`PurePath("C:/upload/").name` 이 마지막 디렉터리 이름을 준다. 디렉터리 경로는 업로드에서
나올 수 없는 입력이고, 그것을 감지하는 분기는 근거 없는 복잡도라 **테스트 쪽을 고쳤다**
(`""`, `"   "`, `"/"`, `"C:\\"` 로 바꿈 — 이것들은 실제로 빈 키가 된다).

### `index_document()` 가 빈 문서에서 옛 청크를 남길 뻔했다

처음에 `if records:` 안에 `ensure_collection` · `delete` · `upsert` 를 다 넣었다. 그러면
문서가 빈 문서로 바뀌었을 때 delete 를 건너뛰어 **옛 청크가 통째로 남는다.** 테스트를 쓰기
전에 코드를 다시 읽다가 발견했고, `delete` 를 `if` 밖으로 뺐다(`ensure_collection` 만 안에
남는다 — 차원을 알 수 없어서다). `test_document_emptied_leaves_nothing` 으로 박았다.

### `.qdrant/` 가 gitignore 에 없었다

`IndexingConfig.qdrant_path` 기본값이 `PROJECT_ROOT/.qdrant` 다. `git status` 를 보다가
알아챘다 — 누구든 `index_document()` 를 기본 설정으로 한 번 돌리면 벡터 DB 바이너리가
저장소에 들어간다. 같은 이유로 `offline_config` 도 저장 위치를 `tmp_path` 로 덮게 고쳤다.
**여기서 막는 것은 키가 아니라 위치**라, embedding 때와 이유가 다르다.

## 7. 남은 것

- **실제 1536차원으로 한 번도 안 돌렸다.** `test_indexing_integration.py` 가 그 자리이고
  사용자 승인이 필요하다. 저장 크기·검색 지연이 가짜 8차원 기준이라는 뜻이다
- **backend 색인 엔드포인트가 없다.** `index_document()` 까지가 이번 몫이다. `IndexingError`
  매핑은 미리 넣어뒀으므로 엔드포인트만 붙이면 된다
- **`top_k=5` 는 임시값이다.** 근거는 `plan_log/평가-세트.md` 가 닫혀야 나온다
- **`search(filters=...)` 를 안 만들었다.** 사용자 결정이고, 쓸 축이 `document_id` 뿐이다 —
  `page` 는 HWPX 쪽 수 함정 때문에 못 쓴다. metadata 저장·반환은 된다
- **`.qdrant/` 유출을 테스트로 못 막았다.** 기본 설정으로 `index_document()` 를 부르는 코드가
  들어오면 다시 새어나갈 수 있다
- **모델을 바꾸면 옛 컬렉션이 디스크에 남는다.** 롤백과 맞바꾼 것이라 지금은 문제가 아니다
- **동시 접근을 안 쟀다.** qdrant 로컬 모드가 배타 잠금을 건다는 것은 확인했지만, 서버와
  스크립트가 실제로 부딪히는 상황은 재현하지 않았다
