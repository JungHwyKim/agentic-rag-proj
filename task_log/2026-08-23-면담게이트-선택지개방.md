# 면담 마지막 문항의 답만으로 계획 확정 게이트가 열리게 한다

- 작업일: 2026-08-23
- 검증 방법: 훅 단위 테스트(합성 payload 8축) + 대안 가드 변이 검사 1건 + 대화 전사 114건 대조 + 전체 pytest·ruff. **외부 API 호출 없음** (`-m integration` 안 돌림)

  *"그 답변만으로는 게이트가 안 열린다"* 가 이 작업으로 거짓이 됐다.

## 2. 설계 결정

### 답만 보고, 그 문항에 대안이 있었을 때만 연다

사용자 요청은 "선택지에서 골랐으면 바로 설계서가 나오게" 하나였다. 문제는 **무엇을 근거로
열 것인가**였고, 후보 셋을 대화 전사 114건(답 236개)으로 대조해 골랐다.

| 후보 | 열림 | 오탐 | 왜 안 골랐나 |
|---|---:|---:|---|
| 질문·선택지 텍스트까지 훑기 | 9 | 5 | 문구를 *논의하는* 문항이 전부 열린다 |
| 답만 보기 | 4 | 1 | 아래 오탐이 그대로 통과한다 |
| **답 + 대안 선택지 존재** (고름) | **3** | **0** | 누락도 0 |

가른 것은 오탐 1건의 정체다 — 선택지가 `'"설계서 작성" 포함 변형'` /
`'정확히 "설계서 작성해줘" 만'` 이라 **어느 쪽을 골라도 열리는 문항**이었다. 하필 이 훅의
문구 정규식을 정하던 라운드다. 진짜 3건은 전부 대안(`라운드 더` 등)이 있었다.

그래서 가드가 재는 것은 임계값이 아니라 **"사용자가 진짜 갈림길에서 골랐는가"** 다. 분포의
틈을 고를 필요가 없는 의미의 경계라는 점에서 `pdf.py:_MARK_AREA_RATIO` 와 같은 모양이다.
부수 효과로 **모델이 모든 선택지에 문구를 넣어 스스로 게이트를 여는 길**이 닫힌다.

버린 것 하나 더 — **`header` 를 고정값으로 못 박고 그 문항만 보기.** 그럴듯했지만 실측으로
그런 `header` 를 쓴 문항이 **0건**이라 진짜 3건을 전부 놓친다. 새 관례를 만들면서 근거는
하나도 없는 안이었다.

### 안내 한 줄을 세션당 1회로 묶지 않는다 — 기존 리마인더와 반대로

같은 훅의 `HINT`(plan mode 리마인더)는 `claim_session(HINTED_NS)` 로 세션당 한 번이다.
매 프롬프트마다 붙으면 그게 소음이기 때문이다. **`ANSWER_HINT` 는 반대 판단을 했다** —
게이트가 열리는 순간에만 나오고, 그때 안 나오면 모델이 사용자에게 문구를 다시 청한다.
그 왕복이 이 작업이 없애려던 바로 그것이라, 묶으면 두 번째 라운드부터 기능이 사라진다.

같은 이유로 `_in_plan_mode()` 로 감싸지 않았다. 리마인더는 *모든* 프롬프트에서 후보라 모드
확인이 필수지만, 이 경로는 트리거가 이미 좁다(114건 중 3건, 전부 설계 논의 세션). 반대로
그 필드를 못 읽는 하네스에서는 **경로가 조용히 통째로 죽는다** — 잃는 쪽이 훨씬 크다.

### `PreToolUse` matcher 는 안 넓혔다

`PostToolUse` 만 넓히면 되는데 대칭으로 맞추고 싶은 유혹이 있다. 넓히면 **면담 질문 자체가
`deny` 된다** — `_handle_pre_tool_use()` 는 `ExitPlanMode` 가 아니면 그냥 돌아가지만, 그
가드가 언젠가 느슨해지면 게이트가 자기 입력을 막는다. `test_other_tools_are_untouched` 를
`["Write", "AskUserQuestion"]` 로 parametrize 해 박아 뒀다.

부수적으로 `test_hook_wiring.py:NON_SHELL_PRETOOLUSE` 의 주석
(*"plan_interview_check 는 ExitPlanMode 만 본다"*)도 그대로 참으로 남는다.

### 답을 `tool_response` 와 `tool_input` 양쪽에서 찾는다

`_hookutil.prompt_text()` 가 `prompt`/`user_input` 을 둘 다 보는 것과 같은 판단이다. 저쪽은
이름을 하나로 믿었다가 **게이트가 한 번도 안 열린 채** 유지됐다(2026-08-21 발견). 이 도구는
스키마상 `answers` 가 **입력에도** 있어 하네스가 어느 쪽에 실을지가 계약이 아니다.

반대로 **짝을 못 지은 답은 버린다.** 선택지를 모르면 대안 가드를 못 걸고, 가드 없는 개방이
이 경로가 막으려는 바로 그것이다. 버려서 안 열려도 문구 경로가 살아 있어 사용자는 안 갇힌다.

## 4. 실패 분석

**막다른 길로 끝난 시도는 없었다.** 대신 전제 하나를 실측으로 뒤집었다.

CLAUDE.md 에 *"`AskUserQuestion` 의 선택지에 그 문구를 넣어 사용자가 골라도 **안 열린다.**
선택지 답은 도구 결과라 그 이벤트가 아예 안 생긴다(실측: 2026-08-22)"* 가 못 박혀 있었다.
**관찰은 맞았고 결론이 한 칸 넓었다** — 안 열린 이유는 `UserPromptSubmit` 이 안 생겨서지
답을 볼 방법이 없어서가 아니다. `PostToolUse` 는 도구 이름 matcher 라 이 도구에도 배선되고,
그 payload 의 `tool_response` 가 답을 통째로 담고 있다.

그대로 믿었으면 "하네스가 안 해준다"로 요청을 반려했을 것이다. **한 번 실측으로 닫은
문장이라도 그것이 닫은 범위를 다시 봐야 한다** — 저 문장이 실제로 증명한 것은
"`UserPromptSubmit` 은 안 생긴다" 하나였다.

**함께 드러난 별건 하나(안 고침).** 이 세션은 plan mode 라 저장소 파일을 하나도 안 고쳤는데
`task_log_check.py` 의 Stop 검사가 막았다. 세션 시작 마커는 10:48:31 인데 훅이 나열한 10개
파일 mtime 은 전부 09:38~10:11 로, **다른 세션의 미커밋 변경**이었다. 원인은 `_handle_stop()`
이 "기록했는가"는 세션 마커로 보면서 **"무엇이 바뀌었는가"는 `changed_paths()`(git status)**
로 보는 비대칭이다. 2026-08-17 에 닫은 버그의 뒤집힌 짝이고(그때는 지난 세션의 미커밋
*기록* 이 통과시켰다), 같은 docstring 이 "일을 하고도 막히는 오탐은 무력화의 한 형태"라고
적어둔 종류다. **이번 범위에 안 넣었다** — 다른 훅·다른 판정이고, 고치는 방향
(`paths_newer_than()`)이 "커밋 안 한 채 세션을 넘긴 작업"을 영영 안 걸리게 만드는 저울을
먼저 요구한다. `plan_log/plan-면담.md` 미결에 있다.

## 5. 회귀 테스트

전부 `tests/hooks/test_plan_interview_check.py` 다.

| 2·4절 항목 | 막은 테스트 |
|---|---|
| 답변으로 게이트가 열린다 | `test_answer_opens_the_gate` |
| **대안 없는 문항은 안 연다** (실측 오탐 그대로) | `test_answer_without_an_alternative_leaves_the_gate_closed` |
| 질문·선택지 텍스트로는 안 연다 | `test_phrase_only_in_the_question_leaves_the_gate_closed` |
| Other 자유입력도 받는다 | `test_free_text_answer_opens_the_gate` |
| 부정형 답을 거른다 | `test_negated_answer_leaves_the_gate_closed` |
| `tool_input` 폴백이 산다 | `test_answers_from_tool_input_open_the_gate` |
| 두 이벤트가 이어진다 | `test_exit_plan_mode_passes_after_an_answer` |
| 안내를 throttle 하지 않는다 | `test_answer_hint_is_emitted_every_time` |
| `PreToolUse` 가 면담 질문을 안 막는다 | `test_other_tools_are_untouched[AskUserQuestion]` |

**두 번째 줄이 이 변경의 핵심 회귀선이다.** 대안 가드를 `if True` 로 바꿔 돌리니 정확히
그 하나만 실패했다(1 failed, 149 passed).

**못 막은 것 둘.** ① 배선 — 단위 테스트는 핸들러를 직접 부르므로 `AskUserQuestion` 에
`PostToolUse` 가 실제로 도는지는 못 잰다. ② 모델이 선택지를 기울여 쓰는 경우 — 가드는
"대안이 있었나"만 보고 "그 대안이 진짜였나"는 못 본다. `SKILL.md` 규칙으로만 지탱한다.

  ④ 계획 제시 뒤 마커가 지워지고 재진입 시 다시 막히는가.

  `PostToolUse` 가 이 도구에 안 돈다는 것을 `plan_log/plan-면담.md` 에 기각 근거로 남기고
  문서를 되돌린다

  담아야 한다
