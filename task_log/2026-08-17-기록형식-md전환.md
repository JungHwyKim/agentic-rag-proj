## 2. 설계 결정

### 확장자만 바꾸는 안을 버리고, 문장은 그대로 둔 채 마크업만 얹었다.

`git mv` 만 하면 바이트가 완벽히 보존된다. 그런데 읽으라고 만든 문서가 안 읽히게 된다 —
열 0 의 `1.`~`7.` 절 제목이 하나의 순서목록으로 뭉치고, 공백으로 열을 맞춘 블록이 한 줄로
흐르고, `_hookutil` 같은 밑줄 식별자가 기울임이 된다. 그러면 `.md` 로 바꾼 값이 없다.

반대쪽 극단(문장까지 다듬는 재작성)도 버렸다. 이 저장소 기록의 값어치는 2절·4절 —
그때 무엇을 버렸고 무엇을 잘못 짚었나 — 에 있는데, 지금 아는 것으로 문장을 고치면
과거 기록이 아니라 현재의 요약이 된다.

그래서 규칙을 4개로 좁혀 기계적으로 적용했다: 첫 줄에 `#`, 열 0 의 `N. 제목` 에 `##`,
절 본문의 공통 들여쓰기(3칸)만 제거, 정렬이 뜻인 블록은 표 아니면 코드펜스.

### 표로 재구성하려면 원문에 열 이름이 이미 있어야 한다.

정렬 블록 처리는 사용자가 "진짜 마크다운 표" 로 골랐다. 다만 전부 표로 바꿀 수는 없다 —
열 이름 없이 들여쓰기로만 계층을 만든 블록(`routing-diff` 의 "실데이터 표 9개",
훅 시나리오 기대값, 회귀 테스트 목록)을 표로 만들려면 열 이름을 **지어내야** 한다.
지어낸 열 이름은 원문에 없던 해석이므로 그런 블록은 펜스에 원문 그대로 뒀다.

이 규칙은 실제로 한 번 어겼다가 얻었다 — 4절 참고.

### 정렬로만 표현된 대응 관계는 말로 남긴다.

splitter 기록의 `100자 미만 청크  6 / 0 / 3 / 3` 은 바로 위 4행(문서 4개)에 순서로
대응한다. 표로 바꾸면 그 시각 단서가 사라져 "위 표 순서" 를 덧붙였다.
**이번 변환에서 텍스트를 더한 자리는 여기 하나뿐**이고, 대조 스크립트가 이것을
화이트리스트로 따로 출력한다 — 조용히 통과시키면 다음에 두 곳이 되고 그다음엔 안 센다.

### 파일명은 확장자만 바꿨다. 날짜 소급 부여를 버렸다.

`phase1` 과 `routing-diff-시행령개정안` 만 날짜가 없다. 균일하게 만들 수 있었지만,
얻는 것은 이름의 균일함뿐이고 INDEX 링크와 `plan_log/*.md` 상호참조가 더 어긋난다.

## 4. 실패 분석

### (가) 대조 스크립트가 내 손실 두 건을 잡았다. 규칙보다 검증이 먼저 옳았다.

변환을 다 끝내고 스크립트를 돌리니 7개 중 2개가 틀렸다.

- `cleaner` 기록의 `검색 품질  : 해당 없음` 을 `### 검색 품질` + `해당 없음` 두 줄로
  올리면서 콜론 한 글자를 잃었다. 원문 한 줄 그대로 `### 검색 품질  : 해당 없음 …` 으로 되돌렸다.
- `splitter` 기록의 표 아래 세 줄에 라벨과 값을 가르는 `—` 를 더했다. 원문은 공백 두 칸으로
  갈라져 있었다. 공백은 정규화에서 지워지지만 `—` 는 안 지워진다 — **더한 게 맞으니 잡힌 것**이다.
  전부 걷어내 원문 표기로 돌렸다.

둘 다 "마크다운답게" 만들려다 생겼고 눈으로는 안 보였다. 계획에 검증을 넣지 않았으면
그대로 커밋됐을 것이고, 기록이 한 글자씩 조용히 달라지는 것이 이 작업에서 제일 나쁜 결말이다.

### (나) 열 이름이 없는 블록을 표로 만들었다가 되돌렸다.

`cleaner` 기록 2절의 신호 비교 블록을 마크다운 표로 바꿨다. 원문 셀이
`진짜 머리말 25.8%(HWPX) <-> 89.3%(PDF)` 인데, 이걸 `HWPX` / `PDF` 열로 쪼개면서
셀 안의 `(HWPX)` `(PDF)` 표기를 지워버렸다. 대조에서 걸리기 전에 알아채고 펜스로 되돌렸다.

여기서 2절의 규칙이 나왔다 — **원문에 열 이름이 있는 블록만 표로 만든다.** 열을 내가
만들어내는 순간 그건 옮기기가 아니라 해석이다.

### (다) 계획서에 R4b(펜스) 로 적어둔 블록을 R4a(표) 로 바꿨다.

`routing-diff` 의 "사용자 확인 vs 코드 검출" 대조표를 계획에서는 펜스로 분류해 뒀는데,
그 뒤 사용자가 "정렬 블록은 진짜 마크다운 표로" 를 골랐다. 그 블록은 열 이름(`사용자 확인` /
`코드 검출`)과 행 이름(`표` / `이미지`)이 원문에 다 있어 표 쪽이 맞다. 계획을 따르지 않고
사용자 선택을 따랐다 — 계획서의 그 줄이 선택 이전에 쓰인 것이었다.
