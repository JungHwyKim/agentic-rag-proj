# PDF 표 기본 핸들러를 llamaparse 에서 pymupdf 로 바꿨다

- 작업일: 2026-08-19
- 검증 방법: `pytest` 전체 + `ruff`. **외부 API 호출 없음** — 이 변경이 오히려 유료 호출을 끈다

## 1. 무엇을 바꿨나

- `rag_pipeline/config.py` — `ContentRoutingConfig.table_pdf_handler` 기본값을 `pymupdf` 로.
  왜 그 값인지를 주석으로 붙였다
- `.env.example` · `.env` — `TABLE_PDF_HANDLER=pymupdf`. `.env` 가 명시적으로 `llamaparse`
  를 덮고 있어 기본값만 바꾸면 실제 동작이 안 변한다
- `tests/ingestion/loader/content/test_router.py` — `_online_config()` 가 기본값에 기대
  LlamaParse 경로를 타고 있었다. `table_pdf_handler="llamaparse"` 를 명시로 바꿨다
- `CLAUDE.md` — 폴백 사슬 절에 "기본값이 `pymupdf` 라 이 경로가 꺼져 있다"를 근거와 함께 추가

## 2. 설계 결정

결정 자체는 [plan_log/표-경로.md](../plan_log/표-경로.md) 1회차에서 근거와 기각안까지 정했다.
여기서는 **구현하면서 갈린 것**만 적는다.

### `.env` 까지 바꾼다

기본값만 바꾸면 이 저장소에서는 아무 일도 안 일어난다 — `.env` 가 `llamaparse` 를 명시하고
있어 설정이 그걸 이긴다. "기본값을 바꾼다"의 의도가 동작을 바꾸는 것이므로 세 곳을 함께
고쳤다. `.env` 는 gitignore 라 커밋에는 안 실린다.

### 테스트를 기본값에 기대지 않게 한다

`_online_config()` 가 `table_pdf_handler` 를 안 넣고 기본값에 기대고 있었다. 기본값을 바꾸자
그 파일의 LlamaParse 테스트가 통째로 `table_native` 로 내려갔다. **주제가 LlamaParse 경로인
파일이 그 설정을 명시하지 않은 것 자체가 결함**이라, 기본값을 되돌려 맞추지 않고 테스트가
자기 전제를 적도록 고쳤다.

버린 안: `_online_config()` 를 그대로 두고 기본값 변경을 테스트 밖으로 미루기. 그러면 다음에
기본값을 또 바꿀 때 같은 자리에서 다시 깨진다.
