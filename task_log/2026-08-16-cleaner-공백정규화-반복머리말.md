## 2. 설계 결정

### 판정 신호로 '등장 횟수 비율'이 아니라 '걸친 폭'을 골랐다.

걸친 폭 = (마지막 등장 쪽 - 첫 등장 쪽 + 1) / 전체 쪽수

같은 문서(신뢰가능 AI 가이드)를 로더가 HWPX 97쪽 / PDF 28쪽으로 센다. 이 분모
차이에서 두 신호가 갈렸다.

```
등장 횟수 비율   진짜 머리말 25.8%(HWPX) <-> 89.3%(PDF)    요동친다
걸친 폭          진짜 머리말 93.8%(HWPX) <-> 89.3%(PDF)    거의 같다
```

분자와 분모가 함께 부풀기 때문이다. 오탐 후보(표 머리행 문구들)는 폭이
29.9~45.4% 라 60% 임계값에서 깨끗하게 갈린다. 50/60/70% 모두 픽스처 5개에서
오탐 0 이고, 오탐 최댓값 45.4% 와 진짜 최솟값 89.3% 사이에서 60% 가 양쪽으로
여유가 있다(아래로 1.32배 · 위로 1.49배).

같은 문서의 두 포맷에서 제거 개수가 똑같이 25개로 나오는 것이 이 선택의 증거다.

### 판정 대상을 PARAGRAPH 로 제한했다.

표를 넣으면 양식·체크리스트처럼 같은 표가 여러 쪽 반복되는 문서에서 진짜 데이터
표가 통째로 지워진다. 지금 픽스처에서 같은 표의 최대 반복은 2회(학교기록물,
AI 가이드 PDF)라 임계값 3쪽에 안 걸리지만 우연히 안전한 것이다.
문단만 봐도 판정 결과가 동일해(실측) 잃는 것 없이 위험만 없앤다.

### 텍스트가 아니라 '쪽 첫 요소'인 것만 지운다.

텍스트만 보고 지웠다면 표지·부제·뒤표지에 있는 같은 제목 3개까지 사라졌을
것이다. 실제로 두 포맷 모두 그 3개가 남는 것을 확인했다(p1 표지 / p2·p4 부제 /
p28·p97 뒤표지).

### 지운 내역을 warnings 가 아니라 removed_texts 에 남긴다.

처음에는 warnings 에 넣었다(4절 참고). warnings 의 정의는 "파싱 중 발생했으나
치명적이지 않았던 문제" 인데, 정상적으로 머리말을 지운 것은 문제가 아니다.
섞으면 파싱 경고를 보는 쪽이 노이즈에 묻힌다.

### 버린 것 — PUA(사설영역) 문자 제거.

U+F046, U+F031 같은 기호 폰트 글리프가 본문에 들어온다. 다만 픽스처 5개를
통틀어 8개(요소 3개)뿐이라 규칙 하나를 늘릴 값어치가 없다고 판단했다.

### 버린 것 — 꼬리말(쪽 마지막 요소) 방향.

대칭으로 구현하면 쉽지만, 픽스처 5개에 임계값을 넘는 꼬리말이 0건이라 검증할
데이터가 없다. 검증 안 된 삭제 경로를 기본으로 켜지 않기로 했다.

### 버린 것 — order 재부여.

지운 자리의 번호를 메워 0..n-1 로 만들 수도 있었다. order 의 계약상 용도는
정렬 하나뿐이고(schemas/document.py) elements 에는 이미 빈틈이 있다 —
image_handler="skip" 으로 이미지 리전이 요소를 0개 만든 자리가 시행령 문서에서만
12개다. 지키지도 못하는 연속성을 위해 전 요소의 order 를 덮어쓰고 의미를
"정리 후 위치" 로 바꿀 이유가 없다.

## 4. 실패 분석

등장 횟수 비율 20% 로 설계를 확정하고 "픽스처 5개·포맷 2개에서 오탐 0, 가장 가까운
생존자 8.3% 대비 2.4배 여유" 라고 사용자에게 보고까지 했다. 틀렸다.

사용자가 "AI 가이드 PDF 89.3% 지워짐이 무슨 말이냐" 고 물어서 표를 다시 설명하다
같은 문서인데 HWPX 97쪽 / PDF 28쪽인 것을 발견했다. PDF 파일 자체를 열어보니
28쪽이었다. 즉 HWPX 쪽 계산이 과다 분할하고 있고, 등장 비율의 분모가 틀려 있었다.

쪽 수가 교정되면 'AI 활동'·'기획'·'도입/설치/운영'·'AI 원칙 실행가이드'·
'기획자/감리사' 다섯 개가 6.2% -> 21.4% 로 뛰어 임계값 20% 를 넘는다. 전부
문단이라 문단 제한으로도 못 막는다. 즉 내가 근거로 댄 "2.4배 여유" 는 버그가
만든 착시였고, 쪽 계산을 고치는 순간 오탐이 시작될 설계였다.

교훈: 비율을 쓸 때 분모가 신뢰할 수 있는 값인지 먼저 확인해야 한다. 같은 문서의
두 포맷을 비교하지 않았으면 못 잡았다.

지운 내역을 warnings 에 넣었다가 되돌렸다.

pytest 에서 test_extracts_body_without_warnings(로더 테스트)가 깨지며 드러났다.
그 테스트는 "파싱에 경고가 없어야 한다" 를 보는데, 머리말을 정상 제거한 사실이
같은 칸에 들어가 파싱 실패처럼 보였다. removed_texts 필드를 따로 만들어 갈랐다.
테스트가 설계 오류를 잡아준 사례다.

test_characters.py 가 세 규칙을 다 태우고 있었다.

1차 때는 규칙이 하나뿐이라 clean() 기본값으로 테스트해도 됐는데, 규칙이 늘자
'\t 가 남는다' 단언이 깨졌다(공백 규칙이 탭을 공백으로 줄인다). 텍스트가 왜
바뀌었는지 못 가리는 상태였다. 파일마다 자기 규칙만 켜도록 격리했다.
