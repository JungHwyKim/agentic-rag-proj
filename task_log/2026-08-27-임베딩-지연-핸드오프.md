## 0. 이 문서를 믿기 전에 트리와 대조한다

**핸드오프는 가설이다.** 이 저장소는 세션 여럿이 동시에 쓰고, 이 세션에서만 다른 세션이
커밋을 여섯 번 넣었다. 아래 넷을 **먼저** 확인하고 시작한다.

| 확인할 것 | 어떻게 | 이 문서를 쓸 때의 값 |
|---|---|---|
| 리랭커가 켜져 있나 | `.env` 의 `RERANK_PROVIDER`·`RERANK_MODEL`·`RERANK_DEVICE` | `local` · `BAAI/bge-reranker-v2-m3` · `cuda` (**저장소 커밋본은 꺼진 채다**) |
| 임베더가 GPU 인가 | `.env` 의 `EMBEDDING_DEVICE` | `cuda` · 모델 `nlpai-lab/KURE-v1` · `EMBEDDING_BATCH_SIZE` 는 코드 기본값 100 |
| 대상 파일이 있나 | `original_files/` — **gitignore 라 다른 머신엔 없다** | `260630_(EU TRQ) OJ_L_202601457_EN_TXT__1e4cfb.pdf` · 1,780,529바이트 · sha256 앞 12자 `be7a8a5e5544` |
| GPU·서버를 누가 쓰나 | `ListAgents` 로 피어 확인 + `netstat -ano \| grep :8000` | 이 세션은 `--reload` 로 도는 uvicorn 하나를 쓰고 있었다 |

**대상 파일이 없으면 아무 문서나 쓰면 안 된다.** 이 건의 성질은 **청크가 길다**는 것이다
(청크당 1,011자 · 총 183,007자). 짧은 청크 문서로 재면 문제가 안 나타난다.
없으면 사용자에게 그 PDF 를 다시 올려 달라고 청한다.

## 1. 확정된 것 — 다시 재지 않아도 된다

**테서랙트도 Vision 도 아니다.**

| 항목 | 실측 |
|---|---|
| 문서 | 28쪽 · 추출 가능한 텍스트 54,035자(쪽당 1,930자) · **이미지 1개** |
| `detect_regions` | 2.54초 · 리전 658개 (TEXT 651 · TABLE 6 · IMAGE 1) |
| `classify` | 0.37초 · 이미지 1개가 **OCR** 로 갈림, VISION 0 |
| **파싱+청킹 전체** | **3.30초** (`ingest` 3.29 + `split` 0.01) |
| 청킹 결과 | **청크 181개 · 183,007자 · 청크당 평균 1,011자** |
| `.cache/content` | 그 시간대 **0건** → Vision·LlamaParse 호출 자체가 없었다 |

**서버에서 시간이 간 곳도 확정이다.** 임베딩 캐시 파일의 mtime 을 **모델 salt 로 갈라** 얻었다
(주 임베더와 그림자는 salt 가 달라 캐시 파일이 갈린다).

| 무엇 | 구간 | 걸린 시간 |
|---|---|---|
| 주 임베딩 (KURE · 로컬 GPU) | 01:20:08 ~ 01:24:41 | **272.9초** |
| 그림자 (OpenAI) | 01:24:50 ~ 01:24:52 | **1.3초** |

업로드 임시파일이 `01:17:46` 이니 앞 구간까지 합쳐 **7분 6초**, 그중 파싱은 3.3초다.
**네트워크(그림자)는 무관하다.**

가르는 방법이 다시 필요하면 이 조각이다.

```python
from rag_pipeline.ingestion.embedding.base import cache_salt_for
from rag_pipeline.ingestion.loader.content.base import content_hash
from backend.app.core.config import SHADOW_EMBEDDING

salt = cache_salt_for(config)                      # 주 임베더 / SHADOW_EMBEDDING 각각
path = Path(".cache/embedding") / f"{content_hash(text.encode('utf-8'), salt=salt)}.json"
path.stat().st_mtime                               # 이 청크가 언제 임베딩됐나
```

## 2. 확정 안 된 것 — 그리고 **이미 세 번 헛짚었다**

| 헛짚은 결론 | 무엇이 틀렸나 |
|---|---|
| *"워밍업이 모델을 안 들고 있다"* | VRAM 이 낮은 것만 보고 세웠다. `warmup_errors == []` 이고 캐시에 흔적도 있었다(워밍업 입력이 `uuid4` 라 늘 한 줄씩 미스로 남는다) |
| *"`--reload` 가 워밍업을 무력화한다"* | 커밋까지 갔다(`c6ec8a5` → `a3c3c81` 로 되돌림). `--reload` 없는 서버 하나를 유휴로 두고 재니 `4959 → 542 → 7686 → 322 MiB` 로 움직였다 |
| *"배치 크기가 손잡이다"* | 스윕이 100/48/24/12 = 471.75 / 412.82 / 209.71 / 369.34초로 **단조롭지 않았고**, 같은 `batch=48` 이 다른 회차에서 **16.16초**였다 |

**공통 원인은 이 머신의 GPU 수치가 불안정하다는 것이다.**

- `nvidia-smi --query-gpu=memory.used` 가 **요청 없이 유휴로 둔 같은 프로세스**에서 7GB 넘게
  오르내린다(위 4959 → 322). WDDM 이 GPU 메모리를 가상화해 밀어내는 것으로 보인다
- `nvidia-smi --query-compute-apps` 는 프로세스별 메모리를 전부 `[N/A]` 로 낸다 — **귀속을
  못 본다.** "누가 들고 있나"를 이 도구로는 못 묻는다
- 그래서 **VRAM 숫자를 근거로 결론을 내면 안 된다.** 위 셋이 전부 그렇게 났다

한 번은 경합 가설과 맞는 그림도 나왔다 — 리랭커를 함께 올린 회차가 **283.09초**로 서버의
272.9초와 거의 일치했고, 상주분이 3015 → 5173 MiB 로 늘며 임베딩 활성값 여유가 4.7GB →
2.5GB 로 반토막이었다. **그러나 위 편차 때문에 이 일치를 근거로 쓸 수 없다.**

## 3. 그래서 무엇을 어떻게 재나

**전제 넷을 지켜야 답이 나온다.**

1. **서버를 내린다.** 같은 GPU 를 잡고 있으면 변인이 둘이 된다. 내리기 전에 `ListAgents` 로
   다른 세션이 쓰는지 확인한다(사용자 소유 프로세스다 — 승인을 받고 내린다)
2. **설정마다 3회 이상 돌리고 중앙값을 본다.** 1회는 이 건에서 이미 두 번 배신했다
3. **순서를 섞는다** — `A B A B A B`. 앞 회차가 뒤를 데운다(`16.16초` 가 정확히 그 자리였다:
   283초짜리 직후에 같은 설정이 16초로 나왔다)
4. **임베딩 캐시를 끈다**(`embedding_cache_enabled=False`). 안 끄면 두 번째부터 전량 히트라
   0초가 나온다

**가르는 변인은 하나다 — 리랭커를 함께 올리는가.** 배치 크기는 이번에 근거가 안 섰으므로
같은 회차에 섞지 않는다(변인이 둘이 되면 또 못 가른다).

```python
# scratchpad 에 두고 저장소에 남기지 않는다. PYTHONPATH=. 로 저장소 루트에서 돌린다.
# 무료다 — 로컬 모델만 쓰고, index_document() 를 안 타므로 그림자(OpenAI)를 안 부른다.
import statistics, subprocess, time, uuid
from pathlib import Path

from backend.app.api.routes.query import _warmup_candidates
from rag_pipeline.config import ContentRoutingConfig, EmbeddingConfig, IngestConfig
from rag_pipeline.ingestion.embedding import get_embedder
from rag_pipeline.ingestion.indexing import document_id_for
from rag_pipeline.ingestion.pipeline import ingest
from rag_pipeline.ingestion.splitter import split
from rag_pipeline.retrieval import get_reranker

TARGET = next(Path("original_files").glob("*EU TRQ*"))
KEY = "260630_(EU TRQ) OJ_L_202601457_EN_TXT.pdf"

free = IngestConfig()
object.__setattr__(free, "_content", ContentRoutingConfig(image_handler="ocr", table_pdf_handler="pymupdf"))
texts = [c.text for c in split(ingest(TARGET, original_name=KEY, config=free),
                               free.splitter, document_key=document_id_for(KEY))]
assert len(texts) == 181, f"청크 수가 달라졌다: {len(texts)} — splitter 가 바뀌었는지 본다"

cfg = IngestConfig()
cold = EmbeddingConfig(**{**cfg.embedding.model_dump(), "embedding_cache_enabled": False})


def run(with_reranker: bool) -> float:
    """프로세스를 새로 띄워 한 회차를 잰다. 같은 프로세스에서 리랭커를 '내릴' 방법이 없다."""
    e = get_embedder(cold)
    if with_reranker:
        r = get_reranker(cfg.rerank)
        q = str(uuid.uuid4())          # 캐시에 걸리면 가중치가 안 올라온다
        r.rerank(q, _warmup_candidates(q))
    e.embed_documents(texts[:1])       # 가중치 적재를 시간에서 뺀다
    e.usage.reset()                    # max_embedding_tokens_per_doc 이 회차 간에 누적된다
    t = time.perf_counter()
    e.embed_documents(texts)
    return time.perf_counter() - t
```

**`run()` 은 회차마다 프로세스를 새로 띄워야 한다** — 한 프로세스 안에서 리랭커를 내릴 수단이
없어서, 같은 프로세스로 A/B 를 섞으면 "리랭커 없음" 회차가 실은 리랭커가 올라온 상태가 된다.
바깥에서 `subprocess` 로 `python -c "...; print(run(True))"` 를 번갈아 여섯 번 부른다.

## 4. 판정 기준

- **두 중앙값이 2배 이상 갈리고, 각 조건 안의 3회 편차가 그보다 작으면** → 경합 확정.
  그때 비로소 *"리랭커를 GPU 에서 내린다"* 가 근거 있는 선택이 된다
- **안 갈리거나 편차가 여전히 더 크면** → 이 축이 아니다. 다음 후보는 셋이다
  (a) 청크 길이 자체(1,011자 · 이 코퍼스 평균의 2배) (b) sentence-transformers 의 길이 정렬·
  패딩 (c) WDDM 페이징 — 이 경우 **이 머신에서는 못 닫는다**로 적고 넘기는 것도 답이다
- **어느 쪽이든 `EMBEDDING_BATCH_SIZE` 는 지금 근거가 없다.** 스윕이 단조롭지 않았다

## 5. 비용

- **위 절차는 과금 0이다.** `index_document()` 를 안 타므로 그림자(OpenAI)가 안 불린다
- **서버 경유로 재색인을 반복해 재면 회차마다 그림자 임베딩이 유료로 나간다.**
  이 세션에서 실제로 그렇게 세 번 냈고 **사전 승인을 못 받았다**. 그림자는 `.env` 에 안 보이고
  `.qdrant/collection/` 에 `documents_text-embedding-3-small_default` 가 있는 것으로만 드러난다
- 리랭커를 유료로 옮기는 안은 **적재 문제와 별개로** 근거가 있다(품질 동률: 리랭킹이 실제로
  걸린 같은 50건에서 로컬 0.6992 vs 유료 0.7070). 대가는 질의당 과금과 **17% 폴백**이다.
  적재를 고치려고 사는 것은 위 판정이 난 뒤에 정한다

## 7. 배경 — 이 문제가 어떻게 열렸나

사용자가 *"새 문서 하나에 1분"* 을 물어 시작했고, 그 건은 **임베딩 모델을 문서마다 다시
올리던 것**이라 `b98b02e`(`index_document(embedder=)` 주입)로 닫혔다. 이 핸드오프는 **그다음에
올라온 다른 문서**(EU TRQ · 6~7분)이고, 원인이 다르다 — 모델 적재가 아니라 임베딩 연산
자체다. 두 건을 섞지 말 것.
