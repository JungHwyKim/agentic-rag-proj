# 판정 채점 도구에 재작성 축을 열었다 — 물음은 「off/fuse 가 오염됐나」였고 답은 **반대쪽**이었다

- 작업일: 2026-08-29
- 검증 방법: ruff + 전체 pytest + **변이 검사 2종**. 3절 실측은 저장소에 이미 있는
  리포트·세트 파일을 읽은 것이라 **외부 API 호출 0회**. 계단 세 판(유료)은 **안 돌렸다** —
  사용자 승인 대기. `-m integration` 미실행

## 1. 무엇을 바꿨나

- `evaluation/verdicts.py`
  `--rewrite` 축을 열었다(`score_verdicts(rewrite=)` → `eval_config` → `get_rewriter()` →
  `retrieve(rewriter=)`). 그리고 결과 JSON 이름을 `report_name()` 으로 뽑아 **리랭커·재작성까지**
  넣었다. `meta` 에 재작성·리랭킹 회계 여섯 칸이 늘었다
- `tests/evaluation/test_verdicts.py`
  축이 실제로 검색에 닿는가 · 꺼짐이 `None` 으로 가는가 · 이름이 계단 세 조합을 가르는가 셋

`.claude/hooks/auto_test_check.py` 와 `evaluation/config.py` 는 **안 고쳤다** —
`("evaluation/", "tests/evaluation")` 매핑이 이미 있고, 쓸 프로필 넷(`local-gpu`·`cohere`·
`off`·`fuse`)도 이미 있다.

## 2. 설계 결정

### 물음을 먼저 뒤집었다 — 오염된 것은 off/fuse 가 아니라 혼동행렬 쪽이다

사용자 물음은 *«혼동행렬이 전부 `local-gpu` 인데 운영은 `cohere` 다. 이것도 off/fuse 비교에
영향을 주나»* 였다. **답은 «아니다» 이고, 그것이 착수 전 첫 일이었다.**

- `score_verdicts()` 가 `eval_config()` 에 `rewrite=` 를 안 넘기고 `retrieve()` 에 `rewriter=`
  도 안 넘긴다. 혼동행렬 넷은 전부 **`rewrite=off` 고정**이라 이 도구는 off/fuse 를
  **한 번도 물은 적이 없다.** 거꾸로 35~39·43회차의 off/fuse 결론도 혼동행렬을 근거로 안 쓴다
- 「리랭커가 off/fuse 를 가른다」는 참이지만(39회차) **그 답이 이미 운영 리랭커 위에서 났다** —
  `cohere` 흡수됨(조합이 리랭커 단독을 이긴 질의 **0/60**)이고 43회차 판 2도 `cohere` 다.
  여기서 `local-gpu` 는 오염원이 아니라 **반대편 대조군**이다

**뒤집으면 실재하는 구멍이 나온다** — 어긋난 축이 리랭커 하나가 아니라 **넷**이다
(리랭커 · 재작성 `off`↔`fuse` · 라벨 `answerable` 21↔18/25 · 프롬프트 판 표기 이전↔`v3`).
B-1 이 18·20·21회차부터 같은 줄을 적어 두었는데, **새로 생긴 것은 소비자다**: 44회차가
재시도 루프를 화면에 이었고 그 루프는 `insufficient` 로 흐름을 가른다. 판정을 운영 조건에서
안 쟀다는 것이 곧 **루프가 언제 도는지를 안 쟀다**는 뜻이다.

**버린 것** — *«리랭커 축만 닫자»*(도구 그대로 `--rerank cohere` 한 판). 리랭커는 닫히지만
재작성이 여전히 `off` 라 **또 운영이 아닌 세 번째 표**가 생기고, 다시 재는 것이 유료다.

### 대조군을 3판 계단으로 — 축을 하나씩만 민다

`local-gpu×off` → `cohere×off` → `cohere×fuse`. 컬렉션은 `h-cohere-18w3` 하나로 못 박는다.

**버린 것 둘** — *2판*(라벨 갱신본 + 운영본)은 두 축이 함께 움직여 **차이의 출처를 못 가른다.**
*1판*(운영만)은 제일 싸지만 옛 넷과 견줄 자리가 없다. 43회차가 컬렉션을 하나로 고른 것과
같은 잣대다 — «컬렉션이 달라서 갈렸나» 를 남기지 않는다.

**1판은 옛 표의 재현이 아니라 새 기준선이다.** 옛 넷은 라벨이 21건이고 `mini` 표는 프롬프트
판 표기 이전이라, 1판이 옛 표와 다른 것을 리랭커 탓으로 읽으면 안 된다 — **계단이 필요한
이유가 그것이다.**

### 꺼짐 처리를 `retry_diff` 와 반대로 했다

`retry_diff.py` 는 재작성이 꺼지면 `SystemExit` 로 멈춘다. 저쪽은 *재시도가 질의를 바꾼 회차*
를 재므로 재작성이 곧 **재는 대상**이기 때문이다. **여기는 반대다** — `off` 가 기본값이자
계단의 첫 칸이고, 지금까지의 혼동행렬이 전부 그 위에서 나왔다.

**모양이 제일 비슷한 파일을 베끼면 여기서 틀린다** — 저쪽 가드를 그대로 옮기면 **기본 실행이
죽는다.** `hybrid.py:retrieve()` 가 이미 `rewriter is None` 을 가르므로 `None` 을 그대로
넘기는 것이 곧 «재작성 없이 도는 경로» 다. 모듈 docstring 에 두 도구가 왜 갈리는지 적었다.

### 리포트 이름을 넓혔다 — 안 넓히면 계단 세 판이 서로를 덮는다

지금 이름은 `{label}-verdicts-{evaluator}-{prompt}.json` 이라 계단 셋이 전부
`h-cohere-18w3-verdicts-mini-v3.json` **한 자리를 다툰다.** 13회차가 luna v1 로 v3 표를
실제로 잃어 프롬프트 판이 들어갔는데, **그때는 리랭커·재작성 축이 없었다.**
`answer_eval.report_name()` 이 43회차에 `rerank`·`top_k` 를 넣은 것과 같은 자리다.

**`top_k` 는 안 넣었다** — 한 실행이 `--top-k 5 10` 을 **한 파일의 `runs`** 로 담아
`answer_eval` 과 사정이 다르다.

### 회계 칸을 `meta` 에 실었다 — 계획에 없던 유일한 추가

계획은 `rewrite_*` 만 적었는데 `rerank_calls`·`rerank_cache_hits`·`rerank_reranked`·
`rerank_candidates` 도 함께 실었다. **게이트를 리포트에서 바로 읽을 수 있어야 하기 때문**이고,
로컬 갈래의 게이트가 `rerank_reranked / rerank_candidates + rerank_cache_hits` 라
**`reranked` 없이는 「돌았다」와 「안 돌았다」가 안 갈린다**(40회차). 없으면 판마다 별도
스크립트를 써야 하고, 그 스크립트는 기록에 안 남는다.

## 4. 실패 분석

**계획의 「무료 배선 확인」이 실은 무료가 아니었다.** 검증 4번에 *«`--rerank off --rewrite off`
로 한 판 돌려 옛 코드와 표가 같은지 본다»* 를 적었는데, **판정 호출은 리랭커와 무관하게 돈다** —
43건 × 2 `top_k` = 86 유료 호출이고, 기존 표가 `local-gpu` 위에서 나와 `off` 순위는 판정 캐시가
전량 미스다. 승인 없이 돌릴 수 없어 **안 돌렸다.** 그 자리는 변이 검사 둘과 기본 인자 경로의
단위 테스트가 대신 지킨다 — 다만 **«진짜 `QueryRewriter` 가 이 경로에서 돈다» 는 아직 미확인**이고
7절에 적었다.

**긴 heredoc 이 또 한 번 접혔다.** 250줄짜리 패치 스크립트를 `cat <<'PYEOF'` 로 쓰려다
`unexpected EOF while looking for matching '` 로 죽었다 — 2026-08-28 채점자 회차가 겪은 것과
같은 모양이다. 파일은 안 생겼고 `evaluation/verdicts.py` 도 안 건드려졌다(`git status` 로 확인).
편집 도구로 갈아타 12조각으로 나눠 넣었다. **긴 편집을 한 heredoc 에 담지 않는다.**

**회차 번호를 두 번 고쳤다.** 세션 시작 스냅샷(`gitStatus`)에는 마지막이 43회차였고 계획을
쓸 때 파일을 보니 44까지였는데, 회차를 적으려는 순간 **46까지 있고 워킹트리가 깨끗**했다.
피어가 그 사이 셋을 커밋한 것이다. 45로 잡았다가 47로 고쳤다. **핸드오프는 가설이라
쓰기 직전에 다시 본다** 가 여기서 값을 했다(46회차도 같은 자리에서 같은 일을 겪었다).
