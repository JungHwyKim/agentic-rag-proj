## 2. 설계 결정

### (a) 자동 테스트 훅을 PostToolUse 에 달았다. PreToolUse 를 버렸다.

취향이 아니라 강제였다. tests/hooks/test_hook_wiring.py 의
test_pretooluse_covers_both_shells 가 PreToolUse 의 *모든* matcher 에
re.fullmatch(matcher, "Bash") 와 "PowerShell" 을 요구한다. matcher 를
"Write|Edit" 로 둔 PreToolUse 그룹을 추가하면 그 테스트가 깨지고, 그러면
pre_commit_check 가 커밋 자체를 막는다.

그 테스트를 고치는 선택지도 있었지만 버렸다. 테스트가 옳다 — PreToolUse
matcher 가 한쪽 셸만 덮으면 도구를 Bash 에서 PowerShell 로 바꾸는 것만으로
유료 테스트 차단도 커밋 전 검사도 통째로 우회된다.

### (b) 테스트를 두 층으로 갈랐다. 매 편집마다 전체 pytest 를 버렸다.

실측(이 세션):

```
전체                        234개  18.3초
tests/ingestion/cleaner      40개   6.7초
tests/ingestion/loader/document 84개 5.3초
tests/ingestion/loader/content  38개 3.1초
tests/hooks                  46개   0.6초
tests/api                     7개   0.6초
```

한 작업에서 파일을 대여섯 번 고치면 그 차이가 그대로 쌓인다. 대신 영역별은
그 영역만 보므로 Stop 에서 전체를 한 번 돌려 메운다.

### (c) config.py / schemas/ / exceptions.py / tests/conftest.py 는 **일부러 매핑하지 않았다**(UNMAPPED_BY_DESIGN).

전 영역에 영향을 주므로 부분 실행이 무의미하다. 그냥 빼면 "빠뜨린 것"과
구별이 안 되므로 명시적 집합으로 뒀다. test_hook_wiring.py 의
LIBRARY_MODULES = {"_hookutil.py"} 와 같은 역할이다.

### (d) 매핑 누락을 산문이 아니라 테스트로 막았다.

사용자가 "새 단계가 추가될 때 테스트 매핑도 함께 추가한다" 를 규칙으로 넣자고
제안했다. 방향은 맞지만 CLAUDE.md 한 줄로는 못 막는다 — paid_test_check.py 가
그 교훈을 남겼다. -m integration 금지는 CLAUDE.md·스킬 3개·에이전트까지 5곳에
적혀 있었는데도 "전부 모델을 향한 설득"이었고, 그래서 훅으로 못박았다.

그래서 배선 테스트의 짝을 만들었다:

```
test_every_hook_script_is_wired  <->  test_every_stage_is_mapped
test_wired_scripts_exist         <->  test_mapped_targets_exist
LIBRARY_MODULES                  <->  UNMAPPED_BY_DESIGN
```

새 단계를 만든 사람의 선택지는 둘뿐이 된다 — 매핑을 넣거나, 안 넣는 이유를
UNMAPPED_BY_DESIGN 에 적거나. 아무것도 안 하면 pytest 가 실패하고
pre_commit_check 가 커밋을 막는다. 산문은 CLAUDE.md 6단계에 보조로만 뒀다.

### (e) retrieval-specialist 와 rag-evaluator 를 **얇게** 썼다. 상세 설계를 버렸다.

청크 전략·하이브리드 가중치·리랭커를 지금 쓰면 대부분 폐기되고, 폐기된 안이

5절이 "못 막았다"고 적어둔 것을 막았다. 훅의 시간 제한은 두 겹인데
(바깥 = settings.json 의 timeout, 안쪽 = 훅 코드의 *_TIMEOUT_SEC),
안쪽이 더 짧아야 훅이 스스로 멈추고 사유를 남길 수 있다. 뒤집히면 훅이 침묵한 채
강제 종료되고 검사가 안 돌았다는 것조차 아무도 모른다.

순진하게 '내부 제한의 합 < 바깥' 으로 짰다면 pre_commit_check 가 멀쩡한데도
실패한다 — 검사 4개의 합이 120+120+120+600=960 인데 예산은 900 이다. 이건 버그가
아니라 의도된 설계다. 개별 검사가 걸렸을 때 사유를 남기는 것이 목적이라 제일 큰
하나(600)가 예산 안에 들면 충분하다.

이벤트별로 가른 이유: auto_test_check 는 PostToolUse 에서 영역별(90초)만,
Stop 에서 전체(540초)만 돈다. 한쪽으로 뭉뚱그리면 Stop 예산(600)으로 PostToolUse
를 재게 돼 검사가 무의미해진다.

### (k) code_reviewer_plan.md 를 '커밋한 뒤 삭제' 했다. 그냥 삭제를 버렸다.

이미 실행 완료된 지시서(커밋 6041b47)가 루트에 untracked 로 떠 있었다. 루트에
"이렇게 만들어라"가 있으면 나중에 보는 사람이 아직 안 한 일로 착각한다.

그냥 지우면 git 이 추적한 적이 없어 복구할 수 없다. 그래서 둘로 나눴다 —
있는 그대로 한 번 커밋해 이력에 박고, 다음 커밋에서 지운다. 한 커밋 안에서
추가와 삭제가 상쇄되면 이력에 아무것도 안 남으므로 반드시 나눠야 한다.
이후 `git show <커밋 SHA>:code_reviewer_plan.md` 로 언제든 꺼낼 수 있다.

## 4. 실패 분석

### (a) 훅이 조용히 아무것도 안 하고 있었다. 원인은 BOM 이었다. **되돌리지 않고 공용부를 고쳤다.**

배선 확인을 하는데 cleaner 편집 payload 를 넣어도 0.1초 만에 exit 0 으로 끝났다.
tests/ingestion/cleaner 는 6.7초가 걸리므로 안 돌았다는 뜻인데, 에러도 경고도
없었다.

PowerShell 이 파이프에 UTF-8 BOM 을 붙인다. _hookutil.read_payload() 는
encoding="utf-8" 로 읽고 있어서 json.load 가 "Unexpected UTF-8 BOM" 으로
죽는데, 그건 ValueError 하위라 read_payload 의 except 에 먹혀 None 이 되고,
"판단 근거 없음 = 통과" 경로로 조용히 빠진다.

제일 나쁜 건 이게 auto_test_check 만의 문제가 아니라는 점이다.
**task_log_check.py 와 plan_log_check.py 도 같은 구멍을 갖고 있었다.**
셋 다 _hookutil.read_payload() 를 쓴다.

그리고 이건 이 저장소가 이미 한 번 겪은 함정이다. paid_test_check.py 는 자체
stdin 읽기에 utf-8-sig 를 박아두고 docstring 에 "실제로 이 훅을 검증하다
겪었다" 라고 적어놨다. **그 교훈이 공용부로 오지 않아서 다시 걸렸다.**

고침: _hookutil.read_payload() 를 utf-8-sig 로 바꿨다. BOM 이 없는 입력도
그대로 읽으므로 잃는 것이 없다.

### (b) BOM 회귀 테스트를 쓰다가 import sys 를 빠뜨렸다. 방금 만든 훅이 그걸 잡았다.

Edit 직후 PostToolUse 훅이 tests/hooks 를 돌려 NameError 두 개를 stderr 로
되먹였다. 계획서에 "일부러 깨는 변경을 넣어 확인한다"고 적어둔 검증을
실수로 대신 한 셈이다. 훅이 의도대로 돈다는 제일 강한 증거다.

### (c) ruff 2건.

SIM102(중첩 if)와 I001(import 정렬). 고쳤다.
tests/hooks 는 sys.path 로 얹는 평평한 모듈이라 auto_test_check 가
서드파티(pytest)보다 먼저 와야 한다.
